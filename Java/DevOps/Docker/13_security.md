
# 1. 先明确威胁模型：你要防什么

容器不是虚拟机，它共享宿主机内核。Docker 安全问题通常集中在：

1. **镜像供应链**：镜像里混入恶意代码、漏洞依赖、后门。
2. **运行时逃逸**：容器内进程利用内核漏洞/配置不当拿到宿主机权限。
3. **权限过大**：`--privileged`、挂载 docker.sock、过多 capabilities。
4. **敏感信息泄露**：镜像层、环境变量、日志、卷。
5. **网络暴露面**：不必要的端口暴露、弱口令服务直接暴露公网。

工程结论：Docker 安全不是“某个参数”，而是一套从构建到运行的边界治理。

# 2. 镜像安全：最小化与可追溯

## 2.1 最小化镜像与攻击面

1. 使用多阶段构建，把构建工具链留在 builder stage。
2. 选择更小的运行时基础镜像（distroless/alpine/精简版 JRE 等，结合你的兼容性要求）。
3. 用 `.dockerignore` 排除 `.git`、本地缓存、密钥文件等。

## 2.2 漏洞扫描与依赖治理

建议把扫描放入 CI：

1. 定期扫描基础镜像与业务镜像。
2. 对高危漏洞设置阻断策略（例如 CVSS>=9 阻断）。

提示：扫描不等于修复；修复路径通常是升级基础镜像/依赖版本、或做补丁。

## 2.3 tag 与 digest

1. tag 可能被覆盖。
2. digest 是不可变标识。

生产关键环境建议以 digest 锁定部署版本（避免 tag 漂移）。

# 3. 运行时权限：最小权限原则

## 3.1 不要用 `--privileged`

`--privileged` 近似把宿主机能力开给容器，除非你非常清楚代价（例如某些特殊的系统级容器）。

## 3.2 capabilities：只加需要的，能删就删

Docker 默认会给一组 capabilities。

策略：

1. 优先 `--cap-drop=ALL`，再按需 `--cap-add`。
2. 避免给 `SYS_ADMIN`（这是著名的“准特权”能力）。

示例：

```bash
docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE my-app:1.0
```

## 3.3 以非 root 用户运行

建议：

1. Dockerfile 用 `USER` 指定非 root。
2. 宿主机上挂载目录的权限要配合调整。

## 3.4 文件系统只读 + tmpfs

```bash
docker run --read-only --tmpfs /tmp:rw,noexec,nosuid,size=64m my-app:1.0
```

价值：

1. 降低被写入后门文件的概率。
2. 强制你把“需要写”的目录显式挂载出来（更清晰的边界）。

# 4. 最危险的配置之一：挂载 docker.sock

```bash
-v /var/run/docker.sock:/var/run/docker.sock
```

风险：

1. 拿到 docker.sock 基本等价拿到宿主机 root（可以启动特权容器、挂载宿主机根目录等）。

建议：

1. 尽量不要把 docker.sock 暴露给业务容器。
2. 如果是 CI 场景，优先使用更隔离的方案（例如远程构建、受控的 build service）。

# 5. 网络暴露面：默认最小开放

建议：

1. 容器间互访用内部网络，不要把所有服务都 `-p` 暴露到宿主机。
2. 对外只暴露入口（网关/Nginx/API），内部 DB/Redis 不映射端口。
3. 避免把 Docker API、数据库端口直接暴露公网。

# 6. 密钥与敏感信息

常见泄露路径：

1. 写进镜像层（Dockerfile `ENV`、COPY 了密钥文件）。
2. 写进 compose 文件并提交到 Git。
3. 打到日志里。

实践建议：

1. 本地开发可用 `.env`，但不要提交。
2. 生产使用更规范的密钥管理（平台能力/外部 Secret Manager）。
3. 任何密钥轮换要有流程与审计。

# 7. 审计与基线（落地清单）

上线前检查（建议做成自动化）：

1. 镜像来源可信（私有仓库/签名/白名单）。
2. 镜像最小化、无构建工具残留。
3. 非 root 用户运行。
4. 禁止 privileged。
5. capabilities 最小化。
6. 根文件系统只读（可行则启用）。
7. 不挂载 docker.sock。
8. 不暴露不必要端口。
9. 资源限制（见 `12_resource_limits.md`）。

# 8. 面试要点

| 问题 | 答题关键词 |
|------|------------|
| 容器安全的核心差异 | 共享内核，容器不是 VM |
| 最危险的挂载是什么 | docker.sock（≈宿主机 root） |
| 如何做最小权限 | 非 root、cap-drop/添加最小能力、read-only |
| 如何做供应链安全 | 镜像扫描、最小化、tag/digest 策略、可追溯 |
