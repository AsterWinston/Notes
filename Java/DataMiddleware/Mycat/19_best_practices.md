
# 1. 分片键设计原则

```
✓ 分片键选择优先级：
  1. 高频查询的 WHERE 条件列
  2. 不可变的业务主键
  3. 区分度高的列（避免数据倾斜）

✗ 避免使用的分片键：
  1. 频繁修改的列 → 修改可能触发数据迁移
  2. 区分度低的列 → 数据倾斜
  3. 不在查询条件中的列 → 全分片扫描
```

**常见分片键模式**：

| 业务场景 | 推荐分片键 | 算法 |
|---------|-----------|------|
| 订单系统 | `order_id` (Snowflake) | 取模 |
| 用户系统 | `user_id` | 取模 / Hash |
| 日志系统 | `create_time` | 日期分片 |
| 多租户 SaaS | `tenant_id` | 枚举 / 取模 |
| 电商商品 | `seller_id` | 取模 |
| 金融交易 | `trade_no` | 取模 |

# 2. 数据源规划

```
容量评估公式：

每分片数据量 = 预估总量 / 分片数
每分片 QPS = 总 QPS × (精确分片比例 / 分片数 + 全扫描比例)

示例：
  预估 1 亿条订单
  目标单表 ≤ 2000 万条
  → 分片数 = 10000万 / 2000万 = 5 → 向上取 8（2 的幂）
  
  总 QPS = 5000
  精确路由比例 = 80% (QPS = 4000)
  全分片扫描比例 = 20% (QPS = 1000)
  
  每分片 QPS = 4000/8 + 1000 = 500 + 1000 = 1500
  → 单 MySQL 实例可承载
```

# 3. 索引设计

```sql
-- 分片表的索引设计注意事项：

-- 1. 分片键必须在索引中（通常就是主键）
CREATE INDEX idx_id ON orders(id);     -- 已有主键索引

-- 2. 非分片键需要全局索引 → 用全局表或 ES
-- Mycat2 没有全局二级索引，跨分片非分片键查询 = 全表扫描

-- 3. 每张分片表独立建索引
-- ER 子表的关联键必须有索引
CREATE INDEX idx_order_id ON order_items(order_id);
```

# 4. 读写分离策略

```json
// 推荐配置
{
  "clusters": {
    "order_cluster": {
      "clusterType": "MASTER_SLAVE",
      "readBalanceType": "BALANCE_ALL",
      "master": { "name": "master", "weight": 0 },     // 不参与读
      "replicas": [
        { "name": "slave1", "weight": 10 },
        { "name": "slave2", "weight": 10 }
      ]
    }
  }
}
```

**建议**：
- Master 权重设为 0，专注写入
- Slave 权重按配置分配（高性能机器权重大）
- 关键业务（如支付后查订单）强制走 Master

# 5. 全局表使用规范

```
适合作为全局表的表：
  ✓ 数据量 < 10 万行
  ✓ 修改频率低（天/周级别）
  ✓ 被多个分片表关联查询

不适合作为全局表：
  ✗ 数据量大且增长快
  ✗ 频繁修改
  ✗ 只需要在特定分片使用（用 ER 表）
```

# 6. 事务使用规范

```
1. 尽量单分片事务（WHERE 包含分片键）
2. 跨分片事务自动升级为 XA：注意性能开销（20-40%）
3. 事务超时控制：
   - 默认 30s，大事务适当延长
   - 写操作事务 < 5s（避免长时间锁）
4. 全局表修改 = 多节点 XA 事务（慎用）
```

# 7. 监控与告警

```
必须监控的指标：
□ Mycat2 前端连接数（接近 maxCon 时告警）
□ 后端连接池利用率（> 80% 告警）
□ QPS 和 RT（P50 / P99）
□ 分片命中率（越低性能越差）
□ 数据节点健康状态
□ JVM 堆内存 / GC 频率

推荐告警阈值：
□ 数据节点 OFFLINE → 立即告警
□ 前端连接 > 80% → 告警
□ P99 RT 突增 3 倍 → 告警
□ Full GC > 1 次/分钟 → 告警
```

# 8. DON'T 清单

```
✗ 不要用分片键以外的列做 WHERE 高频查询
✗ 不要在大表中使用 DISTINCT + ORDER BY（无分片键）
✗ 不要在分布式事务中做批量全分片操作
✗ 不要用 OFFSET 做深度分页（用游标/WHERE id > ?）
✗ 不要频繁修改全局表（每次 UPDATE 都是 XA 事务）
✗ 不要在生产环境直接修改配置文件而不 reload
✗ 不要忘记定期清理日志文件
✗ 不要在 Mycat2 层做复杂的 JOIN（推给应用层或 ES）
```
