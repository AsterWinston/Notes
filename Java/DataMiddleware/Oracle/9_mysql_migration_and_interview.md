# 1. 迁移总体思路

从 MySQL 迁移到 Oracle，难点不在"把数据搬过去"，而在**语义差异**。很多 SQL 在 MySQL 能跑，改到 Oracle 会报错；更多 SQL 不报错，但结果悄悄变了。这类"静默错误"比编译错误危险得多，往往上线后才发现。

迁移可以拆成四条线并行推进：

```text
┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐
│ 结构迁移    │   │ 数据迁移    │   │ 应用适配    │   │ 验证与切换  │
│ 表/索引/约束│   │ 全量+增量   │   │ SQL/ORM/事务│   │ 对账/压测   │
└────────────┘   └────────────┘   └────────────┘   └────────────┘
```

**设计考量**：不要一开始就追求"全自动转换"。工具能处理 70% 的 DDL，剩下 30% 涉及数据类型、函数、分页、事务语义，必须人工 review。迁移项目最常见的失败原因是"工具转完就上线"，没有做逐条 SQL 的语义核对。

| 工具 | 能力 | 适用 |
|------|------|------|
| SQL Developer Migration Workbench | 结构转换、数据迁移、语法检查 | 中小规模、官方推荐 |
| AWS SCT + DMS | 评估、转换、持续复制 | 上云场景 |
| Data Pump | 逻辑导出导入 | 已转换的结构 |
| GoldenGate | 增量实时同步、双跑 | 停机窗口极小的核心系统 |

> **行业实践**：核心系统通常采用"**全量 + 增量 + 双跑比对 + 灰度切换**"：工具做全量与结构转换，GoldenGate 追增量，双跑期间持续对账，确认无误后切流，把停机窗口从小时级压到分钟级。

# 2. 语法差异

## 2.1 标识符与引号

MySQL 用反引号包裹标识符，Oracle 用双引号，且双引号会**强制大小写敏感**。迁移时应去掉所有反引号，统一用小写加下划线、不加引号；只有对象名与保留字冲突时才用双引号，但要承担后续所有引用都必须带引号的代价。

```sql
-- MySQL
SELECT `user_name` FROM `order`;
-- Oracle：不加引号，自动转大写
SELECT user_name FROM orders;
```

## 2.2 字符串拼接与 NULL

MySQL 用 `CONCAT`，任一参数为 NULL 结果就是 NULL；Oracle 用 `||`，且把 NULL 当空串。`CONCAT('a', NULL)` 在 MySQL 返回 NULL，`'a' || NULL` 在 Oracle 返回 `'a'`。如果业务依赖"有 NULL 就整体为 NULL"，迁移后结果会变。

## 2.3 空字符串即 NULL

Oracle 把 `''` 当作 NULL，这是迁移中最容易踩的坑之一。

```sql
-- MySQL：空串和 NULL 是两回事
SELECT * FROM users WHERE nickname = '';
-- Oracle：下面这条永远查不到（'' 就是 NULL）
SELECT * FROM users WHERE nickname = '';
SELECT * FROM users WHERE nickname IS NULL;   -- 正确写法
```

同时，`NOT NULL` 列在 Oracle 里插入 `''` 会直接报错，而 MySQL 允许。迁移时要检查所有"默认空串"的字段，决定是改成 NULL 还是给一个有意义的默认值。

## 2.4 常用函数对照

| MySQL | Oracle | 说明 |
|-------|--------|------|
| `IFNULL(a, b)` | `NVL(a, b)` | 空值替换 |
| `IF(cond, a, b)` | `CASE WHEN` 或 `DECODE` | 条件表达式 |
| `NOW()` | `SYSDATE` / `SYSTIMESTAMP` | 当前时间 |
| `DATE_FORMAT(d, fmt)` | `TO_CHAR(d, fmt)` | 日期格式化 |
| `STR_TO_DATE(s, fmt)` | `TO_DATE(s, fmt)` | 字符串转日期 |
| `DATEDIFF(a, b)` | `a - b`（单位天） | 日期差 |
| `DATE_ADD(d, INTERVAL 1 DAY)` | `d + 1` 或 `ADD_MONTHS` | 日期加减 |
| `GROUP_CONCAT(x)` | `LISTAGG(x, ',')` | 分组拼接 |
| `SUBSTRING(s, p, l)` | `SUBSTR(s, p, l)` | 截取 |
| `LOCATE(sub, s)` | `INSTR(s, sub)` | 查找位置 |
| `RAND()` | `DBMS_RANDOM.VALUE` | 随机数 |
| `UUID()` | `SYS_GUID()` | 唯一标识 |

## 2.5 多行插入

MySQL 支持一条 `INSERT` 插多行，Oracle 传统写法要用 `INSERT ALL`：

```sql
INSERT ALL
  INTO users (id, name) VALUES (1, 'a')
  INTO users (id, name) VALUES (2, 'b')
SELECT * FROM dual;
```

## 2.6 ON DUPLICATE KEY 与 MERGE

MySQL 的 `INSERT ... ON DUPLICATE KEY UPDATE` 对应 Oracle 的 `MERGE`：

```sql
MERGE INTO account a
USING (SELECT 1 AS id FROM dual) s
ON (a.id = s.id)
WHEN MATCHED THEN UPDATE SET a.balance = a.balance + 100
WHEN NOT MATCHED THEN INSERT (id, balance) VALUES (1, 100);
```

`UPDATE ... JOIN` 同样可以改写成 `MERGE`，`DELETE ... JOIN` 则改写成 `DELETE ... WHERE EXISTS` 相关子查询。

## 2.7 DDL 差异

| MySQL | Oracle | 说明 |
|-------|--------|------|
| `DROP TABLE IF EXISTS t` | 23ai 前需 PL/SQL 捕获异常 | 无 `IF EXISTS` |
| 建表内联 `INDEX` | 单独 `CREATE INDEX` | Oracle 索引是独立对象 |
| `AUTO_INCREMENT` | `IDENTITY` 或序列 | 见第 4 节 |
| `ENGINE=InnoDB` | 无此概念 | 存储由表空间管理 |
| 内联 `COMMENT` | 单独 `COMMENT ON` | 注释语句独立 |

```sql
-- Oracle 中安全删表（23ai 之前）
BEGIN
    EXECUTE IMMEDIATE 'DROP TABLE tmp_orders';
EXCEPTION
    WHEN OTHERS THEN
        IF SQLCODE != -942 THEN RAISE; END IF;   -- -942 表示表不存在
END;
/
```

## 2.8 排序中的 NULL

MySQL 升序时 NULL 排在最前，Oracle 升序时 NULL 默认排在最后。跨库迁移后分页结果可能不一致，需要显式写 `ORDER BY col NULLS FIRST` 或 `NULLS LAST`。

# 3. 分页

MySQL 的 `LIMIT offset, size` 在 Oracle 里没有直接对应。12c 之前用 `ROWNUM`，12c 之后用 `OFFSET ... FETCH`。

```sql
-- 12c 之前：取第 21-30 条
SELECT *
FROM (
    SELECT t.*, ROWNUM rn
    FROM (SELECT * FROM orders ORDER BY created_at DESC) t
    WHERE ROWNUM <= 30
)
WHERE rn > 20;

-- 12c 之后：同样的第 21-30 条
SELECT * FROM orders
ORDER BY created_at DESC
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

`ROWNUM` 的陷阱是 `WHERE ROWNUM > 20` 永远为空：ROWNUM 在结果集生成时分配，第一行不满足 `> 20` 就被丢弃，永远不会产生第 21 行。

| MySQL | Oracle 12c+ | Oracle 11g 及更早 |
|-------|-------------|-------------------|
| `LIMIT 10` | `FETCH FIRST 10 ROWS ONLY` | 子查询 + `ROWNUM <= 10` |
| `LIMIT 20, 10` | `OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` | 双层子查询 + `ROWNUM` |

> **注意**：深分页在两种数据库里都慢，`OFFSET 100000` 仍要扫描并丢弃前 10 万行。迁移时应借机改成**基于游标的分页**：记住上一页最后一条的 `id` 或 `created_at`，用 `WHERE id > :last_id ORDER BY id FETCH FIRST 10 ROWS ONLY` 继续取。

# 4. 自增

MySQL 的自增绑定在列上，插入时自动填值，可以用 `LAST_INSERT_ID()` 取刚插入的 id。Oracle 有两种写法。

```sql
-- 写法一：12c 起的 IDENTITY 列
CREATE TABLE orders (
    id      NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id NUMBER NOT NULL,
    amount  NUMBER(18, 2) NOT NULL
);
INSERT INTO orders (user_id, amount) VALUES (1, 99.00);

-- 写法二：序列 + 触发器（老版本）
CREATE SEQUENCE seq_orders START WITH 1 INCREMENT BY 1 NOCACHE;
CREATE OR REPLACE TRIGGER trg_orders_id
BEFORE INSERT ON orders FOR EACH ROW
BEGIN
    IF :NEW.id IS NULL THEN
        SELECT seq_orders.NEXTVAL INTO :NEW.id FROM dual;
    END IF;
END;
/
```

Oracle 取刚插入的 id 用 `RETURNING INTO`：

```sql
DECLARE
    v_id NUMBER;
BEGIN
    INSERT INTO orders (user_id, amount) VALUES (1, 99.00)
    RETURNING id INTO v_id;
END;
/
```

迁移注意事项：历史 id 已存在时，建 `IDENTITY` 会从 1 开始撞主键，应先插历史数据，再用 `ALTER SEQUENCE ... RESTART START WITH 最大值+1` 调整起点；序列取号后回滚不归还，业务不要假设 id 连续；MySQL 每表独立自增，Oracle 序列可共享，建议按表建独立序列。

# 5. 日期与数据类型

| MySQL | Oracle | 说明 |
|-------|--------|------|
| `DATE` | `DATE` | MySQL 的 DATE 只有日期，Oracle 的 DATE 含时分秒 |
| `DATETIME` | `DATE` 或 `TIMESTAMP` | 需要小数秒时用 TIMESTAMP |
| `TIME` | 无独立类型 | 用 `VARCHAR2(8)` 或 DATE 的时间部分 |
| `TINYINT` | `NUMBER(3)` | Oracle 无 1 字节整数 |
| `INT` | `NUMBER(10)` | — |
| `BIGINT` | `NUMBER(19)` | — |
| `BIGINT UNSIGNED` | `NUMBER(20)` | 无 UNSIGNED，靠精度覆盖 |
| `DECIMAL(p, s)` | `NUMBER(p, s)` | 语义一致 |
| `VARCHAR(n)` | `VARCHAR2(n CHAR)` | 明确字符语义 |
| `TEXT` / `LONGTEXT` | `CLOB` | 大文本 |
| `TINYINT(1)` 当布尔 | `NUMBER(1)` 或 `CHAR(1)` | Oracle SQL 层无 BOOLEAN 列 |
| `ENUM` | `VARCHAR2 + CHECK` | 无原生 ENUM，也可拆字典表 |
| `JSON` | `JSON`（21c+）或 `CLOB + CHECK` | 版本差异 |

日期函数方面，`SYSDATE` 到秒，`SYSTIMESTAMP` 到小数秒；日期加减以"天"为单位，`SYSDATE + 1` 是明天，`SYSDATE + 1/24` 是一小时后；月份加减用 `ADD_MONTHS`，日期差用 `MONTHS_BETWEEN`。跨时区业务应存 UTC，用 `TIMESTAMP WITH TIME ZONE` 配合 `AT TIME ZONE` 展示。

> **注意**：MySQL 的 `DATE` 只存年月日，Oracle 的 `DATE` 存到秒。从 MySQL 迁移日期字段后可能多出 `00:00:00`，比较和展示都要留意；`UNSIGNED` 没有对应类型，要用更大的 `NUMBER` 精度覆盖。

# 6. 迁移步骤

## 6.1 评估

统计表数量、数据量、大字段、分区、存储过程、触发器和事件；梳理应用侧 SQL（ORM 生成、手写、报表、定时任务）；标出高风险点：`LIMIT`、`ON DUPLICATE KEY`、`GROUP_CONCAT`、`''`、`UNSIGNED`、`ENUM`、日期函数、存储过程。

## 6.2 结构与数据

用 SQL Developer Migration Workbench 或 AWS SCT 生成 Oracle DDL，人工 review 数据类型、索引、约束、注释、表空间、分区和序列起点。数据迁移小规模用 CSV + SQL*Loader 或外部表，大规模用 Data Pump 或 GoldenGate；增量阶段追平后做一次全量对账：行数、金额汇总、关键业务指标、抽样明细。

## 6.3 应用适配

替换 JDBC 驱动与连接串（`jdbc:mysql://` 改为 `jdbc:oracle:thin:@//`），ORM 方言切到 Oracle（如 Hibernate `Oracle12cDialect`），检查分页插件、批量插入、`getGeneratedKeys`、`LIMIT` 拼接；确认 `autocommit`、隔离级别、异常回滚行为；表名列名统一小写，避免双引号。

## 6.4 验证与切换

```text
1. 结构比对：表、索引、约束数量与定义一致
2. 数据比对：行数、汇总值、抽样明细
3. 功能回归：核心链路跑通
4. 性能压测：TPS、P95 延迟、慢 SQL
5. 双跑对账：新旧库并行，定时比对
6. 灰度切流：按用户/流量比例切换
7. 回滚预案：保留旧库与回切脚本
```

> **行业实践**：切换窗口内最怕"数据还在写，旧库已停"。正确顺序是：停写 → 追平增量 → 对账 → 切读 → 切写 → 观察 → 旧库只读保留。每一步都要有明确的回滚点和负责人。

# 7. 自检题

## 7.1 为什么 Oracle 里 `WHERE name = ''` 查不到数据？

因为 Oracle 把空字符串 `''` 当作 NULL，而 NULL 与任何值比较结果都是 UNKNOWN，`WHERE` 只保留 TRUE 的行。正确写法是 `WHERE name IS NULL`。从 MySQL 迁移时，所有空串判断都要改成 `IS NULL`，并注意 `NOT NULL` 列插入 `''` 会报错。

## 7.2 Oracle 如何实现 MySQL 的 `LIMIT 20, 10`？

12c 及以上用 `OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY`；12c 之前用两层子查询配合 `ROWNUM`，内层排序并限制上界，外层用 `rn > 20` 过滤下界。要注意 `WHERE ROWNUM > n` 直接写在单层查询里永远返回空。

## 7.3 MySQL 的 `AUTO_INCREMENT` 迁移到 Oracle 有哪两种方案？

一是 12c 起的 `GENERATED BY DEFAULT AS IDENTITY` 列；二是老版本的"序列 + `BEFORE INSERT` 触发器"，触发器在 `:NEW.id` 为空时取 `seq.NEXTVAL`。迁移历史数据后要把序列起点调到当前最大 id 之后，避免主键冲突。

## 7.4 为什么 MySQL 的 `DATE` 迁到 Oracle 后多出了时间？

MySQL 的 `DATE` 只存年月日，Oracle 的 `DATE` 存年、月、日、时、分、秒。迁移后原日期会带上 `00:00:00`，展示和比较时要注意。如果需要小数秒，应改用 `TIMESTAMP`。

## 7.5 Oracle 的默认隔离级别是什么？和 MySQL 有什么不同？

Oracle 默认 READ COMMITTED，MySQL InnoDB 默认 REPEATABLE READ。Oracle 没有独立的 REPEATABLE READ 级别，需要更强一致性时用 SERIALIZABLE（快照隔离 + 冲突检测，可能报 `ORA-08177`）。迁移时要重新评估依赖"事务内可重复读"的逻辑。

## 7.6 迁移后 `CONCAT` 结果为什么变了？

MySQL 的 `CONCAT` 遇到 NULL 返回 NULL；Oracle 用 `||` 拼接时把 NULL 当空串，`'a' || NULL` 返回 `'a'`。如果业务依赖"有 NULL 则整体为 NULL"，需要显式用 `CASE WHEN ... IS NULL THEN NULL ELSE ... END` 保持原语义。

## 7.7 迁移中最容易被忽略的验证是什么？

**语义对账**，而不只是行数对账。行数一致不代表结果一致：排序中 NULL 的位置、日期精度、字符串拼接、空串与 NULL 的差异，都可能让同一条 SQL 返回不同结果。应对核心报表和关键接口做"新旧库结果集逐行比对"。

# 8. 总结

| 主题 | 核心结论 |
|------|---------|
| 迁移思路 | 结构、数据、应用、验证四条线并行，工具转 70%，人工 review 30% |
| 语法 | 反引号改双引号/去引号，`CONCAT` 改 `||`，`IFNULL` 改 `NVL` |
| 空串 | Oracle 中 `''` 即 NULL，判断改 `IS NULL` |
| 分页 | 12c+ 用 `OFFSET FETCH`，老版本用 `ROWNUM` 子查询 |
| 自增 | `IDENTITY` 或序列 + 触发器，迁移后调整序列起点 |
| 日期 | MySQL `DATE` 无时间，Oracle `DATE` 到秒，需要小数秒用 `TIMESTAMP` |
| 数据类型 | `UNSIGNED` 用更大精度覆盖，`ENUM` 用 `CHECK` 或字典表 |
| 迁移步骤 | 评估 → 结构 → 数据 → 应用 → 对账 → 灰度 → 回滚预案 |

Oracle 系列到这里告一段落。回看这九篇，主线其实只有三条：**实例与存储决定数据放在哪、事务与锁决定并发下对不对、索引与备份决定跑得快不快和丢不丢**。把这三点串起来，再结合 MySQL、PostgreSQL 的对比去理解差异，遇到新问题时就不会只停留在"这个语法怎么写"，而是能判断"这个设计为什么这样"。
