
# 1. 概述

Apache ShardingSphere 是**分布式数据库生态系统**，可以将任意数据库转换为分布式数据库，通过数据分片、读写分离、数据加密、影子库等能力增强数据库。

2020 年成为 Apache 顶级项目，5.x 是当前主力版本。

# 2. 双模式架构

ShardingSphere 提供两种接入方式：

```
ShardingSphere-JDBC                ShardingSphere-Proxy
┌──────────┐                       ┌──────────┐
│   App    │                       │   App    │
│ ┌──────┐ │                       └────┬─────┘
│ │  SDK  │ │                            │ MySQL Protocol
│ └──┬───┘ │                       ┌────▼─────┐
└────┼─────┘                       │  Proxy   │
     │ 直连 DB                      └────┬─────┘
     ▼                                   │
┌──────────┐                        ┌────▼─────┐
│  MySQL   │                        │  MySQL   │
└──────────┘                        └──────────┘
```

| 维度 | ShardingSphere-JDBC | ShardingSphere-Proxy |
|------|-------------------|---------------------|
| 部署方式 | SDK 嵌入应用 | 独立部署代理 |
| 语言限制 | Java | 无（MySQL/PostgreSQL 协议） |
| 网络开销 | 无（直连 DB） | +1 跳 |
| 运维复杂度 | 配置随应用发布 | 独立运维 |
| 性能 | 高 | 中 |
| 异构语言 | 不支持 | 支持 |
| 版本升级 | 随应用 | 独立升级 |

# 3. 核心能力矩阵

| 能力 | 说明 | 适用场景 |
|------|------|---------|
| **数据分片** | 水平分库分表，多种分片算法 | 大数据量表拆分 |
| **读写分离** | 写主读从，动态发现从库 | 读多写少场景 |
| **数据加密** | 字段级透明加解密 | 敏感数据保护 |
| **影子库** | 全链路压测，流量染色 | 生产环境压测 |
| **分布式事务** | XA / Seata AT / BASE | 跨库一致性 |
| **DistSQL** | 在线配置变更 | 运维管理 |
| **治理中心** | 熔断、禁用从库、集群管理 | 高可用 |

# 4. ShardingSphere 5.x 新特性

| 特性 | 说明 |
|------|------|
| **全新 SQL 解析引擎** | ANTLR 4 解析器，支持 MySQL/PostgreSQL/openGauss/SQL Server/Oracle |
| **DistSQL** | 类 SQL 的在线运维语言 |
| **插件化架构** | SPI 全插件化，功能可插拔 |
| **弹性伸缩** | 在线扩缩容（ElasticJob 集成） |
| **异构数据库联邦查询** | 支持跨数据库类型的关联查询 |
| **Agent 可观测性** | OpenTelemetry 集成，自动埋点 |

# 5. vs Mycat2 vs Vitess

| 维度 | ShardingSphere | Mycat2 | Vitess |
|------|---------------|--------|--------|
| **接入方式** | JDBC + Proxy | Proxy | Proxy |
| **SQL 方言** | MySQL/PG/openGauss/SQLServer/Oracle | MySQL 8.0 | MySQL 5.7/8.0 |
| **配置变更** | DistSQL 在线变更 | JSON 热加载 | vtctl/vtgate |
| **分布式事务** | XA/Seata/BASE | XA | 2PC |
| **弹性伸缩** | ✓ | 手动 | ✓ 原生支持 |
| **社区活跃** | ★★★★★ | ★★★☆☆ | ★★★★☆ |
| **Apache 项目** | ✓ | ✗ | ✗（CNCF） |

# 6. 核心设计理念

1. **SQL 贯穿始终**：Parse → Rewrite → Route → Execute → Merge 五大引擎
2. **插件化**：所有功能通过 SPI 可插拔，分片算法/数据源/治理中心均可替换
3. **连接治理**：Proxy 模式提供连接池、熔断、限流等治理能力
4. **数据库透明**：应用层感知不到分库分表，SQL 自动改写为物理 SQL
5. **生态开放**：支持多种注册中心、事务管理器、数据库方言
