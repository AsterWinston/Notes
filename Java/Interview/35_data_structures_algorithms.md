# 1. 知识点
- **数组** — 连续内存存储，下标O(1)随机访问，插入删除需移动元素O(n)，大小固定（静态数组）或动态扩容（ArrayList 1.5倍扩容）
- **链表** — 非连续内存，通过指针连接，插入删除O(1)（需先定位到位置），查找O(n)，无扩容开销，额外存储指针空间
- **数组vs链表对比** — 数组适合读多写少、已知大小场景；链表适合频繁插入删除、大小未知场景；数组CPU缓存友好（局部性原理），链表不友好
- **栈(Stack)** — LIFO后进先出，push/pop/peek操作O(1)，可用数组或链表实现，典型应用：函数调用栈、括号匹配、表达式求值、浏览器前进后退
- **后缀表达式(逆波兰式)** — 操作符位于操作数之后，无需括号即可表示优先级，用栈求值：遇数字入栈，遇操作符弹出两个计算后入栈
- **括号匹配** — 遇左括号入栈，遇右括号与栈顶匹配则出栈，最后栈空则匹配成功
- **队列(Queue)** — FIFO先进先出，enqueue入队/dequeue出队O(1)，可用于BFS、消息队列、线程池任务队列
- **双端队列(Deque)** — 两端均可入队出队，Java中ArrayDeque可作栈也可作队列，LinkedList也实现了Deque
- **BFS(广度优先搜索)** — 借助队列实现，逐层遍历，适合求最短路径（无权图）、树的层次遍历
- **哈希表(HashTable)** — 通过散列函数将key映射到数组下标，理想情况O(1)增删查，装载因子=元素数/容量
- **散列函数** — 将任意长度输入映射为固定长度输出，好的散列函数应均匀分布、计算快、碰撞少，Java中Object.hashCode()，HashMap二次散列扰动
- **链地址法(Separate Chaining)** — 冲突时用链表/红黑树存储同位置元素，HashMap默认策略，链表长度>=8且数组长度>=64时转红黑树
- **开放地址法(Open Addressing)** — 冲突时按探测序列找下一个空位（线性探测/平方探测/双重散列），ThreadLocalMap使用，缓存友好但删除麻烦需标记
- **装载因子(Load Factor)** — 元素数/容量，HashMap默认0.75，超过则扩容rehash（容量翻倍），trade-off：太小浪费空间，太大增加冲突概率
- **二叉树** — 每个节点最多两个子节点，第k层最多2^(k-1)个节点，高度h最多2^h-1个节点
- **满二叉树** — 除叶子节点外所有节点都有两个子节点，且所有叶子在同一层
- **完全二叉树** — 除最后一层外每层都满，最后一层节点从左到右连续排列，堆正基于此结构
- **二叉搜索树(BST)** — 左子树所有节点值<根值<右子树所有节点值，中序遍历有序，查找/插入/删除平均O(logn)最坏O(n)
- **平衡二叉树(AVL)** — 任意节点左右子树高度差<=1，查找O(logn)，插入删除需旋转维持平衡：LL右旋、RR左旋、LR左旋再右旋、RL右旋再左旋
- **红黑树** — 弱平衡BST，5条性质：1)节点非红即黑 2)根黑 3)叶(NIL)黑 4)红节点子必黑 5)任意节点到叶子路径黑节点数相同；最坏查找O(logn)，调整最多3次旋转，插入删除比AVL快
- **红黑树插入** — 新节点默认红色，然后根据叔节点颜色分情况变色+旋转修复
- **HashMap树化** — Java 8+中，单个桶链表长度>=8且数组容量>=64时转为红黑树，<=6时退化为链表（中间差值7防频繁转换）
- **TreeMap** — Java中基于红黑树实现的有序Map，按key自然顺序或Comparator排序，containsKey/put/get/remove均为O(logn)
- **B树(B-Tree)** — 多路平衡搜索树，节点内存储多个key和data，所有叶子在同一层，中间节点也存数据，适合磁盘IO（一个节点=一个磁盘页）
- **B+树** — B树变体，数据只存叶子节点，中间节点只存key做索引，叶子之间用链表连接支持范围查询，MySQL InnoDB的主索引(聚簇)和辅助索引都用B+树
- **B+树优势** — 不存data的中间节点可存更多key → 树更矮 → IO更少；叶子链表支持范围扫描和排序；查询稳定必须到叶子
- **堆(Heap)** — 完全二叉树，大顶堆(每个节点>=子节点)用于升序堆排序，小顶堆(每个节点<=子节点)用于优先队列、TopK
- **堆操作** — 插入O(logn)：放最后然后上浮(siftUp)；删除堆顶O(logn)：最后元素替换堆顶然后下沉(siftDown)；建堆O(n)：从最后一个非叶节点依次下沉
- **堆排序** — 建堆O(n) + 依次取堆顶与末尾交换再调整O(nlogn)，总体O(nlogn)，原地排序但不稳定
- **优先队列(PriorityQueue)** — Java中基于小顶堆实现，入队O(logn)出队O(logn)查看队首O(1)，自定义比较器可变为大顶堆
- **TopK问题** — 求前K大用小顶堆(size=k)，求前K小用大顶堆(size=k)，时间复杂度O(nlogk)
- **数据流中位数** — 用两个堆：大顶堆存较小一半，小顶堆存较大一半，保持两堆大小差<=1，中位数从堆顶取，插入O(logn)
- **跳表(SkipList)** — 有序链表基础上增加多层索引指针，每层按概率(通常0.5)决定是否升层，查找/插入/删除均为O(logn)，Redis zset有序集合底层使用
- **跳表vs红黑树** — 跳表实现简单，范围查找方便，并发友好（可局部锁定），但空间消耗大（额外指针）
- **图** — 由顶点和边组成，分为有向图/无向图、带权图/无权图、有环图/无环图(DAG)
- **邻接矩阵** — 二维数组存储边，O(1)判断是否相邻，空间O(V^2)，适合稠密图
- **邻接表** — 数组+链表/List，空间O(V+E)，适合稀疏图，大多数情况下使用
- **图的BFS** — 从起点出发队列逐层遍历，找无权图最短路径，时间复杂度O(V+E)
- **图的DFS** — 递归/栈深入探索，可用于判断连通性、找环、拓扑排序，时间复杂度O(V+E)
- **拓扑排序** — 有向无环图的线性排序，Kahn算法(BFS+入度表)或DFS+逆后序，应用：编译依赖、课程安排
- **Dijkstra最短路径** — 贪心+松弛操作，不能有负权边，时间复杂度O((V+E)logV)（优先队列优化），求单源最短路径
- **Floyd最短路径** — 动态规划，三重循环O(V^3)，可处理负权边（不能有负环），求所有点对最短路径
- **最小生成树(MST)** — Kruskal：按边权排序+并查集判断环，O(ElogE)；Prim：从点出发每次选最小边扩展，O((V+E)logV)
- **冒泡排序** — 相邻两两比较交换，每轮最大元素沉底，O(n^2)，稳定，优化：加flag提前终止
- **选择排序** — 每轮选最小/大元素放到已排序列末尾，O(n^2)，不稳定（交换可能破坏顺序）
- **插入排序** — 将未排序元素插入已排序序列合适位置，O(n^2)，对近乎有序数据O(n)，稳定
- **希尔排序** — 分组插入排序，增量序列递减(gap序列)，最后gap=1即插入排序，时间复杂度取决于序列O(n^1.3)~O(n^2)，不稳定
- **快速排序** — 选枢轴partition，左边<=枢轴<右边，递归，平均O(nlogn)最坏O(n^2)，枢轴优化：三数取中/随机，不稳定
- **归并排序** — 分治法：递归拆分到单个元素，再合并有序子数组，O(nlogn)，需要额外O(n)空间，稳定
- **堆排序** — O(nlogn)，原地排序，不稳定
- **计数排序** — 统计每个值出现次数，O(n+k)k为值域范围，稳定(反向填充)，适合范围有限整数
- **桶排序** — 将数据分到多个桶，每个桶内排序再合并，O(n+k)，适合数据分布均匀
- **基数排序** — 按位数从低位到高位分别排序(需稳定排序如计数排序)，O(d(n+k))，适合位数固定的整数/字符串
- **排序稳定性总表** — 稳定：冒泡、插入、归并、计数、桶、基数；不稳定：选择、希尔、快排、堆排
- **顺序查找** — 遍历数组逐个比较，O(n)，无需数据有序
- **二分查找** — 有序数组，每次折半，O(logn)，注意mid计算防溢出(low+(high-low)/2)，循环条件low<=high
- **哈希查找** — O(1)，空间换时间，需处理冲突
- **递归** — 函数调用自身，需有终止条件(基线条件)，每层递归产生新栈帧，过深导致StackOverflow
- **分治法** — 分解子问题→解决子问题→合并结果，经典：归并排序、快速排序、二分查找
- **汉诺塔** — 递归经典问题，f(n)=2f(n-1)+1，时间复杂度O(2^n)
- **斐波那契** — 递归f(n)=f(n-1)+f(n-2)有大量重复计算，可优化为迭代O(n)或矩阵快速幂O(logn)
- **动态规划(DP)** — 两个核心性质：最优子结构(大问题最优解包含子问题最优解)、重叠子问题(子问题重复计算)；自顶向下记忆化搜索 vs 自底向上递推
- **DP经典问题** — 0-1背包(每件物品取或不取)、最长公共子序列LCS、最长递增子序列LIS、爬楼梯、硬币找零、编辑距离
- **贪心算法** — 每步取当前最优，不保证全局最优，适用场景需证明贪心选择性质(局部最优→全局最优)
- **贪心经典** — 霍夫曼编码(频率高用短码)、活动选择(最早结束优先)、Dijkstra、Prim、找零(面额特殊时可)
- **回溯算法** — 试探性搜索，不满足则回退尝试其他选择，本质是DFS+剪枝，时间复杂度通常指数级
- **回溯经典** — N皇后(列+主对角线+副对角线判冲突)、全排列(used数组标记)、子集、数独(行+列+宫判重)、组合总和
- **剪枝** — 提前排除不可能产生解的分支，如N皇后同行不放置、剩余全用最优也达不到时剪枝(限界函数)
- **并查集(Union-Find)** — 维护不相交集合，find找根+路径压缩(摊还O(α(n)))，union按秩合并，应用：连通分量、朋友圈/岛屿数量、Kruskal、判断图是否有环
- **布隆过滤器(Bloom Filter)** — 位图+多个Hash函数，插入将所有hash位置1，查询所有位均为1则"可能存在"(有误判)，任一为0则"一定不存在"；Redis Bloom模块、Guava BloomFilter
- **布隆过滤器应用** — 缓存穿透防护(查询不存在数据先过布隆过滤)、判断URL是否已爬取、垃圾邮件过滤
- **LRU缓存** — 最近最少使用淘汰，Java中用LinkedHashMap(accessOrder=true,覆写removeEldestEntry)或手动哈希表+双向链表(头放最新尾放最旧)
- **限流算法** — 计数器(固定窗口，临界问题)、滑动窗口(平滑统计)、漏桶(恒定速率流出，可缓冲突发)、令牌桶(恒定速率生成令牌，允许突发流量)
- **负载均衡算法** — 轮询RoundRobin(依次分配)、加权轮询WeightedRR(按权重比例)、随机Random、最少连接LeastConnections(分给连接最少的)、源地址哈希IP-Hash(同IP固定分配到同节点)、一致性哈希(虚拟节点解决数据倾斜)
- **一致性哈希** — 将节点和key映射到同一个环上(0~2^32-1)，key顺时针找最近节点；节点增减只影响相邻节点数据，配合虚拟节点解决数据倾斜

# 2. 面试题

## 2.1 数组和链表的区别是什么？
数组是连续内存，O(1)随机访问，插入删除O(n)需移动元素，CPU缓存友好；链表非连续内存通过指针连接，查找O(n)，插入删除(定位后)O(1)，额外存储指针开销，无扩容问题。数组大小固定(静态)或需扩容，动态扩容时涉及复制开销。选择：读多写少用数组，频繁增删用链表。

## 2.2 栈有哪些应用场景？
1) 函数调用栈：保存函数调用上下文，递归深度过大会StackOverflow
2) 括号匹配：左括号入栈右括号匹配出栈
3) 表达式求值：中缀转后缀(操作符栈)，或后缀求值(操作数栈)
4) 浏览器前进后退：两个栈分别存后退历史和前进历史
5) 撤销操作：每次操作入栈，撤销时出栈

## 2.3 HashMap的实现原理？
JDK 1.8中HashMap = 数组(Node[]) + 链表 + 红黑树。put流程：1)算hash(key.hashCode()异或高16位); 2)判断是否扩容; 3)数组下标=(n-1)&hash，若空直接放; 4)若有元素，先判断首节点equals，是则替换; 5)遍历链表/红黑树判断equals; 6)链表长度>=8且capacity>=64时转红黑树; 7)插入后size>threshold(capacity*loadFactor)则扩容到2倍。扩容时rehash，原位置或原位置+旧容量。get同理，先hash定位下标，再比较首节点，然后遍历链表或红黑树。

## 2.4 什么是红黑树？为什么HashMap使用红黑树？
红黑树是自平衡二叉搜索树，5条性质保证树高度不超过2log(n+1)，查找/插入/删除O(logn)。HashMap使用红黑树是为了防止hash冲突严重时链表退化为O(n)查找；链表长度>=8且数组容量>=64时树化，<=6时退化成链表。选红黑树而非AVL因为红黑树插入删除旋转次数少(最多3次vs AVL的O(logn))，对插入频繁的HashMap更合适。

## 2.5 B树和B+树有什么区别？为什么MySQL使用B+树？
区别：1)B树数据可存在中间节点，B+树数据只在叶子节点；2)B+树叶子之间用双向链表连接，支持范围查询，B树需中序遍历；3)B+树中间节点不存数据可容纳更多key → 树更矮 → 磁盘IO更少；4)B+树查询必须到叶子，查询稳定性好。MySQL InnoDB使用B+树：聚簇索引叶子存完整行数据，二级索引叶子存主键值(回表查询)；叶子链表支持order by、范围查询、排序等。

## 2.6 快速排序的原理和时间复杂度？如何优化？
快排基于分治：选枢轴pivot，partition使左边<=pivot<右边，递归排序左右。平均O(nlogn)，最坏O(n^2)(顺序/逆序时每次都分出一个元素)。优化：1)三数取中(左中右取中值)或随机选枢轴避免最坏；2)小数组转插入排序(threshold通常10~50)；3)三路快排处理大量重复值(荷兰国旗问题分三区< = >)。递归深度可用栈模拟是非递归。不稳定。

## 2.7 什么是动态规划？和分治法、贪心法的区别？
DP用于有重叠子问题和最优子结构的问题，通过保存子问题结果避免重复计算。与分治法区别：分治子问题独立(如归并)，DP子问题重叠。与贪心区别：贪心每步最优选择不能回退，不一定全局最优；DP穷举所有可能取最优。经典DP：0-1背包、LCS最长公共子序列、爬楼梯。

## 2.8 如何用两个栈实现队列？
栈A负责入队(push)，栈B负责出队(pop/peek)。出队时若栈B为空，将栈A全部弹出压入栈B，再从栈B出栈。这样FIFO：先入A的在栈B顶部先出。均摊时间复杂度O(1)，因为每个元素最多入栈出栈各两次。

## 2.9 什么是布隆过滤器？原理和应用场景？
布隆过滤器是概率型数据结构，由位数组+多个Hash函数组成。插入：将key经k个hash函数计算位置，对应位全部置1。查询：所有hash位置都为1返回"可能存在"(有误判)，任一为0返回"一定不存在"。特点：不存储原数据节省空间，有误判率(取决于位数组大小和hash函数个数)，不能删除。应用：缓存穿透防护(过滤不存在的key)、URL去重、垃圾邮件过滤。

## 2.10 LRU缓存如何实现？
两种实现：1)Java LinkedHashMap：构造参数accessOrder=true，覆写removeEldestEntry(当size>capacity返回true)自动移除最老元素。2)手动：哈希表+双向链表。get时移动该节点到链表头；put时若key存在更新值并移到头部，若满则删除尾部节点再头插。哈希表负责O(1)查找，链表负责维护顺序，两个操作都是O(1)。

## 2.11 如何实现一个堆排序？
堆排序步骤：1)建堆：从最后一个非叶节点开始(索引n/2-1)自底向上调整(siftDown)，O(n)；2)排序：依次将堆顶(最大值)与末尾元素交换，堆大小减1，然后从堆顶siftDown调整，重复n-1次，O(nlogn)。总体O(nlogn)，原地排序，不稳定。升序用大顶堆，降序用小顶堆。

## 2.12 TopK问题的最优解法？
求前K大的元素：维护一个大小为K的小顶堆，遍历所有元素，若当前元素>堆顶则弹出堆顶并插入当前元素。时间复杂度O(nlogK)，空间O(K)。若K很小用此方案最优。若求前K小则用大顶堆。若K接近n，直接全排序O(nlogn)可能更优。若数据量极大无法全加载内存，还可用分治法或桶思路。

## 2.13 图的DFS和BFS有什么区别？
DFS(深度优先)：递归或栈实现，沿着一条路径走到底再回溯，应用包括拓扑排序、连通分量、找环、回溯题。BFS(广度优先)：队列实现，一层一层向外扩展，应用包括最短路径(无权图)、树的层序遍历、网络爬虫。时间复杂度均为O(V+E)，差别在访问顺序和数据结构。

## 2.14 一致性哈希是什么？为什么需要虚拟节点？
一致性哈希把节点和key都映射到一个hash环[0,2^32-1]，key顺时针找到第一个节点负责存储。节点增减时只有相邻节点数据受影响，比取模哈希迁移量小得多。问题：节点少时数据分布不均(数据倾斜)。虚拟节点：每个物理节点对应多个虚拟节点分散在环上，数倍后分布更均匀，微调权重也方便。

## 2.15 什么是Dijkstra算法？处理不了什么情况？
Dijkstra是单源最短路径算法，贪心策略：每次选未访问中距离起点最近的点，用它松弛邻居距离，重复直到所有点访问完。优先队列优化O((V+E)logV)。不能处理负权边：已确定最短路径的点可能之后被更短路径更新导致错误(如先锁定了A再发现A→B的负边)。负权图用Bellman-Ford。

## 2.16 什么是死锁？如何检测和避免？（交叉题：OS）
死锁是多个进程互相等待对方释放资源，导致都无法推进。四个必要条件：互斥、占有且等待、不可抢占、循环等待。预防：破坏任一条件。避免：银行家算法，分配前判断是否进入不安全状态。检测：资源分配图判定是否有环。Java中：jstack查看线程状态(BLOCKED锁等待)，死锁线程两个都在等对方锁。

## 2.17 令牌桶和漏桶限流的区别？
漏桶：请求进入桶，以恒定速率流出处理，超出桶容量丢弃；流量整形，不管多突发出去都是平稳的。令牌桶：以恒定速率向桶中加令牌，请求来需获取令牌才能处理，桶满令牌丢弃；允许一定程度的突发流量（桶里积累令牌可一次性消耗）。令牌桶更灵活，适合允许突发场景；漏桶更严格平滑。

## 2.18 跳表(SkipList)的原理和Redis为什么使用它？
跳表是有序链表+多层索引：原始链表为第0层，每层以概率p(通常0.5)决定是否升级到上一层，上层节点稀疏下层密集。查找从最高层开始，每层找到第一个>=目标的节点，若大于则下到下一层；平均O(logn)。Redis zset用跳表而非红黑树：实现简单，范围查找直接(顺链表遍历即可)，并发下可局部加锁粒度更细，适合按score范围操作(zrange/ zrank)。

## 2.19 回溯算法解N皇后的思路？
N皇后：N×N棋盘放N皇后，彼此不能同行同列同对角线。回溯思路：逐行放置，每行尝试所有列，检查是否安全（同列/左对角线row+col相同/右对角线row-col相同），安全则放置并递归下一行，不满足则回退(移除)尝试下一列，找到一种方案或全部方案。剪枝：同行一定冲突无需判断，每行只有一个皇后。时间复杂度O(N!)。
