
# 1. 什么是 JVM

- JVM（Java Virtual Machine）是一个虚拟计算机，运行在所有 Java 程序中。
- 它是"一次编译，到处运行"的基石——`.class` 文件运行在 JVM 之上，屏蔽了底层操作系统差异。
- HotSpot VM 是 Oracle JDK / OpenJDK 的默认 JVM 实现，也是最常用的。

# 2. JDK / JRE / JVM 的关系

```
┌─────────────────────────────────┐
│              JDK                │
│  ┌───────────────────────────┐  │
│  │           JRE             │  │
│  │  ┌─────────────────────┐  │  │
│  │  │        JVM          │  │  │
│  │  ├─────────────────────┤  │  │
│  │  │    核心类库          │  │  │
│  │  └─────────────────────┘  │  │
│  ├───────────────────────────┤  │
│  │  开发工具（javac, jar,   │  │
│  │  jshell, javadoc...）     │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

| 概念 | 说明 |
|------|------|
| JDK | Java Development Kit，包含 JRE + 开发工具 |
| JRE | Java Runtime Environment，包含 JVM + 核心类库 |
| JVM | Java Virtual Machine，负责加载并执行字节码 |

- 从 Java 11 开始，Oracle 不再提供独立的 JRE，JDK 自带运行时。

# 3. JVM 的架构

```
源文件(.java) → javac → 字节码(.class) → JVM
                                              │
                        ┌─────────────────────┤
                        │                     │
                   类加载子系统            运行时数据区
                        │                     │
                        ▼                     ▼
                  ┌───────────┐       ┌───────────────┐
                  │ 加载/连接 │       │ 方法区｜堆    │
                  │ /初始化   │       │ 虚拟机栈｜PC  │
                  └───────────┘       │ 本地方法栈    │
                                      └───────┬───────┘
                                              │
                                        执行引擎
                                        ▼
                                  ┌─────────────┐
                                  │ 解释器｜JIT  │
                                  │ GC｜本地接口 │
                                  └─────────────┘
```

核心三大组件：
- **类加载子系统**：将 `.class` 文件加载到内存。
- **运行时数据区**：方法区、堆、栈、程序计数器、本地方法栈。
- **执行引擎**：解释器 + JIT 编译器 + GC。

# 4. 主流 JVM 实现

| JVM | 特点 | 使用场景 |
|-----|------|----------|
| HotSpot VM | Sun/Oracle 官方，JDK 默认 | 企业开发主力 |
| OpenJ9 | IBM 开源，启动快、内存占用低 | 云原生、微服务 |
| GraalVM | Oracle 开源，多语言运行时、AOT 编译 | 高性能、多语言互操作 |
| Zing VM | Azul 商业版，C4 算法实现亚毫秒 GC | 金融交易、低延迟系统 |
| Dalvik/ART | Google Android 虚拟机 | Android 平台 |

# 5. HotSpot 名称由来

- "Hot Spot" 即"热点"。
- JVM 并不对所有代码做即时编译，而是先解释执行，然后探测出"热点代码"（频繁执行的方法或循环），交给 JIT 编译器优化编译为本地机器码。
- 热点探测策略：
  - **基于采样**（Sample Based）：定期检查栈顶，找到经常出现的方法。
  - **基于计数器**（Counter Based）：为每个方法/循环维护调用计数器，超过阈值触发 JIT。
  - HotSpot 使用**基于计数器**策略。

# 6. 编译与解释并存

```
.java  →  javac  →  .class  →  JVM
                                ├── 解释器（逐行解释字节码，快速启动）
                                └── JIT编译器（热点代码编译为机器码，高效运行）
```

- 解释器：启动时使用，响应快，但执行效率低。
- JIT 编译器：运行时编译热点代码为本地机器码，缓存后直接执行，效率高。
- 这种结合称为"混合模式"（Mixed Mode）。

查看当前模式：
```bash
java -version
# 输出示例：
# Java HotSpot(TM) 64-Bit Server VM (build 25.xxx, mixed mode)
```

强制使用解释模式（-Xint）或编译模式（-Xcomp）：
```bash
java -Xint MyClass        # 纯解释，极慢
java -Xcomp MyClass       # 纯编译，启动慢
java -Xmixed MyClass      # 混合模式（默认）
```

# 7. JVM 规范与实现分离

- **JVM 规范**（Specification）：定义 JVM 必须遵守的行为标准，但不规定具体实现方式。
- **JVM 实现**（Implementation）：如 HotSpot、OpenJ9，各自采用不同方式实现规范。
- 这也是任何遵循 JVM 规范的语言（Kotlin、Scala、Groovy、Clojure）都能跑在 JVM 上的原因。

| 规范规定 | 实现自由发挥 |
|----------|-------------|
| 类文件格式 | GC 算法 |
| 字节码指令集 | JIT 编译器策略 |
| 运行时数据区结构 | 对象内存布局细节 |
| 类加载/链接/初始化流程 | 指令优化方式 |
| 虚拟机启动/退出行为 | 线程调度方式 |
