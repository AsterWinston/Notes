# 1.设计对象并使用

## 1.1类

### 1.1.1定义类

```
<authority> class <class_name>{
	<variable>
	<function>
	<constructor>
	<code_segment>
	<internal_class>
}
```

### 1.1.2使用类

```
<class_name> <var_name> = new <class_name>()
```

### 1.1.3类的分类

```
1.1.3.1JavaBean类:用来描述一类事物的类，在JavaBean类中，是不写main方法的
1.1.3.2测试类:编写main方法的类叫测试类
1.1.3.3工具类
```

### 1.1.4注意事项

```
1.1.4.1一个Java文件中可以定义多个类，且只能一个类是public修饰，而且public修饰的类名必须是代码文件名，实际开发中只建议一个文件定义一个类
1.1.4.2成员变量的完整定义格式是:修饰符 数据类型 变量名=初始化值;//一般无需指定初始化值，存在默认值，数值类型默认0，boolean默认false，引用类型默认null
```

### 1.1.5面向对象思想

```
面向对象（Object Oriented Programming, OOP）是 Java 的核心编程范式。

核心概念：
  万物皆对象：现实世界中的任何事物都可以抽象为程序中的对象。
  对象包含属性和行为：
    属性：对象的静态特征，对应类的成员变量（字段）。
    行为：对象的动态特征，对应类的成员方法。
  三大特性：封装、继承、多态。

面向对象 vs 面向过程：
  面向过程：关注"怎么做"，按步骤一步步实现功能。适合简单任务。
  面向对象：关注"谁来做"，将数据和操作封装在一起。适合大型项目，便于扩展和维护。
```

## 1.2对象

```
对象是类的实例化，是具体存在的实体。

对象的创建过程：
  1. 加载类信息（.class 文件加载到方法区）
  2. 在栈内存中声明引用变量
  3. 在堆内存中通过 new 关键字开辟对象空间
  4. 执行构造方法进行对象初始化
  5. 将堆内存中的地址赋值给栈中的引用变量

对象的组成部分：
  - 对象头（Mark Word + Klass Pointer）：存储对象自身的运行时数据（哈希码、GC分代年龄、锁状态等）和指向类元数据的指针
  - 实例数据：即成员变量的值
  - 对齐填充：JVM要求对象起始地址必须是8字节的整数倍

匿名对象：没有变量接收的对象，只能使用一次。例如：new Student().show();
```

# 2.封装:对象代表什么，就得封装对应的数据，并提供数据对应的行为

```
封装是面向对象编程的核心特性之一，指隐藏对象的属性和实现细节，仅对外提供公共的访问方式。

封装的设计原则：
  2.1 合理隐藏：使用 private 关键字将属性声明为私有，防止外部直接修改
  2.2 合理暴露：通过 public 的 getter/setter 方法提供可控的访问接口

封装的好处：
  2.3 提高安全性：在 setter 方法中可以添加数据校验逻辑，防止非法数据
  2.4 提高复用性：内部实现改变时，只要对外接口不变，调用者无需修改代码
  2.5 高内聚低耦合：将数据和操作数据的方法绑定在一起，降低模块间的依赖

示例：
  public class Student {
      private String name;
      private int age;

      public void setName(String name) {
          if (name != null && !name.trim().isEmpty()) {
              this.name = name;
          }
      }

      public String getName() {
          return name;
      }

      public void setAge(int age) {
          if (age >= 0 && age <= 150) {
              this.age = age;
          }
      }

      public int getAge() {
          return age;
      }
  }
```

# 3.this关键字:指向调用当前方法的类对象，可以显示写出形参，也可以不写

```
this 关键字代表当前对象的引用，用于区分成员变量和局部变量。

this 的本质：
  每个非静态方法中都隐含着一个 this 引用，指向调用该方法的当前对象。
  this 在编译之后会作为方法的第一个参数隐式传入。

使用场景：
  3.1 区分成员变量和局部变量：当形参名与成员变量名相同时，使用 this.xxx 明确指定成员变量
  3.2 调用本类的其他构造方法：this(...) 必须在构造方法的第一行，且不能与 super(...) 同时存在
  3.3 传递当前对象作为参数：例如 register(this)
  3.4 在内部类中引用外部类实例：OuterClass.this

注意事项：
  this 不能用在静态方法中（静态方法属于类，不属于对象）
  this(...) 调用构造方法时，必须是第一条语句
  构造方法之间不能循环调用（会导致编译错误）
```

# 4.构造方法

## 4.1格式

```
<authority> <class_name>([params]){
	<func_body>;
}
```

## 4.2特点

```
4.2.1方法与类名相同
4.2.2没有返回值类型，连void也没有
4.2.3没有具体的返回值（不能由return带回结果数据）
4.2.4如果没有定义构造方法，系统将给出一个默认的无参构造方法
4.2.5如果定义了构造方法，系统将不再提供默认的构造方法（所以无论是否使用，建议都应该手动书写无参构造 ，防止定义有参构造后，没有无参构造可用）
```

## 4.3执行时机

```
4.3.1创建对象的时候由虚拟机调用，不能手动调用构造方法
4.3.2每创建一次对象，就会调用一次构造方法
```

## 4.4构造方法的重载

```
构造方法支持重载，即可以定义多个参数列表不同的构造方法。

示例：
  public class Student {
      private String name;
      private int age;

      // 无参构造
      public Student() {}

      // 单参构造
      public Student(String name) {
          this.name = name;
      }

      // 全参构造
      public Student(String name, int age) {
          this.name = name;
          this.age = age;
      }
  }

构造方法链：
  可以使用 this(...) 在构造方法中调用本类的其他构造方法，实现代码复用：

  public Student() {
      this("无名", 0);  // 调用全参构造，必须在第一行
  }

  public Student(String name) {
      this(name, 0);    // 调用全参构造
  }

  public Student(String name, int age) {
      this.name = name;
      this.age = age;
  }
```

# 5.标准JavaBean

```
JavaBean 是一种 Java 语言写成的可重用组件。

标准规范（也称为 POJO 规范）：
  5.1 类名需要见名知意
  5.2 成员变量使用private修饰
  5.3 提供至少两个构造方法：无参构造 + 带全部参数的构造方法
  5.4 提供每一个成员变量对应的set...()和get...()方法
  5.5 如果还有其他业务行为方法，也需要写上
  5.6 建议实现 Serializable 接口（如果涉及序列化）

5.7 快速编写javabean
  5.7.1 alt+insert 快捷键（在 IDEA 中快速生成 getter/setter/构造方法）
  5.7.2 ptg插件（可通过 JSON 等多种方式快速生成 JavaBean）
  5.7.3 Lombok 库：使用 @Data、@Getter、@Setter、@AllArgsConstructor 等注解自动生成模板代码
```

# 6.对象内存图

```
Java 内存分配（JVM 运行时数据区）：

  栈 (Stack)：
    - 存储局部变量、方法参数、对象引用
    - 每个线程拥有独立的栈空间
    - 每个方法调用对应一个栈帧
    - 遵循"先进后出"，方法执行完毕栈帧弹出

  堆 (Heap)：
    - 存储所有通过 new 创建的对象和数组
    - 被所有线程共享
    - 是 GC（垃圾回收）管理的主要区域
    - 可细分为新生代（Eden、Survivor0、Survivor1）和老年代

  方法区 (Method Area)：
    - 存储类信息、常量、静态变量、即时编译器编译后的代码
    - JDK8 以前称为"永久代"（PermGen），位于堆外
    - JDK8 以后改为"元空间"（Metaspace），使用本地内存

对象创建的内存流程（以 Student s = new Student() 为例）：
  1. 方法区加载 Student.class
  2. 栈中声明变量 s（引用变量）
  3. 堆中 new 出 Student 对象空间（含成员变量默认值）
  4. 执行构造方法初始化
  5. 将堆中对象的地址赋值给栈中的 s

两个引用指向同一个对象：
  Student s1 = new Student();
  Student s2 = s1;  // s2 和 s1 指向堆中同一个对象
  s2.setName("张三");
  System.out.println(s1.getName());  // 输出"张三"（通过 s1 也能看到修改）
```

# 7.成员变量、局部变量

```
7.1 定义位置不同
  成员变量：定义在类中，方法外
  局部变量：定义在方法内、方法参数、构造方法参数、代码块内

7.2 生命周期不同
  成员变量：随对象的创建而存在，随对象的销毁而消失
  局部变量：随方法的调用而存在，随方法的执行完毕而消失

7.3 内存位置不同
  成员变量（实例变量）：存储在堆内存中
  局部变量：存储在栈内存中

7.4 默认值不同
  成员变量：有默认初始值
    - 整数类型（byte/short/int/long）：0
    - 浮点类型（float/double）：0.0
    - 字符类型（char）：'\u0000'（空字符）
    - 布尔类型（boolean）：false
    - 引用类型（类/数组/接口）：null
  局部变量：没有默认值，必须手动赋值后才能使用

7.5 修饰符不同
  成员变量：可以使用 private、public、protected、static、final 等修饰
  局部变量：只能使用 final 修饰

7.6 就近原则
  当局部变量和成员变量同名时，在方法内优先使用局部变量。
  若想使用成员变量，需用 this.变量名 加以区分。

7.7 static 修饰的成员变量（静态变量/类变量）
  存储在方法区（JDK8+ 在堆中），随类的加载而加载，被所有对象共享。
  可使用 类名.变量名 直接访问，也可通过对象名访问（不推荐）。
```

# 8.内存回收与垃圾回收（GC）

```
Java 自动管理内存，GC线程负责回收不再被引用的对象。

对象可回收的判断标准：
  8.1 引用计数法（Java未采用）：每个对象维护一个引用计数器
  8.2 可达性分析算法（Java采用）：从 GC Roots 出发，无法到达的对象即为可回收对象

GC Roots 包括：
  - 栈中引用的对象（局部变量表）
  - 方法区中静态变量引用的对象
  - 方法区中常量引用的对象
  - 本地方法栈中 JNI 引用的对象
  - 被同步锁（synchronized）持有的对象

手动触发 GC：
  System.gc();  // 建议 JVM 执行垃圾回收，但不保证立即执行
  Runtime.getRuntime().gc();

finalize() 方法（已废弃，JDK9 起不推荐使用）：
  对象被回收前会调用 finalize() 方法，用于资源释放。
  由于执行时机不确定，不应依赖此方法释放关键资源。
```
