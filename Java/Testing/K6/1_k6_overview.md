# 1. 定义与定位

## 1.1 什么是 k6
k6 是一款用 Go 编写、以 JavaScript 编写脚本的性能测试/负载测试工具。它面向工程化压测场景，强调可编程、可版本化、可自动化。

核心特征：
- 脚本即代码：测试逻辑与断言用 JS 编写，便于复用和工程化。
- 轻量运行：每个 VU 对应独立的 JS 运行时实例，由 Go 协程调度。
- 指标驱动：内置丰富指标与阈值，适合在 CI 中做质量闸门。

## 1.2 设计理念与核心取舍
- 可重复性：脚本与配置可纳入 Git，保证测试可复现。
- 简化分布式复杂度：开源版以单机为主，分布式交给 k6 Cloud 或 k6-operator。
- 性能优先：避免 GUI 开销，鼓励以代码表达负载模型。

## 1.3 适用与不适用场景
### 1.3.1 适用
- API 与微服务压测、容量评估
- CI/CD 中的性能回归检查
- 需要脚本化、模块化的复杂场景
- 对统计指标与阈值有明确诉求的团队

### 1.3.2 不适用
- 强依赖 GUI 录制的测试团队
- 需要复杂浏览器交互的端到端场景（更适合 Playwright/JMeter 插件）
- 没有性能基线、无法定义 SLO 的项目

# 2. 核心能力与优势

## 2.1 脚本化与可编程
- 以 JS 表达请求、断言、数据驱动和流程控制
- 与现代工程工具链兼容（lint、测试、打包）

## 2.2 轻量并发模型与性能
- VU 由 Go 协程调度，启动和调度成本低
- 指标采集开销可控，适合长时间稳定性测试

## 2.3 扩展与生态
- 通过 xk6 扩展能力（输出、协议、自定义逻辑）
- 可与 InfluxDB、Prometheus、Grafana 等集成

# 3. 关键概念速览

## 3.1 VU、迭代与脚本结构
- VU（Virtual User）：一个并发执行单元
- 迭代（Iteration）：VU 执行 `default` 函数的次数

```javascript
import http from "k6/http";
import { check } from "k6";

export const options = { vus: 10, duration: "30s" };

export default function () {
  const res = http.get("https://example.com");
  check(res, { "status is 200": (r) => r.status === 200 });
}
```

## 3.2 执行器与负载模型
- 闭合模型：并发数固定，响应慢会降低吞吐
- 开放模型：按到达率发请求，更贴近真实流量

## 3.3 指标、检查与阈值
- 指标：吞吐、延迟、错误率、资源消耗
- 检查（check）：业务断言
- 阈值（threshold）：质量闸门

# 4. 与常见工具对比

## 4.1 k6 vs JMeter
- k6：脚本化、轻量、易入 CI
- JMeter：GUI 友好、协议插件丰富、入门门槛低

## 4.2 k6 vs Gatling/Locust
- k6：JS 生态、学习成本低
- Gatling：Scala DSL，性能高但学习成本更高
- Locust：Python 生态，分布式能力成熟

## 4.3 选型建议
- 追求工程化与自动化：优先 k6
- 依赖 GUI 录制：优先 JMeter
- 需要大规模分布式：k6 Cloud 或 Locust 集群

# 5. 压测类型与目标

## 5.1 常见测试类型
- 负载测试：验证目标 QPS 下的稳定性
- 压力测试：找出系统瓶颈与极限
- 稳定性测试：长时间运行观察资源泄漏
- 突刺测试：流量短时飙升的承受能力

## 5.2 目标与指标
- 目标要量化：P95 延迟、错误率、吞吐
- 与业务 SLO 对齐，避免无目标压测
