# 1. 压测端性能优化目标

## 1.1 为什么要优化压测端
- 压测端瓶颈会导致结果失真
- 需要确保压力来自被测系统而非客户端

## 1.2 资源模型
- CPU：JS 运行时与加解密开销
- 内存：VU 数与响应体缓存
- 网络：带宽与连接数限制

# 2. VU 与资源关系

## 2.1 VU 成本评估
- 每个 VU 有独立 JS 运行时
- 高 VU 会显著增加内存占用

## 2.2 资源瓶颈识别
- `http_req_blocked` 升高可能是客户端资源不足
- 吞吐下降但服务端无压力是客户端瓶颈信号

# 3. 脚本优化策略

## 3.1 减少不必要的解析
- 只解析必要字段
- 对大响应使用 `discardResponseBodies`

## 3.2 控制日志与调试
- 日志会严重降低吞吐
- 调试阶段与正式压测阶段分离

## 3.3 合理的思考时间
- `sleep` 用于模拟真实节奏
- 防止无限高频请求导致客户端过载

# 4. 网络与连接优化

## 4.1 连接复用
- 复用连接减少握手消耗

## 4.2 超时设置
- 合理超时减少无效等待
- 超时过短会放大网络波动

# 5. 客户端扩展策略

## 5.1 水平扩展
- 当单机达瓶颈时，可通过分布式执行扩展

## 5.2 监控客户端
- 压测端也需要 CPU、内存、带宽监控
- 避免客户端隐性瓶颈
