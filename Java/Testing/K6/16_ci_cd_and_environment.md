# 1. CI/CD 集成目标

## 1.1 为什么要集成
- 把性能回归纳入持续交付
- 提前发现性能劣化

## 1.2 适用场景
- 关键 API 回归测试
- 版本发布前的性能门禁

# 2. 集成策略

## 2.1 关键原则
- 选择稳定可重复的测试场景
- 设定清晰阈值，避免误报

## 2.2 结果归档
- 保存 summary 与原始指标
- 与构建版本关联

# 3. 环境管理

## 3.1 多环境配置
- 不同环境使用不同配置
- 控制环境差异带来的误判

## 3.2 机密与权限
- 用 CI 机密管理注入 token
- 避免将敏感信息写入脚本

# 4. 失败处理

## 4.1 阈值失败
- 失败需直接阻断 pipeline
- 输出清晰的失败原因

## 4.2 非预期故障
- 网络异常需与服务端故障区分
- 可在 pipeline 中设置重试策略

# 5. 常见问题

## 5.1 环境不一致
- 环境差异会导致性能结论失真

## 5.2 测试耗时过长
- 在 CI 中执行短链路、核心场景
