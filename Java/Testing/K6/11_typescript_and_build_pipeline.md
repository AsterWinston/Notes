# 1. 为什么要用 TypeScript

## 1.1 类型约束带来的收益
- 减少运行时错误
- 提升大型脚本的可维护性

## 1.2 适合 TS 的场景
- 场景复杂、模块多
- 需要团队协作与代码规范

# 2. 构建流程设计

## 2.1 基本思路
- 使用 TS 编写
- 通过打包工具输出可运行的 JS

## 2.2 构建脚本示例

```bash
# 伪示例：以实际工具为准
npm run build
```

# 3. 兼容性要点

## 3.1 ES 语法限制
- k6 运行时不支持全部浏览器 API
- 需避免使用 DOM、Window 等对象

## 3.2 模块解析
- 相对路径更稳定
- 尽量避免运行时动态 import

# 4. 规范与质量

## 4.1 类型定义
- 为公共模块提供类型声明
- 保持类型与实现一致

## 4.2 Lint 与格式化
- 在 CI 中做静态检查
- 避免脚本风格差异导致维护成本上升

# 5. 常见问题

## 5.1 打包体积过大
- 只引入必要依赖
- 避免引入浏览器端大型库

## 5.2 运行时错误
- 编译目标与 k6 运行时不匹配
- 需检查目标 JS 版本
