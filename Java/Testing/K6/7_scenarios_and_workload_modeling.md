# 1. 场景与 workload 概念

## 1.1 场景的意义
场景用于描述“不同用户群体在不同时间的行为模式”。它是将业务需求转化为可执行负载模型的关键抽象。

## 1.2 workload 组成
- 并发或到达率
- 业务路径比例
- 预热、稳定、降载阶段

# 2. 多场景设计

## 2.1 独立场景配置
k6 通过 `scenarios` 支持多场景并行：

```javascript
export const options = {
  scenarios: {
    browse: {
      executor: "constant-vus",
      vus: 20,
      duration: "2m"
    },
    buy: {
      executor: "ramping-arrival-rate",
      startRate: 5,
      timeUnit: "1s",
      preAllocatedVUs: 10,
      stages: [
        { target: 20, duration: "1m" },
        { target: 5, duration: "1m" }
      ]
    }
  }
};
```

## 2.2 分流与比例控制
- 通过不同场景控制流量占比
- 或在单场景中以随机/权重控制路径比例

# 3. 典型 workload 模式

## 3.1 负载测试
- 稳定并发或稳定到达率
- 目标是确认在预期负载下的稳定性

## 3.2 压力测试
- 逐级加压直到系统失败
- 观察瓶颈点与降级策略

## 3.3 稳定性测试
- 低波动、长时间运行
- 关注资源泄漏、堆积、慢查询增长

## 3.4 突刺测试
- 短时间高峰
- 验证弹性与限流能力

# 4. 指标与采样策略

## 4.1 预热期与稳定期区分
- 预热阶段不计入核心指标
- 通过时间窗口或标签进行过滤

## 4.2 采样精度与性能
- 高采样频率会影响客户端性能
- 保持采样与执行开销的平衡

# 5. 负载建模常见错误

## 5.1 不考虑业务路径比例
- 单一接口压测无法反映真实系统负载

## 5.2 直接使用并发数代替业务量
- 并发数只是手段，吞吐与延迟才是目标
