# 1. 分布式执行概览

## 1.1 开源版限制
开源版 k6 以单机执行为主，分布式能力需要借助外部系统或云服务。

## 1.2 常见方案
- k6 Cloud：官方云服务
- k6-operator：在 Kubernetes 中调度分布式执行

# 2. k6 Cloud

## 2.1 适用场景
- 需要快速扩展到大规模并发
- 不希望维护分布式基础设施

## 2.2 注意事项
- 关注数据隐私与网络连通性
- 评估成本与并发规模

# 3. k6-operator（Kubernetes）

## 3.1 适用场景
- 已有 K8s 集群
- 需要可控的分布式执行

## 3.2 关键点
- 统一脚本与配置管理
- 保证节点资源与网络稳定

# 4. 分布式压测的难点

## 4.1 时钟与指标一致性
- 跨节点时间偏差会影响聚合

## 4.2 网络与带宽
- 客户端网络不足会限制压测规模

# 5. 选型建议

## 5.1 小规模
- 单机执行即可，避免复杂化

## 5.2 大规模
- 优先考虑 k6 Cloud 或 K8s 方案
