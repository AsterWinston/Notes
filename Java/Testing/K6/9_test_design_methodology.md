# 1. 测试设计方法论

## 1.1 需求澄清
- 明确业务目标：吞吐、延迟、错误率
- 确定关键路径与关键接口

## 1.2 设定基线
- 从小规模测试建立基线
- 记录历史曲线，形成对比标准

# 2. 测试类型与策略

## 2.1 负载测试
- 验证目标 QPS 下的稳定性
- 关注延迟分位数与错误率

## 2.2 压力测试
- 逐步加压至系统崩溃或降级
- 识别瓶颈点与容量上限

## 2.3 稳定性测试
- 长时间测试验证资源泄漏
- 观察慢查询、连接池、GC 等指标

## 2.4 突刺测试
- 短时高峰验证系统弹性
- 关注限流与扩容策略

# 3. 业务场景建模

## 3.1 用户路径与权重
- 不同路径占比决定真实流量结构
- 用权重模拟用户分布

## 3.2 思考时间与节奏
- 加入 `sleep` 模拟用户操作间隔
- 业务流程越真实，结果越可信

# 4. 结果分析与结论

## 4.1 关键指标解读
- 延迟上升与错误率增加需区分原因
- 吞吐与并发、延迟存在耦合关系

## 4.2 结论表达
- 用明确结论而非单纯数据
- 给出“是否达标”的判定

# 5. 常见设计误区

## 5.1 目标不清晰
- 无指标与阈值的压测无法形成结论

## 5.2 只关注吞吐
- 吞吐提升但延迟不可接受也不合格

## 5.3 忽视环境一致性
- 环境差异会导致结论失真
