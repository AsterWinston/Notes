
# 1. 什么是 Nacos

Nacos（Dynamic Naming and Configuration Service）是阿里巴巴开源的一款更易于构建云原生应用的**动态服务发现**、**配置管理**和**服务管理**平台。其名称来源于 **Na**ming and **Co**nfiguration **S**ervice 的首字母缩写。

Nacos 致力于帮助开发者发现、配置和管理微服务。它提供了一组简单易用的特性集，能够快速实现动态服务发现、服务配置、服务元数据及流量管理。

# 2. 核心能力

Nacos 提供了四大核心功能模块：

## 2.1 服务发现与服务健康检查

- 支持基于 DNS 和基于 RPC 的服务发现
- 服务提供者通过 SDK/API 注册服务后，服务消费者可通过 DNS 或 HTTP 接口发现服务
- 实时健康检查，阻止向不健康的主机或服务实例发送请求
- 支持传输层（PING 或 TCP）和应用层（HTTP）健康检查
- 对于复杂的云环境和网络拓扑环境（如 VPC、边缘网络），提供了服务健康监测模式

## 2.2 动态配置管理

- 以中心化、外部化和动态化的方式管理所有环境的配置
- 消除了配置变更时重新部署应用和服务的需求
- 让配置管理变得更加高效和敏捷
- 支持配置版本跟踪、一键回滚、灰度发布

## 2.3 动态 DNS 服务

- 支持权重路由，更容易实现中间层负载均衡
- 支持灵活的路由策略、流量控制和数据中心区域的 DNS 解析服务
- 对以 DNS 协议为基础的服务发现场景提供原生支持

## 2.4 服务及其元数据管理

- 支持从微服务平台建设的视角管理数据中心的所有服务及元数据
- 包括：管理服务描述、生命周期、静态依赖分析、健康状态、流量管理、路由及安全策略、SLA 等

## 5.1 选型建议

- **只需要服务发现**：小规模可用 Eureka，中大规模考虑 Nacos
- **只需要配置中心**：Apollo 配置管理功能最完善；Nacos 也可以胜任
- **两者都需要**：Nacos 是最优选择，避免维护两套系统
- **需要原生多数据中心支持**：Nacos 和 Consul 都是好选择
- **需要严格的强一致性**：Consul（基于 Raft）；Nacos 也可切换到 CP 模式

# 6. 核心概念

## 6.1 服务（Service）

一个服务是一个逻辑上的概念，代表一组功能相同的实例集合。在 Nacos 中，服务通过 `服务名` 来唯一标识。

## 6.2 实例（Instance）

一个服务可以对应多个实例，每个实例代表一个具体的网络可访问端点（IP:Port）。实例分为两种类型：

- **临时实例（Ephemeral）**：通过心跳保活，心跳超时则自动剔除
- **持久实例（Persistent）**：由 Nacos Server 主动健康检查，不会自动剔除

## 6.3 命名空间（Namespace）

命名空间用于实现**租户级别的隔离**。不同命名空间下的服务和配置完全隔离，常用于多环境隔离（开发/测试/生产）。

## 6.4 分组（Group）

Group 用于在同一 Namespace 下做更细粒度的分组。默认 Group 为 `DEFAULT_GROUP`。

## 6.5 配置（Configuration）

在系统开发过程中，开发者通常会将一些需要变更的参数、变量等从代码中分离出来独立管理。配置管理是 Nacos 的核心功能之一。

## 6.6 配置集（Data ID）

在 Nacos 中，Data ID 是配置的最小单元，通常由应用名、配置文件类型和 Profile 共同构成。

# 7. 设计理念

Nacos 的整体设计哲学是：

```
高内聚的微服务内核 + 可插拔的功能扩展
```

核心设计原则：

1. **约定大于配置**：最小化配置项，提供开箱即用的默认值
2. **AP/CP 灵活切换**：注册中心场景默认 AP 模式，配置中心走 CP 模式
3. **无单点故障**：集群模式下每个节点对等，通过 Raft 或 Distro 协议保证一致性
4. **高性能**：内存注册表 + 异步推送 + 增量同步，支持万级服务实例
5. **易扩展**：插件化存储（Derby/MySQL）、插件化鉴权、SPI 机制

# 8. 适用场景

- **微服务架构**：这是 Nacos 最典型的应用场景，同时作为注册中心和配置中心
- **云原生应用**：与 Kubernetes、Service Mesh 配合，替代 K8s Service 的 DNS 方案
- **多环境管理**：利用 Namespace 隔离开发、测试、预发、生产环境
- **配置动态化管理**：业务开关、限流阈值、灰度策略等需要动态变更的场景
- **容量规划与管理**：服务元数据管理和服务生命周期管理
