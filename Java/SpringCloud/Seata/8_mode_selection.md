
# 1. 模式对比矩阵

| 维度 | AT | TCC | Saga | XA |
|------|-----|-----|------|-----|
| **实现复杂度** | 低 | 高 | 中 | 低 |
| **业务侵入性** | 无 | 高（三阶段接口） | 中（补偿方法） | 无 |
| **回滚方式** | 自动 undo_log | 手动 Cancel | 手动补偿 | 数据库 XA 协议 |
| **性能** | 中高 | 高 | 高 | 低 |
| **锁粒度** | 全局行锁 | 业务预留 | 无锁 | 数据库行锁（长） |
| **一致性级别** | 最终一致 | 最终一致 | 最终一致 | 强一致 |
| **读隔离性** | 读未提交 | 取决于实现 | 无隔离 | 读已提交 |
| **资源类型** | 仅数据库 | 数据库 + RPC + MQ | 任意 | 仅数据库（XA 支持） |
| **幂等要求** | 框架保证 | 需手动保证 | 需手动保证 | 数据库保证 |
| **依赖组件** | undo_log 表 | 业务状态表 | 补偿服务 | 数据库 XA 驱动 |
| **故障恢复** | 自动 | 需保证幂等 | 需保证幂等 | XA Recovery |

# 2. 模式选择决策树

```
需要分布式事务？
  │
  ├── 仅涉及数据库？
  │     ├── 需要强一致？
  │     │     └── 是 → XA 模式
  │     │
  │     └── 不需要强一致
  │           ├── 不想改代码 → AT 模式
  │           └── 追求极致性能 → TCC 模式
  │
  ├── 涉及非数据库资源（MQ、缓存、外部API）？
  │     ├── 可以直接改造 → TCC 模式
  │     └── 无法改造 → Saga 模式
  │
  └── 长事务（分钟/小时级）？
        └── Saga 模式
```

# 3. 各模式典型场景

## 3.1 AT — 通用首选

```
场景：电商下单
  订单服务（MySQL）→ 账户服务（MySQL）→ 库存服务（MySQL）
  涉及：3 个数据库，都是 MySQL
  要求：最终一致
  选择：AT 模式 ✓
  理由：零侵入、自动回滚、性能好
```

## 3.2 TCC — 高性能场景

```
场景：红包发放
  红包服务 → 发送 100 元红包
    Try: 冻结账户 100 元，生成红包
    Confirm: 扣款成功 → 红包到账
    Cancel: 解冻 100 元，回收红包
  
  涉及：账户余额（DB）、红包记录（DB）、消息推送（MQ）
  要求：高并发 + 高性能
  选择：TCC 模式 ✓
  理由：自定义预留机制，比全局锁更灵活，可涉及 MQ
```

## 3.3 Saga — 长事务/编排

```
场景：差旅报销流程
  员工提交 → 经理审批 → 财务打款 → 通知员工
  整个流程可能需要数小时甚至数天。
  
  涉及：多个服务，可能包含人工审批节点
  要求：最终一致，允许中间状态
  选择：Saga 模式 ✓
  理由：无锁、长事务、可编排、支持补偿
```

## 3.4 XA — 强一致性

```
场景：银行转账
  账户A（DB1）→ 扣款 1000
  账户B（DB2）→ 入账 1000
  
  涉及：2 个数据库
  要求：强一致性（不允许少钱或多钱）
  选择：XA 模式 ✓
  理由：数据库原生 XA，Phase 2 提交前数据锁定
```

# 4. 混合使用

Seata 支持在同一全局事务中混合使用不同模式：

```java
@GlobalTransactional
public void createOrder(Order order) {
    // 分支1: AT 模式（库存扣减）
    orderMapper.insert(order);           // AT 自动代理

    // 分支2: TCC 模式（账户扣款，需要预留+确认）
    accountTccService.tryDebit(userId, amount, orderId);

    // 分支3: Saga 补偿式（发送通知，支持补偿）
    notificationSaga.send(order);
}
```

# 5. 性能对比（参考基准）

```
测试条件：4C8G，MySQL 5.7，单表 10w 行

| 模式   | TPS    | P99 RT | CPU  | 锁等待 |
|--------|--------|--------|------|--------|
| 无事务  | 5000   | 15ms   | 40%  | —     |
| AT     | 4200   | 22ms   | 55%  | 中    |
| TCC    | 4600   | 18ms   | 50%  | 低    |
| Saga   | 4800   | 16ms   | 45%  | 无    |
| XA     | 2500   | 45ms   | 60%  | 高    |
```

> AT 模式开销主要来自 undo_log 写入（额外 SQL）和前置/后置镜像查询。

# 6. 选型建议总结

| 优先级 | 场景 | 推荐模式 |
|--------|------|---------|
| 1 | 通用分布式事务 | AT |
| 2 | 高性能 + 可改造 | TCC |
| 3 | 长事务 / 异构系统 | Saga |
| 4 | 强一致性 | XA |
