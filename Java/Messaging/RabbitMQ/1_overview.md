# 1. 什么是消息队列（MQ）

消息队列是一种跨进程、跨服务的异步通信机制，核心思想是 **生产者将消息发送到队列，消费者从队列中获取消息**，实现双方在时间上的解耦。

| 特性 | 说明 |
|------|------|
| **异步通信** | 发送方无需等待接收方处理完成即可继续执行 |
| **解耦** | 生产者和消费者通过队列解耦，彼此独立演进 |
| **削峰填谷** | 平滑突发流量，保护下游系统不被压垮 |
| **可靠投递** | 消息持久化、确认机制保证不丢失 |
| **顺序性** | 部分 MQ 支持分区有序或全局有序 |
| **广播/路由** | 一条消息可以被多个消费者消费（发布订阅） |

## 1.1 没有 MQ 的系统 vs 有 MQ 的系统

```
━━ 没有 MQ ━━
[服务A] ──同步调用──→ [服务B]
[服务A] ──同步调用──→ [服务C]      强耦合、串行、任一下游故障影响上游
[服务A] ──同步调用──→ [服务D]

━━ 有 MQ ━━
[服务A] ──发送消息──→ [MQ] ──投递──→ [服务B]
                       ├───投递──→ [服务C]    解耦、异步、下游故障不影响上游
                       └───投递──→ [服务D]
```

# 2. 什么是 RabbitMQ

**RabbitMQ** 是由 **Rabbit Technologies（后被 VMware/Tanzu 收购，现为 Broadcom 旗下）** 开发的开源消息中间件，采用 **Erlang/OTP** 编写，原生实现了 **AMQP 0-9-1** 协议，也通过插件支持 AMQP 1.0、MQTT、STOMP 等协议。

| 维度 | 说明 |
|------|------|
| 开发语言 | Erlang / OTP |
| 协议支持 | AMQP 0-9-1（原生）、AMQP 1.0、MQTT 3.1.1、STOMP、HTTP |
| 许可证 | 自 3.13 起对核心部分采用 Apache 2.0 许可 |
| 官网 | https://www.rabbitmq.com |
| GitHub | https://github.com/rabbitmq |
| 首次发布 | 2007 年 |

## 2.1 RabbitMQ 核心优势

| 优势 | 说明 |
|------|------|
| **AMQP 标准** | 完整实现 AMQP 0-9-1，互操作性强，多语言客户端 |
| **灵活路由** | Exchange + Binding 模型支持复杂路由策略 |
| **高可靠** | 消息持久化、生产者确认、消费者确认三重保障 |
| **可扩展** | 集群、镜像队列、仲裁队列、Federation/Shovel 插件 |
| **管理界面** | 内置 Management 插件，HTTP API 功能强大 |
| **插件生态** | 丰富的插件：延迟消息、Shovel、Federation、MQTT 等 |
| **社区活跃** | 生态成熟，文档完善，Spring 官方集成首选 |

# 3. AMQP 协议简介

**AMQP（Advanced Message Queuing Protocol）** 是一个开放的、标准的应用层消息中间件协议，旨在解决跨平台、跨语言的消息通信问题。

## 3.1 AMQP 模型核心三要素

```
┌───────────────────────────────────────────────────────────┐
│                     AMQP 0-9-1 模型                       │
│                                                           │
│  ┌──────────┐         ┌──────────┐        ┌──────────┐   │
│  │ Publisher │ ──msg──→│ Exchange │──msg──→│  Queue   │   │
│  └──────────┘         └──────────┘        └──────────┘   │
│                            │                  │           │
│                     (Binding Key)        ┌──────────┐    │
│                                          │ Consumer  │    │
│                                          └──────────┘    │
└───────────────────────────────────────────────────────────┘
```

| 组件 | 作用 |
|------|------|
| **Producer（生产者）** | 发送消息的应用程序 |
| **Consumer（消费者）** | 接收消息的应用程序 |
| **Broker（消息代理）** | RabbitMQ 服务器本身 |
| **Virtual Host（虚拟主机）** | 逻辑隔离单元，类似命名空间 |
| **Connection（连接）** | 客户端与 Broker 之间的 TCP 连接 |
| **Channel（信道）** | 连接内的轻量级虚拟连接，复用 TCP |
| **Exchange（交换机）** | 接收消息并根据规则路由到队列 |
| **Queue（队列）** | 消息存储缓冲区 |
| **Binding（绑定）** | Exchange 与 Queue 之间的关联规则 |
| **Routing Key（路由键）** | Producer 发送消息时指定，Exchange 据此路由 |
| **Binding Key（绑定键）** | Binding 时指定的匹配规则 |

## 3.2 AMQP 0-9-1 消息流转过程

```
1. Producer 建立 Connection，创建 Channel
2. Producer 声明 Exchange（如果 Dynamic=true 可不声明）
3. Producer 通过 Exchange + RoutingKey 发送消息
4. Exchange 根据类型和 BindingKey 匹配规则，将消息路由到匹配的 Queue
5. Queue 存储消息
6. Consumer 通过 Channel 从 Queue 获取消息
7. Consumer 处理完成后发送 ACK
```

# 4. RabbitMQ 发展历史

| 版本 | 发布时间 | 关键特性 |
|------|----------|----------|
| 1.0 | 2007 年 | 初始版本，实现 AMQP 0-8 |
| 1.4 | 2009 年 | AMQP 0-9-1 支持 |
| 2.0 | 2010 年 | 新持久化层、内存流量控制 |
| 2.7 | 2011 年 | 死信队列（DLX）、TTL |
| 3.0 | 2012 年 | Policy 策略、Federation 联合 |
| 3.2 | 2013 年 | 优先级队列 |
| 3.3 | 2014 年 | Publisher Confirm 性能提升 |
| 3.5 | 2015 年 | 惰性队列（Lazy Queue） |
| 3.6 | 2015 年 | 新配置系统、HTTP API 增强 |
| 3.7 | 2017 年 | AMQP 1.0 插件、多语言管理界面 |
| 3.8 | 2019 年 | **Quorum Queues**（仲裁队列）、Prometheus 监控、OAuth 2.0 |
| 3.9 | 2021 年 | **Streams**（流数据类型）、新管理界面 |
| 3.10 | 2022 年 | OAuth 2.0 增强、Stream 插件 GA |
| 3.11 | 2022 年 | 单活跃消费者（SAC）、MQTT QoS 2 |
| 3.12 | 2023 年 | 新 MQTT 5.0 插件、Khepri 数据库（实验性） |
| 3.13 | 2024 年 | **Khepri 元数据存储（GA）**、Mnesia→Khepri 迁移 |

> **重要变更**：从 RabbitMQ 3.12 起，核心采用 Apache 2.0 许可。Khepri（基于 Raft 的元数据存储）在 3.12 引入、3.13 正式替代 Mnesia。

# 5. RabbitMQ vs Kafka vs RocketMQ vs ActiveMQ

## 5.1 全方位对比

| 维度 | RabbitMQ | Kafka | RocketMQ | ActiveMQ |
|------|----------|-------|----------|----------|
| 开发语言 | Erlang | Java / Scala | Java | Java |
| 协议 | AMQP、MQTT、STOMP | 自定义二进制协议 | 自定义（类 JMS） | AMQP、MQTT、OpenWire |
| 消息模型 | Exchange → Queue 路由 | Topic → Partition → Offset | Topic → MessageQueue | JMS Queue/Topic |
| 吞吐量 | 万级/秒 | **十万~百万/秒** | 十万级/秒 | 万级/秒 |
| 延迟 | 微秒~毫秒级 | 毫秒级 | 毫秒级 | 毫秒级 |
| 消息顺序 | 单 Queue 有序 | Partition 内有序 | Queue 内有序 | 单 Queue 有序 |
| 消息回溯 | 不支持（消费即删除） | **支持（基于 Offset）** | 支持 | 不支持 |
| 事务消息 | 不支持（TX 性能差） | 不支持（幂等实现） | **原生支持** | 支持 JMS 事务 |
| 延时消息 | 插件（rabbitmq_delayed_message_exchange） | 不支持 | **内置支持** | 插件 |
| 集群 | Mirror Queue / Quorum Queue | 原生分布式 | 原生分布式（Dledger） | Master-Slave |
| 持久化 | 消息/队列/交换机可持久化 | 磁盘顺序写，零拷贝 | 同步刷盘/异步刷盘 | 基于 KahaDB/JDBC |
| 管理界面 | 功能强大的管理插件 | Kafka Manager / AKHQ | 内置控制台 | 内置 Web Console |
| 社区活跃度 | 高 | **极高** | 高（阿里开源） | 低（已归档/停维） |
| 典型场景 | 微服务异步通信、任务分发 | 日志/流处理、大数据管道 | 电商交易、金融场景 | 传统企业 JMS |

## 5.2 场景选择建议

```
┌──────────────────────────────────────────────────────────┐
│                     选型决策树                            │
│                                                          │
│  是否需要消息回溯？                                        │
│   └─ 是 → Kafka（日志存储）/ RocketMQ（事务+回溯）        │
│   └─ 否 → 继续判断                                        │
│                                                          │
│  是否需要事务消息（分布式事务）？                            │
│   └─ 是 → RocketMQ                                        │
│   └─ 否 → 继续判断                                        │
│                                                          │
│  吞吐量是否超过 10万 QPS？                                 │
│   └─ 是 → Kafka / RocketMQ                                │
│   └─ 否 → RabbitMQ（灵活路由 / 微服务首选）                │
│                                                          │
│  是否需要复杂路由（多条件分发）？                             │
│   └─ 是 → RabbitMQ（Exchange 路由模型原生支持）             │
│   └─ 否 → 均可                                            │
│                                                          │
│  技术栈/Ops 能力？                                        │
│   └─ Java 体系 → RocketMQ / Kafka / RabbitMQ              │
│   └─ 简单运维 → RabbitMQ（管理界面 / 文档最成熟）           │
└──────────────────────────────────────────────────────────┘
```

# 6. RabbitMQ 典型应用场景

| 场景 | 说明 | 示例 |
|------|------|------|
| **异步解耦** | 服务间异步通信，降低耦合 | 订单创建后异步发短信/邮件/记账 |
| **削峰填谷** | 平滑突发流量 | 秒杀时前端直接落 MQ，后端匀速消费 |
| **任务分发** | 将耗时任务分发给 Worker 处理 | 视频转码、图片处理、Excel 导出 |
| **广播通知** | 通知多个服务同步状态变更 | 配置更新广播、缓存失效通知 |
| **延迟处理** | 定时任务替代方案 | 30 分钟未支付自动取消订单 |
| **RPC 调用** | 双向异步通信 | 跨语言服务调用 |
| **日志收集** | 收集分布式日志（小规模） | 日志 → RabbitMQ → Logstash → Elasticsearch |
| **IoT 设备通信** | MQTT 协议接入 | 物联网设备消息上报与指令下发 |
