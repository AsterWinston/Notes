切片（slice）是 Go 最核心、最常用的数据结构，但它的"引用语义 + 底层数组共享 + 扩容机制"让无数人踩坑。数组则是切片的地基。这一章深入底层，把切片彻底讲透。

# 1. 数组

## 1.1 数组的特性

```go
var a [5]int                 // 长度 5 的数组，零值是 [0,0,0,0,0]
b := [3]int{1, 2, 3}         // 字面量
c := [...]int{1, 2, 3}       // 编译器自动推断长度
d := [5]int{1: 10, 3: 30}    // 按索引初始化 [0,10,0,30,0]
```

★ **关键认知**：Go 数组是**值类型**，且**长度是类型的一部分**——`[3]int` 和 `[4]int` 是不同类型。把数组传给函数会**整体拷贝**，所以数组很少直接使用，多数场景用切片。

## 1.2 数组的内存布局

```
[5]int 在内存中是连续 40 字节（5 × 8 字节）：

  a[0]   a[1]   a[2]   a[3]   a[4]
┌──────┬──────┬──────┬──────┬──────┐
│  1   │  2   │  3   │  4   │  5   │
└──────┴──────┴──────┴──────┴──────┘
```

# 2. 切片的底层结构

## 2.1 slice header 三字段

★ **关键认知**：切片在内存中是一个 24 字节（64 位系统）的结构体，由**三个字段**组成：

```go
// runtime/slice.go 中的定义
type slice struct {
    array unsafe.Pointer   // 指向底层数组的指针
    len   int              // 当前长度（已用元素数）
    cap   int              // 容量（底层数组长度）
}
```

```
slice（24 字节）
┌──────────────┬────────┬────────┐
│ array 指针   │  len   │  cap   │
└──────┬───────┴────────┴────────┘
       │
       ▼
   底层数组：[1][2][3][4][5][ ][ ]
             │←── len=5 ──→│
             │←────── cap=7 ──────→│
```

## 2.2 切片的三种创建方式

```go
// 1. 字面量
s := []int{1, 2, 3}

// 2. make（指定 len 和 cap）
s := make([]int, 5)        // len=5, cap=5
s := make([]int, 5, 10)    // len=5, cap=10（预分配容量）

// 3. 从数组或切片切片（共享底层数组）
arr := [5]int{1, 2, 3, 4, 5}
s := arr[1:4]              // [2,3,4]，len=3，cap=4（从索引 1 到数组末尾）
```

★ **关键认知**：`arr[1:4]` 的 cap 不是 3 而是 **4**——因为切片 cap 是从起始位置到底层数组末尾的长度。这个细节直接决定了 `append` 何时触发扩容。

# 3. len 与 cap 的语义

```go
s := make([]int, 3, 5)
len(s)   // 3：实际可访问的元素个数
cap(s)   // 5：底层数组的容量

// 只能访问 [0, len) 范围：
s[4]     // 报错：index out of range [4] with length 3
s[2]     // 合法
```

★ **关键认知**：`len` 是"已分配可用的长度"，`cap` 是"底层数组总容量"。访问超过 `len` 但小于 `cap` 的位置会**运行时 panic**（不是编译错误）。想扩大可见范围，用切片操作 `s[:5]`（前提是 cap 足够）。

# 4. append 与扩容机制

## 4.1 append 的基本行为

```go
s := []int{1, 2, 3}
s = append(s, 4)       // 必须接收返回值！append 可能返回新切片

// 批量追加
s = append(s, 5, 6, 7)
s = append(s, []int{8, 9}...)   // 展开切片
```

★ **关键认知**：`append` 的返回值**必须重新赋值**给原变量。因为 append 可能触发扩容，返回一个指向新底层数组的切片。忽略返回值是 Go 里最常见的 bug：`append(s, 4)` 而不用 `s = append(s, 4)`。

## 4.2 扩容策略（源码级）

★ **关键认知**：`append` 在 `cap` 不足时触发扩容，策略在 `runtime/slice.go` 的 `growslice` 中实现：

```
扩容规则（Go 1.18+ 的简化版）：
1. 若新长度 > 2 倍旧 cap，直接扩到新长度
2. 否则：
   - 旧 cap < 256：新 cap = 旧 cap × 2（翻倍）
   - 旧 cap >= 256：按约 1.25 倍的增长率缓慢递增（平滑过渡）
3. 最后按内存对齐/大小类别向上取整
```

```
示例：
cap=1  → append 后 cap=2
cap=2  → cap=4
cap=4  → cap=8
cap=128 → cap=256（翻倍）
cap=512 → cap≈848（1.25 倍平滑增长）
```

★ **关键认知**：扩容**不是原地扩展**，而是分配一个更大的新数组、把旧元素拷贝过去、返回指向新数组的切片。所以扩容后，旧的底层数组和基于它的其他切片不会受影响。

## 4.3 扩容的性能启示

★ **关键认知**：频繁 append 触发扩容会带来反复的分配 + 拷贝开销。若已知大致元素数量，应提前 `make([]T, 0, n)` 预分配容量：

```go
s := make([]int, 0, 1000)   // 预分配，避免 1000 次 append 触发多次扩容
for i := 0; i < 1000; i++ {
    s = append(s, i)
}
```

# 5. 切片共享底层数组的陷阱

## 5.1 多个切片共享底层

★ **关键认知**：切片操作和赋值拷贝的只是 24 字节的 header，**底层数组是共享的**。这是切片最大的坑：

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]          // b = [2,3]，但和 a 共享底层数组
b[0] = 100
fmt.Println(a)       // [1, 100, 3, 4, 5] —— a 被连带修改了！
```

## 5.2 append 导致的"意外修改"

```go
a := []int{1, 2, 3, 4}
b := a[:2]           // b = [1,2]，cap=4，共享底层数组
b = append(b, 99)    // b = [1,2,99]，但底层数组第 3 个位置被改成 99
fmt.Println(a)       // [1, 2, 99, 4] —— a 的第 3 个元素被污染！
```

★ **关键认知**：当 `b` 的 cap 足够时，`append(b, ...)` 会**直接写到底层数组**，从而"污染"共享同一数组的 `a`。避免这类 bug 的方法是：切片后若可能 append，用 `b := a[:2:2]`（三下标切片，把 cap 也限定为 2），强制 append 时拷贝到新数组。

## 5.3 三下标切片

```go
a := []int{1, 2, 3, 4}
b := a[:2:2]         // len=2, cap=2（限制 cap）
b = append(b, 99)    // cap 不足，分配新数组，a 不受影响
fmt.Println(a)       // [1,2,3,4] 安全
```

# 6. copy 函数

```go
src := []int{1, 2, 3, 4, 5}
dst := make([]int, 3)
n := copy(dst, src)   // 拷贝 min(len(dst), len(src)) = 3 个元素
fmt.Println(dst)      // [1,2,3]
```

★ **关键认知**：`copy` 返回**实际拷贝的元素个数**（两个切片长度的较小值），且**不会自动扩容** dst。想完整复制一个切片，要 `dst := make([]int, len(src)); copy(dst, src)`。

# 7. 小结

| 概念 | 要点 |
|------|------|
| 数组 | 值类型，长度是类型一部分，很少直接用 |
| slice 结构 | 指针 + len + cap（24 字节） |
| make | 可预分配 cap，避免扩容 |
| append | 必须接收返回值；cap 不足触发扩容 |
| 扩容策略 | <256 翻倍，>=256 约 1.25 倍 |
| 共享底层 | 切片间共享数组，append 可能互相污染 |
| 三下标切片 | `a[:2:2]` 限制 cap，隔离 append 影响 |
