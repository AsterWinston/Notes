一个 Go 程序的组织方式与它的编译链接过程密不可分。理解 `package`、`main`、`import` 的语义，以及从 `.go` 源码到可执行文件的完整流水线，是深入语言底层的第一级台阶。

# 1. 程序的基本组成

## 1.1 最小可运行程序

```go
// 文件名可以是任意名，如 main.go
package main          // 声明包名，main 包是程序入口

import "fmt"          // 导入标准库

func main() {         // main 函数，程序从这里开始执行
    fmt.Println("Hello, Go")
}
```

★ **关键认知**：一个可执行程序必须同时满足两点——`package main` + `func main()`。`main` 函数没有参数、没有返回值，它是运行时启动后调用的第一个用户函数。

## 1.2 package 的语义

```
package 是 Go 的基本组织单位：

1. 同一目录下的所有 .go 文件必须声明同一个包名
2. 包名可以和目录名不同（但惯例上保持一致）
3. 一个包 = 一个编译单元，编译产物是一个 .a 归档
```

★ **关键认知**：Go 的"包"既不是 Java 的单文件类，也不是 C++ 的头文件 + 源文件。它把"目录"和"命名空间"绑定：import 路径定位目录，目录内所有文件共同构成一个包。因此同一个包内的多个文件可以互相访问对方未导出（小写开头）的标识符。

# 2. import 与可见性

## 2.1 import 的几种形式

```go
import "fmt"                          // 常规导入
import (
    "fmt"
    "strings"
)                                     // 分组导入
import f "fmt"                        // 别名导入（f.Println）
import . "fmt"                        // 点导入（不推荐，直接 Println）
import _ "github.com/go-sql-driver/mysql"  // 空白导入：只执行包的 init 函数
```

## 2.2 导出规则：大小写即可见性

★ **关键认知**：Go 没有 `public`/`private` 关键字，**标识符首字母大小写决定可见性**——大写字母开头即导出（对外可见），小写开头即包内私有。这是 Go 最简洁也最容易让新手困惑的设计之一：一个名字改个大小写，访问权限就变了。

```go
package user

var Name  string  // 导出：其他包可访问 user.Name
var age   int     // 私有：只有 user 包内部可访问
func New() {}     // 导出
func init() {}    // 私有
```

## 2.3 import 循环依赖检测

★ **关键认知**：Go **禁止包的循环导入**（A imports B，B imports A）。这是编译期强制的，会在报错 `import cycle not allowed` 时直接失败。它迫使你设计出清晰的单向依赖层次，是 Go 工程化的体现之一。

# 3. 从源码到可执行文件

## 3.1 编译链接流水线

```
.go 源码
  │
  ▼  ① 词法/语法分析（scanner/parser）
AST（抽象语法树）
  │
  ▼  ② 类型检查（type checker）
类型化 AST
  │
  ▼  ③ 中间表示（SSA 构造）
GOSSAFUNC 可见的 SSA 形式
  │
  ▼  ④ 机器码生成
目标架构汇编
  │
  ▼  ⑤ 汇编（asm）
.o 目标文件
  │
  ▼  ⑥ 链接（link）
可执行文件 / 归档
```

★ **关键认知**：Go 编译器 `cmd/compile` 内部是经典的"前端 → 中端 → 后端"三段式。前端做词法语法分析与类型检查，中端把 AST 转成 SSA（静态单赋值）并做优化，后端生成目标机器码。逃逸分析发生在 AST→SSA 之前，内联、死代码消除等优化发生在 SSA 阶段。

## 3.2 分段查看编译过程

```
go build -x              # ★ 打印每一步实际执行的命令，看清 compile/asm/link 全流程
go build -work           # 保留临时工作目录，可查看中间产物
go build -gcflags="-S"   # 打印生成的汇编代码
GOSSAFUNC=main go build  # 生成 SSA 可视化 HTML，研究编译优化的利器
```

## 3.3 可执行文件的构成

```
Go 可执行文件 = 用户代码 + 运行时（runtime）+ 静态链接的标准库

特点：
1. 静态链接：默认不依赖系统动态库（CGO_ENABLED=0 时完全静态）
2. 自带运行时：GC、调度器、栈管理都编译进二进制
3. 体积较大：一个 Hello World 也有约 1.2MB（因为包含了整个运行时）
```

★ **关键认知**：Go 的"单文件部署"能力正来源于**静态链接 + 内置运行时**。相比之下 Java 需要 JVM、Python 需要解释器。这是 Go 在容器化、微服务场景大受欢迎的根本原因——一个二进制 + 一个基础镜像即可部署。

# 4. init 函数与初始化顺序

## 4.1 init 函数的特性

```go
package main

func init() {
    // 每个包可以有多个 init 函数
    // 在 main 执行前、包内所有变量初始化后自动调用
    // 不能手动调用，没有参数和返回值
}
```

## 4.2 初始化顺序

★ **关键认知**：Go 的初始化遵循严格的确定性顺序：

```
1. 先初始化被 import 的包（深度优先，按 import 顺序）
2. 每个包内：先初始化包级变量（按声明顺序），再执行 init 函数（按声明顺序）
3. 最后才执行 main 包自己的变量初始化和 init
4. 最后执行 main 函数
```

这种确定性保证了程序启动行为可预测，但也意味着 `init` 里不应做依赖外部状态或顺序敏感的事——它让代码难以测试。

# 5. 目录结构与惯例

## 5.1 推荐的工程布局

```
project/
├── go.mod
├── main.go              # 入口
├── cmd/                 # 多个可执行程序入口（大型项目）
│   ├── server/main.go
│   └── worker/main.go
├── internal/            # 私有包，外部模块不可导入
│   └── service/
├── pkg/                 # 可被外部引用的库代码
└── api/                 # protobuf/IDL 定义
```

★ **关键认知**：这套布局（`cmd`/`internal`/`pkg`）是社区惯例而非语言强制。其中唯一有**语言语义**的是 `internal`——其余都是约定，编译器并不关心目录名。

# 6. 小结

| 概念 | 要点 |
|------|------|
| package | 目录级编译单元，同目录必须同包名 |
| main 包 | 可执行程序入口，需 package main + func main |
| import | 完整模块路径，禁止循环导入 |
| 可见性 | 首字母大小写决定导出与否 |
| init | 自动执行，顺序确定但应慎用 |
| 编译 | AST → 类型检查 → SSA → 机器码 → 链接 |
