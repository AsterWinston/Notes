Go 保留了指针，但刻意砍掉了 C 指针最危险的部分（指针运算、随意类型转换），并用 `new`/`make` 分工管理内存。理解 Go 指针的"安全受限"设计，是理解值传递、方法接收者、以及后续 unsafe 章节的关键。

# 1. 指针基础

## 1.1 取地址与解引用

```go
var x int = 10
var p *int = &x        // & 取地址，p 指向 x
*p = 20                // * 解引用，通过指针修改 x
fmt.Println(x)         // 20

var pp **int = &p      // 二级指针（指向指针的指针）
```

★ **关键认知**：`&` 取地址，`*` 解引用。指针的零值是 `nil`。Go 指针和 C 一样是"指向某内存地址"的概念，但类型系统更严格。

## 1.2 指针的用途

```
1. 让函数能修改调用者的变量（值传递下，改副本无效）
2. 避免大结构体的值拷贝开销
3. 表示"可空"的引用（区别于值类型的非空语义）
```

# 2. Go 指针 vs C 指针

★ **关键认知**：Go 指针相比 C 指针**刻意弱化了能力**，以换取安全：

| 特性 | C 指针 | Go 指针 |
|------|--------|---------|
| 指针运算 | `p++`、`p+1` | ❌ 禁止 |
| 任意类型转换 | `(int*)p` | ❌ 禁止（需 unsafe） |
| 解引用空指针 | 崩溃（UB） | panic |
| 指向栈上变量 | 危险（悬垂） | 安全（逃逸分析兜底） |

```go
p := &x
p++       // 编译错误：invalid operation: p++ (non-numeric type *int)
```

★ **关键认知**：Go 禁止指针运算，从根源上杜绝了 C/C++ 里数组越界、缓冲区溢出等内存安全问题。这既是安全设计，也决定了 Go 无法像 C 那样直接操作内存布局——需要时得借助 `unsafe` 包（见汇编与 unsafe 章节）。

# 3. 值传递与指针传递

## 3.1 函数参数总是值拷贝

★ **关键认知**：Go 的函数参数**永远是值传递**——传入函数的是变量的**副本**。想修改原变量，必须传指针：

```go
func change(x int) {   // 值传递，改的是副本
    x = 100
}

func changePtr(p *int) {  // 传指针
    *p = 100
}

n := 1
change(n)         // n 仍是 1
changePtr(&n)     // n 变成 100
```

## 3.2 指针传递 vs 值传递的选择

★ **关键认知**：不是所有情况都该用指针。Go 的哲学是"默认值传递，需要修改或用大结构体时才用指针"。小结构体（如几十字节内）值拷贝的栈上开销极低，反而避免了指针解引用的间接寻址和 GC 压力。

# 4. new 与 make 的分工

## 4.1 new —— 分配并返回指针

```go
p := new(int)      // 分配一个 int，零值初始化，返回 *int
*p = 10

// 等价于：
var x int
p := &x
```

★ **关键认知**：`new(T)` 分配一块 T 大小的内存，**零值初始化**，返回 `*T` 指针。它和 `&T{}` 几乎等价，实际开发中用得不多（更多人直接 `&T{}`）。

## 4.2 make —— 只用于三种内建类型

```go
s := make([]int, 0, 10)     // slice
m := make(map[string]int)   // map
c := make(chan int, 10)     // channel
```

★ **关键认知**：`make` **只能**用于 slice、map、channel 这三种内建类型，它们内部都包含指向底层数据结构的指针。`make` 负责**初始化内部结构**并返回（值而非指针）。不能 `make(int)`，也不能 `new(map)`——`new` 出来的 map 是 nil，不可写。

## 4.3 new vs make 对比

| 操作 | new | make |
|------|-----|------|
| 适用类型 | 任意类型 | 仅 slice/map/chan |
| 返回值 | *T 指针 | T（已初始化） |
| 初始化 | 零值 | 内部结构就绪 |

# 5. 指针与 GC

★ **关键认知**：Go 的 GC 基于**可达性分析**——从根（全局变量、栈上变量、寄存器）出发，能通过指针追踪到的对象就是"存活"的。因此指针是 GC 追踪对象生命周期的**边**。理解指针关系，是理解逃逸分析、内存泄漏（对象被无意持有）的基础（详见 GC 章节）。

# 6. unsafe.Pointer 预告

★ **关键认知**：Go 在安全指针之外，保留了 `unsafe.Pointer` 这个"逃生舱"，它相当于 C 的 `void*`，可以：

```
1. 任意指针类型 ↔ unsafe.Pointer 互转
2. uintptr ↔ unsafe.Pointer 互转（做指针运算）
3. 绕过类型系统做底层操作（如零拷贝 string/[]byte 转换）
```

但它破坏了 Go 的所有内存安全保证，且错误使用会导致 GC 误判（uintptr 不被 GC 追踪）。生产代码应尽量避免，只在性能关键的底层库中谨慎使用（详见汇编与 unsafe 章节）。

# 7. 小结

| 概念 | 要点 |
|------|------|
| 指针 | & 取址，* 解引用，零值 nil |
| 无指针运算 | 语言级安全设计 |
| 值传递 | 函数参数永远是副本 |
| new | 分配零值，返回 *T |
| make | 仅 slice/map/chan，初始化内部结构 |
| unsafe.Pointer | 逃生舱，慎用 |
