Electron 最大的性能"黑点"是**体积大、内存高、启动慢**——它扛着一个 Chromium。因此 Electron 的性能优化,很大程度是"**驯服 Chromium 的开销**"。本篇讲清启动速度、内存占用、多窗口代价与 GPU 相关优化。

# 1. 启动速度

## 1.1 冷启动的耗时点

```
启动慢的来源:加载 Electron/Chromium 本身 + 主进程初始化 + 渲染进程加载页面
优化:延迟加载、按需初始化、隐藏到 ready-to-show 再显示
```

★ **关键认知**：首次启动慢的三大来源——**Chromium 本身、主进程初始化、页面加载**。⚠ 优化思路:**主进程别在启动时做一堆重活**(延迟到需要时)、**窗口 ready-to-show 再 show**(避免白屏等待感)、**渲染进程首屏轻量化**。

## 1.2 延迟初始化

```javascript
// ✗ 启动时:同步读大配置、注册一堆东西、加载大模块
// ✓ 启动时只做"显示窗口必需"的,其余按需(delayed require / 懒初始化)

let heavyModule
function useHeavyModule() {
  if (!heavyModule) heavyModule = require('./heavy')   // 用到才加载
  return heavyModule
}
```

★ **关键认知**：主进程**按需加载**重量模块、**延迟初始化**非关键功能(自启、检查更新放后台)。⚠ "启动只做显示窗口这件事",是桌面应用启动优化的第一原则;把可省的初始化统统往后挪。

# 2. 内存占用

## 2.1 Electron 为什么吃内存

```
Chromium 多进程:每个窗口一个渲染进程,每个都有基准内存开销
主进程 + GPU 进程 + 各渲染进程 + (可能的)工具进程
→ 天然比原生应用吃内存
```

★ **关键认知**：Electron 内存高是**架构代价**——多进程隔离(每个渲染进程独立)带来安全,也带来内存开销。⚠ 所以内存优化集中在"**减少进程数、让每个进程少占**",而不是妄想追平原生。

## 2.2 减少内存的实践

```javascript
// 窗口不用时销毁,而非隐藏(隐藏仍占内存)
win.close()  // 而非 win.hide()

// 关闭后台的"标签页崩溃/无用的子窗口"
// 懒加载大组件,避免一次全挂载
```

★ **关键认知**：**不复用/不显示的东西就"关闭"而非"隐藏"**(隐藏仍占内存);卸载大对象引用;渲染进程内懒加载大组件。⚠ "隐藏省内存"是误区——隐藏的窗口渲染进程还活着;真省内存要 destroy。

# 3. 多窗口的代价

## 3.1 每个窗口都是开销

★ **关键认知**：**每个 BrowserWindow 都是一个完整渲染进程**(有独立内存、独立 JS 环境)。⚠ 因此"开一堆窗口"是 Electron 内存失控的头号原因;设计上**能用一个窗口内做多视图(路由/多标签页),就别开多个 BrowserWindow**。

## 3.2 进程共享的边界

★ **关键认知**：想让多个窗口**共享资源/内存**,现实是它们仍是独立进程,只能靠 IPC 传数据,不能共享 JS 对象。⚠ 这是为什么"多窗口"要在设计阶段就慎重;若只是"多个页面",优先**单窗口 + 前端路由**,而非多 BrowserWindow。

# 4. GPU 与渲染

## 4.1 硬件加速

```javascript
// 某些场景(GPU 兼容性问题、虚拟机、无头环境)可关闭硬件加速
app.disableHardwareAcceleration()
```

★ **关键认知**：默认开启**硬件加速(GPU 渲染)**,通常更流畅;⚠ 但在**虚拟机、远程桌面、某些老旧显卡**下 GPU 反而出问题(花屏、崩溃),此时 `disableHardwareAcceleration()` 关掉能救急。这是"白屏/花屏"排查的第一开关。

## 4.2 渲染进程内的性能

★ **关键认知**：渲染进程内,前端那套优化(懒加载、虚拟列表、减少重渲染)完全适用——它是 Chromium。⚠ 别把桌面应用的渲染进程当"无限性能",大列表、大动画该优化照样优化;前端优化的所有技巧在这里都有效。

# 5. 性能清单

| 手段 | 针对 |
|------|------|
| 延迟初始化/按需 require | 启动慢 |
| ready-to-show 再显示 | 白屏等待感 |
| 关闭而非隐藏窗口 | 内存高 |
| 单窗口 + 路由代替多窗口 | 多进程开销 |
| disableHardwareAcceleration | GPU 兼容问题 |
| 前端懒加载/虚拟列表 | 渲染进程性能 |

★ **关键认知**：Electron 性能优化 = **"少加载(延迟)、少进程(单窗口)、少占(关闭勿隐藏)、少白屏(ready-to-show)"** + 前端优化照搬。它不像原生那样资源无限,别把 Chromium 当纯原生用。

# 6. 本篇小结与下一步

★ **关键认知**：Electron 性能重点在"驯服 Chromium"——启动靠延迟初始化、内存靠关闭而非隐藏、多窗口要克制(优先单窗口+路由)、GPU 问题可关硬件加速。前端优化技巧在渲染进程照常有效。
