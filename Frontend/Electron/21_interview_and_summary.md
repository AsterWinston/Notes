本篇是 Electron 系列的收官:先过一遍面试最高频的 10 道题(要点 + 示例),再画出 21 篇的知识地图与进阶方向。Electron 面试的深水区是"**多进程模型、IPC、安全、打包更新**",这篇一次对齐。

# 1. 高频面试题 10 道

## 1.1 主进程与渲染进程的区别

**要点**:主进程**一个**,管窗口/菜单/系统 API(权限全);渲染进程**每窗口一个**,管界面(能力如浏览器,受限)。判据:"网页能做吗?"

★ **关键认知**:主进程=管家(系统),渲染进程=网页(界面),靠 IPC 协作(第 3 篇)。

## 1.2 IPC 通信的几种方式

**要点**:`invoke/handle`(请求-响应,拿结果)、`send/on`(单向通知)、`webContents.send`(主推渲染)。

```javascript
ipcRenderer.invoke('read'); ipcMain.handle('read', async () => data)
```

★ **关键认知**:要结果用 invoke/handle;返回值须可序列化;event.sender 是精确回复/校验来源(第 5 篇)。

## 1.3 预加载脚本(preload)的作用

**要点**:主/渲染之间的**安全桥**——contextIsolation 隔离,contextBridge 暴露"最小必要"API 到 window.api,不暴露 ipcRenderer 本体。

★ **关键认知**:白名单思想,只暴露具体功能(第 4 篇)。

## 1.4 Electron 的安全措施

**要点**:渲染进程不可信;守 `nodeIntegration:false` + `contextIsolation:true` + `sandbox` + CSP + preload 最小暴露 + 主进程校验。

★ **关键认知**:分层防御,每层最小权限;CSP 挡 XSS,主进程验来源+验参数(第 16 篇)。

## 1.5 Electron 为什么体积大

**要点**:每个应用**打包了一个 Chromium** + Node,几十到上百 MB。

★ **关键认知**:代价是体积/内存,换来的是"Web 技术 + 跨平台一致";轻量替代是 Tauri(系统 webview)(第 1 篇)。

## 1.6 如何打包与自动更新

**要点**:electron-builder 打包(win=NSIS/mac=DMG/linux=AppImage);electron-updater 检测/下载/安装;发布到 GitHub Releases 或自建源。

★ **关键认知**:appId 是唯一标识,签名是分发前提;更新要可观测、可回退(第 13、14 篇)。

## 1.7 asar 是什么

**要点**:把应用源码**归档成单个只读文件**(app.asar),减少文件数、加载快。

★ **关键认知**:只读,所以**写入数据走 userData**,不写安装目录/asar(第 13 篇)。

## 1.8 数据该存在哪

**要点**:`app.getPath('userData')` 是**应用专属数据目录**(三平台自动正确);配置用 electron-store,结构化数据用 SQLite,文件用 fs。

★ **关键认知**:永远不写安装目录(可能只读)、不写 asar(只读);userData 是标准位置(第 10 篇)。

## 1.9 重活(CPU 密集)放哪

**要点**:别放主进程(会卡整个应用);用 utilityProcess(跑自己 JS)、child_process(调系统命令)、worker_threads(线程)、渲染层 Web Worker。

★ **关键认知**:让"响应用户的进程"保持轻快,重活挪到独立进程/线程(第 17 篇)。

## 1.10 与 Tauri / 原生相比怎么选

**要点**:Electron(Web 技术 + Chromium,生态成熟、跨平台 UI 一致、体积大);Tauri(系统 webview + Rust,体积小);原生(性能最好、成本最高)。

★ **关键认知**:"要 Web 全栈 + 一致 UI + 快迭代"选 Electron;"要小体积 + 愿碰 Rust"选 Tauri(第 1 篇)。

# 4. 进阶方向

| 方向 | 做法 | 收益 |
|------|------|------|
| 做一个完整小应用 | 托盘 + 设置 + 文件 + 更新 | 串起全链路 |
| Tauri 对比实践 | 用 Tauri 重写一个小工具 | 理解选型差异 |
| 源码浅读 | 读 Electron 主/渲染进程源码 | 印证模型 |
| 多窗口架构 | 主窗 + 子窗 + 状态同步 | 复杂应用能力 |
| CI 多平台打包 | GitHub Actions 出三端包 | 发布自动化 |
| native 模块实战 | 写一个简单 addon | 理解原生边界 |

★ **关键认知(全系列收束)**:Electron 的本质是**"用多进程模型把 Web 技术与系统能力缝合起来的桌面框架"**——Chromium 管界面、Node 管系统、主/渲染进程各司其职、IPC 做桥。把 21 篇浓缩一句:**把界面交给渲染进程(Web 技术)、把系统能力交给主进程(Node)、用 preload 安全地桥接、用打包与更新把应用送达用户,始终守住"渲染进程不可信"的安全底线**——掌握这些,你就从"会写 Electron"进阶到"能做好一个可发布的桌面应用"。至此,前端从 HTML/CSS 到 Vue/React 再到桌面(Electron)的完整地图,你都有了。
