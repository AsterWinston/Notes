纯 HTML 是死的——内容一旦写好就不变。真实项目里,页面结构往往要"套数据"动态生成,于是有了模板语法、模板引擎,以及 Vue/React 这类"把 HTML 变成组件"的框架。本篇讲清这三层演进:从字符串拼接,到模板引擎,再到框架组件化,厘清它们各解决什么问题、边界在哪。

# 1. 从静态到动态

## 1.1 三种生成 HTML 的思路

```javascript
// 层次一:字符串拼接(快糙猛,但易错、易注入)
const html = '<li>' + name + '</li>'

// 层次二:模板引擎(声明式,数据 + 模板 = HTML)
// template: '<li><%= name %></li>'

// 层次三:框架组件(模板 + 响应式 + 状态,自动更新 DOM)
// Vue: <li>{{ name }}</li>
```

★ **关键认知**：从拼字符串到模板引擎到框架组件,演进的本质是**从"命令式拼 DOM"到"声明式描述结构"**——你只描述"结构长啥样 + 数据填哪",生成/更新的脏活交给工具。⚠ 三层各有适用场景:**字符串拼接只在无依赖的极小脚本里凑合,模板引擎在多页应用/服务端渲染里仍有价值,框架是复杂交互 SPA 的首选**。

# 2. 模板语法与引擎

## 2.1 模板语法的两种风格

```html
<!-- 插值风格(EJS/Handlebars):<%= %> 插入值,<% %> 包裹逻辑 -->
<% users.forEach(function(u) { %>
  <li><%= u.name %></li>
<% }) %>

<!-- 双花括号风格(Mustache/Vue):{{ }} 插值 -->
{{#each users}}
  <li>{{ name }}</li>
{{/each}}
```

★ **关键认知**：主流模板语法分两派——**`<% %>`(类 EJS)**、**`{{ }}`(类 Mustache)**;它们共同的最小核心是**插值**(在 HTML 里挖洞填数据)+ **循环/条件**。⚠ "无逻辑模板(Mustache)"与"有逻辑模板(EJS)"之争的本质是**模板里能写多少代码**——前者克制(只插值+简单循环),后者放纵(几乎能写任意 JS),Vue 的模板介于其间(可写表达式,不能写语句)。

## 2.2 模板引擎的定位

★ **关键认知**：模板引擎(服务端渲染常用,如 EJS、Pug、Handlebars)做的是**编译期/服务端一次性地"模板 + 数据 → HTML 字符串"**。⚠ 它**不追踪变化**——数据变了要重新渲染整块 HTML,没有"只更新变的那部分"的精细控制;这正是它与前端框架的根本区别。

# 3. 框架如何"接管" HTML

## 3.1 Vue 的模板

```vue
<template>
  <!-- 语法上就是 HTML,但 {{ }} 是响应式挖洞,数据变了自动更新 -->
  <ul>
    <li v-for="u in users" :key="u.id">{{ u.name }}</li>
  </ul>
</template>
```

★ **关键认知**：Vue 的 `.vue` 单文件组件里,`<template>` 写的是**合法的 HTML + 扩展指令**(`v-for`、`:key`),由编译器转成 render 函数(见 Vue 第 21 篇)。⚠ 要点:"模板是 HTML 的超集"——能写 HTML 的地方都能写 Vue 模板,语法学习成本极低,这是 Vue 上手快的重要原因。

## 3.2 React 的 JSX

```jsx
// React 用 JSX:把 HTML 结构写进 JavaScript,由 Babel 转成函数调用
function List({ users }) {
  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  )
}
```

★ **关键认知**：React 的 JSX 不是 HTML——它**长得很像 HTML 的 JS 语法**,最终被编译成 `React.createElement` 调用。⚠ 与 Vue 模板的差异:**模板是"受限的 HTML"**(编译器可静态优化),JSX 是"自由的 JS"(灵活但难优化);JSX 与 HTML 的细节点(如 `className` vs `class`、`htmlFor` vs `for`)来自"它是 JS、得避开保留字"。

# 4. HTML 与框架的边界

| 维度 | 纯 HTML | 模板引擎 | Vue | React |
|------|---------|---------|-----|-------|
| 动态能力 | 无 | 服务端一次性 | 响应式自动更新 | 响应式自动更新 |
| 更新粒度 | — | 整体重渲染 | 组件级 | 组件级 |
| 语法 | HTML | HTML + 插值 | HTML + 指令 | JSX(类 HTML) |
| 运行环境 | 浏览器 | 服务端 | 浏览器(可 SSR) | 浏览器(可 SSR) |

★ **关键认知**：框架与 HTML 不是替代关系,而是**"建立在 HTML 之上"**——Vue 模板最终编译成 `h()` 调用生成 DOM,React JSX 编译成 `createElement` 生成 DOM。⚠ 理解这条:"**框架不管你用什么语法,最终都是操作 HTML/DOM**",是打通"HTML 基础"与"前端框架"的关键认知。

# 5. 何时用什么

★ **关键认知**：选型三问——**页面复杂交互多吗?**(是→框架);**是服务端多页/邮件模板吗?**(是→模板引擎);**只是一张静态页?**(是→纯 HTML 甚至纯 Markdown 转 HTML)。⚠ 别拿着框架去做静态页(杀鸡用牛刀),也别在交互密集的场景硬拼字符串。工具是为人服务的,匹配场景最重要。

# 6. 本篇小结与下一步

★ **关键认知**：三层演进——字符串拼接(命令式)→ 模板引擎(声明式一次性)→ 框架(声明式 + 响应式)。框架建立在 HTML 之上,模板/JSX 殊途同归,最终都生成 DOM。选型看"交互复杂度 + 渲染环境"。
