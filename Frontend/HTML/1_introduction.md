HTML 是万维网的结构语言——用一套标签把"这是什么"描述清楚，浏览器负责解析成 DOM 树并渲染。本篇讲清 HTML 的定位与"语义标记"的本质、浏览器的解析渲染流程，以及围绕标准的几件事（WHATWG、Living Standard、DOCTYPE 的历史包袱），为整个系列定好心智坐标。

# 1. HTML 是什么

## 1.1 一句话定位

HTML（HyperText Markup Language，超文本标记语言）是一种**标记语言**，不是编程语言——它**描述内容的结构与语义**，而非逻辑与算法。

```html
<!-- HTML 的职责：告诉浏览器"这是一段什么内容"，而非"怎么计算" -->
<h1>这是一级标题</h1>
<p>这是<span>强调的</span>一段正文。</p>
<ul>
  <li>这是一个列表项</li>
</ul>
```

★ **关键认知**：HTML 里没有变量、没有循环、没有运算——它是**纯标记**。它的目标读者有两个：**浏览器**（据此渲染）与**搜索引擎/屏幕阅读器**（据此理解语义）。⚠ 因此"HTML 写对了没有"不是看"长得像不像"，而是看"语义用得准不准"——一个 `<div>` 满天飞的页面，视觉上照样能拼出 `<h1>` 的效果，但机器读不懂它的结构。

## 1.2 HTML / CSS / JavaScript 的分工

| 层次 | 技术 | 职责 | 类比 |
|------|------|------|------|
| 结构 | HTML | 内容是什么、怎么组织 | 骨架 |
| 表现 | CSS | 长什么样、怎么排版 | 皮肤 |
| 行为 | JavaScript | 怎么交互、怎么动 | 肌肉 |

★ **关键认知**：三者**职责分离**是老生常谈但永不过时的原则——HTML 只关心结构与语义，样式交给 CSS，交互交给 JS。⚠ 违背它（如用 `<br>` 换行做排版、用 `<table>` 做布局、把样式全堆进 `style` 属性）都会让结构混乱、难以维护与访问。

# 2. 浏览器如何解析 HTML

## 2.1 从字节到 DOM 树

```
 字节流（网络）
     │
     ▼
  解码 + 分词（tokenizer）    字符 → 标签/文本/注释 等 token
     │
     ▼
  构建 DOM 树（tree construction）   token → 节点，按层级嵌套成一棵树
     │
     ▼
  渲染树 → 布局 → 绘制（与 CSS 合成）
```

★ **关键认知**：浏览器把 HTML 解析成**DOM 树（Document Object Model）**——一颗由元素节点、文本节点组成的树。JS 里 `document.querySelector` 操作的正是这颗树。⚠ DOM 树 ≠ 源码字符串：源码里的缩进、空白、书写顺序只是表象，DOM 树才是浏览器与 JS 真正面对的数据结构。

## 2.2 容错解析

```html
<!-- HTML 对这些"错误"极其宽容，浏览器会自行修复 -->
<p>没有闭合的段落
<ol>
  <li>第一项</li>
  <!-- 漏了 </ol> -->
```

★ **关键认知**：HTML 的解析器是**容错（error-tolerant）的**——标签写错、漏闭合，浏览器不会报错，而是按一套规则自动修正（补全闭合、忽略非法嵌套）。⚠ 容错是双刃剑：好处是页面几乎不会"崩"，坏处是**错误被悄悄吞掉**，最终 DOM 结构可能和你写的大相径庭——这正是需要校验器（第 14 篇）与语义规范的原因。

# 3. 标准的三件事

## 3.1 WHATWG 与 Living Standard

★ **关键认知**：HTML 标准由 **WHATWG**（Web Hypertext Application Technology Working Group）维护，采用 **Living Standard**（活标准）——它**没有版本号**，持续滚动更新，永远指向最新。⚠ 这与 CSS/JS 的分版发布（CSS3、ES2023）不同：HTML 只有一个持续演进的规范，别执着于"HTML5 之后的 HTML6 什么时候出"。

## 3.2 DOCTYPE 的历史包袱

```html
<!-- 现代 HTML 的唯一正确 DOCTYPE：极简声明 -->
<!DOCTYPE html>
```

```html
<!-- 旧时代的冗长 DTD 声明（仅供历史对照，勿用） -->
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Strict//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd">
```

★ **关键认知**：`<!DOCTYPE html>` 只有一个作用——**告诉浏览器用"标准模式（standards mode）"渲染**，避免进入兼容旧页面的"怪异模式（quirks mode，盒子模型行为不同）"。⚠ 它**不是 HTML 标签**（大小写无所谓、不需要闭合），只是文档第一行必须写的声明；省略它可能触发怪异模式，让布局莫名走样。

## 3.3 语义化与可访问性是标准的一等公民

★ **关键认知**：现代 HTML 标准的核心价值观是**语义化（semantic）**与**可访问性（accessibility）**——一大批标签（`<article>`、`<nav>`、`<header>`、`<footer>`）正是为"让机器读懂结构"而生。⚠ 这是本系列的暗线，第 9、10 篇会专章展开；先记住：**选标签的默认动作，是想"这个内容在语义上是什么"**。

# 4. 一个最小合法页面

## 4.1 完整骨架

```html
<!DOCTYPE html>                 <!-- 1. 声明标准模式 -->
<html lang="zh-CN">             <!-- 2. 根元素 + 语言（无障碍/搜素必需） -->
  <head>                        <!-- 3. 元信息：不直接显示 -->
    <meta charset="UTF-8">      <!--    字符编码，避免乱码 -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>我的第一个页面</title><!-- 浏览器标签页标题 -->
  </head>
  <body>                        <!-- 4. 可见内容 -->
    <h1>你好，HTML</h1>
  </body>
</html>
```

★ **关键认知**：一个合法页面的骨架是 **DOCTYPE + `<html>` + `<head>` + `<body>`**。其中 `<head>` 放不直接显示的元信息（编码、标题、样式链接），`<body>` 放可见内容。⚠ `lang="zh-CN"` 和 `charset="UTF-8"` 是两处"看不见但很重要"的细节——前者帮助屏幕阅读器选对发音，后者防止中文乱码。
