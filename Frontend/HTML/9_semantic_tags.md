同样是"布局分区",`<div>` 与 `<article>`/`<section>`/`<nav>` 的区别全在**语义**——前者只是盒子,后者声明了内容的性质。本篇讲清"语义化"到底为什么重要、这些结构性标签各代表什么、如何正确选择,以及"文档大纲"这个曾经辉煌又悄然淡出的概念。

# 1. 语义化为什么重要

## 1.1 语义化的三个受益者

| 受益者 | 语义化带来的价值 |
|--------|-----------------|
| 搜索引擎 | 读懂页面结构,精准收录与排序 |
| 屏幕阅读器 | 为用户播报"这是导航/这是正文" |
| 开发者 | 结构自明,代码可读可维护 |

★ **关键认知**：语义化的本质是"**让机器也能读懂内容性质**"。`<div>` 只表达"这里有个盒子",`<nav>` 却表达"这里是导航"——浏览器、读屏、爬虫都依赖后者。⚠ 语义化不改变外观(视觉上 `<div>` 和 `<article>` 几乎一样),它是**给机器看的说明书**,价值"看不见但真实"。

## 1.2 div 与 span 的定位

```html
<!-- div/span 是"无语义容器"：实在找不到语义标签时才用的兜底 -->
<div class="card">
  <span class="badge">仅用来加样式或脚本挂载点</span>
</div>
```

★ **关键认知**：`div`(块级)与 `span`(行内)是**通用容器**,本身**无语义**——它们在"没有更合适的语义标签"时才用。⚠ 原则:**先想语义标签,再退到 div/span**;满屏 `div` 意味着语义信息为零,机器只能靠猜。

# 2. 结构性标签逐一看

## 2.1 header / footer / main

```html
<body>
  <header>       <!-- 页头：logo、站点导航 -->
    <img src="logo.png">
    <nav>...</nav>
  </header>

  <main>         <!-- 主内容：每页唯一,放页面核心内容 -->
    <h1>文章标题</h1>
    <p>正文……</p>
  </main>

  <footer>       <!-- 页脚：版权、联系、声明 -->
    <p>© 2025</p>
  </footer>
</body>
```

★ **关键认知**：`<header>`/`<footer>` 不限于"整页"——**区块(article)内部也能有自己的 header/footer**;而 `<main>` 是**每页唯一**、"该页独有的主要内容"。⚠ 别把"全站在每页都一样的导航/页脚"放进 `<main>`,它们的更恰当位置是页面级 header/footer。

## 2.2 nav（导航）

```html
<nav aria-label="主导航">
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/docs">文档</a></li>
  </ul>
</nav>
```

★ **关键认知**：`<nav>` 包裹**主要导航链接**,让读屏用户能一键跳到导航、爬虫能识别站点结构。⚠ **不是所有链接组都用 nav**——比如正文里的相关链接、页脚的友情链接可能不需要;真正的"站点导航一级列表"才用。多个 nav 用 `aria-label` 区分(如"主导航""面包屑")。

## 2.3 article / section / aside

```html
<article>               <!-- 可独立分发的内容：一篇文章、一条帖子 -->
  <h2>文章标题</h2>
  <p>正文……</p>
  <aside>               <!-- 与主内容相关但可剥离的附加信息 -->
    <p>相关阅读</p>
  </aside>
</article>

<section>               <!-- 有主题、通常带标题的区块 -->
  <h2>功能特性</h2>
  <p>……</p>
</section>
```

★ **关键认知**：三者的选择标准——**`article` 能"独立成篇被转发/订阅"**(博客正文、评论)、**`section` 是有标题的主题区块**(章节)、**`aside` 是"与主内容相关但不属于主线"的附加**(侧栏、相关链接)。⚠ article 与 section 常被搞混的判据:**"这段内容拿出来,还算一个完整的、自足的东西吗?"** 算,用 article;只是文章里的一节,用 section。

# 3. 如何选择:一张决策表

| 内容 | 该用什么 |
|------|---------|
| 整页头/区块头 | `<header>` |
| 整页脚/区块脚 | `<footer>` |
| 站点导航链接 | `<nav>` |
| 页面唯一主内容 | `<main>` |
| 可独立转载的整体(文章/评论) | `<article>` |
| 有标题的主题区块 | `<section>` |
| 附加/侧栏信息 | `<aside>` |
| 找不到以上语义 | `<div>` / `<span>` |

★ **关键认知**：选标签的本质是**回答"这段内容在语义上是什么"**——独立成篇用 article,主题分节用 section,附加信息用 aside,导航用 nav,实在没有语义的纯容器才落到 div/span。

# 4. 文档大纲:一个被淡出的概念

## 4.1 曾经的"隐式大纲"

★ **关键认知**：早期 HTML5 试图用 `h1-h6` **自动生成文档大纲(Outline)**——每出现一个 `<h1>` 就开启一个新 section 层级。这催生了"每个 section 都用 h1"的写法。⚠ **这一算法从未被浏览器完整实现,已从规范中移除**——现在的主流做法回归朴素:按层级用 `h1 → h2 → h3`,整页一个 `h1`。

## 4.2 现在的正解

```html
<main>
  <h1>文章总标题(唯一 h1)</h1>

  <section>
    <h2>第一节</h2>       <!-- 层级跟随:用 h2 -->
    <section>
      <h3>第一节的小节</h3> <!-- 再细用 h3 -->
    </section>
  </section>

  <section>
    <h2>第二节</h2>
  </section>
</main>
```

★ **关键认知**：**别在 section 里重开 `h1`**——现代最佳实践是**标题层级严格递减**(h1→h2→h3),整页唯一 h1。⚠ 有人仍纠结"section 内能否用 h1",答案是:**能写,但不再有当年设想的自动降级好处**,反而易造成大纲混乱,老老实实按层级递减最稳妥。

# 5. 本篇小结与下一步

★ **关键认知**：语义化 = 让机器读懂内容;结构性标签各表其意(article 独立成篇/section 主题分节/aside 附加/nav 导航/main 主内容);选标签永远先答"这在语义上是啥"。文档大纲已简化,回归 h1→h2→h3 层级递减。
