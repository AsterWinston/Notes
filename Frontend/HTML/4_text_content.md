一篇文档的内容，90% 是"文字"：标题、段落、列表、引用、代码…… 用对标签，不只让文字有恰当外观，更让机器读懂它们的语义层级。本篇讲清这些**纯内容标签**的语义、适用场景，以及最常见的误用——尤其那个"该用 `<b>` 还是 `<strong>`"的经典纠结。

# 1. 标题与段落

## 1.1 六级标题 h1~h6

```html
<h1>一级标题（页面唯一）</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<!-- 一直到 h6，层级递减，重要性递减 -->
```

★ **关键认知**：`h1~h6` 表示**语义层级**，不是"字号大小"——`h1` 是最高级别标题，`h6` 最低。⚠ 一个页面**通常只有一个 `h1`**（页面主标题），其余按层级细分子标题；不要因为"想要小字"就用 `h6`、想要大字就用 `h1`——那是排版需求，应交给 CSS，而不是扭曲语义。

## 1.2 段落与换行

```html
<p>第一个段落。段落之间自动有间距。</p>
<p>第二个段落。连续文字换行不会自动分段。</p>
<p>这是第一行<br>这是第二行（<br> 是强制换行，非分段）</p>
```

★ **关键认知**：`<p>` 是**段落**（语义单位），`<br>` 是**强制换行**（视觉单位）。⚠ 别用 `<br>` 拼段落间距、别用多个空 `<p>` 制造空白——`<br>` 只用于"内容里确实需要换行"（如地址、诗歌），间距属于 CSS。

# 2. 列表

## 2.1 无序 / 有序 / 描述列表

```html
<!-- 无序列表：顺序无关（如功能点） -->
<ul>
  <li>支持暗黑模式</li>
  <li>支持多端同步</li>
</ul>

<!-- 有序列表：顺序有意义（如步骤） -->
<ol>
  <li>安装依赖</li>
  <li>启动服务</li>
</ol>

<!-- 描述列表：术语 + 解释 -->
<dl>
  <dt>HTML</dt>
  <dd>超文本标记语言</dd>
  <dt>CSS</dt>
  <dd>层叠样式表</dd>
</dl>
```

★ **关键认知**：三张列表各管一摊——`ul` **顺序无关**、`ol` **顺序有关**、`dl` **术语定义**。⚠ 常见的语义错误是"① ② ③ 顺序内容用 ul 手写数字""名词解释用 table 硬凑"，其实都该用对应的列表标签。

## 2.2 列表嵌套

```html
<ul>
  <li>前端
    <ul>            <!-- 嵌套子列表：子项真正属于父项 -->
      <li>HTML</li>
      <li>CSS</li>
    </ul>
  </li>
  <li>后端</li>
</ul>
```

★ **关键认知**：列表可**任意嵌套**，且子列表必须**写进某个 `<li>` 内部**（而非直接放 `<ul>` 下）。⚠ 嵌套错位（子 `<ul>` 不在 `<li>` 里）是解析器最容易"修出意外结构"的写法之一。

# 3. 引用与出处

## 3.1 blockquote / q / cite

```html
<!-- 块引用：整段引用他人内容，独占一块 -->
<blockquote cite="https://example.com/source">
  <p>站在巨人的肩膀上。</p>
  <cite>—— 牛顿</cite>
</blockquote>

<!-- 行内引用：嵌在句子里的短引用 -->
<p>他说 <q cite="https://example.com">学以致用</q>。</p>
```

★ **关键认知**：`blockquote` 是**块级引用**，`q` 是**行内引用**，`cite` 标**出处/作品名**（如书名、作品、作者）。⚠ 视觉上浏览器会给引用加缩进/引号，但语义才是重点——用它们能让搜索引擎与无障碍工具识别出"这是别人说的话"；出处优先写在 `cite` 属性或 `<cite>` 标签里，而非当普通文本。

# 4. 强调与文本语义

## 4.1 strong / em / b / i 的区别

```html
<p>这是一段<strong>非常重要</strong>的内容。</p>   <!-- 语义：重要，加粗 -->
<p>这是一段<em>需要强调</em>的内容。</p>          <!-- 语义：语气强调，斜体 -->
<p>这是<b>加粗</b>与<i>斜体</i>，纯视觉效果。</p>   <!-- 无语义，只改样式 -->
```

★ **关键认知**：`strong` / `em` 带**语义**（重要 / 强调，屏幕阅读器会加重朗读），`b` / `i` **纯表现**（加粗 / 斜体，无语义）。⚠ 这是语义化最经典的考点——**优先用 `strong`/`em`**；只有当"仅仅想改变外观、无任何强调含义"时才用 `b`/`i`（后两者的合法场景其实很少，如专业术语的斜体）。

## 4.2 其他行内文本标签

```html
<code>const x = 1</code>        <!-- 行内代码片段 -->
<mark>高亮标记的关键词</mark>      <!-- 高亮，如搜索结果命中 -->
<small>小字注释、免责声明</small>   <!-- 附属说明 -->
<sub>下标</sub> 与 <sup>上标</sup>  <!-- 化学式 H<sub>2</sub>O、平方 x<sup>2</sup> -->
<abbr title="HyperText Markup Language">HTML</abbr> <!-- 缩写，悬停看全称 -->
<time datetime="2025-01-01">元旦</time>  <!-- 机器可读的时间 -->
```

★ **关键认知**：这一串**行内语义标签**各司其职——`code` 代码、`mark` 高亮、`small` 小字、`sub/sup` 上下标、`abbr` 缩写、`time` 时间。⚠ 它们的存在意义是"让机器读懂这段文字是什么"：`<time datetime>` 让日历/搜索能解析日期，`<abbr title>` 让用户看到全称。

# 5. 语义区块概述

## 5.1 结构性分区标签

```html
<header>页面/区块的头部（logo、导航）</header>
<nav>导航链接集合</nav>
<main>页面主要内容（每页唯一）</main>
<article>可独立分发的内容（文章、帖子）</article>
<section>有标题的主题区块</section>
<aside>侧边栏、与主内容相关的附加信息</aside>
<footer>页面/区块的脚部（版权、联系）</footer>
```

★ **关键认知**：这套**结构性分区标签**（HTML5 新增）取代了"`<div>` 套 `<div>` 加 class"的老做法——`<header>`/`<footer>`/`<nav>`/`<article>`/`<section>`/`<aside>`/`<main>` 让文档骨架语义自明。⚠ 它们**外观与 `<div>` 几乎一样**，价值全在语义（第 9 篇专章展开）；`<main>` 每页只能有一个。

# 6. 本篇小结与下一步

★ **关键认知**：文本内容标签的选型原则——**先问"这是语义上的什么"**：标题用 h1~h6、列表用 ul/ol/dl、引用用 blockquote/q、强调用 strong/em、结构用 header/nav/article/section。语义对了，SEO 与无障碍自然受益。
