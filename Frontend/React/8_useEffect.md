`useEffect` 是让组件执行"副作用"(发请求、订阅、操作 DOM)的大门,也是 React 新手踩坑最多的地方——依赖数组、清理函数、无限循环。本篇把 useEffect 的心智模型讲透:它是什么、依赖数组怎么决定执行时机、清理函数干什么,以及与 Vue 的 watch 的对照。

# 1. useEffect 是什么

## 1.1 副作用与渲染分离

```jsx
import { useEffect, useState } from 'react'

function User({ id }) {
  const [user, setUser] = useState(null)

  useEffect(() => {
    // 副作用:渲染完成后执行(发请求)
    fetch(`/api/user/${id}`).then(r => r.json()).then(setUser)
  }, [id])   // 依赖数组:[id] 变了才重新执行

  return <div>{user ? user.name : '加载中…'}</div>
}
```

★ **关键认知**：`useEffect(fn, deps)` 的定位——**"渲染完成后,执行副作用"**;副作用(fetch、订阅、DOM 操作)不该混在渲染期间做。⚠ 触发时机:**每次渲染后**,React 检查依赖数组,`deps` 里的值**与上次不同**就重新执行副作用。

## 1.2 与渲染的关系

```
渲染阶段(纯) ──▶ commit(提交 DOM) ──▶ effect 阶段(副作用)
   只计算视图          更新 DOM          处理数据请求/订阅等
```

★ **关键认知**：React 把组件逻辑分两段——**渲染(纯计算,不该有副作用)** 与 **effect(副作用,渲染后跑)**。⚠ 牢记:**渲染必须"纯"**(别在返回 JSX 前发请求/改全局),副作用一律进 useEffect——这是 React 心智模型的地基。

# 2. 依赖数组

## 2.1 三种依赖写法

```jsx
useEffect(() => { ... })         // 无依赖:每次渲染后都执行
useEffect(() => { ... }, [])     // 空依赖:只在首次挂载后执行一次
useEffect(() => { ... }, [a, b]) // 有依赖:a 或 b 变了才执行
```

★ **关键认知**：依赖数组三态——**无依赖(每次)、`[]`(仅挂载一次)、`[a,b]`(依赖变才执行)**。⚠ 依赖数组告诉 React"**副作用依赖了哪些值**",必须**诚实**列全:副作用里用到的**响应式值(state/props)** 都应列入,漏了会读到旧值。

## 2.2 漏依赖与闭包旧值

```jsx
const [count, setCount] = useState(0)

useEffect(() => {
  console.log(count)   // 依赖漏了 count → ESLint 会警告,且闭包捕获旧值
}, [])
```

★ **关键认知**：漏写依赖 → **闭包旧值**——effect 闭包捕获的是"**那次运行时的 state 快照**",依赖没变就不重跑,读到旧 count。⚠ "eslint-plugin-react-hooks" 的 `exhaustive-deps` 规则就是专门抓这个的;别用关闭规则来"绕过"警告,那是掩耳盗铃。

# 3. 清理函数

## 3.1 为什么需要清理

```jsx
useEffect(() => {
  const timer = setInterval(() => tick(), 1000)   // 挂起定时器
  return () => clearInterval(timer)               // 清理函数:卸载/下次执行前调用
}, [])
```

★ **关键认知**：effect 里挂起的**资源(定时器、订阅、事件监听、请求)**,要返回一个**清理函数**,在**组件卸载**或**effect 再次执行前**调用。⚠ 不清理会导致**内存泄漏**(组件卸了,定时器/监听还在,还引用着旧组件)。

## 3.2 清理的时机

```
挂载 → 执行 effect → …依赖变 → 先跑"上一次的清理函数" → 再执行新 effect → …卸载 → 跑清理
```

★ **关键认知**：清理函数在**两个时机**跑——**依赖变化重跑前**、**组件卸载前**。⚠ 这是 React 声明式的体现:不用手动判断"什么时候该取消",React 在正确的时机替你调用清理函数。

# 4. 与 Vue 的对照

| 维度 | React useEffect | Vue watch/watchEffect |
|------|-----------------|----------------------|
| 依赖 | 手动声明依赖数组 | 自动追踪 |
| 旧值 | 无(需自己记) | watch 提供 oldValue |
| 清理 | return 函数 | watch 的 onCleanup |
| 执行 | 挂载即执行(含首次) | watch 默认惰性,watchEffect 立即 |

★ **关键认知**：二者本质相同(副作用 + 变化触发),**最大差异是依赖追踪**——Vue 靠 Proxy **自动**收集,React 靠**手写依赖数组**。⚠ 这带来 React 独有的"依赖数组漏写 → 闭包旧值"心智负担(第 15 篇详解),也带来"显式声明"的**可预测性**;没有绝对好坏,是两种设计取向。

# 5. 常见坑

## 5.1 无限循环

```jsx
useEffect(() => {
  setCount(count + 1)   // ⚠ 改 state → 触发渲染 → effect 又跑 → 再改 → 无限
}, [count])
```

★ **关键认知**：effect 里**改了依赖数组中的值**,就形成"改→渲染→跑→改"的**无限循环**。⚠ 解法:确保"effect 不需要该依赖"或"改成不依赖旧值的函数式更新";出现"组件疯狂重渲染"先查这个。

## 5.2 把 effect 当生命周期用

★ **关键认知**：别用 useEffect 硬套 class 生命周期的旧思维(`componentDidMount`/`didUpdate`)。⚠ 正确心智是"**每次渲染后,把依赖变了的副作用跑一遍**"——按"副作用依赖什么"去想,而不是"这是挂载还是更新"。

# 6. 本篇小结与下一步

★ **关键认知**：useEffect(fn, deps)= 渲染后执行副作用;依赖数组决定了何时重跑(必须列全,否则闭包旧值);返回清理函数释放资源;别在 effect 里改依赖中的值(无限循环)。React 靠"手动依赖",Vue 靠"自动追踪",这是两大框架的核心分歧之一。
