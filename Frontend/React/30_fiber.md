到原理篇了。React 性能的关键转折,是一套叫 **Fiber** 的架构——它把"一次性同步算出整棵树"改成"**可中断、分优先级、可恢复**"的增量更新。本篇讲清 Fiber 是什么、双缓存树、lanes 优先级、时间切片,以及它如何支撑并发特性。

# 1. Fiber 是什么

## 1.1 从递归到可中断

```
旧架构(React 15):递归渲染,一个组件接一个,不可中断
  → 树一大,一次更新可能阻塞主线程几十上百 ms,掉帧

Fiber:把"组件树"展开成"链表",遍历可暂停、可中断、可恢复
  → 每个 Fiber 是一个工作单元,做完一个可"让出"给浏览器
```

★ **关键认知**：**Fiber** 是把 React 的组件树**扁平化为链表**的数据结构——每个 Fiber 代表一个组件/节点,记录它自己的状态、返回父/子/兄弟的指针、要做的更新。⚠ 链表让遍历变得**可暂停/恢复**(做到哪记到哪),这是"可中断渲染"的数据基础。

## 1.2 Fiber 的双重身份

★ **关键认知**：Fiber 既是**数据结构**(组件树里的一个节点),又是**工作单元**(一次要处理的一小块)。⚠ 理解这个双关:协调器顺着 Fiber 链表走,每处理一个节点就完成一格工作,随时能让出控制权——这就是"时间切片"的原理。

# 2. 双缓存树(double buffering)

## 2.1 current 与 workInProgress

```
两棵树交替使用:
  current(当前屏幕上显示的树) + workInProgress(正在内存里构建的新树)

更新时:基于 current 复制出一棵 workInProgress,在新树上改,
算完后 指针一换,workInProgress 变成新的 current
```

★ **关键认知**：**双缓存树**——React 维护两棵 Fiber 树:`current`(已提交、屏幕上)与 `workInProgress`(正在构建)。⚠ 好处:**新树在内存里构建,不满意可丢弃**,构建完才"换指针"上屏——这让"渲染一半被更高优先级打断"成为可能(旧树还在,新树丢弃重来即可)。

## 2.2 为什么用双缓存

★ **关键认知**：双缓存树的本质是"**用空间换可中断**"——`current` 永远是稳定可显示的,`workInProgress` 随便折腾。⚠ 这也是"每次渲染都产生一棵新树"的来源(第 4 篇的"重渲染"背后就是这机制);第 31 篇的 Diff 也发生在这"新旧两棵树"之间。

# 3. lanes 优先级

## 3.1 更新也有优先级

```
更新分优先级(用 lanes,车道/位掩码表示):
  同步更新(输入、点击) —— 最高,立即处理
  默认更新 —— 一般
  过渡更新(startTransition 的) —— 低,可让路
  空闲更新 —— 最低,闲置才做
```

★ **关键认知**：**lanes** 是 React 给"更新"划分的**优先级**——输入/点击是同步高优先级,`startTransition` 标的是低优先级。⚠ 这是第 25 篇并发特性的原理层:高优先级更新能**打断**低优先级的渲染(就是因为渲染不再是一次性不可中断,而是按 lane 分先后)。

## 3.2 为什么是 lanes(批量数)

★ **关键认知**：lane 是**位掩码**,一次能表达多个优先级(一个更新可能属于多个 lane),便于"批处理判断"。⚠ 别纠结叫法(Fiber 早期用 expirationTime,后改 lanes),关键是:React 通过优先级**决定"谁先渲染、谁能让谁让路"**。

# 4. 时间切片与调度

## 4.1 时间切片(time slicing)

```
渲染一个大更新时:
  处理一个 Fiber(工作单元)
    → 时间片用完了?(如 5ms)→ 暂停,让出主线程(浏览器处理输入/绘制)
    → 下一空闲再回来继续
```

★ **关键认知**：**时间切片**——把大更新切成一格一格,每做一格**检查时间片是否用完**,用完就**让出主线程**给浏览器(处理输入、重绘),下一帧再继续。⚠ 这是"大数据重算不卡 UI"的实现机制:渲染不再霸占主线程,而是**碎片化 + 可让路**;配合 `MessageChannel`/`requestIdleCallback` 等调度。

## 4.2 Scheduler 调度器

★ **关键认知**：这套"让出/恢复/优先级"由 **Scheduler(调度器)** 负责——它决定**何时渲染、渲染哪个优先级的更新**。⚠ Scheduler 与 Fiber、lanes 三位一体:lanes 定优先级,Fiber 可中断,Scheduler 指挥调度,共同构成 React 的并发底座。

# 5. 协调流程全貌

```
触发更新(setState)
  → 标记有更新的 Fiber(按 lane 记优先级)
  → Scheduler 调度 → 开始 render 阶段
      → 沿 Fiber 树遍历,Diff 新旧(第 31 篇),生成 workInProgress
      → 可被高优先级打断(丢弃重来)
  → commit 阶段:把 workInProgress 切换为 current,更新真实 DOM(不可中断)
```

★ **关键认知**：React 更新分两阶段——**render(可中断,算差异)** 与 **commit(不可中断,写 DOM)**。⚠ 只有 render 阶段可中断;commit 一旦开始必须做完(否则 DOM 半更新状态)。这也解释了"**副作用要放 commit 之后(useEffect)**""**渲染要纯**(可安全重来)"这些规则。

# 6. 本篇小结与下一步

★ **关键认知**：Fiber = 可中断的链表工作单元;双缓存树保证"随时可弃新树";lanes 给更新分优先级;时间切片让渲染碎片化、可让路;Scheduler 统一调度。并发特性的底层,就是这套"可中断 + 分优先"的架构。
