每次状态更新,React 都会生成一棵新的 Fiber 树,然后**Diff(协调)** 新旧两棵树,算出最小 DOM 更新。本篇讲清 Diff 的三条策略假设、单节点与列表 Diff 的具体算法,以及 **key** 在其中的决定作用——这是 React 渲染机制最经典的一环。

# 1. Diff 的三条策略

## 1.1 让 O(n³) 变成 O(n)

```
树的精确 diff 是 O(n³)(太慢,不可用)
React 用三条假设,把它降到 O(n):
  1. 只同层比较(不跨层)
  2. 元素类型不同,直接重建整棵子树
  3. 用 key 标识"谁是谁"
```

★ **关键认知**：React 的 Diff 基于**三条启发式假设**,把复杂度从 O(n³) 压到 **O(n)**——**只同层比较、类型不同就重建、key 定身份**。⚠ 这三条是"牺牲极少见的极端场景,换取绝大多数场景的高效";理解它们,才能理解"为什么某些写法 Diff 表现差"。

# 2. 单节点 Diff

## 2.1 类型相同 vs 不同

```jsx
// 旧: <div>...</div>   新: <div>...</div>
//   → 类型相同:复用 DOM,只更新变化的 props

// 旧: <div>...</div>   新: <p>...</p>
//   → 类型不同:卸载旧 div,新建 p(子节点也全部重建)
```

★ **关键认知**：单节点 Diff 先看 **`type`**——**相同就复用 DOM、更新 props;不同就整棵重建**(不再递归比细节)。⚠ 这就是"别把组件类型在条件里换来换去"的原因:类型一变,子树全重建,状态全丢。

## 2.2 复用的含义

```
<div className="a"> → <div className="b">
  不是"删旧 div 建新 div",而是"复用一个 div,只改 className"
```

★ **关键认知**：类型相同 = **复用 DOM 节点**(保留其子节点的组件状态),只改变化的属性。⚠ 复用正是"input 焦点不丢、子组件 state 不重置"的原因——理解了复用,就理解了"为什么改了 props 但输入框没清空"这类问题。

# 3. 列表 Diff

## 3.1 无 key 时的按序比较

```
旧: [A, B, C]
新: [D, A, B, C](头部插入 D)
无 key 时按 index 逐个比较:
  0: A → D(类型不同,重建 D)
  1: B → A(重建)
  2: C → B(重建)
  3: 新 C(新建)
结果:全错位,4 个元素全重建
```

★ **关键认知**：无 key 时列表**按 index 顺序比较**——头部插入导致后面全部"错位",几乎所有元素都被重建。⚠ 这正是第 5 篇"为什么要有 key"的机制层答案:**key 让 React 按"身份"而非"位置"对齐**。

## 3.2 有 key 时按身份匹配

```
旧: [A(key=a), B(key=b), C(key=c)]
新: [D, A(key=a), B(key=b), C(key=c)]
有 key:先按 key 找相同身份的旧节点
  A/B/C 都能匹配到旧的,只需 "移动"(复用),只有 D 是新建
结果:复用 A/B/C,只新建 D —— 高效且状态保留
```

★ **关键认知**：有 key,React 先做**"新旧 key 的匹配"**——key 相同的复用(必要时移动 DOM),key 新的才新建。⚠ 这决定了组件的**状态保留**:有正确 key,重排/插入时组件实例跟着 key 走,状态不丢、不串。

## 3.3 key 的正确与错误

```jsx
// ✓ 正确:稳定唯一的业务 id
<li key={user.id}>

// ✗ 错误:index 当 key(插入/删除/重排时会被"原地复用",状态错乱)
<li key={index}>
```

★ **关键认知**：key 必须**稳定且唯一**;用 `index` 当 key 在插入/重排时,会发生"下标不变但内容变了"的元素被**原地复用**,状态(输入框、组件本地 state)串行。⚠ 这与 Vue 第 5、20 篇是**同一个原理**,是 React/Vue 面试共同的高频题。

# 4. 移动与复用优化

## 4.1 最后的"收尾移动"

★ **关键认知**：列表 Diff 里,匹配完 key 后,React 会算"哪些要移动、移动几个",用**最小移动**把顺序对齐(类似"找最长稳定子序列")。⚠ 这一层的优化是"复用之外再省移动",了解即可,重点是知道"**key 是复用与移动正确性的前提**"。

## 4.2 同层 diff 的边界

★ **关键认知**：Diff 只在**同层**进行——跨层的移动/变化,React "看不到"。⚠ 因此"把节点从 A 层移 B 层"这种操作,对 React 等于"删了重建";想要它在 DOM 上"移动",就要让结构保持在同层。

# 5. Diff 与整体流程

```
setState → 生成新 Fiber 树 → Diff(render 阶段,可中断)
  → 算出 effect(哪些 DOM 要增删改)
  → commit 阶段:一次性应用到真实 DOM(不可中断)
```

★ **关键认知**：Diff 发生在 **render 阶段**(算差异、可中断),结果是一份"**DOM 变更清单**",交给 **commit 阶段**一次性应用。⚠ 这是第 30 篇两阶段的具体化:render 只"算"不改 DOM,commit 才"动手"——所以 render 可以随便中断重来,commit 必须一气呵成。

# 6. 本篇小结与下一步
