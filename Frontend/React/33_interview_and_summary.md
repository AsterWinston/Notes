# 1. 高频面试题 12 道

## 1.1 useState 的更新机制

**要点**:`setState` 触发重渲染;对象/数组要**不可变**(新引用)才可检测;多次 setState 会**批处理**;依赖旧值用**函数式更新**。

```jsx
setCount(count + 1)      // 闭包旧值,连写三次只 +1
setCount(c => c + 1)     // 函数式,基于前值,三次 +3
setTodos([...todos, x])  // 不可变,新引用
```

★ **关键认知**:不可变 + 函数式更新是 useState 的两大命门(第 4 篇)。

## 1.2 受控组件与非受控组件

**要点**:受控**值由 state 掌控**(单一数据源,灵活),非受控**值由 DOM 维护**(ref 读,简单)。

★ **关键认知**:官方推荐受控;大表单受控太啰嗦/每击键重渲染,故有 React Hook Form(第 7、21 篇)。

## 1.3 useEffect 的依赖数组

**要点**:`[]` 只挂载跑一次,`[a]` a 变才跑,无依赖每次跑;依赖要**诚实**,否则闭包旧值。

★ **关键认知**:依赖数组是"变化触发",闭包在依赖没变时读旧值(第 8、15 篇)。

## 1.4 useMemo 与 useCallback 的区别

**要点**:`useMemo` 缓存值(昂贵计算),`useCallback` 缓存函数引用(稳引用配 memo)。

★ **关键认知**:`useCallback(fn,deps)` === `useMemo(() => fn, deps)`;单独用 useCallback 无意义,要配 React.memo(第 9 篇)。

## 1.5 为什么 Hook 不能在条件里调用

**要点**:Hooks 靠**调用顺序**对应 Fiber 上的 Hook 链表节点,条件调用会打乱顺序→状态错乱。

★ **关键认知**:顺序即地址,这是 rules-of-hooks 的根本原因(第 15、32 篇)。

## 1.6 React 的闭包陷阱

**要点**:回调/effect 捕获"创建那次渲染"的 state 快照;定时器/空依赖 effect 里读到旧值。

```jsx
useEffect(() => {
  const t = setInterval(() => setCount(count + 1), 1000)  // count 永远是初始值
  return () => clearInterval(t)
}, [])
```

★ **关键认知**:解药是函数式更新 `c => c + 1`(第 4 篇)。

## 1.7 为什么列表要 key,为什么不用 index

**要点**:key 让 diff **按身份复用**(而非按位置);index 在插入/重排时"原地复用错位",状态串行。

★ **关键认知**:用业务唯一 id,别用 index(第 5、31 篇)。

## 1.8 React.memo 是什么

**要点**:**浅比较 props**,不变就跳过重渲染;配合 useCallback 稳住函数引用才生效。

★ **关键认知**:memo 卡组件、useCallback 卡引用,是性能优化黄金搭档(第 24 篇)。

## 1.9 Fiber 架构解决什么

**要点**:把递归不可中断的渲染,改成**链表可中断**;配合双缓存树/lanes/时间切片,实现并发(可让路)。

★ **关键认知**:"可中断 + 分优先级"是并发特性的底层(第 30 篇)。

## 1.10 Diff 算法的优化策略

**要点**:三条假设拍平到 O(n)——只同层比、类型不同重建、key 定身份。

★ **关键认知**:类型不变就复用 DOM(状态保留),类型变就整棵重建(第 31 篇)。

## 1.11 为什么渲染要是纯函数

**要点**:并发下渲染可被打断、重来、丢弃;有副作用会重复执行/结果不一致。

★ **关键认知**:渲染纯、副作用进 useEffect,是并发渲染的正确性要求(第 1、25 篇)。

## 1.12 与 Vue 的核心差异

**要点**:**依赖追踪**(手动依赖数组 vs 自动 Proxy)、**模板编译 vs 运行时**、**状态更新**(快照+setState vs Proxy 直接改)。

★ **关键认知**:Vue 把优化放编译期(静态提升/patchFlag),React 放运行时(Fiber/调度)(第 11、15 篇)。
