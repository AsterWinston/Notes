CSS 的名字"层叠样式表"里藏着一个终极奥秘:**Cascade(层叠)**——当多个规则同时命中同一个元素,到底谁说了算。本篇讲清样式的三种引入方式、层叠与继承两大传播机制、来源优先级与 !important,把"为什么我的样式不生效"这个千古之谜的底层规则一次说透。

# 1. 三种引入方式

## 1.1 内联 / 内部 / 外部

```html
<!-- 方式一:内联样式(style 属性,直接写在元素上) -->
<p style="color: red;">内联样式</p>

<!-- 方式二:内部样式(<style> 标签,写在 head 里) -->
<style>
  p { color: blue; }
</style>

<!-- 方式三:外部样式表(link 引入,最常用、最可维护) -->
<link rel="stylesheet" href="style.css">
```

★ **关键认知**：三种引入方式的**适用范围**——外部样式表(工程首选,可复用、可缓存)、内部 `<style>`(单页/演示)、内联 `style`(极少数动态样式)。⚠ 生产项目**用外部样式表**,内联样式会让样式散落难维护,且与"结构表现分离"相悖。

## 1.2 导入 @import

```css
/* @import 在 CSS 里引入另一个样式表(放在文件最顶部) */
@import url("base.css");

/* 也可导入外部字体 */
@import url('https://fonts.googleapis.com/css?family=Roboto');
```

★ **关键认知**：`@import` 在 CSS 内引入另一个 CSS。⚠ 它会**增加层请求**、延迟加载,现代工程里**更推荐构建工具合并或直接在 HTML 里多个 `<link>`**,@import 主要用于引入字体或遗留代码。

# 2. 层叠 Cascade

## 2.1 层叠的优先级顺序

```
一条规则最终生效,要依次比较(从高到低):

1. 来源与 !important
   ★ author !important > user !important > author 普通 > user 普通 > 浏览器默认
2. 特异性(specificity)     ID > class/属性/伪类 > 元素/伪元素
3. 源码顺序                同特异性时,写在前面的覆盖前面的
```

★ **关键认知**：层叠的三道关卡——**先是来源(谁写的+有没有 !important),再是特异性(选择器有多"专一"),最后是顺序(谁在后)**。⚠ 记一个常见结果:**行内样式 > id 选择器 > class 选择器 > 元素选择器**;而 `!important` 能跳过特异性比较直接获胜(因此是"核武器",慎用)。

## 2.2 来源的胜负

```css
/* 用户代理样式(浏览器默认): p 有 margin */
/* 作者样式(你写的)会覆盖浏览器默认 */
p { margin: 0; }
```

★ **关键认知**：来源分三级——**作者(author,你写的)、用户(user,用户在浏览器里自定义的)、用户代理(UA,浏览器默认)**;通常作者样式覆盖浏览器默认。⚠ Standard 里的微妙点:**用户的 `!important` 优先级高于作者的 `!important`**(无障碍考虑,让用户能强制放大字体),这是少数作者无法覆盖的情形。

# 3. 继承 Inheritance

## 3.1 哪些属性会继承

```css
/* 文本/字体类属性大多会继承(颜色、字体、行高……) */
body {
  color: #333;       /* 后代元素继承这个颜色 */
  font-family: serif;/* 后代继承字体 */
}

/* 布局/盒模型类属性大多不继承(width、margin、padding、border) */
```

★ **关键认知**：**文本类**属性(`color`、`font-*`、`line-height`、`text-align` 等)会**继承**给后代;而**盒模型/布局类**(`width`、`margin`、`border`、`background` 等)**不继承**。⚠ 记住这条,很多"为什么子元素没继承背景"的疑问就解了——因为 background 根本不属于可继承属性。

## 3.2 控制继承的四个值

```css
p {
  border: inherit;    /* 强制继承父元素的值 */
  color: initial;     /* 回退到属性初始值 */
  margin: unset;      /* 可继承则继承,否则用初始值 */
  all: revert;        /* 回退到浏览器默认样式 */
}
```

★ **关键认知**：四个控制继承的万能值——`inherit`(强制继承)、`initial`(回退初始)、`unset`(能继承则继承否则初始)、`revert`(回到浏览器默认)。⚠ `revert` 尤其好用于"重置个别元素回默认样式";`all: unset` 能一次清空一个元素的所有样式。

# 4. 层叠与继承的联动

## 4.1 一起作用的例子

```css
/* 层叠决定"给 div 上最后是哪个 color";继承决定"子 p 是否拿到" */
div { color: blue; }        /* 作用于 div 及其可继承后代 */
div.special { color: red; } /* 特异性更高,覆盖上面的 blue */

/* 结果:普通 div 内文字蓝色,带 special 类的 div 内文字红色
   且各自内部的 <p> 会继承这个颜色 */
```

★ **关键认知**：**层叠**(解决同一元素的冲突)与**继承**(解决后代是否延用)是两条正交的机制,常被混为一谈。⚠ 排查"样式不生效"的顺序:**先看是否被层叠覆盖(优先级),再看属性是否根本不在继承范围**。

# 5. 特异性 specificity 速记(预览)

```css
/* 特异性用 (id数, class/属性/伪类数, 元素/伪元素数) 三元组比较 */
#nav .item a:hover   /* (1, 2, 1):1 个 id,2 个 class/伪类,1 个元素 */
```

★ **关键认知**：特异性是一个"三元组"而非数字,逐位比较(先比 id 数,再比 class 数,再比元素数)。⚠ 详细的计算规则、`:is()`/`:where()` 如何影响,以及"特异性不叠加成三位数"这类误区,见第 2 篇专章。

# 6. 本篇小结与下一步

★ **关键认知**：CSS = 选择器命中 + 属性描述 + **层叠决胜负 + 继承传后代**。层叠三道关卡:来源/+`!important` → 特异性 → 顺序;继承只发生在文本类属性。排查不生效,按此顺序走一遍。
