CSS 通常是页面性能的"隐性玩家"——一个选择器写得重、一个属性触发回流,都可能让滚动卡顿、动画掉帧。本篇讲清 CSS 性能的四个关键点:选择器性能、重绘与回流的区分、`will-change` 的正确用法,以及 `contain` 这个"限定布局范围"的新特性。

# 1. 选择器性能

## 1.1 从右往左匹配

```css
/* 浏览器从"最右"的选择器开始匹配,再向左回溯 */
.foo .bar .baz .title { }   /* 先找所有 .title,再逐个往上查祖先 */
```

★ **关键认知**：CSS 选择器**从右往左匹配**——先命中"最右那个"(如 `.title`),再逐级回溯验证祖先。⚠ 因此**最右的选择器越宽泛(`*`、元素选择器),匹配的开销越大**;实践上:避免通配 `*`、避免深层级宽匹配,但这些在现代浏览器里通常已是**微优化**,不必过度纠结。

## 1.2 实用建议

```css
/* 够用且高效:靠"类"这一级,避免链式深匹配 */
.list-item { }         /* 好 */
#app .content li a { } /* 差:深 + 右侧是元素 */
```

★ **关键认知**：性能的实用底线——**优先用"类"做最右选择器、别堆超深的链**;但**选择器性能是"微优化"**,真正的大头在下面的"回流/重绘"。⚠ 别本末倒置:与其纠结选择器,不如优先保证"不该回流的不回流"。

# 2. 重排与重绘

## 2.1 两者的区别

```
回流(reflow/重排):geometry 变了(尺寸、位置)→ 重新计算布局 → 重新绘制
  · width/height/margin/top/left/display 等改变
  · 代价高:它会"波及"兄弟与后代

重绘(repaint):只说外观,布局不变
  · color/background/box-shadow 等
  · 代价较低
```

★ **关键认知**：**回流(重排)** 是"几何变了、重新布局"(改动尺寸/位置,代价高、会波及周边);**重绘**是"仅视觉变了、布局不动"(改颜色/背景)。⚠ 性能优化的大原则是**"少触发回流"**——把高频变化的实现尽量引到"既不回流也不重绘"的合成层(composite)。

## 2.2 三个层级

```
回流(reflow) > 重绘(repaint) > 合成(composite,只 transform/opacity)
（代价从高到低）
```

★ **关键认知**：浏览器渲染的三档开销——**回流 > 重绘 > 合成**;`transform`/`opacity` 走**合成层**,几乎零布局开销、GPU 加速。⚠ 这就是第 12、13 篇反复强调"动画只用 transform/opacity"的原因:它们属于**最便宜的合成**,不碰那两档贵的。

# 3. 触发回流的操作

## 3.1 读写引发

```css
/* 布局类属性改动触发回流 */
.el { width: 200px; margin: 0; top: 0; display: block; }
```

```javascript
// JS 里"读几何、写几何"交替,会造成强制同步布局(性能大坑)
el.style.width = '100px'
const h = el.offsetHeight   // 强制读布局 → 触发回流
el.style.width = '200px'
```

★ **关键认知**：改 `width/height/margin/top/display` 等**几何属性**触发回流;JS 里"**写→读→写**"布局属性会造成**强制同步回流**(每次读都强制提前计算)。⚠ 优化:先**批量读**(把要读的一次读完)再**批量写**,或把要改的东西一次性改完,别读一个写一个。

## 3.2 减少回流的工程手法

```css
/* 方案一:脱离文档流,回流被"隔离"在局部 */
.el { position: absolute; }

/* 方案二:contain 限制布局影响范围(见下) */
.el { contain: layout; }
```

★ **关键认知**：减少回流的两招——**让经常改的元素脱离文档流**(absolute/fixed,它改了只影响自身不波及兄弟)、**用 contain 圈定范围**。⚠ 高频改尺寸/位置的响应式组件、拖拽目标,尤其值得用这两招。

# 4. will-change 正确用法

## 4.1 预告与滥用

```css
.animated {
  will-change: transform;   /* 预告"进出 transform 会变",提前升层 */
}
```

★ **关键认知**：`will-change` **预告**浏览器"某属性即将变化",让它**提前做优化**(如升到合成层)。⚠ **别滥用**(不要 `* { will-change: all }`)——每个都升层会**爆内存**;只在"确知要动画"的少数元素上,且动画结束后最好移除。

## 4.2 配合动画

```css
/* 入场前加 will-change,动画完移除(JS 控制)比较理想 */
.card:hover { will-change: transform; }
.card { transition: transform 0.3s; }
```

★ **关键认知**：will-change 的理想用法是**"走近了才预告,用完就回收"**——hover 时加上,配合 transition 做动画。⚠ 静态写在元素上长期保持,是它被误解滥用的重灾区。

# 5. contain 限定布局

## 5.1 contain 的作用

```css
.widget {
  contain: content;   /* 限定:内部变化不影响外部布局 */
}
```

★ **关键认知**：`contain` 告诉浏览器:"**这个元素的内部变化不会溢出影响外部**",让浏览器**跳过不必要的全局布局/绘制**。⚠ 它适用于"独立、自包含"的组件(卡片、视频、列表项)——内部怎么变都不动外面,是较新的性能优化手段。

## 5.2 常用取值

```css
.el { contain: layout; }  /* 仅在布局上隔离 */
.el { contain: style; }   /* 样式作用域隔离 */
.el { contain: content; } /* layout + paint 组合 */
.el { contain: strict; }  /* 全开(需元素有确定尺寸) */
```

★ **关键认知**：`contain` 分多档——`layout`(布局隔离)、`paint`(绘制裁剪)、`content`(layout+paint 常用)、`strict`(全开)。⭐ **`contain: content`** 是"独立组件"最实用的档位。⚠ `strict` 要求元素尺寸确定,否则内容可能被裁,需谨慎。

# 6. 性能清单

| 手法 | 针对 | 收益 |
|------|------|------|
| 动画只用 transform/opacity | 回流/重绘 | 走合成,GPU 加速 |
| 高频改动脱离文档流 | 回流波及 | 隔离回流范围 |
| JS 批量读写布局 | 强制同步回流 | 减少回流次数 |
| will-change 精准预告 | 动画元素 | 提前升层 |
| contain: content | 独立组件 | 跳过无关布局 |

★ **关键认知**：CSS 性能四件事——**选择器(微优化,别纠结)、少触发回流(大头)、动画只用合成属性、contain 限定范围**。核心一句话:**让改动留在最便宜的层级,且影响范围最小**。

# 7. 本篇小结与下一步

★ **关键认知**：性能层级"回流 > 重绘 > 合成";动画只用 transform/opacity(合成);改几何会回流,用脱离流 + contain 隔离;will-change 精准预告不滥用。CSS 性能的本质是"别做贵的、把贵的圈小"。
