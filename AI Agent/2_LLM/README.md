# 1. 模块定位

本模块讲解大语言模型「怎么训练出来的、怎么推理的、有哪些模型可选」。掌握这些后，你才能理解 Prompt 为什么有效、上下文为什么有限、推理成本为什么高。

## 1.1 本模块解决什么问题

- 能力从何而来：预训练、微调、对齐各自贡献了什么。
- 生成如何发生：自回归、采样、KV Cache、量化。
- 模型如何选型：能力、成本、合规、私有化的权衡。

把这三个问题串起来，就形成了从"模型是什么"到"该用哪个模型"的完整链条。

## 1.2 与其他模块的关系

```
1_Foundations/Transformer  （结构基础）
          ↓
2_LLM                      （训练 + 推理 + 选型）
          ↓
3_Prompt / 4_LLMEngineering / 11_ModelCustomization
```

## 1.3 适用读者

- 需要为业务选择模型、估算成本的后端工程师。
- 需要理解上下文与缓存机制的 Agent 开发者。
- 需要判断何时微调、何时用推理模型的架构师。

## 1.4 学习方式建议

| 阶段 | 建议做法 |
|------|----------|
| 初读 | 抓结论，跳过公式 |
| 精读 | 推导公式，理解约束 |
| 应用 | 结合自己的业务算一遍成本 |

## 1.5 关键问题链

本模块围绕一条问题链展开：

```
模型怎么获得能力？
      ↓  Training
一次生成要花多少算力与显存？
      ↓  Inference
面对具体业务该选谁？
      ↓  Models
```

- 能力问题回答不了，就无法判断微调是否必要。
- 成本问题回答不了，就无法设计并发与预算。
- 选型问题回答不了，就无法落地。

# 2. 学习目标

## 2.1 知识目标

- 理解预训练、SFT、RLHF/DPO 各阶段在做什么。
- 理解自回归生成、采样参数、KV Cache、量化对效果与性能的影响。
- 建立模型谱系认知，能够根据场景做模型选型。
- 理解推理优化为何能把吞吐提升数倍。
- 理解推理模型与普通模型的成本差异来源。

## 2.2 能力目标

### 2.2.1 会估算

能根据参数量、精度、序列长度，粗略估算显存占用与单次请求成本。

```
权重显存 ≈ 参数量 × 每参数字节数
KV 显存 ≈ 2 × 层数 × KV 头数 × 头维 × 序列长 × 批大小 × 字节数
```

### 2.2.2 会选型

| 能力 | 对应文件 |
|------|----------|
| 读懂训练流程 | Training/ |
| 估算推理成本与延迟 | Inference/ |
| 做出模型选型决策 | Models/ |

### 2.2.3 会判断

能识别"该用 RAG 还是微调""该用普通模型还是推理模型"这类常见决策点。

## 2.3 非目标

本模块不深入实现细节（如手写反向传播、CUDA 算子），这些属于框架与工程模块。

## 3.2 Inference/

### 3.2.1 文件说明

| 文件 | 大纲 |
|------|------|
| `1_autoregressive_generation.md` | 逐 Token 生成过程、Prefill 与 Decode 两阶段 |
| `2_sampling_strategies.md` | Temperature、Top-k、Top-p、Beam Search、重复惩罚 |
| `3_kv_cache.md` | KV Cache 原理、显存占用估算、优化手段 |
| `4_quantization.md` | FP16 / INT8 / INT4、GPTQ / AWQ / GGUF、精度与速度权衡 |
| `5_inference_optimization.md` | vLLM、PagedAttention、连续批处理、投机解码 |
| `6_reasoning_models.md` | 推理模型（o1/R1 类）、思维链内化、测试时计算扩展 |

### 3.2.2 学习重点

```
Prefill（处理 prompt，算力密集）
      ↓
Decode（逐 token 生成，访存密集）
      ↓
KV Cache（避免重复计算，显存瓶颈）
```

- 采样参数决定"创造力"与"稳定性"。
- KV Cache 与量化共同决定并发能力。
- 连续批处理与投机解码是吞吐优化的核心。

粗略估算一次请求的显存与成本：

```java
long weightBytes = params * bytesPerParam;          // 权重
long kvBytes = 2L * layers * kvHeads * headDim
             * seqLen * batch * bytesPerParam;        // KV Cache
long total = weightBytes + kvBytes;
```

### 3.2.3 学习顺序建议

先读 `1_autoregressive_generation.md` 建立生成直觉，再读 `3_kv_cache.md` 理解瓶颈，最后读 `5_inference_optimization.md` 掌握优化手段。

### 3.3.2 学习重点

- 开源与闭源的选择往往由合规与成本驱动。
- 选型是多目标权衡，没有唯一最优解。

| 选型维度 | 关键问题 |
|----------|----------|
| 能力 | 任务是否在模型强项区 |
| 上下文 | 最长输入是否放得下 |
| 延迟 | 能否满足用户体感 |
| 成本 | 单位请求是否可承受 |
| 私有化 | 是否允许数据出域 |

# 5. 常见问题

## 5.1 概念疑问

| 问题 | 简要回答 |
|------|----------|
| 上下文为什么有限 | 注意力复杂度与 KV Cache 显存随长度增长 |
| 为什么推理贵 | 逐 token 生成 + KV Cache 访存 |
| 微调与 RAG 如何选 | 知识用 RAG，风格/格式用微调 |

## 5.2 学习建议

- 每个文件先看结论，再看推导。
- 遇到公式先想"它在约束什么资源"。
- 把训练阶段与推理成本联系起来理解。

## 5.3 常见误区

| 误区 | 纠正 |
|------|------|
| 参数越大越好 | 需匹配任务与预算 |
| 上下文越长越好 | 成本与噪声同步上升 |
| 量化一定掉点 | 多数场景可忽略 |
| 推理模型万能 | 简单任务反而更差 |

## 5.4 与工程实践的结合

- 成本核算：把 token 单价、平均输出长度、并发量代入即可估算月度开销。
- 上下文设计：长文档优先走前缀缓存，固定部分放最前。
- 路由设计：用轻量模型兜底，把复杂请求升级到强模型。
- 监控设计：持续跟踪 TTFT、TPOT、思考 token 占比。

# 6. 关键知识点速览

## 6.1 核心结论

- 大模型本质是"下一 Token 概率分布生成器"。
- SFT 教格式，RLHF/DPO 调偏好。
- 上下文长度、KV Cache、量化共同决定推理成本与延迟。
- 模型选型没有最优，只有"场景最优"。

## 6.2 检查清单

- 能说清预训练、SFT、RLHF 的区别。
- 能估算一次请求的大致 token 成本。
- 能根据延迟/成本/合规给出选型建议。
- 知道何时该用推理模型，何时不该。
- 能解释连续批处理与投机解码为何加速。

## 6.3 延伸阅读

- 训练：缩放定律、对齐方法对比。
- 推理：KV Cache、量化、连续批处理。
- 选型：开源与闭源对比、多模态能力边界。
- 工程：路由、缓存、成本监控与性能调优。
