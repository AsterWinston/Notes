# 1. 什么是量化

结论先行：量化（quantization）用更低的数值精度表示模型参数与激活，用可控的精度损失换取显存下降与速度提升，是本地部署与低成本推理的核心技术。

## 1.1 定义与动机

**量化** = 用更低的数值精度表示模型参数，减少显存与计算。

### 1.1.1 显存与计算的双重收益

- 显存：参数字节数直接下降，模型更容易放进显卡或内存。
- 带宽：推理多为访存瓶颈，读更少字节即更快。
- 计算：低精度整数运算在部分硬件上吞吐更高。

```
FP32（32 位）→ FP16（16 位）→ INT8（8 位）→ INT4（4 位）
```

### 1.1.2 精度谱系

| 精度 | 每参数字节 | 70B 模型显存 |
|------|:----------:|:------------:|
| FP32 | 4 | 280 GB |
| FP16/BF16 | 2 | 140 GB |
| INT8 | 1 | 70 GB |
| INT4 | 0.5 | 35 GB |

从 FP32 到 INT4，显存相差 8 倍，这正是"消费级显卡跑大模型"的可行性来源。

## 1.2 量化的数学

### 1.2.1 仿射量化公式

最常用的是仿射（线性）量化，把浮点值映射到整数：

```
q = round(x / s) + z
```

- x：原始浮点值
- s：缩放因子（scale）
- z：零点（zero point）
- q：量化后的整数

### 1.2.2 反量化与误差

推理时用整数计算、必要时反量化回浮点：

```
x_hat = (q - z) * s
```

误差 |x - x_hat| 主要来自 round 的舍入，最大约为 s/2。因此 s 越小、可表示范围越窄，误差越小但动态范围也越小。

### 1.2.3 缩放因子的确定

对称量化取 z=0，s = max(|x|) / (2^(b-1) - 1)；非对称量化让 [min, max] 映射到整数区间。分组量化（group-wise）为每组单独算 s，能显著降低误差。

### 1.2.4 数值示例

把权重张量 [-1.0, -0.5, 0.0, 0.5, 1.0] 量化为 8bit 对称整数（b=8，范围 [-127, 127]）：

```
s = max(|x|) / 127 = 1.0 / 127 ≈ 0.00787
q_i = round(x_i / s)

x = -1.0  -> q = -127
x = -0.5  -> q =  -64
x =  0.0  -> q =    0
x =  0.5  -> q =   64
x =  1.0  -> q =  127

反量化: x_hat = q * s
  -127 * 0.00787 ≈ -1.0   (误差 ≈ 0)
   -64 * 0.00787 ≈ -0.504 (误差 ≈ 0.004)
```

最大误差约 s/2 ≈ 0.0039，这就是 8bit 几乎无损的直观来源。

### 1.2.5 误差来源分解

| 来源 | 说明 | 缓解 |
|------|------|------|
| 舍入误差 | round 造成 | 增大位宽/分组 |
| 截断误差 | 超出范围被截断 | 选合适 min/max |
| 累积误差 | 层间传播 | 校准、误差补偿 |

## 1.3 边界与坑

- 量化误差在层间会累积，逐层最优不等于全局最优。
- 激活的动态范围远大于权重，量化激活更难。
- 极低位宽（2~3 bit）在部分模型上会出现能力断崖。
- 反量化有额外开销，不是"免费"的加速。

### 1.3.1 量化与训练的关系

推理量化通常冻结权重，只做数值近似；而 QAT 会在训练中主动适应量化。二者目标不同：前者求"部署友好"，后者求"误差最小"。混用需注意训练框架与推理框架对量化语义的定义是否一致。

# 2. 量化类型

结论先行：按"何时量化"分为训练后量化（PTQ）与量化感知训练（QAT），前者简单、后者效果好但成本高。

## 2.1 PTQ（训练后量化）

| 类型 | 说明 | 时机 |
|------|------|------|
| PTQ（训练后量化） | 训练完后量化 | 简单 |
| QAT（量化感知训练） | 训练时模拟量化 | 效果好、成本高 |

PTQ 不需要重新训练，只需少量校准数据估计缩放因子，工程上最常用。

### 2.1.1 PTQ 流程

```
1. 加载 FP16 模型
2. 喂入校准数据，统计激活/权重的 min/max 或分布
3. 计算每层/每组 scale 与 zero point
4. 写出量化权重
5. 用评测集验证精度
```

### 2.1.2 校准的要点

- 校准样本要覆盖真实输入分布，几百条即可。
- 只用前向，不需要标签。
- 校准顺序会影响统计，通常固定随机种子。

## 2.2 QAT（量化感知训练）

在训练前向中插入伪量化节点，让模型"感知"量化误差并学会补偿。效果通常优于 PTQ，但需要训练资源与数据。

```
PTQ:  训练完成 --> 量化 --> 部署
QAT:  训练(含伪量化) --> 量化 --> 部署
```

### 2.2.1 伪量化示意

```
前向:
  w_q = dequant(quant(w))     # 量化再反量化，引入误差
  y   = x * w_q               # 用带误差的权重前向
反向:
  梯度绕过 round（用 STE，直通估计器）传回
```

round 不可导，用直通估计器（STE）让梯度近似通过，使量化误差可被训练修正。

## 2.3 对比与选择

| 维度 | PTQ | QAT |
|------|:---:|:---:|
| 成本 | 低 | 高 |
| 效果 | 好 | 更好 |
| 数据需求 | 少量校准 | 完整训练集 |
| 适用 | 通用部署 | 极低位宽/高要求 |

- 边界与坑：QAT 的伪量化算子与真实推理算子可能有差异。
- 生产建议：优先 PTQ；只有当 PTQ 精度不达标时才上 QAT。

# 3. 常见量化格式

结论先行：不同格式面向不同硬件与场景，选择时先看推理框架支持，再看精度与速度。

## 3.1 格式总览

| 格式 | 位宽 | 特点 |
|------|:----:|------|
| GPTQ | 4 bit | GPU 友好，精度好 |
| AWQ | 4 bit | 激活感知，效果优 |
| GGUF | 2~8 bit | llama.cpp 用，CPU 友好 |
| bitsandbytes | 4/8 bit | 易用，训练+推理 |
| FP8 | 8 bit | H100 原生支持 |
| SmoothQuant | 8 bit | 激活平滑 |

## 3.2 分组量化与粒度

| 粒度 | 说明 | 精度 | 开销 |
|------|------|:----:|:----:|
| 逐张量 | 整个张量共享 s | 低 | 最小 |
| 逐通道 | 每通道一个 s | 中 | 中 |
| 分组 | 每 G 个权重一个 s | 高 | 较大 |

多数 4bit 方案默认分组大小 G=128，这是精度与开销的常见折中。

### 3.2.1 分组量化示意

```
权重向量: [w1 w2 w3 w4 | w5 w6 w7 w8 | ...]
           组1: scale s1     组2: scale s2

每组独立量化，误差只在组内累积，组越小越精确
```

## 3.3 生产建议

- 先确认目标框架支持哪些格式，再选型。
- 同一模型不同格式的精度需实测，不要只看论文数字。
- 记录量化配置（位宽、分组、校准集），便于复现。

# 4. GPTQ

结论先行：GPTQ 是 GPU 上最主流的 4bit 权重量化方法，逐层量化并用校准数据最小化量化误差。

## 4.1 原理

### 4.1.1 逐层误差补偿

```
逐层量化，用校准数据最小化量化误差
```

对每层权重，按列依次量化，并用 Hessian（二阶导数矩阵）信息把已量化列引入的误差补偿到尚未量化的列上，使该层输出误差最小。

```
目标: min || W X - W_hat X ||^2
其中 W 为原始权重, W_hat 为量化权重, X 为校准输入
```

### 4.1.2 校准数据

校准集只需几百条代表性样本，用于估计激活统计量。数据分布越接近真实场景，量化后表现越好。

### 4.1.3 GPTQ 量化步骤

```
1. 收集每层校准输入 X
2. 计算 Hessian H = 2 X X^T
3. 逐列量化权重，按 H 的逆补偿误差到剩余列
4. 更新剩余权重，继续下一列
5. 写回量化结果
```

逐列量化的好处是：先量化的列引入的误差，能在后续列上被"抵消"一部分，从而整体输出误差最小。

## 4.2 使用

```python
from auto_gptq import AutoGPTQForCausalLM

model = AutoGPTQForCausalLM.from_quantized(
    "model-gptq-4bit",
    use_safetensors=True,
    device="cuda")
```

```java
// 反量化示意：GPTQ 权重以 int4 存储，配 scale/zero
static double dequant(int q, double scale, int zero) {
    return (q - zero) * scale;
}

// 推理时通常先反量化到 FP16 再送入矩阵乘（或直接用融合算子）
```

## 4.3 边界与坑

| 优点 | 缺点 |
|------|------|
| 精度损失小 | 量化耗时 |
| GPU 推理快 | 需校准数据 |

- 校准集过小或不具代表性会导致某些能力明显退化。
- 量化是一次性的，换校准集需重新量化。
- 部分实现与最新模型结构兼容滞后。

# 5. AWQ（激活感知权重量化）

结论先行：AWQ 认为并非所有权重同等重要，通过激活值大小识别关键通道并保护其精度，通常略优于 GPTQ。

## 5.1 核心洞察

```
核心洞察：
  不是所有权重都同等重要
  保留重要通道的精度，量化其余

按激活值大小识别"重要"权重
```

对激活值大的通道，其权重对输出影响大，因此对这些通道做缩放保护（等价于降低其量化误差），其余通道正常量化。

```
激活大的通道 --> 权重乘以缩放因子 --> 量化 --> 反缩放
```

### 5.1.1 数学形式

AWQ 寻找逐通道缩放向量 s，使得量化误差最小：

```
s* = argmin_s || Q(W * diag(s)) * diag(s)^-1 * X - W X ||
```

其中 Q 表示量化算子。通过把"重要通道"的权值放大、量化后再缩回，等价于让这些通道获得更细的量化分辨率。

## 5.2 与 GPTQ 对比

| 对比 | GPTQ | AWQ |
|------|:----:|:---:|
| 精度 | 好 | 略好 |
| 速度 | 快 | 快 |
| 通用性 | 好 | 好 |

> AWQ 在多数评测上略优于 GPTQ。

## 5.3 生产建议

- 追求效果优先选 AWQ 4bit。
- 兼容性优先选 GPTQ 4bit。
- 两者都需量化后评测，差异可能随模型与任务变化。

# 6. GGUF（llama.cpp）

结论先行：GGUF 是面向 CPU 与混合推理的单文件格式，支持 2~8bit 多级量化，是本地部署的主流选择。

## 6.1 设计目标

```
专为 CPU/混合推理设计：
- 支持 2~8 bit 多种量化
- 单文件、易分发
- CPU + GPU 混合推理
```

## 6.2 使用与量化级别

```bash
# 用 llama.cpp 量化
./quantize model.gguf model-q4.gguf Q4_K_M

# 推理
./llama-cli -m model-q4.gguf -p "你好"
```

| 量化级别 | 质量 | 大小 |
|----------|------|------|
| Q8_0 | 最好 | 大 |
| Q5_K_M | 好 | 中 |
| Q4_K_M | 平衡（推荐） | 小 |
| Q3_K_M | 一般 | 更小 |
| Q2_K | 差 | 最小 |

## 6.3 边界与坑

- 级别后缀 K 表示 k-quant（分块量化），M/S 表示中等/小尺寸。
- CPU 推理速度受内存带宽限制，量化收益明显。
- GPU 上 GGUF 并非最优，需与 GPTQ/AWQ 对比。

# 7. 量化的影响

结论先行：位宽越低显存越省、速度越快，但质量损失非线性，INT4 是当前性价比拐点。

## 7.1 位宽与显存/速度

| 位宽 | 显存 | 速度 | 质量损失 |
|:----:|:----:|:----:|:--------:|
| FP16 | 100% | 1x | 0 |
| INT8 | 50% | 1.5~2x | 极小 |
| INT4 | 25% | 2~3x | 小 |
| INT2 | 12.5% | — | 明显 |

## 7.2 质量损失规律

```
经验：
  INT8：几乎无损失
  INT4：轻微损失，可接受
  INT2~3：明显损失，慎用
```

损失通常先体现在长链推理、数学、代码等对精度敏感的任务上，闲聊类任务则较不敏感。

### 7.2.1 为什么低位宽损失非线性

量化噪声相当于给每层注入扰动，模型越深扰动越易被放大。当位宽低到一定程度，可表示的状态数急剧减少，模型无法再"绕过"噪声，能力出现断崖。这也是 2bit 难以实用的根本原因。

## 7.3 评测方法

- 用标准基准（如 MMLU、GSM8K）对比量化前后。
- 用业务自有测试集验证，标准基准好不代表业务好。
- 关注"最差样本"而非仅看平均分。

### 7.3.1 评测清单

| 维度 | 指标 | 方法 |
|------|------|------|
| 知识 | 准确率 | 标准问答集 |
| 推理 | 正确率 | 数学/逻辑题 |
| 代码 | 通过率 | 单元测试 |
| 格式 | 合法率 | JSON/工具调用 |
| 长文 | 一致性 | 长文档问答 |

## 7.4 生产建议

- INT8 可放心使用；INT4 需评测后上线。
- 对精度敏感任务保留高精度版本做 A/B。
- 记录量化前后指标，形成回归基线。

# 8. KV Cache 量化

结论先行：不仅权重可量化，KV Cache 也可从 FP16 降到 INT8，省一半显存，支持更长上下文与更大批。

## 8.1 原理

```
不仅权重可以量化，KV Cache 也可以：
  FP16 → INT8 → 省一半显存
```

对缓存的 K、V 张量按 token 或按通道计算缩放因子，存整数、用时反量化。

```
KV FP16 显存: 2 × L × H × d × n × b × 2
KV INT8 显存: 2 × L × H × d × n × b × 1   (减半)
```

### 8.1.1 量化粒度

| 粒度 | 说明 | 精度 |
|------|------|:----:|
| 逐 token | 每个 token 一组 scale | 中 |
| 逐通道 | 每个通道一组 scale | 高 |
| 逐头 | 每个 KV 头一组 scale | 中高 |

粒度越细精度越高，但元数据开销也越大，需权衡。

## 8.2 与权重量化的差异

| 维度 | 权重量化 | KV 量化 |
|------|:--------:|:-------:|
| 量化对象 | 静态参数 | 动态激活 |
| 校准 | 一次性 | 运行时统计 |
| 影响 | 全任务 | 长上下文更敏感 |

KV 量化是动态的，误差随序列累积，长上下文下更需谨慎。

## 8.3 生产建议

| 优点 | 缺点 |
|------|------|
| 支持更长上下文 | 可能影响质量 |
| 支持更大批 | — |

- 长上下文服务优先尝试 KV INT8。
- 对长文档问答做专项评测，确认无退化。

# 9. 选择建议

结论先行：先定硬件与框架，再在位宽与格式间取舍，INT4 是多数场景的甜点。

## 9.1 场景推荐

| 场景 | 推荐 |
|------|------|
| GPU 推理、追求效果 | AWQ 4bit |
| GPU 推理、兼容性好 | GPTQ 4bit |
| CPU / 本地部署 | GGUF Q4_K_M |
| 显存充足 | FP16/BF16 |
| 极致省显存 | INT4 + KV 量化 |

## 9.2 决策流程

```
显存够用? ── 是 ──> FP16/BF16（质量最好）
     |
     否
     v
GPU 推理? ── 是 ──> AWQ / GPTQ 4bit
     |
     否
     v
CPU/本地 ──> GGUF Q4_K_M
     |
     仍不够
     v
INT4 + KV 量化 + 更低位宽（谨慎）
```

## 9.3 生产建议

- 量化不是越狠越好，先满足质量再省显存。
- 混合方案（权重 INT4 + KV INT8）常是最优组合。

### 9.3.1 组合方案对照

| 方案 | 权重 | KV | 相对显存 | 适用 |
|------|:----:|:--:|:--------:|------|
| 高质量 | FP16 | FP16 | 100% | 显存充足 |
| 均衡 | INT8 | INT8 | 50% | 通用 |
| 省显存 | INT4 | FP16 | 25% | 单请求长文 |
| 极省 | INT4 | INT8 | 12.5% | 高并发长文 |

# 10. 生产注意事项

结论先行：量化最大的风险是"悄无声息的精度退化"，必须用评测与监控兜底。

## 10.1 风险清单

| 风险 | 建议 |
|------|------|
| 量化损失被低估 | 量化后必须评测 |
| 校准数据不当 | 用代表性数据 |
| 格式不兼容 | 确认推理框架支持 |
| 只量化权重 | KV Cache 也可量化 |
| 盲目追求低位宽 | INT4 是性价比拐点 |

## 10.2 最佳实践

- 建立"量化前后"对比基线，纳入 CI。
- 校准集覆盖业务主要输入分布。
- 上线后监控输出质量与拒答率变化。
- 保留回滚到高精度版本的能力。

## 10.3 常见误区

- 只看模型大小，不看实际延迟（反量化有开销）。
- 用通用基准代替业务评测。
- 认为所有层都能同等压缩。

## 10.4 上线检查表

| 检查项 | 通过标准 |
|--------|----------|
| 标准基准 | 退化在可接受范围 |
| 业务测试 | 关键用例无回归 |
| 格式合法率 | 与量化前持平 |
| 峰值显存 | 满足目标并发 |
| 延迟 P99 | 满足 SLA |
| 回滚方案 | 高精度版本可切换 |

# 11. 小结

## 11.1 核心结论

- 量化用低精度表示参数，减少显存与计算。
- GPTQ/AWQ 是 GPU 主流 4bit 量化。
- GGUF 适合 CPU/本地部署。
- INT8 几乎无损失，INT4 轻微损失。

## 11.2 工程实践

- 量化后必须评测，校准数据要代表性。
- KV Cache 量化是长上下文省显存的又一杠杆。
- 量化是精度与资源的权衡，而非单纯的"免费加速"。
