# 1. 什么是预训练

## 1.1 定义与直觉

**结论先行**：预训练（Pretraining）是在海量无标注文本上用自监督目标训练大模型，学习通用语言知识与世界知识，产出基础模型（Base Model）。

### 1.1.1 定义

**预训练** = 在海量文本上用自监督目标训练大模型，学习通用的语言知识与世界知识。

```
输入：海量文本（万亿 token）
目标：预测下一个 token
产出：基础模型（Base Model）
```

### 1.1.2 三个要素

| 要素 | 内容 | 说明 |
|------|------|------|
| 数据 | 万亿级 token | 网页、书籍、代码等 |
| 目标 | 下一 Token 预测 | 自监督，无需人工标注 |
| 产出 | Base Model | 有知识、未对齐 |

## 1.2 预训练在流程中的位置

### 1.2.1 三阶段图

```
① 预训练（Pre-training）  → Base Model：学知识
② 监督微调（SFT）         → 学会遵循指令
③ 对齐（RLHF/DPO）        → 符合人类偏好
```

### 1.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 跳过预训练 | 知识不足 | 从开源 Base 起步 |
| 混淆三阶段 | 目标不同 | 明确阶段职责 |
| 期望 Base 听指令 | 未对齐 | 进入 SFT 阶段 |

> 预训练决定能力上限，后训练决定能力释放方式。

# 2. 训练目标

## 2.1 下一 Token 预测

**结论先行**：预训练的核心目标是因果语言建模（Causal LM），即在每个位置预测下一个 token，损失为所有位置交叉熵之和。

### 2.1.1 原理

```
下一 Token 预测（Causal LM）：
  输入:  [BOS] 今天 天气 真
  目标:  今天 天气 真 好

损失 = 所有位置的交叉熵之和
```

模型只能看到左侧上下文（因果掩码），因此可并行计算所有位置的损失。

### 2.1.2 损失函数

```
L = - (1/T) Σ_t log P(x_t | x_<t ; θ)
```

| 符号 | 含义 |
|------|------|
| x_t | 第 t 个 token |
| x_<t | 前 t-1 个 token |
| θ | 模型参数 |
| T | 序列长度 |

### 2.1.3 Python 实现

```python
logits = model(input_ids)
loss = cross_entropy(
    logits[:, :-1].reshape(-1, vocab_size),
    input_ids[:, 1:].reshape(-1))
```

> 注意错位：用位置 t 的预测去拟合位置 t+1 的真实 token。

## 2.2 为什么有效

### 2.2.1 隐式表示

> 这个简单目标让模型学会了语法、事实、推理的**隐式表示**。

```
预测下一个词 → 必须掌握：
  语法结构（词序、搭配）
  世界知识（事实、常识）
  推理模式（因果、逻辑）
```

### 2.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 目标太简单 | 误以为学不到能力 | 规模足够即涌现 |
| 忽略错位 | 训练目标错位 | 检查 shift |
| 只算末位 | 浪费监督信号 | 全位置计算 |

# 3. 数据规模

## 3.1 规模演进

**结论先行**：预训练数据量从数十 GB 增长到十几万亿 token，但数据质量比数量更重要。

### 3.1.1 数据表

| 模型 | 训练数据 |
|------|----------|
| GPT-2 | 40 GB |
| GPT-3 | 3000 亿 token |
| LLaMA 2 | 2 万亿 token |
| LLaMA 3 | 15 万亿 token |
| DeepSeek-V3 | 14.8 万亿 token |

### 3.1.2 增长趋势

```
40 GB ──▶ 3000 亿 ──▶ 2 万亿 ──▶ 15 万亿 token
       （约 5 个数量级的增长）
```

## 3.2 质量与数量

### 3.2.1 对比

| 维度 | 数量 | 质量 |
|------|------|------|
| 作用 | 覆盖广度 | 决定有效学习 |
| 风险 | 噪声、重复 | 规模受限 |
| 手段 | 扩大来源 | 过滤、去重 |
| 优先级 | 次要 | 首要 |

> 数据规模持续增长，**数据质量比数量更重要**。

### 3.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 只堆数量 | 低质数据拖累 | 严格过滤 |
| 忽略配比 | 偏科 | 领域配比 |
| 数据泄漏 | 评测污染 | 隔离评测集 |

# 4. 数据来源与处理

## 4.1 数据来源

**结论先行**：数据来自网页、书籍、代码、论文、百科、对话，需经过清洗、去重、去毒、去隐私、配比五步处理。

### 4.1.1 来源表

| 来源 | 特点 | 占比直觉 |
|------|------|----------|
| 网页 | 量大、质量参差 | 高 |
| 书籍 | 质量高、量少 | 中 |
| 代码 | 结构化、逻辑强 | 中 |
| 论文 | 专业、密度高 | 低 |
| 百科 | 事实准、规范 | 低 |
| 对话 | 交互性强 | 低 |

## 4.2 处理流水线

### 4.2.1 五步图

```
来源：网页、书籍、代码、论文、百科、对话
处理：
  ① 去重（MinHash、精确去重）
  ② 质量过滤（启发式规则、分类器）
  ③ 去毒（移除有害内容）
  ④ 隐私清洗（PII 移除）
  ⑤ 领域配比（代码、数学、多语言）
```

### 4.2.2 质量过滤代码

```python
# 质量过滤示例
def is_high_quality(doc):
    if len(doc) < 200: return False                    # 太短
    if mean_word_length(doc) > 10: return False        # 异常
    if symbol_ratio(doc) > 0.1: return False           # 符号过多
    if contains_blacklist(doc): return False           # 黑名单
    return True
```

### 4.2.3 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 过滤过度 | 误删有效数据 | 抽检校准 |
| 去毒不全 | 残留有害内容 | 分类器 + 人工 |
| PII 遗漏 | 隐私泄露 | 正则 + NER |
| 配比失衡 | 某语言/领域差 | 按目标调比 |

# 5. 去重的重要性

## 5.1 重复数据的危害

**结论先行**：重复数据会让模型死记硬背、浪费算力并污染评测，因此去重是数据质量的第一道关。

### 5.1.1 危害

```
重复数据的问题：
- 模型死记硬背 → 泛化差
- 浪费训练算力
- 评估数据污染
```

### 5.1.2 量化直觉

```
若某文档重复 k 次，等效学习率对该内容放大 k 倍
→ 分布失衡，模型偏向高频重复片段
```

## 5.2 去重方法

### 5.2.1 方法表

| 方法 | 粒度 |
|------|------|
| 精确去重 | 完全相同 |
| MinHash | 近似重复 |
| 段落级 | 文档内重复 |

### 5.2.2 MinHash 直觉

```
① 对文档做 n-gram 集合
② 用 k 个哈希函数取最小值 → 签名
③ 签名相似度 ≈ Jaccard 相似度
④ 超过阈值判为重复
```

| 概念 | 含义 |
|------|------|
| n-gram | 连续 n 个词/字符 |
| Jaccard | 交集/并集 |
| 签名 | 压缩后的指纹 |

### 5.2.3 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 只做精确去重 | 近似重复漏网 | 加 MinHash |
| 阈值过低 | 误删相似文档 | 调阈值 |
| 跨集污染 | 训练含评测 | 全局去重 |

# 6. 训练过程

## 6.1 训练流程

**结论先行**：预训练流程为数据准备、分词、初始化、分布式训练、监控、保存检查点的闭环。

### 6.1.1 六步图

```
① 数据准备（清洗、去重、配比）
② 分词（BPE/SentencePiece）
③ 初始化参数
④ 分布式训练（数据/张量/流水线并行）
⑤ 监控 loss 与梯度
⑥ 定期保存检查点
```

### 6.1.2 分词说明

| 方法 | 特点 |
|------|------|
| BPE | 字节对合并，通用 |
| SentencePiece | 语言无关，含空格 |
| WordPiece | BERT 系常用 |

## 6.2 并行策略

### 6.2.1 三种并行

| 并行 | 切分对象 | 适用 |
|------|----------|------|
| 数据并行 | 批次 | 模型可单卡放下 |
| 张量并行 | 层内矩阵 | 单层过大 |
| 流水线并行 | 层间 | 模型过深 |

```
数据并行：每卡一份模型，分数据
张量并行：一层拆到多卡，算完再同步
流水线并行：不同层放不同卡，微批流动
```

### 6.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 通信瓶颈 | 并行开销大 | 3D 并行组合 |
| 检查点不全 | 无法恢复 | 存优化器状态 |
| 数据不洗牌 | 收敛差 | 全局 shuffle |
| 断点丢进度 | 重训昂贵 | 定期存 ckpt |

# 7. 训练成本

## 7.1 估算公式

**结论先行**：训练算力近似为 6×参数量×token 数，用它可以快速估算成本量级。

### 7.1.1 公式

```
成本 ≈ 6 × 参数量 × 训练 token 数（FLOPs）

例：70B 模型 × 2T token
  ≈ 6 × 70e9 × 2e12 = 8.4e23 FLOPs
  ≈ 数千张 GPU 训练数月
```

### 7.1.2 示例计算

```python
def training_flops(num_params, num_tokens):
    # 前向 2ND + 反向 4ND ≈ 6ND
    return 6 * num_params * num_tokens

flops = training_flops(70e9, 2e12)   # 8.4e23 FLOPs
```

| 项 | 系数 | 说明 |
|----|------|------|
| 前向 | 2N | 每个参数一次乘加 |
| 反向 | 4N | 梯度约两倍前向 |
| 合计 | 6N | 每 token |

> 预训练成本极高，只有少数机构能承担。

## 7.2 成本构成

### 7.2.1 成本表

| 成本项 | 说明 |
|--------|------|
| GPU 机时 | 主要开销 |
| 数据清洗 | 人力 + 算力 |
| 电力与散热 | 数据中心 |
| 工程人力 | 并行调优 |
| 失败重训 | 不稳定代价 |

### 7.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 低估 6ND | 忽略通信开销 | 加 20%~50% 余量 |
| 忽略重训 | 发散需重来 | 稳定性优先 |
| 只算 GPU | 漏数据/电力 | 全成本核算 |

# 8. Base Model 的能力

## 8.1 已有能力

**结论先行**：Base Model 已具备语法、世界知识、一定推理与补全能力，但不会遵循指令，需要后训练才能成为助手。

### 8.1.1 能力列表

```
Base Model 已经具备：
- 语法知识
- 世界知识
- 一定推理能力
- 补全能力
```

### 8.1.2 能力来源

| 能力 | 来自 |
|------|------|
| 语法 | 下一 token 预测 |
| 事实 | 海量文本记忆 |
| 推理 | 规模与数据多样性 |

## 8.2 缺失能力

### 8.2.1 缺失列表

```
但不会：
- 遵循指令（未对齐）
- 拒绝有害请求
- 结构化输出
```

### 8.2.2 Python 示例

```python
# Base model 的行为
```

### 8.2.3 边界与坑

# 9. 训练稳定性

## 9.1 常见问题与对策

**结论先行**：大规模训练常见 loss 尖刺、梯度爆炸、数值溢出与发散，需要 Warmup、梯度裁剪与混合精度来稳住。

### 9.1.1 问题表

| 问题 | 对策 |
|------|------|
| Loss 尖刺 | 降低学习率、重启 |
| 梯度爆炸 | 梯度裁剪 |
| 数值溢出 | BF16、混合精度 |
| 训练发散 | Warmup |

### 9.1.2 Warmup 与裁剪

```
Warmup：lr 从 0 线性升到峰值，避免早期发散
裁剪：||g|| > c 时缩放到 c，抑制爆炸
```

| 超参 | 作用 | 建议 |
|------|------|------|
| warmup steps | 预热步数 | 1%~5% 总步数 |
| max grad norm | 裁剪阈值 | 1.0 附近 |
| 精度 | 数值范围 | BF16 优先 |

## 9.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 无 Warmup | 早期发散 | 必加预热 |
| 裁剪过松 | 抑制不住 | 调阈值 |
| FP16 溢出 | loss scale 抖动 | 换 BF16 |
| 尖刺不处理 | 持续恶化 | 回滚 ckpt |

# 10. 生产注意事项

## 10.1 风险清单

**结论先行**：预训练的生产风险集中在数据质量、重复、污染、稳定性与成本，需要在数据与训练两侧同时管控。

### 10.1.1 风险表

| 风险 | 建议 |
|------|------|
| 数据质量差 | 严格过滤 |
| 数据重复 | 去重 |
| 数据污染 | 隔离评测数据 |
| 训练不稳定 | Warmup + 梯度裁剪 |
| 成本失控 | 预估 FLOPs |

### 10.1.2 优先级

| 优先级 | 事项 | 理由 |
|--------|------|------|
| P0 | 数据去重 | 泛化与成本 |
| P0 | 评测隔离 | 结果可信 |
| P1 | 稳定性机制 | 避免重训 |
| P1 | 成本预估 | 预算 |
| P2 | 数据配比 | 效果优化 |

## 10.2 监控

### 10.2.1 指标

| 指标 | 含义 | 告警 |
|------|------|------|
| 训练 loss | 收敛 | 尖刺/不降 |
| 梯度范数 | 稳定性 | 突增 |
| 吞吐 | 效率 | 下降 |
| 检查点间隔 | 可恢复性 | 过长 |

### 10.2.2 建议

- 每次保存检查点都验证可加载、可续训。
- 评测集与训练集做 n-gram 级隔离，防止污染。

# 11. 小结

- 预训练用下一 Token 预测在万亿 token 上训练。
- 数据质量比数量更重要，去重与过滤是关键。
- Base Model 有知识但不会遵循指令。
- 预训练成本极高（数千 GPU 数月）。
- SFT/RLHF 把 Base Model 变成助手。
- 稳定性靠 Warmup、梯度裁剪与 BF16。
