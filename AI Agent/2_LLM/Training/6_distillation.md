# 1. 什么是知识蒸馏

知识蒸馏（Knowledge Distillation，简称蒸馏）用一个强而大的**教师模型**（Teacher）去训练一个小而快的**学生模型**（Student）。

**结论先行**：蒸馏不是复制参数，而是让学生拟合教师的输出分布或推理过程，用更小的容量逼近教师的行为，从而在效果、成本与部署可行性之间取得平衡。

## 1.1 核心直觉

教师的输出不只是"答案"，还包含类别之间的相对关系，这种额外信息被称为"暗知识"（Dark Knowledge）。学生从暗知识中学习，比只学 one-hot 标签获得的信息更多。

```
教师模型（强但大）  ──知识──▶  学生模型（小但快）

  70B 参数                        7B 参数
  GPU 集群部署                    单卡/端侧部署
```

## 1.2 蒸馏的三个要素

| 要素 | 含义 | 常见选择 |
|------|------|----------|
| 教师 | 提供知识的强模型 | 同族大参数量模型 |
| 学生 | 接收知识的模型 | 小参数量、目标结构 |
| 迁移信号 | 蒸馏什么 | logits / 文本 / 推理链 |

### 1.2.1 教师的选择

教师越强，学生的能力上限越高，但调用与部署成本也越大。

| 教师类型 | 优势 | 代价 |
|----------|------|------|
| 同族更大模型 | 结构相近，迁移顺畅 | 需自行部署 |
| 异族大模型 | 能力互补 | 分布差异大 |
| 商业闭源模型 | 能力强 | 仅黑盒、需授权 |

### 1.2.2 学生的选择

学生结构可以与教师同族，也可以完全不同；容量决定能吸收多少知识。

```
学生容量过小 → 无法拟合教师分布（欠拟合）
学生容量适中 → 效果接近教师
学生容量过大 → 蒸馏收益下降（不如直接训练）
```

### 1.2.3 迁移信号的选择

| 信号 | 要求 | 信息量 |
|------|------|:------:|
| 硬标签 | 仅答案 | 低 |
| 软标签 | 需 logits | 高 |
| 推理链 | 需文本 | 中高 |

## 1.3 与相邻概念的区别

| 概念 | 目标 | 是否需要教师 |
|------|------|:------------:|
| 蒸馏 | 压缩能力 | 是 |
| 微调 | 适配特定任务 | 否 |
| 量化 | 降低数值精度 | 否 |
| 剪枝 | 删除冗余结构 | 否 |

> 蒸馏可与量化、剪枝叠加使用，进一步压缩部署体积。

# 2. 两种蒸馏范式

**结论先行**：能否拿到教师的 logits（未归一化分数），决定了走白盒还是黑盒路线；闭源 API 只给文本，只能黑盒蒸馏。

## 2.1 白盒蒸馏

白盒蒸馏（White-box Distillation）使用教师的 logits 或中间层特征作为监督信号，信息量最大，但要求能访问教师内部。

| 信号 | 说明 | 信息量 |
|------|------|:------:|
| 输出 logits | 全部类别的分数 | 高 |
| 中间层特征 | 隐状态对齐 | 很高 |
| 注意力矩阵 | 注意力分布对齐 | 很高 |

## 2.2 黑盒蒸馏

黑盒蒸馏（Black-box Distillation）只用教师生成的输出文本，把文本当作"软标签"或训练数据。

```
白盒：教师 logits ──▶ 学生拟合分布
黑盒：教师文本   ──▶ 学生模仿生成
```

### 2.2.1 文本作为监督信号

学生通过监督微调（SFT）拟合教师的文本输出，本质是把连续分布压缩成离散标签。

### 2.2.2 授权与合规

使用商业模型输出训练自有模型可能受服务条款限制，上线前需确认授权范围。

## 2.3 选择建议

| 条件 | 推荐 |
|------|------|
| 教师权重可访问 | 白盒 + 黑盒混合 |
| 只有 API 文本 | 黑盒 |
| 教师为闭源商业模型 | 黑盒（注意授权条款） |

> 闭源模型只能用黑盒蒸馏，因为 API 不返回 logits。

# 3. 软标签与温度

**结论先行**：软标签（Soft Label）用温度 T 软化概率分布，把"猫狗相似"这类结构信息传递给学生，是蒸馏优于普通监督学习的关键。

## 3.1 硬标签与软标签

```
硬标签：正确答案是"猫"（one-hot）
  猫 1.0，狗 0.0，兔子 0.0

软标签：猫 0.9，狗 0.08，兔子 0.02（概率分布）

软标签包含更多信息：
  "猫和狗有点像" → 学生学到类别间的关系
```

## 3.2 温度的作用

温度 T 作用于 softmax，T 越大分布越平滑，暗知识越明显；T=1 时退化为普通 softmax。

公式：

```
softmax(z_i / T) = exp(z_i / T) / Σ_j exp(z_j / T)
```

| T 取值 | 分布形态 | 适用 |
|:------:|----------|------|
| T→0 | 近似 one-hot | 退化为硬标签 |
| T=1 | 标准分布 | 常规 |
| T=3~5 | 平滑 | 蒸馏常用 |

## 3.3 温度为何要平方缩放

软标签损失用 KL 散度，其梯度尺度与 1/T² 相关，因此乘以 T² 使软、硬损失梯度量级一致。

```
∂(KL) / ∂z  ∝  1 / T²
故乘以 T² 后梯度与温度解耦
```

# 4. 蒸馏损失函数

**结论先行**：蒸馏损失是软标签损失（KL 散度）与硬标签损失（交叉熵）的加权和，α 控制两者比例。

## 4.1 损失构成

```python
def distillation_loss(student_logits, teacher_logits, labels, T=3.0, alpha=0.7):
    # 软标签损失（KL 散度）
    soft_loss = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction='batchmean') * (T * T)

    # 硬标签损失
    hard_loss = F.cross_entropy(student_logits, labels)

    return alpha * soft_loss + (1 - alpha) * hard_loss
```

| 符号 | 含义 | 典型取值 |
|------|------|:--------:|
| T | 温度（软化分布） | 3~5 |
| α | 软标签权重 | 0.5~0.9 |

## 4.2 梯度视角

KL 散度对 logits 的梯度可近似为：

```
∇_z KL ≈ (1 / T) · (p_student - p_teacher)
```

乘以 T² 后，软损失梯度近似 `T · (p_student - p_teacher)`，温度放大梯度信号。

## 4.3 Java 实现示例

```java
static double klDivergence(double[] p, double[] q) {
    double sum = 0.0;
    for (int i = 0; i < p.length; i++) {
        if (p[i] > 1e-12) {
            sum += p[i] * Math.log(p[i] / q[i]);
        }
    }
    return sum;
}

static double[] softmax(double[] logits, double temperature) {
    double[] out = new double[logits.length];
    double max = Double.NEGATIVE_INFINITY;
    for (double v : logits) max = Math.max(max, v / temperature);
    double denom = 0.0;
    for (int i = 0; i < logits.length; i++) {
        out[i] = Math.exp(logits[i] / temperature - max);
        denom += out[i];
    }
    for (int i = 0; i < out.length; i++) out[i] /= denom;
    return out;
}
```

# 5. 数据蒸馏

**结论先行**：数据蒸馏让学生直接学习教师生成的"问题-答案"对，是黑盒蒸馏的主流实现，本质是把教师当作数据生成器。

## 5.1 基本流程

```python
def generate_distillation_data(teacher, prompts):
    data = []
    for prompt in prompts:
        # 教师生成回答（可加推理过程）
        response = teacher.chat(prompt)
        data.append({"instruction": prompt, "output": response})
    return data

# 用生成的数据 SFT 学生模型
train_student(student, generate_distillation_data(teacher, prompts))
```

## 5.2 数据规模与质量

| 维度 | 建议 | 说明 |
|------|------|------|
| 数量 | 万级到百万级 | 视任务复杂度 |
| 多样性 | 覆盖目标分布 | 防止同质化 |
| 过滤 | 去重、去低质 | 提升信噪比 |

### 5.2.1 数量与边际收益

数据量增加到一定程度后收益递减，此时应优先提升质量而非继续堆量。

### 5.2.2 质量过滤

| 过滤手段 | 目标 |
|----------|------|
| 去重 | 减少冗余 |
| 长度过滤 | 剔除异常样本 |
| 交叉验证 | 剔除低置信样本 |

## 5.3 与真实数据混合

把真实标注数据按一定比例混入，能缓解能力上限与错误传播问题。

```
训练集 = 教师生成数据 × (1 - r) + 真实数据 × r
r 通常取 0.1 ~ 0.3
```

# 6. 推理过程蒸馏

**结论先行**：教师不仅给答案，还给出中间推理链（Chain-of-Thought），学生学到"如何推理"而非只记答案，对推理模型尤为关键。

## 6.1 思维链蒸馏

```
教师不仅给答案，还给出推理过程：

问题：3 个苹果 + 2 个苹果 = ?

教师输出：
  推理：3 + 2 = 5
  答案：5

学生学到"如何推理"，而非只记答案
```

> 蒸馏推理过程比蒸馏答案更有效（用于推理模型）。

## 6.2 何时有效、何时失效

| 场景 | 效果 |
|------|------|
| 多步数学推理 | 显著 |
| 代码生成 | 明显 |
| 简单事实问答 | 收益有限 |

## 6.3 边界与坑

- 教师推理链冗长时，学生可能学到冗余步骤，需压缩（如只保留关键步骤）。
- 教师推理链本身有错时，错误会被结构化地学走，需做正确性过滤。
- 学生容量过小时无法容纳长链，需蒸馏"短链"或分阶段蒸馏。

# 7. 蒸馏的收益与代价

**结论先行**：蒸馏用一次性训练成本换取长期推理成本的下降，收益主要在体积、速度、成本三个维度。

## 7.1 收益

| 收益 | 说明 |
|------|------|
| 更小 | 参数量大幅减少 |
| 更快 | 推理速度提升 |
| 更便宜 | 部署成本降低 |
| 保持能力 | 效果接近教师 |

```
例：用 70B 教师蒸馏 7B 学生
  学生达到教师 90% 的能力
  推理成本降到 1/10
```

### 7.1.1 体积与速度

参数量下降带来显存占用与单步访存同时下降，Decode 阶段收益最明显。

### 7.1.2 成本结构

训练侧一次性投入，推理侧长期节省，请求规模越大回本越快。

## 7.2 代价

| 代价 | 说明 |
|------|------|
| 训练开销 | 需运行教师推理 |
| 数据工程 | 生成与筛选数据 |
| 效果损失 | 必然存在精度下降 |

## 7.3 收益估算

```
成本比 ≈ 学生参数量 / 教师参数量
效果比 ≈ 学生能力 / 教师能力

目标：成本比尽量小，效果比尽量接近 1
```

# 8. 蒸馏 vs 微调 vs 量化

**结论先行**：三者目标不同，蒸馏压能力、微调改行为、量化降精度，常组合使用。

## 8.1 蒸馏 vs 微调

| 维度 | 蒸馏 | 微调 |
|------|------|------|
| 数据 | 教师生成 | 人工标注/真实数据 |
| 目标 | 复制教师能力 | 适配特定任务 |
| 教师 | 需要强模型 | 不需要 |
| 适用 | 压缩模型 | 领域适配 |

## 8.2 与量化的组合

```
蒸馏：70B → 7B（结构变小）
量化：FP16 → INT8/INT4（数值变低）

叠加：70B 教师 → 7B 学生 → INT4 部署
```

## 8.3 选择决策表

| 目标 | 首选 |
|------|------|
| 端侧部署 | 蒸馏 + 量化 |
| 领域适配 | 微调（可叠加蒸馏） |
| 降显存 | 量化 |
| 提速 | 蒸馏 + 量化 |

# 9. 蒸馏的风险与缓解

**结论先行**：蒸馏会引入能力上限、错误传播、多样性下降等风险，可通过多教师与混合真实数据缓解。

## 9.1 主要风险

| 风险 | 说明 |
|------|------|
| 能力上限 | 学生难超教师 |
| 错误传播 | 教师的错误被学生学到 |
| 多样性降低 | 输出变得同质化 |
| 数据成本 | 教师调用成本 |

### 9.1.1 能力上限与天花板

学生的上限由教师能力与自身容量共同决定，突破天花板需引入多教师或额外真实数据。

### 9.1.2 错误传播与同质化

教师的系统性偏差会被学生稳定复制，且生成数据缺乏真实世界的多样性。

## 9.2 缓解手段

| 手段 | 作用 |
|------|------|
| 多教师 | 融合不同教师，突破单教师上限 |
| 混合真实数据 | 恢复多样性 |
| 输出筛选 | 降低错误传播 |
| 迭代蒸馏 | 学生反馈再蒸馏 |

## 9.3 反例

```
反例：教师在某类问题上系统性出错
  → 学生把错误当作"标准答案"
  → 蒸馏后该错误更稳定、更难纠正

缓解：对教师输出做交叉验证，剔除低置信样本。
```

# 10. 实际应用场景

**结论先行**：蒸馏广泛用于小模型部署、领域模型、推理模型与多语言迁移。

## 10.1 场景一览

| 场景 | 说明 |
|------|------|
| 小模型部署 | 蒸馏到可本地部署的规模 |
| 领域模型 | 用大模型蒸馏领域能力 |
| 推理模型 | 蒸馏思维链 |
| 多语言 | 用英文能力蒸馏到小语种 |

## 10.2 典型案例结构

```
场景：移动端问答
  教师：云端 70B
  学生：3B，INT8 量化
  信号：黑盒文本 + 少量白盒 logits
  评测：与教师对比准确率、延迟
```

# 11. 生产实践与工程

**结论先行**：生产落地需关注数据管线、评测、成本与授权，避免只用黑盒、只蒸答案、教师有错、无评测四大坑。

## 11.1 工程流水线

```
教师推理 → 数据生成 → 清洗过滤 → SFT 训练 → 评测 → 部署
   │           │           │          │         │
  成本        多样性      信噪比     收敛      回归
```

## 11.2 生产注意事项

| 风险 | 建议 |
|------|------|
| 只用黑盒蒸馏 | 有 logits 时用白盒 |
| 蒸馏答案而非过程 | 蒸馏推理过程 |
| 教师有错 | 筛选教师输出 |
| 多样性降低 | 混合真实数据 |
| 无评测 | 对比师生效果 |

## 11.3 Java 侧评测骨架

```java
record EvalResult(int total, int correct, double avgLatencyMs) {}

static EvalResult evaluate(List<String> prompts, Model student, Model teacher) {
    int correct = 0;
    double latency = 0.0;
    for (String p : prompts) {
        long t0 = System.nanoTime();
        String s = student.chat(p);
        latency += (System.nanoTime() - t0) / 1e6;
        if (matches(s, teacher.chat(p))) correct++;
    }
    return new EvalResult(prompts.size(), correct, latency / prompts.size());
}
```

## 11.4 成本控制

| 项 | 优化手段 |
|----|----------|
| 教师调用 | 缓存、批处理 |
| 数据生成 | 抽样、增量 |
| 训练 | 混合精度、梯度累积 |

# 12. 小结

## 12.1 核心结论

- 蒸馏用大模型训练小模型，核心是迁移暗知识与推理过程。
- 白盒蒸馏用 logits，黑盒蒸馏用输出文本。
- 软标签比硬标签信息更丰富，温度 T 控制分布平滑度。
- 损失是 KL 软损失与交叉熵硬损失的加权和，α 控权重。
- 蒸馏推理过程比蒸馏答案更有效。
- 蒸馏可与量化、剪枝叠加，大幅降低部署成本。

## 12.2 实践要点

- 风险有上限、错误传播与同质化，靠多教师与混合数据缓解。
- 生产关键是数据质量、评测闭环与成本控制。
