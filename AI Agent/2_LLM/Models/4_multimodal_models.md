# 1. 什么是多模态

## 1.1 定义与直觉

**结论先行**：多模态模型（Multimodal Model）能同时处理文本、图像、音频、视频等多种模态（Modality），并做统一理解与生成。

### 1.1.1 定义

**多模态模型** = 能处理多种模态（文本、图像、音频、视频）的模型。

```
文本 + 图像 + 音频 + 视频 → 统一理解与生成
```

### 1.1.2 与单模态的差异

| 维度 | 单模态 | 多模态 |
|------|--------|--------|
| 输入 | 文本 | 文本 + 图像 + 音频 + 视频 |
| 表示 | 词向量 | 跨模态共享空间 |
| 任务 | 生成/分类 | 理解 + 跨模态生成 |
| 难点 | 语言建模 | 对齐（Alignment） |

## 1.2 模态与统一表示

### 1.2.1 模态分类

| 模态 | 典型数据 | 编码方式 |
|------|----------|----------|
| 文本 | 字符串 | BPE 分词 + Embedding |
| 图像 | 像素 | ViT 切块 + 线性投影 |
| 音频 | 波形 | 频谱 + 卷积/Transformer |
| 视频 | 帧序列 | 逐帧编码 + 时序建模 |

### 1.2.2 统一表示直觉

把每种模态都变成"token 序列"，再交给同一个 Transformer（变换器）。

```
图像 patch ──┐
文本 token ──┼──▶ 统一 token 序列 ──▶ Transformer ──▶ 输出
音频帧    ──┘
```

## 1.3 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 认为"什么都强" | 通常某一模态更强 | 分模态验证 |
| 图像理解=OCR | OCR 只是子集 | 明确任务 |
| 视频理解=抽帧 | 时序信息丢失 | 时序编码 |
| 支持上传=能理解 | 分辨率/大小有限 | 预处理 |

> 多模态不是简单拼接，关键在跨模态对齐质量。

# 2. 主要能力

## 2.1 能力总览

**结论先行**：多模态能力分"理解类"与"生成类"，对应不同模型与调用方式。

### 2.1.1 能力表

| 能力 | 说明 | 例子 |
|------|------|------|
| 图像理解 | 看图回答 | 图表分析、OCR |
| 图像生成 | 文生图 | DALL-E、SD |
| 语音识别 | 语音转文字 | Whisper |
| 语音合成 | 文字转语音 | TTS |
| 视频理解 | 视频问答 | 视频摘要 |

### 2.1.2 输入输出矩阵

| 输入 \ 输出 | 文本 | 图像 | 音频 |
|-------------|:----:|:----:|:----:|
| 文本 | LLM | 文生图 | TTS |
| 图像 | VLM/OCR | 图生图 | - |
| 音频 | ASR | - | 语音转换 |

## 2.2 组合能力

### 2.2.1 组合公式

```
图文问答 = 图像编码 + LLM
视频摘要 = 抽帧/时序编码 + LLM
语音助手 = ASR + LLM + TTS
```

### 2.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 混用理解与生成 | 接口不同 | 分别选模型 |
| 忽视模态质量 | 输入差则输出差 | 预处理 |
| 能力过度预期 | 视频/音频弱于图像 | 先验证 |

# 3. 多模态架构

## 3.1 总体架构

**结论先行**：主流架构是"编码器 + 投影层 + LLM"三件套。

### 3.1.1 架构图

```
图像 → [视觉编码器] → 视觉 token ─┐
                                   ├─▶ [LLM] → 输出
文本 → [文本 tokenizer] → 文本 token ┘
```

### 3.1.2 组件表

| 组件 | 作用 |
|------|------|
| 视觉编码器 | 图像 → 特征（如 ViT、CLIP） |
| 投影层 | 视觉特征 → LLM 空间 |
| LLM | 统一理解与生成 |

## 3.2 视觉编码器

### 3.2.1 ViT 原理

ViT（Vision Transformer，视觉变换器）把图像切成 P×P 的 patch（图块），每个 patch 线性投影为一个 token。

```
H×W×3 图像
  │ 切分为 (H/P)×(W/P) 个 P×P patch
  ▼
展平 → 线性层 → patch token → +位置编码 → Transformer
```

图像 token 数 `n ≈ (H/P) × (W/P)`；例：224×224、P=16 → 196 个 token。

### 3.2.2 CLIP 对比学习

CLIP（Contrastive Language-Image Pretraining，对比语言-图像预训练）用对比损失把成对图文拉近、非成对推远。

```
S = (I · T^T) / τ；Loss = 对称交叉熵（行、列各一次）
```

| 符号 | 含义 |
|------|------|
| I / T | 图像 / 文本特征矩阵 |
| τ | 温度系数 |
| 正样本 | 对角线上的配对 |

## 3.3 投影层

### 3.3.1 常见形式

| 形式 | 说明 | 代表 |
|------|------|------|
| 线性层 | 简单高效 | LLaVA |
| MLP | 表达更强 | Qwen-VL |
| Q-Former | 压缩 token 数 | BLIP-2 |
| Perceiver | 交叉注意力 | Flamingo |

### 3.3.2 公式与坑

线性投影最简形式：`z_visual = W · v + b`，把视觉维度 d_v 对齐到 LLM 维度 d_llm。

| 坑 | 说明 | 对策 |
|----|------|------|
| token 过多 | 高分辨率 token 爆炸 | 池化/切图 |
| 编码器冻结 | 对齐差 | 训练投影层 |
| 位置编码错 | 空间信息丢失 | 保留 2D 位置 |
| 模态抢占 | 图像挤占上下文 | 限制 token 预算 |

# 5. 图像理解

## 5.1 基本流程

**结论先行**：图像理解 = 图像编码为 token + 文本指令拼接 + LLM 生成回答。

### 5.1.1 流程

```
图像 ──视觉编码──▶ 视觉 token
                     │
文本问题 ──分词──▶ 文本 token
                     ▼
              LLM 自回归生成 ──▶ 回答
```

### 5.1.2 Java 示例（Spring AI）

```java
// Spring AI
UserMessage message = UserMessage.builder()
        .text("这张图表说明了什么趋势？")
        .media(new Media(MimeTypeUtils.IMAGE_PNG, imageResource))
        .build();

String answer = chatClient.prompt().messages(message).call().content();
```

### 5.1.3 Java 示例（LangChain4j）

```java
// LangChain4j
UserMessage msg = UserMessage.from(
        TextContent.from("这张图有什么问题？"),
        ImageContent.from(imageUrl));
```

## 5.2 高分辨率与边界

### 5.2.1 高分辨率处理

成本与 token 成正比：`成本 ∝ (H/P) × (W/P)`。

| 策略 | 说明 |
|------|------|
| 缩放 | 压到固定分辨率 |
| 切图 | 分块编码再拼接 |
| 关键区域裁剪 | 只送 ROI |
| 先 OCR 再问 | 文本化降 token |

### 5.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 小字识别差 | 分辨率不足 | 切图/裁剪 |
| 多图混淆 | 图与问对不上 | 明确指代 |
| Base64 过大 | 请求超限 | 用 URL 或压缩 |
| 幻觉 | 编造图中不存在内容 | 要求引用位置 |

# 6. 图像生成

## 6.1 原理

**结论先行**：现代文生图多基于扩散模型（Diffusion Model），从随机噪声逐步去噪生成图像。

### 6.1.1 扩散直觉

```
前向：真实图 x0 ──逐步加噪──▶ 纯噪声 xT
反向：纯噪声 xT ──逐步去噪──▶ 生成图 x0
条件：文本编码 c 引导每一步去噪
```

### 6.1.2 训练目标

```
L = E[ || ε - ε_θ(x_t, t, c) ||² ]
ε：真实噪声；ε_θ：网络预测；c：文本条件；t：时间步
```

## 6.2 Java 调用与参数

### 6.2.1 代码

```java
ImageResponse response = imageModel.call(
        new ImagePrompt("一只戴眼镜写代码的橘猫",
                ImageOptionsBuilder.builder()
                        .width(1024).height(1024).build()));

String url = response.getResult().getOutput().getUrl();
```

### 6.2.2 参数说明

| 参数 | 作用 | 建议 |
|------|------|------|
| 尺寸 | 输出分辨率 | 按用途 |
| 步数 | 去噪迭代数 | 20~50 |
| 引导系数 | 提示遵循强度 | 7~12 |
| 种子 | 可复现 | 固定调试 |

## 6.3 模型对比与坑

### 6.3.1 模型表

| 模型 | 特点 |
|------|------|
| DALL-E 3 | OpenAI，提示遵循好 |
| Stable Diffusion | 开源，可本地 |
| Midjourney | 艺术性强 |
| Flux | 开源，质量高 |
| 通义万相 | 中文友好 |

### 6.3.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 文字渲染差 | 图中文字乱码 | 后期叠加 |
| 手部/细节崩 | 结构错误 | 多轮重生成 |
| 版权风险 | 训练数据争议 | 商用前评估 |
| 提示注入 | 违规生成 | 输入过滤 |

# 7. 语音

## 7.1 ASR 与 TTS

**结论先行**：语音能力由 ASR 与 TTS 组成，串联即成语音 Agent。

### 7.1.1 能力表

| 能力 | 模型 |
|------|------|
| ASR（语音转文字） | Whisper、Paraformer |
| TTS（文字转语音） | OpenAI TTS、CosyVoice |

### 7.1.2 语音 Agent 图

```
语音 Agent = ASR → LLM → TTS

麦克风 ──▶ ASR ──▶ 文本 ──▶ LLM ──▶ 回复文本 ──▶ TTS ──▶ 扬声器
```

## 7.2 流式与实时

### 7.2.1 延迟预算

| 阶段 | 典型延迟 | 优化 |
|------|----------|------|
| ASR | 100~500 ms | 流式识别 |
| LLM 首 token | 200~800 ms | 小模型/缓存 |
| TTS 首帧 | 100~400 ms | 流式合成 |
| 合计 | < 1.5 s | 全链路流式 |

### 7.2.2 打断与坑

```
用户说话 ──▶ VAD 检测 ──▶ 停止 TTS ──▶ 重新识别
```

| 坑 | 说明 | 对策 |
|----|------|------|
| 噪声环境 | 识别率骤降 | 降噪/近场 |
| 方言口音 | 误识别 | 专用模型 |
| 全链路非流式 | 延迟高 | 逐段流式 |
| 音频隐私 | 含敏感信息 | 加密/不落盘 |

# 8. 多模态 RAG

## 8.1 架构

**结论先行**：多模态 RAG（检索增强生成）把图片/扫描件与文本一起入库，检索后交给多模态模型生成。

### 8.1.1 架构图

```
图片/扫描件 → 多模态 Embedding（CLIP）或 OCR/图注
                ↓
            统一向量库
                ↓
        查询 → 检索 → 多模态模型生成
```

### 8.1.2 两条路线

| 路线 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 图注/OCR | 先转文本再检索 | 实现简单 | 丢视觉细节 |
| 多模态 Embedding | 图文同空间 | 保留视觉 | 需专用模型 |

## 8.2 检索策略与坑

### 8.2.1 检索策略

| 策略 | 说明 |
|------|------|
| 混合检索 | 文本 + 视觉向量 |
| 重排序 | 交叉编码器精排 |
| 元数据过滤 | 按类型/来源 |
| 多向量 | 一图多向量 |

### 8.2.2 边界与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 图注丢信息 | 细节检索不到 | 保留原图 |
| 向量空间不齐 | 图文不可比 | 同模型编码 |
| 图片过大 | 超上下文 | 压缩/裁剪 |
| 引用不明 | 无法溯源 | 返回图 id |

> 详见 `5_RAG/Advanced/4_multimodal_rag.md`。

# 9. 多模态 Agent

## 9.1 能力

**结论先行**：多模态 Agent 能"看"和"听"，从而操作图形界面、理解图表、生成配图。

### 9.1.1 能力列表

```
Agent 可以：
- 看截图理解界面（Computer Use）
- 读取图表数据
- 生成配图
- 处理语音指令
```

### 9.1.2 典型任务

| 任务 | 输入 | 输出 |
|------|------|------|
| 界面操作 | 截图 | 点击/输入动作 |
| 图表问答 | 图表 | 数值与结论 |
| 内容创作 | 文案 | 配图 |
| 语音助手 | 语音 | 语音回复 |

## 9.2 Computer Use

### 9.2.1 循环

```
截图 ──▶ VLM 理解 ──▶ 规划动作 ──▶ 执行 ──▶ 新截图 ──┐
  ▲                                                    │
  └────────────────────────────────────────────────────┘
```

### 9.2.2 要点与坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 坐标漂移 | 分辨率变化 | 归一化 |
| 误点 | 不可逆操作 | 确认/沙箱 |
| 循环失控 | 无限截图 | 步数上限 |
| 隐私截图 | 含敏感信息 | 脱敏/遮罩 |

# 10. 生产注意事项

## 10.1 风险清单

**结论先行**：主要风险是成本、延迟、隐私、格式与合规，需入口与出口双向管控。

### 10.1.1 风险表

| 风险 | 建议 |
|------|------|
| 成本高 | 多模态 token 更贵，按需 |
| 延迟高 | 视觉推理更慢 |
| 隐私 | 图片/音频含敏感信息 |
| 格式兼容 | 校验 MIME 与支持范围 |
| 生成违规 | 输出侧审核 |
| 大文件 | 限制大小、流式处理 |

### 10.1.2 优先级

| 优先级 | 事项 | 理由 |
|--------|------|------|
| P0 | 隐私与合规 | 法律底线 |
| P0 | 输入校验 | 防崩溃/注入 |
| P1 | 成本控制 | 预算 |
| P1 | 输出审核 | 合规 |
| P2 | 延迟优化 | 体验 |

## 10.2 成本优化与监控

### 10.2.1 优化手段

| 手段 | 效果 |
|------|------|
| 压缩/缩放图片 | 降 token |
| 按需送图 | 降调用 |
| 缓存结果 | 降重复 |
| 小模型前置 | 降成本 |
| 流式返回 | 降感知延迟 |

### 10.2.2 监控指标

| 指标 | 含义 | 告警 |
|------|------|------|
| 图像 token 占比 | 成本结构 | 异常升高 |
| 多模态调用量 | 用量 | 突增 |
| 平均延迟 | 体验 | 超阈值 |
| 审核拦截率 | 合规 | 异常 |

# 11. 小结

- 多模态模型处理文本、图像、音频、视频。
- 架构：视觉编码器 + 投影层 + LLM。
- 主流：GPT-4o、Claude、Gemini、Qwen-VL。
- 语音 Agent = ASR + LLM + TTS。
- 多模态成本与延迟更高，按需使用。
- 生产重点：输入校验、隐私、输出审核。
