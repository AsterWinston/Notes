# 1. 背景与定位

结论先行：深度研究 Agent（Deep Research Agent）的本质是"把分析师的信息搜集—筛选—整合流程自动化，并保证每条结论可溯源"。它不是更强的问答机器人，而是一个带引用的研究流水线。

## 1.1 问题背景

分析师需要花费大量时间搜集、筛选、整合信息。一个行业研究往往需要浏览数十个来源、剔除营销噪音、交叉验证数据、整理成结构化报告。这个过程重复、耗时，且高度依赖个人经验。

传统搜索只解决"找到"，不解决"整合与溯源"；大模型能整合，却容易编造来源。深度研究 Agent 要同时解决这两点：既能多轮自主检索，又能让每条结论落到真实来源上。

## 1.2 产品定位

### 1.2.1 与通用问答的区别

| 维度 | 通用问答 | 深度研究 Agent |
|------|----------|----------------|
| 交互 | 单轮/少轮 | 多轮自主检索 |
| 输出 | 一段回答 | 结构化报告 |
| 来源 | 常无引用 | 每条结论有引用 |
| 耗时 | 秒级 | 分钟级 |
| 成本 | 低 | 中高 |
| 可复核 | 弱 | 引用可点击 |

### 1.2.2 核心价值

- 省时：把数小时调研压缩到数分钟。
- 可信：引用可点击、可复核。
- 全面：多角度、多来源覆盖。
- 一致：结构化输出，便于下游使用。

## 1.3 术语约定

| 术语 | 中文 | 含义 |
|------|------|------|
| Deep Research | 深度研究 | 多轮检索与整合 |
| Sub-question | 子问题 | 分解后的可检索问题 |
| Citation | 引用 | 结论对应的来源 |
| Sufficiency | 充分性 | 信息是否足够回答 |
| Grounding | 有据 | 结论有来源支撑 |
| Chunk | 切片 | 网页清洗后的文本块 |

## 1.4 竞品与边界

### 1.4.1 与搜索/问答/RAG 的关系

```text
搜索        -> 只返回链接列表
RAG 问答    -> 单轮检索 + 生成，无多轮、无报告
深度研究    -> 分解 + 多轮检索 + 整合 + 带引用报告
```

结论先行：深度研究 Agent 是 RAG 的"多轮 + 规划 + 报告"增强版，差异在于自主性与可溯源，而非单次检索质量。

### 1.4.2 产品边界

结论先行：产品只做"公开信息的检索与整合"，不碰需要授权或实时性的数据。

| 做 | 不做 |
|----|------|
| 公开网页检索 | 付费数据库 |
| 静态行业资料 | 实时行情 |
| 引用可溯源 | 全文转载 |
| 结构化报告 | 自动下单/交易 |

# 2. 目标用户

结论先行：目标用户是"需要快速获得可信调研结论"的知识工作者，核心诉求是省时与可信，而非极致深度。

## 2.1 用户画像

| 用户 | 场景 |
|------|------|
| 分析师 | 行业研究、竞品分析 |
| 产品经理 | 市场调研 |
| 咨询顾问 | 快速调研 |
| 投资 | 标的调研 |

## 2.2 典型场景

- 行业格局：市场规模、主要厂商、增长趋势。
- 竞品分析：功能对比、定价策略、用户口碑。
- 技术选型：方案对比、优缺点、落地案例。
- 标的调研：公司背景、财务、风险点。

## 2.3 使用旅程

### 2.3.1 输入与大纲

```text
输入研究问题
   |
   v
系统分解子问题 -> 展示大纲（可编辑）
```

用户先确认大纲，避免系统跑偏，也降低无效检索成本。

### 2.3.2 检索与进度

```text
多轮检索 + 抓取 + 清洗
   |
   v
实时进度（当前子问题、已获来源数）
```

### 2.3.3 复核与导出

```text
整合去重 -> 生成报告 -> 标注引用
   |
   v
用户复核引用 -> 追问/导出
```

# 3. 功能范围

结论先行：核心功能是"分解—检索—整合—报告"四段。实时数据与付费库刻意排除，以控制范围与成本。

## 3.1 核心功能

### 3.1.1 任务分解

把研究问题拆成 3~8 个可检索子问题，并生成大纲供用户确认。

```text
研究问题：AI Agent 市场格局
  ├── 子问题1：市场规模与增速
  ├── 子问题2：主要厂商与产品
  ├── 子问题3：技术趋势
  └── 子问题4：投资建议依据
```

分解质量决定覆盖面。子问题应满足：可检索、无重叠、合起来能回答原问题。

### 3.1.2 多轮检索

对每个子问题做检索，判断充分性，不充分则改写查询继续检索，直到满足或达上限。

```text
while not sufficient and rounds < MAX:
    query = refine(subQuestion, collected)
    docs = search(query)
    collected += fetchAndClean(docs)
    sufficient = judgeSufficiency(subQuestion, collected)
```

### 3.1.3 整合与报告

去重、交叉验证、按大纲组织、生成带引用的结构化报告。

```text
核心功能：
├── 任务分解（研究子问题）
├── 多轮联网检索
├── 网页内容抓取与清洗
├── 信息整合与去重
├── 生成结构化报告
└── 附引用来源
```

## 3.2 非目标

```text
非目标：
├── 实时数据（股价等）
├── 付费数据库接入
```

明确非目标可避免范围蔓延，并降低合规与成本风险。

## 3.3 功能优先级

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 单轮检索 + 生成 | 打通最小闭环 |
| P1 | 任务分解 + 多轮 | 提升覆盖 |
| P2 | 抓取 + 清洗 | 提升质量 |
| P3 | 引用 + 报告 | 可溯源 |
| P4 | 评测 + 优化 | 持续改进 |

# 4. 非功能需求

结论先行：非功能需求里"引用可溯源"是硬约束，其余（时长、成本）是可调预算。

## 4.1 性能与时长

| 维度 | 要求 |
|------|------|
| 单任务时长 | < 10 分钟 |
| 首字节时间 | < 5 秒（先出大纲） |
| 并发 | 支持多任务并行 |
| 可中断 | 用户可取消 |

## 4.2 质量与引用

| 维度 | 要求 |
|------|------|
| 引用 | 每条结论有来源 |
| 覆盖 | 多角度、多来源 |
| 无编造 | 引用真实可访问 |
| 时效 | 优先近期来源 |

### 4.2.1 引用校验策略

结论先行：引用必须"可访问 + 内容匹配"双重校验，仅校验 URL 存在远远不够。

- 可访问性：HTTP 200 且正文可提取。
- 内容匹配：引用句与来源文本相似度超过阈值。
- 去重：同一 URL 合并为一条来源。

未通过校验的结论要么降级为"未证实"，要么删除，绝不保留无来源的断言。

## 4.3 成本与资源

| 维度 | 要求 |
|------|------|
| 单报告成本 | < ¥5 |
| 检索调用 | 每子问题 < N 次 |
| 抓取页数 | 有上限 |
| 缓存 | 相同查询复用 |

### 4.3.1 成本控制手段

- 缓存：相同查询命中缓存，避免重复检索与抓取。
- 分层模型：分解/生成用强模型，充分性判断用中档模型。
- 预算封顶：单任务成本达上限即停止检索，输出当前结果。

## 4.4 合规与安全

- 遵守 robots.txt 与版权，正文引用而非全文转载。
- 网页内容视为不可信，防提示注入（Prompt Injection）。
- 用户研究问题可能含敏感信息，需隔离与脱敏。

# 5. 验收标准

## 5.1 功能验收

- [ ] 报告覆盖任务的主要方面
- [ ] 每条关键结论有引用
- [ ] 引用可访问
- [ ] 无明显编造
- [ ] 时长与成本在预算内

## 5.2 质量验收

| 指标 | 阈值 |
|------|------|
| 要点覆盖率 | > 80% |
| 引用有效率 | > 90% |
| 引用可访问率 | > 95% |
| 事实错误率 | < 5% |

## 5.3 验收方法

```java
public boolean accept(Report report, Task task) {
    boolean covered = coverage(report, task) >= 0.8;
    boolean cited = citationValidator.validRatio(report) >= 0.9;
    boolean inBudget = report.cost().compareTo(MAX_COST) <= 0;
    return covered && cited && inBudget;
}
```

# 6. 技术选型

结论先行：编排用图（Graph）而非纯循环，模型用强模型，检索与抓取分离以便替换。

## 6.1 编排框架

| 组件 | 选择 |
|------|------|
| 框架 | LangGraph4j / Spring AI Alibaba Graph |
| 模型 | 强模型（研究质量关键） |
| 搜索 | 搜索 API |
| 抓取 | Playwright / Jsoup |
| 存储 | 中间结果持久化 |

图编排的优势：节点即步骤（分解、检索、充分性判断、整合、生成），边即条件跳转，天然支持循环与中断。

### 6.1.1 图编排节点设计

```text
[decompose] -> [retrieve] -> [judgeSufficiency]
                   ^                |
                   |  不充分         | 充分
                   +----------------+
                                    |
                                    v
                              [integrate] -> [generate] -> [cite]
```

## 6.2 模型与检索

| 用途 | 模型档位 | 理由 |
|------|----------|------|
| 分解/整合/生成 | 强模型 | 质量关键 |
| 充分性判断 | 中档模型 | 频繁调用 |
| 查询改写 | 中档模型 | 频繁调用 |

## 6.3 存储与可观测

| 数据 | 存储 |
|------|------|
| 中间结果 | 键值/对象存储 |
| 引用 | 关系库 |
| Trace | 日志 + OpenTelemetry |

## 6.4 选型对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| 纯循环编排 | 简单 | 难表达条件跳转 |
| 图编排 | 清晰、可中断 | 学习成本 |
| 多 Agent | 灵活 | 复杂、成本高 |

# 7. 数据模型与接口

结论先行：数据模型围绕"问题—子问题—来源—结论—引用"五元组建模，接口围绕"提交—进度—结果"三件事。

## 7.1 核心数据模型

```java
public record ResearchTask(
        String id,
        String question,
        List<SubQuestion> subQuestions,
        ResearchStatus status
) {}

public record SubQuestion(
        String id,
        String text,
        boolean sufficient,
        List<Source> sources
) {}

public record Source(
        String url,
        String title,
        String snippet,
        Instant fetchedAt
) {}

public record Citation(
        String claimId,
        String sourceUrl,
        String quote
) {}

public record Report(
        String taskId,
        String markdown,
        List<Citation> citations,
        BigDecimal cost,
        long durationMs
) {}
```

## 7.2 关键接口

```java
public interface ResearchService {
    String submit(String question);          // 返回 taskId
    ResearchStatus status(String taskId);     // 查询进度
    Report result(String taskId);             // 获取报告
    void cancel(String taskId);               // 取消任务
}
```

| 接口 | 语义 | 幂等 |
|------|------|------|
| submit | 创建研究任务 | 可用幂等键 |
| status | 查询进度 | 是 |
| result | 拉取报告 | 是 |
| cancel | 取消任务 | 是 |

# 9. 风险与应对

结论先行：研究 Agent 的头号风险是"编造引用"与"成本失控"，其次是注入与过时。

## 9.1 质量风险

| 风险 | 应对 |
|------|------|
| 信息过时 | 时效过滤 |
| 编造引用 | 引用校验 |
| 单一来源 | 强制多来源交叉 |
| 覆盖不足 | 充分性判断 + 追问 |

## 9.2 成本与工程风险

| 风险 | 应对 |
|------|------|
| 成本失控 | 步数与预算上限 |
| 循环检索 | 充分性判断 + 轮数上限 |
| 抓取失败 | 降级为摘要 + 重试 |
| 任务中断 | 中间结果持久化 + 断点续跑 |

## 9.3 合规风险

| 风险 | 应对 |
|------|------|
| 内容注入 | 网页内容视为不可信 |
| 版权问题 | 仅引用、不转载 |
| 数据合规 | 用户问题隔离与脱敏 |

# 10. 小结

## 10.1 关键结论

- 目标是自动产出带引用的研究报告。
- 核心：任务分解、多轮检索、整合、报告。
- 引用可溯源是硬要求。
- 用强模型 + 图编排。
- 需限制步数与成本。

## 10.2 落地清单

- [ ] 先出大纲，用户可确认后再检索。
- [ ] 充分性判断控制检索轮数。
- [ ] 引用做有效性校验（可访问 + 内容匹配）。
- [ ] 网页内容一律不可信，防注入。
- [ ] 成本按任务预算封顶。
- [ ] 中间结果持久化，支持断点续跑。
