# 1. 项目背景与目标

结论先行：智能客服（AI Customer Service，智能客服）的目标不是"完全替代人工"，而是"用知识库自动应答高频问题、把复杂与投诉问题高质量转人工"，从而在保证体验的前提下降低人力成本。

## 1.1 业务背景

### 1.1.1 现状问题

客服团队面临重复问题多、响应慢、人力成本高的问题。具体表现为：

- 重复问题占比高：约 60%–70% 的咨询为高频标准问题。
- 响应慢：高峰期排队严重，首响（首次响应）时间不可控。
- 人力成本高：坐席规模随业务量线性增长，边际成本不降。
- 质量不稳定：不同坐席话术与解决水平参差。

### 1.1.2 项目定位

智能客服基于知识库自动应答，复杂问题转人工。它是一层"前置分流 + 辅助应答"能力，而非独立闭环。

| 定位 | 说明 |
|------|------|
| 分流层 | 拦截高频标准问题 |
| 辅助层 | 为坐席生成建议话术 |
| 兜底层 | 无法处理时转人工 |

### 1.1.3 关键约束

| 约束 | 说明 |
|------|------|
| 合规优先 | 话术与数据访问必须合规 |
| 体验优先 | 宁可转人工，不可答错 |
| 成本可控 | 单次会话成本需可预算 |
| 可演进 | 先通后优，逐步增强 |

## 1.2 项目目标

结论先行：目标需可量化，且区分"业务目标"与"技术目标"，避免只喊口号。

### 1.2.1 业务目标

| 目标 | 度量 |
|------|------|
| 降低重复问题人力 | 自动解决率 > 60% |
| 提升响应速度 | 首响 < 2s |
| 保障体验 | 满意度 > 85% |
| 控制风险 | 投诉 100% 转人工 |

### 1.2.2 技术目标

| 目标 | 度量 |
|------|------|
| 低延迟 | P95 首响 < 2s |
| 高可用 | 可用性 > 99.9% |
| 可观测 | 全链路 Trace 覆盖 |
| 可评测 | 有离线评测集与基线 |

# 2. 目标用户与场景

结论先行：不同角色诉求不同，产品设计要同时服务"客户、客服、运营"三方，其中客户体验优先。

## 2.1 用户角色

| 用户 | 需求 | 关注指标 |
|------|------|----------|
| 客户 | 快速解决问题 | 首响、解决率 |
| 客服 | 辅助应答 | 采纳率、效率 |
| 运营 | 降低人力成本 | 转人工率、成本 |

### 2.1.1 客户画像

- 主要诉求：快速、准确、不用重复描述。
- 典型反感：答非所问、反复澄清、无法转人工。

### 2.1.2 客服画像

- 主要诉求：获得上下文摘要与建议话术。
- 典型痛点：重复问答、信息不全。

### 2.1.3 运营画像

- 主要诉求：降低单会话成本、掌握服务质量。
- 典型痛点：无法量化 AI 贡献、难以定位问题。

## 2.2 典型场景

结论先行：先覆盖三类高频场景（查物流、政策咨询、投诉），再向长尾扩展。

```
场景A：查物流
  客户：我的订单到哪了？
  → 识别售后意图 → 调用 queryOrder → 返回物流状态

场景B：政策咨询
  客户：退货要几天？
  → 识别咨询意图 → RAG 检索退货政策 → 返回

场景C：投诉
  客户：你们太差了，我要投诉！
  → 识别愤怒情绪 → 直接转人工
```

### 2.2.1 场景优先级

| 场景 | 频率 | 优先级 |
|------|------|--------|
| 政策咨询 | 高 | P0 |
| 订单查询 | 高 | P1 |
| 投诉处理 | 中 | P1 |
| 售后申请 | 中 | P2 |

### 2.2.2 场景边界

- 涉及金额赔付：必须转人工。
- 涉及账号安全：必须转人工。
- 涉及法律纠纷：必须转人工。

### 2.2.3 会话生命周期

```
创建会话 → AI 应答 → (转人工?) → 结束 → 满意度收集 → 归档
   │           │           │
   │           │           └── HUMAN 状态
   │           └── AI 状态
   └── status=AI
```

| 状态 | 含义 | 可转移至 |
|------|------|----------|
| AI | AI 应答中 | HUMAN、CLOSED |
| HUMAN | 人工应答中 | CLOSED |
| CLOSED | 会话结束 | 无 |

# 3. 功能范围

结论先行：功能范围要"够用且聚焦"，明确非目标，避免把项目做成大而全的工单系统。

## 3.1 核心功能

```
核心功能：
├── 意图识别（咨询/售后/投诉）
├── 知识库问答（RAG）
├── 工单查询与创建
├── 多轮对话
├── 置信度判断与转人工
└── 满意度收集
```

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 意图识别 | 分类用户意图 | P1 |
| RAG 问答 | 知识库检索增强生成 | P0 |
| 工单工具 | 查询/创建工单 | P2 |
| 多轮对话 | 上下文保持 | P1 |
| 置信度与转人工 | 低置信转人工 | P1 |
| 满意度收集 | 会话后评分 | P3 |

### 3.1.1 功能依赖

```
RAG 问答(P0)
   └── 意图识别(P1)
          └── 转人工(P1)
                 └── 工单工具(P2)
                        └── 满意度/审计(P3)
```

### 3.1.2 功能验收要点

| 功能 | 验收要点 |
|------|----------|
| RAG 问答 | 命中知识库时准确回答 |
| 意图识别 | 投诉必须归类正确 |
| 转人工 | 摘要完整、通知及时 |
| 满意度 | 评分可落库、可统计 |

## 3.2 非目标

```
非目标：
├── 电话客服
├── 复杂工单流转
```

### 3.2.1 为何不做

| 非目标 | 原因 |
|--------|------|
| 电话客服 | 语音链路复杂，先做文本 |
| 复杂工单流转 | 属内部系统职责，非本 Agent |

### 3.2.2 未来可扩展

| 扩展方向 | 前提 |
|----------|------|
| 语音客服 | 文本链路稳定后 |
| 主动外呼 | 合规与授权就绪后 |
| 多语言 | 知识库多语言化后 |

# 4. 非功能需求

结论先行：非功能需求决定系统能否上线，其中合规与可审计是一票否决项。

## 4.1 性能与体验

| 维度 | 要求 | 说明 |
|------|------|------|
| 首响 | < 2s | 含检索与生成 |
| 解决率 | > 60% | 自动解决占比 |
| 转人工率 | < 25% | 转人工占比 |
| 可用性 | > 99.9% | 服务等级 |

### 4.1.1 延迟预算

```
首响 2s 预算分解：
  身份识别       50ms
  情绪+意图识别  600ms
  RAG 检索       300ms
  生成回答       800ms
  后处理/发送    250ms
```

### 4.1.2 吞吐与并发

| 项 | 建议 |
|----|------|
| 峰值 QPS | 按坐席数 × 3 估算 |
| 单实例并发 | 受模型限流约束 |
| 限流 | 按用户与会话双维度 |
| 排队 | 超出容量时降级转人工 |

## 4.2 质量与合规

| 维度 | 要求 |
|------|------|
| 满意度 | > 85% |
| 合规 | 话术合规、可审计 |
| 安全 | 不越权、不泄露隐私 |

### 4.2.1 合规要点

- 话术不得承诺未经授权的赔付。
- 全流程留痕，支持事后审计。
- 用户身份与数据访问严格校验。

### 4.2.2 数据隐私

| 数据 | 处理 |
|------|------|
| 手机号 | 脱敏展示 |
| 订单信息 | 归属校验 |
| 会话记录 | 加密存储、限期保留 |

### 4.2.3 审计要求

| 审计项 | 内容 |
|--------|------|
| 谁 | 用户 ID、坐席 ID |
| 何时 | 时间戳 |
| 做了什么 | 意图、回答、工具调用 |
| 结果 | 是否转人工、满意度 |

- 审计日志不可篡改，独立存储。
- 支持按会话、按用户回溯。
- 保留期限符合监管要求。

# 5. 验收标准

结论先行：验收标准需同时覆盖"功能正确"与"指标达标"，缺一不可。

## 5.1 功能验收

- [ ] 投诉类正确转人工
- [ ] 置信度低时转人工
- [ ] 话术符合品牌规范

### 5.1.1 用例清单

| 用例 | 期望 |
|------|------|
| 政策咨询 | 正确回答 |
| 订单查询 | 返回本人订单 |
| 他人订单查询 | 拒绝 |
| 投诉 | 转人工 |
| 愤怒情绪 | 转人工 |

## 5.2 指标验收

- [ ] 常见问题解决率 > 60%
- [ ] 全流程可审计

| 验收项 | 阈值 | 判定 |
|--------|------|------|
| 解决率 | > 60% | 达标/不达标 |
| 转人工率 | < 25% | 达标/不达标 |
| 满意度 | > 85% | 达标/不达标 |
| 投诉转人工 | 100% | 一票否决 |

### 5.2.1 评测方法

- 离线：固定评测集 + 人工标注。
- 在线：灰度流量 + A/B 对比。
- 抽样：人工复核 5% 会话。

# 6. 技术选型

结论先行：选型优先考虑"团队熟悉度 + 生态成熟度"，Java 生态选 Spring AI 或 LangChain4j。

## 6.1 组件选型

| 组件 | 选择 |
|------|------|
| 框架 | Spring AI / LangChain4j |
| 知识库 | RAG（PGVector） |
| 工单系统 | 内部 API（工具） |
| 转人工 | 工单/IM 对接 |
| 模型 | 中模型 |

### 6.1.1 选型对比

| 维度 | Spring AI | LangChain4j |
|------|-----------|-------------|
| 生态 | Spring 原生 | 独立、轻量 |
| 工具调用 | 注解支持 | 注解支持 |
| 学习曲线 | 低（Spring 用户） | 中 |
| 适合场景 | Spring Boot 项目 | 灵活编排 |

## 6.2 选型理由与替代方案

| 组件 | 理由 | 替代 |
|------|------|------|
| Spring AI | 与 Spring 生态契合 | LangChain4j |
| PGVector | 复用 Postgres | Milvus、Qdrant |
| 中模型 | 成本与质量平衡 | 小模型+大模型分层 |

### 6.2.1 模型分层建议

```
简单意图分类 → 小模型（低成本、低延迟）
回答生成     → 中模型
复杂摘要     → 中模型
```

### 6.2.2 成本估算

| 项 | 估算方式 |
|----|----------|
| 模型调用 | 会话数 × 平均 Token × 单价 |
| 向量检索 | 会话数 × 检索次数 |
| 人工坐席 | 转人工会话数 × 单会话时长 |

# 7. 里程碑与排期

结论先行：里程碑按"先通后优"排序，P0 打通问答闭环，后续逐步加能力。

## 7.1 阶段划分

| 阶段 | 目标 |
|------|------|
| P0 | 知识库问答 |
| P1 | 意图识别 + 转人工 |
| P2 | 工单工具 |
| P3 | 满意度 + 审计 |
| P4 | 评测 + 优化 |

### 7.1.1 排期风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 知识库质量差 | 解决率低 | 先治理知识库 |
| 模型限流 | 延迟升高 | 预留配额、降级 |
| 工单接口不稳 | 工具失败 | 熔断 + 兜底转人工 |

## 7.2 交付物

| 阶段 | 交付物 |
|------|--------|
| P0 | RAG 服务、问答接口 |
| P1 | 意图分类、转人工链路 |
| P2 | 工单工具与鉴权 |
| P3 | 反馈与审计日志 |
| P4 | 评测报告与优化项 |

### 7.2.1 依赖关系

```
P0 ──► P1 ──► P2
        │
        └──► P3 ──► P4
```

### 7.2.2 验收口径

| 阶段 | 验收口径 |
|------|----------|
| P0 | 问答准确率达标 |
| P1 | 投诉 100% 转人工 |
| P2 | 工单工具鉴权通过 |
| P3 | 审计日志完整 |
| P4 | 评测基线建立 |

# 8. 风险与应对

结论先行：客服 Agent 的最大风险是"答错"与"话术不合规"，两者都可能引发投诉升级，必须前置防护。

## 8.1 业务风险

| 风险 | 应对 |
|------|------|
| 答错 | 强约束 + 拒答 |
| 投诉升级 | 直接转人工 |
| 话术不合规 | 话术模板 + 审核 |

### 8.1.1 风险处置原则

- 高风险：一票否决，宁可转人工。
- 中风险：强约束 + 监控。
- 低风险：监控观察。

## 8.2 技术风险

| 风险 | 应对 |
|------|------|
| 越权查询 | 身份校验 |
| 客户情绪 | 情绪识别 + 共情 |
| 检索不到 | 拒答 + 转人工 |

### 8.2.1 风险分级

| 级别 | 示例 | 处置 |
|------|------|------|
| 高 | 投诉、越权 | 一票否决 |
| 中 | 答错、情绪 | 强约束 |
| 低 | 延迟波动 | 监控 |

### 8.2.2 兜底策略

```
任一环节失败：
  模型超时 / 检索为空 / 置信度低
       │
       ▼
  统一兜底：拒答 + 转人工
```

# 9. 小结

## 9.1 关键结论

- 目标是自动应答 + 复杂问题转人工。
- 核心：意图识别、RAG、工单、转人工。
- 转人工率与解决率是关键指标。

## 9.2 后续动作

- 话术合规与可审计是要求。
- 投诉类必须直接转人工。
- 按 P0–P4 里程碑逐步交付。
