# 1. 模块定位

本模块回答"如何把 Agent 从 Demo 变成能上线的系统"。聚焦运行时状态、可靠性、性能成本、架构与部署——这些正是生产事故的高发区。

| 问题 | 对应子目录 |
|------|------------|
| 状态怎么存、怎么恢复？ | Runtime/ |
| 工具调用失败怎么办？ | Reliability/ |
| 太慢、太贵怎么办？ | Performance/ |
| 怎么分层、怎么隔离多租户？ | Architecture/ |
| 怎么部署、怎么发布回滚？ | Deployment/ |

## 1.2 为什么生产工程难

### 1.2.1 三性叠加

Agent 与普通后端服务的关键差异在于"三性叠加"：

```
不确定性（模型输出） + 有状态（会话/记忆） + 有副作用（工具调用）
```

三者的组合放大了每一类故障的影响面：一次重试可能重复下单，一次热更新可能中断长会话，一次扩容可能触发状态覆盖。

### 1.2.2 与普通后端服务的差异

| 维度 | 普通后端 | Agent 服务 |
|------|----------|------------|
| 输出 | 确定 | 不确定 |
| 耗时 | 毫秒级 | 秒到分钟级 |
| 状态 | 轻量 | 会话 + 记忆 |
| 副作用 | 明确 | 工具调用，难回滚 |
| 成本 | 固定 | 随 Token 波动 |

## 1.3 本模块边界

- **包含**：运行时机制、可靠性模式、性能成本、架构治理、部署交付。
- **不包含**：模型训练与微调、Prompt 工程技巧、业务场景设计。
- 上游概念见 `6_AgentCore`、`7_ToolsAndProtocols`、`8_Memory`、`13_Observability`。

# 5. 工程实践清单

## 5.1 上线前检查项

| 检查项 | 合格标准 |
|--------|----------|
| 状态外置 | 重启不丢会话 |
| 幂等 | 副作用带幂等键 |
| 超时 | 每个外部调用都有超时 |
| 重试 | 有退避与上限 |
| 熔断 | 有半开恢复 |
| 降级 | 有备用路径 |
| 可观测 | Trace + 指标齐全 |
| 发布 | 可灰度、可回滚 |
| 版本化 | 定义集中存储、可对比 |
| 限流 | 模型与工具均有配额 |

## 5.2 监控指标

| 指标 | 含义 | 告警示例 |
|------|------|----------|
| 成功率 | 任务成功比例 | < 99% |
| P99 延迟 | 尾延迟 | > 2× 基线 |
| 单次成本 | 每任务成本 | > 预算 |
| 工具错误率 | 工具失败比例 | > 5% |
| 队列积压 | 待处理任务 | > 1000 |

## 5.3 常见反模式

| 反模式 | 后果 | 纠正 |
|--------|------|------|
| 状态放内存 | 无法扩容 | 外置存储 |
| 无限重试 | 雪崩 | 上限 + 死信 |
| 无超时 | 线程耗尽 | 全链路超时 |
| 大 Prompt | 成本飙升 | 预算化裁剪 |
| 硬编码配置 | 无法热更 | 配置中心 |
| 无幂等副作用 | 重复下单 | 幂等键 |
| 单一模型 | 成本失控 | 模型分层 |

# 6. 关键知识点速览

## 6.1 核心结论

- 生产 Agent 的难点是"状态 + 副作用 + 不确定性"三者叠加。
- 超时、重试、幂等、限流、熔断是工具调用的"可靠性五件套"。
- 重试必须配合幂等，否则会重复产生副作用。
- Token 是成本与延迟的核心变量，必须预算化。
- 会话与状态持久化决定了系统能否中断恢复、水平扩展。

## 6.2 高频误区

| 误区 | 纠正 |
|------|------|
| 重试不幂等 | 副作用操作必须带幂等键 |
| 状态放进程内存 | 外置到共享存储才能扩容 |
| 只监控平均值 | 关注 P99 与错误率 |
| 无版本就发布 | 版本化 + 灰度 + 可回滚 |
| 靠重启解决配置 | 热更新 + 原子替换 |
| 无限重试 | 最大次数 + 死信队列 |
