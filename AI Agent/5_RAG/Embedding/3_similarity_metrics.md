# 1. 三种常用度量

向量相似度度量决定"如何比较两个向量"，最常见的是余弦相似度、点积与欧氏距离。三者并非互不相干，在归一化条件下彼此等价。

## 1.1 度量概览

结论先行：三种度量从不同几何角度衡量相似性，选择哪一个取决于向量是否归一化以及向量库的支持情况。

| 度量 | 公式 | 范围 | 特点 |
|------|------|------|------|
| 余弦相似度 | `A·B / (‖A‖‖B‖)` | [-1, 1] | 只看方向，与长度无关 |
| 点积 | `A·B` | (-∞, +∞) | 受长度影响 |
| 欧氏距离 | `‖A-B‖` | [0, +∞) | 越小越相似 |

### 1.1.1 三者关系

```text
归一化后（|A| = |B| = 1）：

cos(A,B) = A . B = 1 - ||A-B||^2 / 2
```

因此在单位球面上，三者单调等价，可按性能择优。

## 1.2 几何直觉

### 1.2.1 余弦

```text
        A
       /
      /  theta
     +---------- B
```

余弦衡量夹角，夹角越小越相似，与向量长度无关。

### 1.2.2 点积

点积同时包含"夹角"与"长度"：`A·B = |A||B|cos(theta)`。长度大的一方会放大得分。

### 1.2.3 欧氏

欧氏距离衡量端点之间的直线距离，越小越相似；对长度与方向都敏感。

## 1.3 边界与坑

- 余弦相似度可为负，表示方向相反；
- 点积无上界，不适合直接做阈值；
- 欧氏距离在未归一化时会被长度主导。

# 2. 余弦相似度

结论先行：余弦相似度是最稳妥的文本相似度度量，只看方向、不受长度影响，适合语义检索。

## 2.1 定义与公式

```text
cos(A, B) = (A . B) / (||A|| * ||B||)

其中 ||A|| = sqrt(sum(Ai^2))
```

取值范围 [-1, 1]，值越大越相似。

## 2.2 Java 实现

### 2.2.1 基础实现

```java
public double cosine(float[] a, float[] b) {
    double dot = 0, normA = 0, normB = 0;
    for (int i = 0; i < a.length; i++) {
        dot += a[i] * b[i];
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }
    return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}
```

### 2.2.2 优化实现

若向量已归一化，可直接计算点积，省去两次开方：

```java
public double cosineNormalized(float[] a, float[] b) {
    double dot = 0;
    for (int i = 0; i < a.length; i++) {
        dot += a[i] * b[i];
    }
    return dot;
}
```

### 2.2.3 数值保护

```java
double denom = Math.sqrt(normA) * Math.sqrt(normB);
if (denom < 1e-12) {
    return 0.0;
}
return dot / denom;
```

## 2.3 边界与坑

- 只关心"方向"，适合文本语义相似度；
- 归一化后，余弦相似度 = 点积；
- 零向量会导致除零，必须保护；
- 各向异性会抬高无关文本的余弦值。

## 2.4 生产建议

默认使用余弦；若已归一化，改用点积提速，并在配置中显式声明。

# 3. 点积

结论先行：点积是计算最快的度量，在向量已归一化时与余弦等价，否则会引入长度偏差。

## 3.1 定义与公式

```text
dot(A, B) = sum(Ai * Bi)
```

无上界，越大越相似。

## 3.2 Java 实现

```java
public double dot(float[] a, float[] b) {
    double sum = 0;
    for (int i = 0; i < a.length; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}
```

### 3.2.1 向量化加速

在支持 SIMD 的场景下，可用 `jdk.incubator.vector` 进一步加速：

```java
// 伪代码：JDK Vector API
var species = FloatVector.SPECIES_256;
// 按 species 分块累加
```

> 说明：Vector API 为孵化特性，需显式启用模块，生产使用需评估兼容性。

## 3.3 归一化下的等价性

```text
若 |A| = |B| = 1，则 dot(A,B) = cos(A,B)
```

因此许多向量库在"已归一化"模式下用内积（IP）等价实现余弦。

## 3.4 边界与坑

- 未归一化时，长向量得分偏高（可能引入偏差）；
- 不同文本长度会放大得分差异；
- 点积分数不可直接与余弦阈值混用。

## 3.5 生产建议

- 计算最快（无除法）；
- **向量已归一化时**，点积等价于余弦；
- 未归一化时，长向量得分偏高。

若选点积，务必在入库前统一归一化。

# 4. 欧氏距离

结论先行：欧氏距离衡量端点直线距离，越小越相似；在归一化向量下与余弦单调对应。

## 4.1 定义与公式

```text
L2(A, B) = sqrt(sum((Ai - Bi)^2))
```

范围 [0, +∞)，越小越相似。

## 4.2 Java 实现

```java
public double euclidean(float[] a, float[] b) {
    double sum = 0;
    for (int i = 0; i < a.length; i++) {
        double d = a[i] - b[i];
        sum += d * d;
    }
    return Math.sqrt(sum);
}
```

### 4.2.1 平方距离优化

若只需排序，可省去开方，直接比较平方距离：

```java
public double squaredEuclidean(float[] a, float[] b) {
    double sum = 0;
    for (int i = 0; i < a.length; i++) {
        double d = a[i] - b[i];
        sum += d * d;
    }
    return sum;
}
```

## 4.3 与余弦的关系

```text
归一化后：||A - B||^2 = 2 - 2 cos(A, B)
```

因此单位球面上，最小化欧氏距离等价于最大化余弦相似度。

## 4.4 边界与坑

- 距离越小越相似，方向与相似度相反，容易搞反；
- 未归一化时受长度影响大；
- 平方距离不满足三角不等式，仅用于排序。

## 4.5 生产建议

- 距离越小越相似；
- 归一化向量下与余弦单调对应。

若库默认 L2，可直接沿用，但阈值需按距离语义校准。

# 5. 如何选择度量

结论先行：选择度量遵循"是否归一化"与"库支持情况"两条主线，并保证建索引与检索一致。

## 5.1 决策树

```text
模型输出已归一化？
   ├── 是 -> 余弦 / 点积 / 欧氏 都等价，选计算最快的（点积）
   └── 否 -> 余弦（最稳妥）
```

## 5.2 场景推荐

**经验法则**：

| 场景 | 推荐 |
|------|------|
| 通用文本检索 | 余弦 |
| 追求性能且向量已归一化 | 点积 |
| 向量库默认 | 跟随库的推荐（如 Milvus 常用 COSINE/IP） |
| 图像特征（已归一化） | 点积 |
| 推荐系统（未归一化） | 点积或余弦按业务 |

## 5.3 一致性原则

> **关键：检索时使用的度量必须与建索引时一致**，否则结果完全错误。

```text
建索引：METRIC = COSINE
检索：  METRIC = L2     -> 结果不可信
```

## 5.4 生产建议

把度量类型写入索引元数据与配置中心，检索侧启动时校验一致，不一致直接拒绝启动。

# 6. 相似度阈值

结论先行：阈值决定"哪些结果算相关"，过低引入噪声，过高漏召回；阈值必须用标注数据校准，且与模型强相关。

## 6.1 阈值的影响

```text
阈值过低：召回无关内容（噪声）
阈值过高：漏掉相关内容（召回不足）
```

## 6.2 校准方法

### 6.2.1 分布法

```java
// 先看分数分布，再定阈值
List<EmbeddingMatch<TextSegment>> matches = store.search(request).matches();
matches.forEach(m -> log.info("score={} text={}", m.score(), m.embedded().text()));
```

1. 用标注数据，画出相关/不相关文档的分数分布；
2. 观察两条分布的重叠区；
3. 在重叠区选择切分点。

### 6.2.2 F1 最优化

```text
阈值过低：召回无关内容（噪声）
阈值过高：漏掉相关内容（召回不足）
```

调优方法：

1. 用标注数据，画出相关/不相关文档的分数分布；
2. 选择使 F1 最优的阈值；
3. 一般余弦相似度阈值在 **0.6~0.75**。

### 6.2.3 阈值扫描

```java
// 伪代码：阈值扫描
for (double t = 0.5; t <= 0.9; t += 0.01) {
    double f1 = evaluate(t);
    record(t, f1);
}
// 取 F1 最大处的阈值
```

## 6.3 边界与坑

> 阈值与模型强相关，换模型必须重新校准。

- 各向异性会使无关文本相似度偏高，阈值可能需上调；
- 混合检索场景下不同检索器分数不可比。

## 6.4 生产建议

把阈值纳入配置管理，并在每次换模型或换库后重新校准。

## 6.5 阈值与 Top-K 的关系

结论先行：阈值与 Top-K 是两种互补的截断方式，阈值保证质量下限，Top-K 保证数量上限。

```text
仅用 Top-K：可能返回一堆低分结果
仅用阈值：可能返回 0 条或过多结果
两者结合：先按阈值过滤，再取 Top-K
```

| 策略 | 优点 | 缺点 |
|------|------|------|
| Top-K | 数量稳定 | 质量无保证 |
| 阈值 | 质量有下限 | 数量不定 |
| 阈值 + Top-K | 兼顾 | 需两者调参 |

### 6.5.1 生产建议

先按阈值过滤，再取 Top-K；若结果为空，可回退到"仅 Top-K"保证可用性。

# 7. 分数不可跨模型比较

结论先行：不同模型的向量空间与分数分布不同，阈值、归一化方式都不可直接迁移。

## 7.1 原因

```text
模型A 的 0.7  !=  模型B 的 0.7
```

每个模型的训练目标、向量分布、各向异性程度不同，导致同一数值的含义不同。

## 7.2 影响

| 迁移行为 | 后果 |
|----------|------|
| 沿用旧阈值 | 召回过多或过少 |
| 混用新旧向量 | 检索完全错误 |
| 跨模型比较分数 | 排序无意义 |

## 7.3 处理方式

```text
换模型 -> 重建索引 -> 重新采样分数分布 -> 重新校准阈值
```

## 7.4 生产建议

在索引元数据中记录模型标识，检索时校验；禁止跨模型的向量混用。

# 8. 距离与相似度的换算

结论先行：向量库返回的可能是"距离"也可能是"相似度"，方向可能相反，使用前必须确认库的语义。

## 8.1 常见换算

| 库中的距离类型 | 与相似度关系 |
|----------------|--------------|
| COSINE（余弦距离） | `sim = 1 - dist` |
| IP（内积） | `sim = ip`（越大越相似） |
| L2（欧氏） | `sim = 1 / (1 + dist)` |

## 8.2 向量库语义

```text
Milvus：COSINE / IP / L2，均可选
Faiss：IndexFlatIP（内积）/ IndexFlatL2（欧氏）
Elasticsearch：cosine / dot_product / l2_norm
```

### 8.2.1 转换示例

```java
public double toSimilarity(String metric, double value) {
    return switch (metric) {
        case "COSINE" -> 1.0 - value;   // 余弦距离
        case "IP" -> value;             // 内积即相似度
        case "L2" -> 1.0 / (1.0 + value);
        default -> throw new IllegalArgumentException("unknown metric: " + metric);
    };
}
```

## 8.3 边界与坑

> 使用向量库时，注意库返回的是"距离"还是"相似度"，方向可能相反。

- `1 - dist` 仅在余弦距离定义为 `1 - cos` 时成立；
- 部分库的 IP 在归一化下等价余弦，未归一化则不等价；
- L2 的换算 `1/(1+dist)` 只是启发式，不具严格语义。

## 8.4 生产建议

统一在检索层把结果归一化为"相似度（越大越相似）"，屏蔽底层差异，避免上层逻辑搞反。

# 9. 常见坑与排查

结论先行：度量相关的问题大多源于"配置不一致"或"语义搞反"，排查应从这两点入手。

## 9.1 坑清单

| 坑 | 后果 | 避免 |
|----|------|------|
| 建索引与检索度量不一致 | 结果错误 | 统一配置 |
| 未归一化却用点积 | 长向量偏置 | 先归一化或改用余弦 |
| 跨模型比阈值 | 阈值失效 | 重新校准 |
| 把距离当相似度 | 排序反了 | 确认库的语义 |
| 忽略维度对齐 | 计算报错 | 同模型同维度 |
| 浮点精度 | 大维度误差 | 用 double 累加 |

## 9.2 排查流程

```text
结果异常？
 ├── 检查索引与检索的 METRIC 是否一致
 ├── 检查向量是否归一化
 ├── 检查返回的是距离还是相似度
 ├── 检查阈值是否随模型更新
 └── 检查维度是否对齐
```

## 9.3 生产建议

把上述检查项固化为启动自检与告警规则。

## 9.4 单元测试

结论先行：相似度函数应具备单元测试，覆盖等价性、边界与方向，防止回归。

```java
@Test
void normalizedDotEqualsCosine() {
    float[] a = normalize(new float[]{0.2f, -0.5f, 0.9f});
    float[] b = normalize(new float[]{0.1f, -0.4f, 0.8f});

    assertEquals(cosine(a, b), dot(a, b), 1e-6);
}

@Test
void zeroVectorIsSafe() {
    float[] z = new float[]{0f, 0f, 0f};
    assertEquals(0.0, cosine(z, new float[]{1f, 0f, 0f}), 1e-9);
}
```

# 10. 生产注意事项

结论先行：度量的生产风险集中在"配置漂移"与"阈值失准"，需通过配置中心与监控固化。

## 10.1 风险清单

| 风险 | 建议 |
|------|------|
| 度量配置漂移 | 配置中心统一管理 |
| 阈值不校准 | 换模型/换库后重新校准 |
| 分数不可解释 | 记录分布，辅助诊断 |
| 混合检索分数不可比 | 用 RRF 融合而非直接加权 |

## 10.2 配置管理

```text
metric = COSINE
normalized = true
threshold = 0.68
model = bge-large-zh-v1.5
```

以上配置应集中存储、版本化，并与索引元数据交叉校验。

## 10.3 监控与告警

| 指标 | 含义 | 异常信号 |
|------|------|----------|
| 分数分布 | 检索健康度 | 分布整体偏移 |
| 空结果率 | 召回质量 | 骤升说明阈值过高 |
| 平均 Top-K 分数 | 质量趋势 | 持续下降 |
| 度量配置校验 | 一致性 | 失败即告警 |

## 10.4 上线检查表

结论先行：上线前逐项核对，确保度量、归一化、阈值与配置完全一致。

```text
[ ] 度量类型已确定并写入配置
[ ] 入库向量已归一化
[ ] 索引与检索度量一致
[ ] 阈值已用标注数据校准
[ ] 返回值为相似度（方向正确）
[ ] 混合检索使用 RRF 融合
[ ] 启动自检覆盖度量校验
```

### 10.4.1 回滚预案

若上线后检索指标异常，回滚到旧配置与旧索引，并保留现场分数分布用于诊断。

# 11. 小结

结论先行：度量选择的核心是"归一化 + 一致性 + 校准"，三者到位，检索结果才可信。

## 11.1 核心要点

- 三种度量：余弦、点积、欧氏；归一化后等价。
- 通用场景选余弦；已归一化可选用点积提速。
- **建索引与检索的度量必须一致**。
- 阈值与模型强相关，需用标注数据校准。
- 不同模型/不同检索器的分数不可直接比较。

## 11.2 决策清单

| 决策 | 建议 |
|------|------|
| 度量 | 默认余弦 |
| 归一化 | 入库统一 |
| 阈值 | 数据校准 |
| 融合 | 用 RRF |
| 校验 | 启动自检 |
