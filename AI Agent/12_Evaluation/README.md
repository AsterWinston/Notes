# 1. 模块定位

"没有评测，就没有优化。" 本模块讲如何用数据衡量 LLM / RAG / Agent 的质量，覆盖指标、数据集、LLM-as-Judge、Agent 轨迹评测与回归测试。

评测不是发版前的一次性动作，而是贯穿「设计—开发—上线—迭代」的持续能力：先定义可度量的标准，再谈优化。

## 1.1 一句话定位

用数据而非感觉判断 LLM 应用的好坏，让每次改动都可度量、可对比、可回归。

## 1.2 覆盖范围

- 评测体系与指标设计。
- 评测集构建、标注与维护。
- LLM-as-Judge 与偏差校准。
- RAG、Agent、轨迹、工具调用评测。
- 基准、回归测试、线上 A/B 实验。
- 评测框架与 Java 侧集成方案。

## 1.3 不覆盖的范围

| 不覆盖 | 去处 |
|--------|------|
| 可观测性采集 | `13_Observability` |
| RAG 实现细节 | `5_RAG` |

| 安全攻防细节 | `14_Safety` |

# 6. 关键知识点速览

## 6.1 核心结论

- 评测先于优化：先能度量，才能改进。
- LLM-as-Judge 便宜高效，但要防位置偏差与自偏好。
- Agent 评测要看"结果"更要看"过程（轨迹）"。
- 评测集要版本化，防止"对测试集过拟合"。
- 回归测试是 Prompt/模型变更的安全网。

## 6.2 检查清单

| 检查项 | 标准 |
|--------|------|
| 有评测集 | 版本化、覆盖边界 |
| 有指标 | 可度量、可对比 |
| Judge 校准 | 与人工一致率达标 |
| 接 CI | 有门禁与基线 |
| 线上验证 | 有 A/B 或灰度 |
| 失败归因 | 保留每条样本详情 |
| 可复现 | 固定种子与版本号 |

## 6.3 常见误区

| 误区 | 纠正 |
|------|------|
| 只看总分 | 保留失败详情用于归因 |
| 评测集过小 | 50~200 条起步 |
| 用感觉代替数据 | 先定义可度量标准 |
| 上线后才想评测 | 评测前置到开发阶段 |
| 离线好就上线 | 必须经线上 A/B 验证 |
| 指标越多越好 | 预设一个主指标 |
| 只跑一次就下结论 | 多次运行取均值 |

## 6.4 一句话记忆

- 没有评测，就没有优化。
- 先定标准，再谈改进。
- 结果与过程都要看。
- 离线防退化，线上验效果。
