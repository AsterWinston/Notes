# 1. 预处理的目标

## 1.1 结论先行

预处理（preprocessing）的唯一目标：把原始文本（raw text）转成"适合模型训练或检索"的规范形式。它不是可有可无的附属步骤，而是决定下游效果上限的第一道工序。

## 1.2 原理：四个核心目标

| 目标 | 说明 | 典型手段 |
|------|------|----------|
| 去噪 | 移除无关内容 | 去 HTML、URL、页眉页脚 |
| 归一化 | 统一格式 | 小写、Unicode、全半角 |
| 截断/填充 | 统一长度 | truncate / pad |
| 分词 | 切成 token | 按词、按字、按子词 |

四个目标之间不是孤立的：清洗去掉噪声后，归一化才能稳定生效；归一化统一了字符形式，分词器（tokenizer）的词汇表命中率才会高。

## 1.3 公式/图示：预处理流水线

```
原始文本
   │
   ▼
[清洗 clean] ── 去 HTML / URL / 控制字符
   │
   ▼
[归一化 normalize] ── 小写 / NFKC / 全半角
   │
   ▼
[分句 / 分块] ── sentence / chunk
   │
   ▼
[分词 tokenize] ── token id 序列
   │
   ▼
[截断/填充] ── 定长张量
   │
   ▼
送入模型 / 建索引
```

## 1.4 边界与坑

| 坑 | 后果 | 规避 |
|----|------|------|
| 清洗规则过激 | 把语义内容一起删掉 | 保留原文副本，可回溯 |
| 索引与查询规则不同 | 召回率骤降 | 抽成同一个函数 |
| 对中文直接套英文规则 | 分词错误 | 中文单独处理 |
| 忽略编码 | 乱码、字符丢失 | 全程 UTF-8 |
| 无版本管理 | 无法定位回归 | 规则版本化 |

## 1.5 要点

- 预处理 = 去噪 + 归一化 + 截断填充 + 分词。
- 目标是"规范化"，不是"美化"。
- 索引侧与查询侧必须共用同一套预处理。

# 2. 清洗

## 2.1 结论先行

清洗（cleaning）是移除对任务无贡献的字符与片段。核心原则：**只删确定无用的，不确定的保留**。

## 2.2 原理：噪声从哪里来

### 2.2.1 结构化噪声

来自网页/文档的结构残留：HTML 标签、Markdown 标记、CSS/JS 片段、表格线、页眉页脚、导航栏。这类噪声有固定模式，适合用正则或解析器处理。

### 2.2.2 非结构化噪声

来自采集或排版：多余空白、重复标点、控制字符、零宽字符、乱码字节、OCR 错误。这类噪声没有固定模式，需要归一化与启发式规则配合。

### 2.2.3 OCR 与扫描噪声

扫描件（scanned document）经 OCR 后常出现形近字错误、断行错误与多余空格。这类噪声无法靠单一正则解决，通常需要：

- 保留 OCR 置信度（confidence），低置信度片段标记待人工复核。
- 用词典或语言模型做后校验。
- 对断行做重新拼接（de-hyphenation）。

## 2.3 公式/图示：清洗函数

```python
import re

def clean_text(text):
    text = re.sub(r'<[^>]+>', '', text)              # 移除 HTML 标签
    text = re.sub(r'http\S+', '', text)              # 移除 URL
    text = re.sub(r'\s+', ' ', text)                 # 合并空白
    text = re.sub(r'[\u0000-\u001F]', '', text)      # 移除控制字符
    return text.strip()
```

| 噪声 | 处理 |
|------|------|
| HTML 标签 | 正则移除 |
| URL/邮箱 | 移除或替换 |
| 多余空白 | 合并 |
| 控制字符 | 移除 |
| 页眉页脚 | 按模式移除 |

## 2.4 边界与坑

| 坑 | 说明 |
|----|------|
| 正则 `.*` 贪婪匹配 | 可能跨行误删整段内容 |
| 删 URL 后语义断裂 | 可替换为占位符而非直接删 |
| 控制字符含 `\n` | 若先合并空白会丢失段落结构 |
| HTML 用正则解析 | 嵌套标签下不可靠，建议用解析器 |

## 2.5 要点

- 清洗优先用解析器处理结构化内容，正则兜底。
- 不确定是否无用的片段，保留或替换占位符。
- 清洗后应保留段落边界信息。

# 3. 归一化

## 3.1 结论先行

归一化（normalization）是把"写法不同但语义相同"的文本映射到同一形式，使匹配、检索、统计不再受书写差异干扰。

## 3.2 原理：归一化为什么有效

同一个词在真实语料里有多种写法：`Apple` / `apple` / `Ａｐｐｌｅ`。若不归一化，它们在词表里就是三个不同的 token，导致统计被稀释、召回被漏掉。归一化等价于给这些写法建立"同义类"。

## 3.3 公式/图示：Unicode 归一化与全半角

### 3.3.1 NFC / NFD / NFKC / NFKD

| 形式 | 含义 | 典型用途 |
|------|------|----------|
| NFC | 组合字符合成 | 通用文本存储 |
| NFD | 分解为基字符+组合符 | 音标处理 |
| NFKC | 兼容分解后再合成 | 检索归一化 |
| NFKD | 兼容分解 | 最激进 |

其中 C = Composition（合成），D = Decomposition（分解），K = Compatibility（兼容）。

### 3.3.2 全角半角

全角字符（full-width）与半角字符（half-width）编码区间不同，例如全角 `Ａ` 是 `U+FF21`，半角 `A` 是 `U+0041`。NFKC 会自动把全角转为半角。

```python
import unicodedata

def normalize(text):
    text = text.lower()                          # 统一小写（英文）
    text = unicodedata.normalize('NFKC', text)   # Unicode 归一化
    text = text.replace('，', ',')                # 全角转半角
    text = text.replace('。', '.')
    return text
```

| 归一化 | 说明 |
|--------|------|
| 大小写 | 英文统一小写 |
| Unicode | NFKC 归一化 |
| 全角/半角 | 统一为半角 |
| 同义词 | 映射到标准形式 |

> 归一化对 BM25 检索很重要（"Apple" 与 "apple" 应匹配）。

### 3.3.3 其他常见归一化

| 类型 | 例子 | 处理 |
|------|------|------|
| 数字 | 3 / 三 / Ⅲ | 统一为阿拉伯数字 |
| 日期 | 2024-1-1 / 2024年1月1日 | 统一为标准格式 |
| 空白 | 全角空格 / 制表符 | 统一为半角空格 |
| 同义 | 电脑 / 计算机 | 映射到标准词 |

```python
def fold(text):
    text = unicodedata.normalize('NFKC', text)
    text = text.replace('\u3000', ' ')       # 全角空格
    text = re.sub(r'[ \t]+', ' ', text)       # 合并空白
    return text.strip()
```

归一化的顺序建议：先 Unicode 归一化，再大小写，再标点/空白，最后同义词映射。顺序颠倒会让规则相互抵消。

## 3.4 边界与坑

| 坑 | 说明 |
|----|------|
| 盲目小写 | 专有名词、代码、化学式会被破坏 |
| NFKC 过度合并 | 某些数学符号被改写，需按场景选 |
| 索引/查询不一致 | 一边归一化一边没有，等于没做 |
| 中文标点直接删 | 会丢失句边界，应转半角而非删 |

## 3.5 要点

- 归一化让"同义写法"命中同一个 token。
- NFKC 是检索场景的常用默认。
- 大小写是否统一要结合任务判断。

# 4. 中文特殊处理

## 4.1 结论先行

中文没有空格分词，且存在繁体/简体、全角/半角两套不一致，必须在预处理阶段显式处理。

## 4.2 原理：中文的三种不一致

| 不一致 | 例子 | 处理 |
|--------|------|------|
| 繁简 | 資料 / 资料 | OpenCC 转换 |
| 全半角 | ，/ , | 全角转半角 |
| 无空格 | 自然语言处理 | 分词器切分 |

繁体与简体若不做映射，同一概念会被编码成完全不同的 token，检索直接失效。

## 4.3 公式/图示：繁简与全半角转换

```python
from opencc import OpenCC
cc = OpenCC('t2s')
simplified = cc.convert(traditional)

def to_halfwidth(text):
    result = []
    for char in text:
        code = ord(char)
        if code == 0x3000:
            code = 0x20
        elif 0xFF01 <= code <= 0xFF5E:
            code -= 0xFEE0
        result.append(chr(code))
    return ''.join(result)
```

全角区间 `U+FF01..U+FF5E` 与半角 `U+0021..U+007E` 一一对应，偏移量为 `0xFEE0`；全角空格 `U+3000` 映射到半角空格 `U+0020`。

## 4.4 边界与坑

| 坑 | 说明 |
|----|------|
| 简繁双向转换有歧义 | 部分字一对多，需上下文模型 |
| 全角转半角误伤 | 全角标点在中文里是正常书写，转换需谨慎 |
| 中文数字混排 | "3个" vs "三个" 需决定是否统一 |
| 直接按字分词 | 会丢失词边界语义 |

## 4.5 要点

- 中文预处理三件事：繁简统一、全半角统一、正确分词。
- 简繁转换优先使用成熟库（OpenCC）。
- 全半角转换要区分"检索归一化"与"显示保留"。

# 5. 截断与填充

## 5.1 结论先行

神经网络需要定长张量，而文本长度天然不一。截断（truncation）与填充（padding）就是把变长序列对齐到固定长度的手段。

## 5.2 原理：为什么需要定长

批处理（batching）要求同一批次内所有样本形状一致，否则无法堆叠成矩阵。截断处理超长样本，填充处理过短样本，二者共同保证形状统一。

## 5.3 公式/图示：pad / truncate

```
max_len = 6
tokens = [a, b, c, d, e, f, g]  → 截断 → [a, b, c, d, e, f]
tokens = [a, b, c]              → 填充 → [a, b, c, PAD, PAD, PAD]
```

```python
def pad_or_truncate(tokens, max_len, pad_id=0):
    if len(tokens) > max_len:
        return tokens[:max_len]           # 截断
    return tokens + [pad_id] * (max_len - len(tokens))  # 填充
```

| 操作 | 说明 |
|------|------|
| 截断 | 超长部分丢弃 |
| 填充 | 短序列补 PAD |

> 现代 LLM 用**动态长度**（不填充），只做截断。

## 5.4 边界与坑

| 坑 | 说明 |
|----|------|
| 从尾部硬截断 | 丢失句尾关键信息，应保留头尾 |
| PAD 参与注意力 | 需用 attention mask 屏蔽 |
| 固定长度过大 | 显存浪费，短样本大量填充 |
| 截断不做提示 | 用户不知内容被丢，应显式提示 |

## 5.5 要点

- 截断防超长，填充对齐形状。
- 填充位置必须用 mask 屏蔽。
- 长文本优先分块，而非硬截断。

# 6. 文本相似度基础

## 6.1 结论先行

相似度是检索、去重、聚类的基础度量。没有一种度量放之四海皆准，要按"字符级 / 集合级 / 向量级 / 词频级"选择。

## 6.2 原理：四类相似度

| 方法 | 说明 | 适用 |
|------|------|------|
| 编辑距离 | 最少编辑次数 | 拼写检查 |
| Jaccard | 集合交并比 | 短文本 |
| 余弦相似度 | 向量夹角 | 语义相似 |
| BM25 | 词频加权 | 检索 |

### 6.2.1 编辑距离（Levenshtein Distance）

衡量把一个字符串改成另一个所需的最少单字符编辑次数（增、删、改）。适合拼写纠错、近似匹配。

### 6.2.2 Jaccard 相似度

以词集合的交集除以并集，忽略词序与频次，适合短文本、集合型去重。

### 6.2.3 余弦相似度

在向量空间里度量夹角，值域 `[-1, 1]`（非负向量为 `[0, 1]`），是句向量检索的标准度量。

### 6.2.4 BM25

在 TF-IDF 基础上引入词频饱和与文档长度归一，是稀疏检索（sparse retrieval）的经典排序函数。

## 6.3 公式/图示

```
编辑距离：min(增, 删, 改) 次数
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
余弦相似度 = (A · B) / (‖A‖ · ‖B‖)
BM25(q, d) = Σ IDF(t) · f(t,d)(k1+1)
             ────────────────────────
             f(t,d) + k1(1 - b + b·|d|/avgdl)
```

其中 `f(t,d)` 是词 `t` 在文档 `d` 中的频次，`|d|` 是文档长度，`avgdl` 是平均文档长度，`k1`、`b` 是超参数（常用 `k1≈1.2`、`b≈0.75`）。

```python
def jaccard(a, b):
    set_a, set_b = set(a.split()), set(b.split())
    return len(set_a & set_b) / len(set_a | set_b)
```

## 6.4 边界与坑

| 坑 | 说明 |
|----|------|
| 用编辑距离做长文本 | 复杂度 O(n·m)，且语义无关 |
| 余弦相似度不分词 | 必须先得到向量 |
| Jaccard 忽略词序 | "猫追狗" 与 "狗追猫" 判为相同 |
| BM25 对同义不敏感 | 词形不同即不匹配，需归一化 |

## 6.5 要点

- 字符级用编辑距离，集合级用 Jaccard。
- 语义级用余弦，检索排序用 BM25。
- 稀疏度量依赖归一化，稠密度量依赖向量质量。

# 7. 去重

## 7.1 结论先行

去重（deduplication）是投入产出比最高的预处理之一：它同时降低向量化成本、索引体积与检索噪声。

## 7.2 原理：去重的三个层次

| 层次 | 判据 | 手段 |
|------|------|------|
| 精确去重 | 完全相等 | 哈希（hash） |
| 近似去重 | 相似度阈值 | MinHash / SimHash |
| 语义去重 | 向量距离 | 句向量近邻 |

精确去重先做，成本最低；近似与语义去重成本更高，用于处理改写与近义。

## 7.3 公式/图示：去重代码

```python
def deduplicate(texts, threshold=0.9):
    unique = []
    for text in texts:
        # 与已有文本比较相似度
        if not any(similarity(text, u) > threshold for u in unique):
            unique.append(text)
    return unique
```

上述实现是 `O(n²)` 的朴素做法，仅适合小规模；大规模应先按哈希分桶，再在桶内比较。

### 7.3.1 精确去重的哈希实现

```python
def exact_dedup(texts):
    seen = set()
    result = []
    for text in texts:
        h = hashlib.md5(text.encode('utf-8')).hexdigest()
        if h not in seen:
            seen.add(h)
            result.append(text)
    return result
```

精确去重是 `O(n)`，应作为去重的第一步无条件执行。

## 7.4 边界与坑

| 坑 | 说明 |
|----|------|
| 阈值过高 | 漏掉近重复 |
| 阈值过低 | 误删不同内容 |
| 全量两两比较 | `O(n²)` 不可扩展 |
| 去重顺序随机 | 保留哪一条不确定，需定策略 |

## 7.5 要点

- 去重显著降低向量化成本与检索噪声。
- 先用哈希精确去重，再考虑近似/语义去重。
- 保留策略（取最新/最长）要明确。

# 8. 分句

## 8.1 结论先行

分句（sentence splitting）把长文本切成句子级单元，是分块（chunking）、句子窗口检索与摘要的前提。

## 8.2 原理：分句的用途

- 句子窗口检索：命中一句后扩展上下文。
- 摘要：以句为单位抽取或生成。
- 逐句分析：情感、实体、标注。
- 分块：句子是天然的语义边界。

### 8.2.1 从分句到分块

分块（chunking）策略常见三种：

| 策略 | 边界 | 特点 |
|------|------|------|
| 固定长度 | 按 token 数 | 简单，可能切断语义 |
| 句子聚合 | 句子边界 | 语义完整，长度不均 |
| 递归分割 | 段落→句子→字符 | 兼顾结构与长度 |

推荐"句子聚合 + 重叠窗口（overlap）"：以句子为单位拼到接近上限，相邻块保留若干句重叠，避免边界信息丢失。

## 8.3 公式/图示：分句实现

```python
import re

def split_sentences(text):
    # 中文分句
    sentences = re.split(r'(?<=[。！？.!?])\s*', text)
    return [s.strip() for s in sentences if s.strip()]
```

```
输入： "今天下雨了。我们没出门！你还好吗？"
输出： ["今天下雨了。", "我们没出门！", "你还好吗？"]
```

用途：句子窗口检索、摘要、逐句分析。

## 8.4 边界与坑

| 坑 | 说明 |
|----|------|
| 省略号/小数点误切 | `3.14`、`等等...` 会被切碎 |
| 英文缩写 | `Mr.`、`e.g.` 误判句末 |
| 无标点长句 | 需设最大长度兜底 |
| 引号跨句 | 分句后引号不成对 |

## 8.5 要点

- 分句是分块与检索的语义边界基础。
- 正则分句需处理缩写、小数点、省略号。
- 无标点文本要有长度兜底切分。

# 9. 生产注意事项

## 9.1 结论先行

预处理是"一次写好、处处复用"的组件。生产环境最大的风险不是算法，而是**规则不一致**与**静默丢信息**。

## 9.2 原理：风险与建议

| 风险 | 建议 |
|------|------|
| 过度清洗 | 可能丢失有用信息 |
| 归一化不一致 | 索引与查询用同一套 |
| 截断丢信息 | 用分块而非硬截断 |
| 未去重 | 成本与噪声 |
| 编码问题 | 统一 UTF-8 |

## 9.3 公式/图示：索引/查询一致性

```
        ┌──────────────┐
文档 ──▶│ preprocess() │──▶ 建索引
        └──────────────┘
        ┌──────────────┐
查询 ──▶│ preprocess() │──▶ 检索
        └──────────────┘
        ↑ 必须是同一个函数（同一版本）
```

### 9.3.1 上线前检查清单

| 检查项 | 通过标准 |
|--------|----------|
| 编码 | 全程 UTF-8，无 BOM 混入 |
| 规则版本 | 索引与查询同版本号 |
| 原文留存 | 可回溯原始文本 |
| 去重 | 精确去重已执行 |
| 长度策略 | 分块优先于硬截断 |
| 监控 | 记录清洗前后长度分布 |

## 9.4 边界与坑

| 坑 | 说明 |
|----|------|
| 规则版本漂移 | 查询侧升级而索引侧未重建 |
| 无原文留存 | 无法回溯与调试 |
| 编码不统一 | 混合编码导致乱码 |
| 日志缺失 | 出问题无法定位 |

## 9.5 要点

- 预处理规则要版本化，索引与查询同版本。
- 保留原文，可回溯、可重建。
- 全程 UTF-8，避免混合编码。

# 10. 小结

## 10.1 关键结论

- 预处理：清洗、归一化、截断填充、分词。
- 归一化对 BM25 检索很重要（大小写、全半角、繁简）。
- 中文需特殊处理（繁简、全半角）。
- 去重能降低成本与噪声。
- 索引与查询必须用同一套预处理。

## 10.2 一句话回顾

预处理的核心是"规范化"，所有规则都要在索引侧与查询侧保持一致并版本化。
