# 1. 什么是 NLP

**结论先行**：自然语言处理（Natural Language Processing，NLP）是让计算机理解与生成人类语言的学科，它既是一组任务，也是一套方法体系。

## 1.1 定义与目标

### 1.1.1 形式化定义

NLP 研究的核心是把语言符号序列映射到某种目标表示：

```
输入：符号序列  x = (x_1, x_2, ..., x_n)
输出：标签 y / 结构树 T / 另一段序列 y = (y_1, ..., y_m)
```

- 当输出是标签时，是分类任务（如情感分析）。
- 当输出是结构时，是句法分析任务（如依存树）。
- 当输出是序列时，是生成任务（如翻译、摘要）。

### 1.1.2 与相关学科的关系

| 学科 | 关注点 | 与 NLP 的关系 |
|------|--------|----------------|
| 语言学 | 语言规律 | 提供先验知识与评测标准 |
| 机器学习 | 从数据中学习 | 提供建模与优化方法 |
| 统计学 | 概率分布 | 提供语言建模的理论基础 |
| 信息论 | 信息度量 | 提供困惑度等评价指标 |

**边界与坑**：NLP 不等于"让模型懂语言"，而是"让模型在语言任务上表现良好"，二者并不等价。

**要点**：NLP 是任务集合 + 方法体系；输出形态决定任务类型。

### 1.1.3 NLP 与语言模型的关系

**结论先行**：语言模型（Language Model，LM）是 NLP 的核心子问题，它估计一段文本出现的概率。

```
语言模型： P(w_1, w_2, ..., w_n)
链式分解： P(w_1..w_n) = P(w_1) · P(w_2|w_1) · ... · P(w_n|w_1..w_{n-1})
```

- 语言模型回答"这句话有多合理"。
- 生成任务本质上是在语言模型上做采样或搜索。
- 理解任务也常借助语言模型预训练得到的表示。

**边界与坑**：概率高不等于语义正确，语言模型只学到统计规律，不保证事实性。

**要点**：语言模型是生成与预训练的共同基础。

## 1.2 语言的层次

**结论先行**：语言可从词法、句法、语义、语用四个层次理解，层次越高越依赖语境。

### 1.2.1 词法层

| 层次 | 任务 | 示例 |
|------|------|------|
| 词法 | 分词、词性标注 | 我/爱/北京 → 我(r) 爱(v) 北京(ns) |

词法层处理最小语言单位，是所有上层任务的基础。

### 1.2.2 句法层

句法层关心词与词之间的结构关系，典型任务是句法分析与依存分析。

```
我 爱 北京
└──┴──┘
   └─ 主谓宾结构：我(主语) 爱(谓语) 北京(宾语)
```

### 1.2.3 语义层与语用层

- 语义层：语义理解、指代消解。例："小明迟到了，因为他睡过头"，"他"指小明。
- 语用层：意图识别、情感分析。例："你可真行"既可能是称赞，也可能是讽刺。

| 层次 | 任务 | 依赖 |
|------|------|------|
| 词法 | 分词、词性标注 | 局部 |
| 句法 | 句法分析、依存分析 | 句子内部 |
| 语义 | 语义理解、指代消解 | 跨句 |
| 语用 | 意图识别、情感分析 | 语境与常识 |

**要点**：层次越高，越需要语境与常识，也越难自动处理。

## 1.3 为什么 NLP 难

**结论先行**：NLP 的困难源于语言的歧义性、稀疏性与组合爆炸。

### 1.3.1 歧义性

同一字符串在不同层级都可能产生多种解释：

```
词法歧义： "研究生命起源" → 研究生/命/起源 或 研究/生命/起源
句法歧义： "咬死了猎人的狗" → 狗被咬死 或 狗咬死了猎人
语义歧义： "苹果" → 水果 或 公司
语用歧义： "外面下雨了" → 陈述天气 或 委婉拒绝
```

### 1.3.2 稀疏性与组合爆炸

- 稀疏性：自然语言词表巨大，很多词组合在语料中从未出现。
- 组合爆炸：长度为 n 的序列，可能的结构数量随 n 指数增长。

```
语言模型需要估计： P(w_1, w_2, ..., w_n)
朴素做法需要枚举所有组合，参数数量指数级
→ 需要链式分解与参数共享（见后续语言模型部分）
```

**要点**：歧义需要上下文消解，稀疏性需要泛化能力。

### 1.3.3 分布假设

**结论先行**：分布假设（Distributional Hypothesis）是统计 NLP 的基石——上下文相似的词，语义也相似。

```
"你吃了一个苹果"
"你吃了一个香蕉"
→ 苹果与香蕉出现在相似上下文，故语义相近
```

```
用共现统计刻画语义： word ≈ 其上下文分布
这就是 Word2Vec / GloVe / 预训练模型的思想源头
```

**边界与坑**：分布假设会引入反义与功能词的干扰，"好"与"坏"上下文相似却语义相反。

**要点**：分布假设把"语义"转化为"上下文统计"，是词向量的理论依据。

# 2. 任务谱系

**结论先行**：NLP 任务可归为理解类、生成类、序列标注三大类，且越来越多任务被统一为序列到序列。

## 2.1 理解类任务

### 2.1.1 文本分类

```
输入：一段文本
输出：一个类别标签
示例：情感分析（正面/负面）、主题分类（体育/财经）
```

### 2.1.2 序列标注

对输入序列的每个位置打标签：

| 任务 | 标签粒度 | 示例 |
|------|----------|------|
| 分词 | 字 | 我/爱/北京 |
| 词性标注 | 词 | 我(r) 爱(v) |
| 命名实体识别 | 字/词 | 北京(B-LOC) |

### 2.1.3 句子对任务

| 任务 | 输出 | 示例 |
|------|------|------|
| 自然语言推理 | 蕴含/矛盾/中立 | 前提-假设关系 |
| 语义相似度 | 分数 | 两句话有多像 |
| 问答 | 答案片段或文本 | 抽取式 / 生成式 |

**要点**：理解类任务的核心是把文本编码为可判别或可匹配的表示。

## 2.2 生成类任务

### 2.2.1 机器翻译

```
源语言序列 → 目标语言序列
"The cat sat." → "猫坐下了。"
```

### 2.2.2 摘要与对话

| 任务 | 特点 |
|------|------|
| 抽取式摘要 | 从原文挑句子 |
| 生成式摘要 | 重写为新句子 |
| 对话生成 | 多轮、需保持一致性 |

### 2.2.3 文本改写

改写包括润色、简化、风格迁移等，强调"保留语义、改变形式"。

**要点**：生成类任务输出空间巨大，评价困难，常用 BLEU、ROUGE 等指标。

## 2.3 任务之间的统一视角

### 2.3.1 统一为序列到序列

```
文本分类：   文本 → 类别词
翻译：       文本 → 文本
问答：       问题+文档 → 答案
摘要：       长文 → 短文
```

只要把不同任务的输入输出都表示为序列，就可用同一个模型框架处理。

### 2.3.2 提示（Prompt）统一范式

LLM 时代，任务差异被转化为提示模板差异，模型本身不变。

**要点**：任务统一是 LLM 通用能力的结构基础。

# 3. 发展历程

**结论先行**：NLP 发展经历规则、统计、深度学习、预训练、大模型五个阶段，总体趋势是人工规则减少、数据驱动增强。

## 3.1 规则时代

| 方面 | 说明 |
|------|------|
| 时间 | 1950s~1980s |
| 方法 | 人工编写规则、专家系统 |
| 代表 | 基于文法的翻译系统 |
| 局限 | 规则难以覆盖语言多样性 |

## 3.2 统计时代

### 3.2.1 特征工程

统计方法依赖人工设计的特征：

```
特征示例：当前词、前后词、词性、是否大写、前后缀
模型示例：HMM、CRF、最大熵、SVM
```

### 3.2.2 概率语言模型

```
链式法则： P(w_1..w_n) = Π P(w_i | w_1..w_{i-1})
N-gram 近似： P(w_i | w_1..w_{i-1}) ≈ P(w_i | w_{i-n+1}..w_{i-1})
```

**边界与坑**：N-gram 面临数据稀疏问题，需要平滑（如 Kneser-Ney）。

## 3.3 深度学习时代

### 3.3.1 分布式表示

2013 年前后，词向量（Word2Vec）让词有了稠密语义表示，特征工程逐渐被表示学习取代。

### 3.3.2 序列建模

| 模型 | 特点 |
|------|------|
| RNN | 处理变长序列，存在梯度问题 |
| LSTM/GRU | 门控机制缓解长依赖 |
| CNN | 并行、局部特征 |
| Transformer | 注意力机制，并行且长依赖（2017） |

### 3.3.3 从序列到注意力

```
RNN：   h_t = f(h_{t-1}, x_t)     串行、难并行、长依赖衰减
CNN：   局部卷积堆叠              并行、感受野有限
注意力： h_t 直接看所有位置         并行、长依赖、可解释
```

```
注意力权重： softmax(QK^T / sqrt(d)) · V
```

**边界与坑**：注意力计算量与序列长度平方成正比，长文本需要稀疏或分块优化。

**要点**：Transformer 是预训练与大模型时代的硬件。

## 3.4 预训练与大模型时代

### 3.4.1 预训练-微调范式

```
第一步：在大规模无标注语料上预训练（学通用表示）
第二步：在下游任务小数据上微调
```

### 3.4.2 规模化

| 阶段 | 时间 | 特点 |
|------|------|------|
| 预训练 | 2018~2020 | BERT、GPT |
| 大模型 | 2020~ | GPT-3+、LLM |

**要点**：范式演进的核心是从"每个任务造特征"到"一个模型学通用表示"。

# 4. 从 Word2Vec 到 BERT 到 GPT

**结论先行**：静态词向量解决"词有语义"，BERT 解决"词随语境变化"，GPT 解决"统一生成"，LLM 解决"规模化通用"。

## 4.1 静态词向量

```
Word2Vec（2013）：静态词向量，一词一向量
  优点：低维稠密、捕捉语义关系
  缺点：无法区分一词多义
```

## 4.2 上下文相关表示

### 4.2.1 BERT

```
BERT（2018）：双向 Transformer 编码器
  预训练任务：掩码语言模型（MLM）+ 下一句预测（NSP）
  擅长：理解类任务（分类、抽取、匹配）
```

### 4.2.2 GPT

```
GPT（2018+）：自回归 Transformer 解码器
  预训练任务：预测下一个 token
  擅长：生成类任务（续写、对话、翻译）
```

## 4.3 三方对比

| 维度 | Word2Vec | BERT | GPT |
|------|----------|------|-----|
| 表示 | 静态 | 上下文相关 | 上下文相关 |
| 方向 | - | 双向 | 单向（左到右） |
| 任务 | 词向量 | 理解 | 生成 |
| 输出 | 词向量 | 编码表示 | 概率分布 |

## 4.4 LLM 的统一

```
LLM（2020+）：规模化自回归模型，用提示统一各类任务
  涌现能力：少样本学习、思维链、指令跟随
```

**边界与坑**：BERT 类模型不擅长开放式生成，GPT 类模型在抽取式任务上不一定优于 BERT 微调。

**要点**：理解与生成是两条主线，现代 LLM 以生成为主、兼顾理解。

## 4.5 训练目标对比

**结论先行**：模型差异的本质是预训练目标不同——掩码预测偏向理解，自回归预测偏向生成。

```
MLM（BERT）：随机遮住部分 token，用双向上下文预测
  "我 [MASK] 北京" → 预测"爱"
  优点：双向信息  缺点：训练与生成不一致

自回归（GPT）：用左侧上下文预测下一个 token
  "我爱" → 预测"北京"
  优点：可直接生成  缺点：单向信息
```

| 目标 | 可见上下文 | 适合 |
|------|------------|------|
| MLM | 双向 | 理解、抽取 |
| 自回归 | 单向（左） | 生成、对话 |
| 前缀 LM | 双向（前缀内） | 条件生成 |

**要点**：目标决定能力边界，选型要先看任务是理解还是生成。

# 5. 关键概念

**结论先行**：Token、Embedding、词表、分词、上下文相关是贯穿本模块的五个基础概念。

## 5.1 Token 与词表

| 概念 | 说明 |
|------|------|
| Token | 模型处理的最小单位，可以是字、词或子词 |
| 词表 | 所有 token 的集合，大小有限 |
| 分词 | 把文本切成 token 的过程 |

```
文本 → 分词 → token 序列 → 查表 → ID 序列 → 模型
```

## 5.2 Embedding

### 5.2.1 定义

Embedding（嵌入）是把离散符号映射为连续向量的函数：

```
embed: token_id → R^d
"猫" → [0.2, -0.5, 0.8, ...]   （d 通常 256~4096）
```

### 5.2.2 词向量与句向量

| 类型 | 粒度 | 用途 |
|------|------|------|
| 词向量 | 词/token | 语义相似、特征 |
| 句向量 | 句/段 | 语义检索、聚类 |

## 5.3 上下文相关

同一词在不同语境得到不同向量：

```
"我去银行取钱"  → 银行 = 金融机构
"河边的银行"    → 银行 = 河岸
```

**要点**：Token 决定输入形式，Embedding 决定语义表示，上下文相关决定表示质量。

### 5.3.1 上下文相关的直觉

```
静态向量： 向量(银行) 与位置无关
动态向量： 向量(银行 | 我去银行取钱) ≠ 向量(银行 | 河边的银行)

实现方式：让 token 向量由整句的加权组合决定
  h_i = Σ_j α_ij · v_j     （α 由注意力给出）
```

**边界与坑**：动态表示提升语义质量，但推理成本更高、缓存更难。

**要点**：上下文相关 = 表示随句子变化，是质量与成本的权衡。

# 6. NLP 与 LLM 的关系

**结论先行**：NLP 是任务域，LLM 是解决这些任务的主流方法，两者是"问题"与"工具"的关系。

## 6.1 任务域与方法

```
NLP 是任务域，LLM 是解决这些任务的主流方法
```

## 6.2 范式对比

| 传统做法 | LLM 做法 |
|----------|----------|
| 为每个任务训练专用模型 | 一个模型 + 提示 |
| 需要标注数据 | 少样本/零样本 |
| 特征工程 | 自动学习 |
| 任务专属输出头 | 统一生成文本 |

## 6.3 边界与坑

- LLM 并非万能：结构化抽取、极低延迟场景仍可用小模型。
- 提示不稳定时，微调或规则仍是有效补充。
- 评测方式不同：传统任务看 F1/准确率，LLM 看人工评估与鲁棒性。

**要点**：选择方法要看任务约束（数据量、延迟、成本、可控性）。

# 7. 本模块的重点

**结论先行**：与 Agent 强相关的是分词、词向量、文本预处理与句向量模型。

## 7.1 分词

```
分词（Tokenization）：理解 Token 与成本
  Token 数 → 成本、延迟、上下文占用
```

## 7.2 词向量

```
词向量：理解 Embedding 基础
  One-hot → Word2Vec/GloVe → BERT → 句向量
```

## 7.3 预处理与句向量

| 主题 | 与 Agent 的关系 |
|------|------------------|
| 文本预处理 | 检索与匹配的基础 |
| 句向量模型 | RAG 的 Embedding 模型选型 |

**要点**：本模块为后续 RAG、Agent 记忆与检索打基础。

### 7.3.1 学习路径

```
第一步：理解 Token 与分词（成本、上下文）
第二步：理解 Embedding（语义表示）
第三步：理解句向量与检索（RAG 基础）
第四步：进入语言模型与 Transformer
```

### 7.3.2 与后续章节的衔接

| 本模块 | 后续章节 |
|--------|----------|
| 分词 | Token 计费、上下文管理 |
| 词向量 | 句向量模型选型 |
| 预处理 | 检索与匹配 |

**要点**：先打牢 Token 与 Embedding，再进入模型与 Agent。

# 8. 常见误区

**结论先行**：初学者常把 Token 当字符、把词向量当万能、把 LLM 当传统模型。

## 8.1 概念误区

| 误区 | 纠正 |
|------|------|
| Token 就是字或词 | Token 是子词单位，依分词器而定 |
| 词向量能处理一词多义 | 静态词向量不能，需上下文相关表示 |
| 词表越大越好 | 词表大则 embedding 参数多、稀有词训练不足 |
| BERT 也能随便生成 | 编码器模型不擅长开放式生成 |

### 8.1.1 关于"理解"的误区

```
误区：模型答对了，就说明它"理解"了语言
纠正：答对可能来自记忆、模式匹配或提示泄漏
验证：换措辞、换数据分布、对抗样本，观察是否稳定
```

**边界与坑**：把语言能力等同于推理能力，会在复杂任务上高估模型。

## 8.2 工程误区

| 误区 | 纠正 |
|------|------|
| 用字符数估 Token | 用对应 tokenizer 精确计算 |
| 所有模型共用一个分词器 | 必须匹配模型对应的 tokenizer |
| 忽视特殊 token | 用户输入需清洗，避免注入 |

**要点**：概念要区分粒度与范式，工程要以 tokenizer 为准。

# 9. 小结

- NLP 涵盖理解、生成、序列标注三类任务。
- 语言分词法、句法、语义、语用四个层次，越高越依赖语境。
- 发展：规则 → 统计 → 深度学习 → 预训练 → 大模型。
- Word2Vec 是静态词向量，BERT 擅长理解，GPT 擅长生成，LLM 通用。
- NLP 是任务域，LLM 是主流方法。
- 与 Agent 最相关的是分词、Embedding 与句向量模型。
- 常见误区集中在 Token 粒度、词向量能力与 tokenizer 匹配上。
