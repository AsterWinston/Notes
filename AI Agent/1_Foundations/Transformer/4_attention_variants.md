# 1. 为什么需要变体

**结论先行**：标准多头注意力（Multi-Head Attention，MHA）在长序列与大批量推理时，受限于键值缓存（KV Cache）显存与 O(n²) 计算量，因此衍生出 MQA、GQA、FlashAttention、滑动窗口等一系列变体，分别从"减少 KV 头数""优化计算访存""限制感受野"三个方向突破。

## 1.1 标准 MHA 的瓶颈

```
标准多头注意力（MHA）的问题：
- KV Cache 显存占用大（每个头都要存 K、V）
- 长序列推理慢
- 注意力计算 O(n²)
```

**原理**：自回归推理时，每个注意力头都要缓存历史的键（Key）与值（Value）。头数越多、序列越长，缓存越大，显存迅速被占满，进而限制批大小与上下文长度。

### 1.1.1 推理显存为何重要

KV Cache 需要在生成全程常驻显存，显存不足会直接限制批大小与上下文长度，进而影响吞吐与可用性，这正是注意力变体研究的直接驱动力。

## 1.2 三个优化方向

| 方向 | 代表方法 | 优化目标 |
|------|----------|----------|
| 减少 KV 头数 | MQA、GQA | 降显存 |
| 优化计算访存 | FlashAttention | 提速度、降显存 |
| 限制感受野 | 滑动窗口、稀疏 | 降复杂度 |

## 1.3 复杂度回顾

**公式**：标准注意力的计算与显存：

```
计算量：O(n² · d)
注意力矩阵显存：O(n² · heads)
KV Cache 显存：O(n · heads · d)
```

其中 n 为序列长度，d 为模型维度，heads 为头数。

**边界与坑**：三个瓶颈并非等价，计算量 O(n²) 制约训练与长序列前向，KV Cache 显存 O(n·heads·d) 制约推理并发，优化时需区分场景。

**要点**：

- MHA 三大瓶颈：KV Cache 大、推理慢、O(n²)。
- 三个优化方向：头数、访存、感受野。
- 需按场景选择优化目标。

# 2. MHA / MQA / GQA

**结论先行**：三者区别只在键与值的头数：MHA 每个查询头都有独立 KV，MQA 所有查询头共享一组 KV，GQA 则把查询头分组、每组共享一组 KV，从而在质量与显存间取得平衡。

## 2.1 MHA：多头注意力

**原理**：把模型维度切成多个头，每个头独立做注意力，最后拼接。查询（Query）、键、值头数相同。

```
MHA（多头注意力）：
  Q: 8 头    K: 8 头    V: 8 头
  KV Cache: 大
```

**公式**：对每个头 h：

```
head_h = softmax(Q_h K_hᵀ / √d_k) V_h
MHA(x) = Concat(head_1, ..., head_H) W_O
```

### 2.1.1 多头为何有效

不同头可关注不同模式（如语法、位置、指代），拼接后由输出投影融合，使模型在多个子空间中并行建模。

## 2.2 MQA：多查询注意力

**原理**：所有查询头共享同一组键与值，KV Cache 缩小到头数的倒数。

```
MQA（多查询注意力）：
  Q: 8 头    K: 1 头    V: 1 头
  KV Cache: 小（1/8）
  质量: 略降
```

| 项目 | 说明 |
|------|------|
| 优点 | KV Cache 最小，推理显存最省 |
| 缺点 | 表达能力下降，质量略逊 |
| 适用 | 极致省显存场景 |

## 2.3 GQA：分组查询注意力

**原理**：把查询头分成若干组，每组共享一组 KV，是 MHA 与 MQA 的插值。

```
GQA（分组查询注意力）：
  Q: 8 头    K: 2 组    V: 2 组
  KV Cache: 中（1/4）
  质量: 接近 MHA（推荐）
```

### 2.3.1 分组映射

设查询头数为 H，KV 组数为 G，则每组负责 H/G 个查询头。G = H 时退化为 MHA，G = 1 时退化为 MQA：

```
G = H  → MHA
G = 1  → MQA
1 < G < H → GQA
```

### 2.3.2 代码实现

```python
# GQA：K/V 头数少于 Q 头数
class GroupedQueryAttention(nn.Module):
    def __init__(self, d_model, num_q_heads, num_kv_heads):
        super().__init__()
        self.num_q_heads = num_q_heads
        self.num_kv_heads = num_kv_heads
        self.head_dim = d_model // num_q_heads

        self.Wq = nn.Linear(d_model, num_q_heads * self.head_dim)
        self.Wk = nn.Linear(d_model, num_kv_heads * self.head_dim)
        self.Wv = nn.Linear(d_model, num_kv_heads * self.head_dim)
```

> **GQA 是当前 LLM 的主流选择**（如 LLaMA 2/3、Qwen）。

## 2.4 三者对比

| 类型 | KV 头数 | KV Cache | 质量 |
|------|:-------:|:--------:|:----:|
| MHA | = Q 头数 | 100% | 最好 |
| GQA | Q 的 1/2~1/8 | 12%~50% | 接近 MHA |
| MQA | 1 | ~12% | 略降 |

**边界与坑**：KV 组数必须整除查询头数，否则分组映射不完整；此外 GQA 需要在推理时把 KV 复制到对应查询头，实现需注意广播正确性。

**要点**：

- MHA 质量最好但缓存最大。
- MQA 缓存最小但质量略降。
- GQA 是质量与效率的平衡点。

# 3. FlashAttention

**结论先行**：FlashAttention 通过分块计算与在线 Softmax，避免在显存中物化 n×n 的注意力矩阵，把注意力显存从 O(n²) 降到 O(n)，同时在数值上与标准注意力等价。

## 3.1 标准注意力的显存瓶颈

```
标准注意力的问题：
  需要物化 n×n 的注意力矩阵 → 显存 O(n²)

FlashAttention：
  分块计算 + 不物化完整矩阵 → 显存 O(n)
  利用 GPU 内存层次（SRAM 快、HBM 慢）
```

**原理**：GPU 上显存带宽（HBM）远慢于片上缓存（SRAM）。标准实现反复在 HBM 读写注意力矩阵，既费显存又费带宽；FlashAttention 把计算保持在 SRAM 内完成。

### 3.1.1 为什么带宽是瓶颈

矩阵乘法本身算力充足，但把 n×n 矩阵写入再读出 HBM 的时间往往超过计算时间，因此减少 HBM 访存成为提速的关键。

## 3.2 分块与在线 Softmax

### 3.2.1 内存层次

| 存储 | 容量 | 速度 | 用途 |
|------|------|------|------|
| SRAM | 小（百 KB 级） | 极快 | 分块计算暂存 |
| HBM | 大（数十 GB） | 慢 | 全局显存 |

### 3.2.2 在线 Softmax 推导

**公式**：Softmax 需要全局最大值来数值稳定。在线算法分块处理，边算边更新运行最大值 m 与归一化因子 l：

```
m_new = max(m_old, max(块内分数))
l_new = l_old · exp(m_old - m_new) + Σ exp(块内分数 - m_new)
O_new = (O_old · l_old · exp(m_old - m_new) + Σ exp(块内分数 - m_new) V) / l_new
```

这样无需保存完整注意力矩阵即可得到正确结果。

## 3.3 效果与代价

| 特性 | 说明 |
|------|------|
| 显存 | 从 O(n²) 降到 O(n) |
| 速度 | 更快（减少 HBM 读写） |
| 精度 | 数值等价（非近似） |

```python
# 使用 FlashAttention
from flash_attn import flash_attn_func
output = flash_attn_func(q, k, v, causal=True)
```

> FlashAttention 是**算法与硬件协同优化**的典范。

**边界与坑**：FlashAttention 需要特定 GPU 架构（如 Ampere 及以后）与自定义核函数支持；它优化的是显存与带宽，而非改变 O(n²) 的计算复杂度，超长序列仍受限。

**要点**：

- 不物化 n×n 矩阵，显存 O(n)。
- 在线 Softmax 保证数值正确。
- 是访存优化，非近似，也未改变复杂度。

# 4. 滑动窗口注意力

**结论先行**：滑动窗口注意力（Sliding Window Attention）让每个位置只关注前后 w 个邻居，把复杂度从 O(n²) 降到 O(n·w)，以局部性换取长序列的可处理性。

## 4.1 局部窗口思想

```
标准注意力：每个位置看所有位置 O(n²)
滑动窗口：每个位置只看前后 w 个位置 O(n·w)
```

```
位置:  1 2 3 4 5 6 7 8
窗口=2：
  5 只看 3,4,6,7
```

**原理**：许多任务中，局部上下文足以支撑当前预测，远距离信息可通过多层堆叠间接传播。

## 4.2 感受野与堆叠

**公式**：堆叠 L 层、窗口宽度 w 后，有效感受野约为：

```
感受野 ≈ L × w
```

| 优点 | 缺点 |
|------|------|
| 复杂度降到 O(n·w) | 丢失长距离直接依赖 |
| 适合长文本 | 需多层堆叠扩大感受野 |

### 4.2.1 窗口与因果掩码

生成任务中，滑动窗口通常与因果掩码叠加：每个位置只关注自身左侧 w 个位置，既满足因果性，又限制缓存长度。

## 4.3 混合方案

> 部分模型采用"局部窗口 + 少量全局"的混合方案。

**原理**：每隔若干层插入一层全局注意力（Global Attention），既保留局部高效，又保证全局信息可达，典型如 Longformer、BigBird 的思路。

**边界与坑**：窗口过小则长依赖需极多层才能覆盖；窗口过大则复杂度回升。窗口大小需结合任务的平均依赖距离设定。

**要点**：

- 局部窗口把复杂度降到 O(n·w)。
- 感受野随层数线性增长。
- 局部 + 全局混合是常见折中。

# 5. 其他高效注意力

**结论先行**：除上述方法外，还有稀疏注意力、线性注意力、分块注意力、多查询潜变量等思路，分别从"少算一些位置对""用核函数近似 Softmax""压缩 KV"等角度降低开销。

## 5.1 稀疏注意力

| 方法 | 思路 |
|------|------|
| 稀疏注意力 | 只计算部分位置对 |
| 分块注意力 | 分块计算 |

**原理**：并非所有位置对都同等重要，按固定模式（局部、跨步、随机）或学习到的模式，只保留部分连接，从而降低计算量。

### 5.1.1 固定模式与学习模式

固定模式无需训练、实现简单，如 Longformer 的局部加跨步；学习模式更灵活，但需额外参数与训练开销。

## 5.2 线性注意力

| 方法 | 思路 |
|------|------|
| 线性注意力 | 用核函数近似 softmax |
| 多查询潜变量 | 压缩 KV |

**公式**：线性注意力利用核函数把 Softmax 分解，使计算可结合律重排：

```
softmax(QKᵀ)V ≈ φ(Q) (φ(K)ᵀ V)
```

先算 φ(K)ᵀV（形状 d×d），再乘 φ(Q)，复杂度降为 O(n·d²)。

## 5.3 其他方法

| 方法 | 核心思想 | 代表 |
|------|----------|------|
| 稀疏注意力 | 选择子集连接 | Longformer |
| 线性注意力 | 核函数重排 | Performer |
| 分块注意力 | 块内块间分开算 | Blockwise |
| 多查询潜变量 | 低秩压缩 KV | MLA |

**边界与坑**：近似方法通常在特定任务上有效，但在需要精确长距离检索的场景可能明显掉点；线性注意力虽降复杂度，却可能损失表达力。

**要点**：

- 稀疏与分块降低连接数。
- 线性注意力用核函数重排降复杂度。
- 压缩 KV 用低秩近似省显存。

# 6. KV Cache 优化

**结论先行**：KV Cache 缓存历史键值以避免重复计算，是自回归推理的必备优化；其显存占用可通过减少 KV 头数、量化、分页与窗口限制等手段压缩。

## 6.1 KV Cache 原理

```
推理时缓存历史 K、V，避免重复计算

显存占用 ≈ 2 × L × n_kv_heads × head_dim × seq_len × batch × 精度
```

**原理**：生成第 t 个 Token 时，只需新算该位置的 Q、K、V，历史 K、V 直接复用，使每步复杂度从 O(t²) 降到 O(t)。

## 6.2 显存估算

| 符号 | 含义 |
|------|------|
| 2 | K 与 V 两份 |
| L | 层数 |
| n_kv_heads | KV 头数 |
| head_dim | 每头维度 |
| seq_len | 序列长度 |
| batch | 批大小 |

**公式**：以 7B 模型、32 层、8 个 KV 头、head_dim=128、序列 4096、批 1、FP16 估算，KV Cache 约数 GB 量级，随批与长度线性增长。

### 6.2.1 一个估算示例

```
2 × L × n_kv_heads × head_dim × seq_len × batch × 2 字节
= 2 × 32 × 8 × 128 × 4096 × 1 × 2
≈ 512 MB
```

## 6.3 优化手段

| 优化 | 效果 |
|------|------|
| GQA/MQA | 减少 KV 头数 |
| 量化 KV Cache | 降低精度省显存 |
| PagedAttention | 分页管理，减少碎片 |
| 滑动窗口 | 限制缓存长度 |

### 6.3.1 量化与分页

量化把 KV 从 FP16 降到 INT8/INT4，显存近似减半或更多；分页（PagedAttention）把 KV 切成固定大小的块，按需分配，消除内存碎片并支持前缀共享。

### 6.3.2 窗口与压缩

滑动窗口只保留最近 w 个位置的 KV；多查询潜变量（MLA）等方法则把 KV 压缩到低维潜空间，进一步降低显存。

**边界与坑**：量化可能引入数值误差，影响长序列质量；分页实现复杂，需要定制核函数；窗口限制会丢失超窗历史。

**要点**：

- KV Cache 是推理必备优化。
- 显存随层数、头数、长度、批线性增长。
- 优化手段可组合使用。

# 7. 选择建议

**结论先行**：选择注意力变体应结合任务场景：训练新模型首选 GQA，推理优化叠加 FlashAttention，超长上下文用滑动窗口或稀疏注意力，极致省显存用 MQA。

## 7.1 按场景选择

| 场景 | 推荐 |
|------|------|
| 训练新模型 | GQA |
| 推理优化 | FlashAttention + GQA |
| 超长上下文 | 滑动窗口 / 稀疏注意力 |
| 极致省显存 | MQA |

## 7.2 组合策略

**原理**：这些方法大多正交，可以叠加。例如"GQA + FlashAttention + KV 量化 + PagedAttention"是当前高并发推理服务的常见组合。

```
GQA（减头数）
  + FlashAttention（省显存、提速）
  + KV 量化（再省显存）
  + PagedAttention（减碎片）
  = 高吞吐推理栈
```

### 7.2.1 组合的代价

每一项优化都会引入实现复杂度或数值误差，组合后需要整体评测，确认吞吐提升不以明显掉点为代价。

**边界与坑**：叠加并非越多越好，量化与近似可能累积精度损失，需要以评测集验证质量是否可接受。

**要点**：

- GQA 是训练默认选择。
- FlashAttention 是推理加速标配。
- 方法正交，可组合但需验证精度。

# 8. 常见误区

**结论先行**：关于注意力变体，常见的误解集中在"是否近似""是否损失质量"两方面，澄清有助于正确选型。

## 8.1 关于近似与等价

| 误区 | 澄清 |
|------|------|
| FlashAttention 是近似算法 | 它数值等价，只是重排计算顺序 |
| GQA 一定掉点 | 分组足够时质量接近 MHA |
| 滑动窗口等于稀疏注意力 | 窗口是固定局部模式，稀疏更一般 |

## 8.2 关于质量损失

| 误区 | 澄清 |
|------|------|
| 省显存必然牺牲质量 | FlashAttention 两者兼得 |
| MQA 质量一定不可用 | 在大模型上损失较小 |
| 线性注意力全面优于 MHA | 复杂度低但表达力可能下降 |

**边界与坑**：方法优劣高度依赖模型规模、任务与序列长度，不能脱离具体设置下结论；选型应以实测为准。

**要点**：

- FlashAttention 非近似。
- GQA 质量接近 MHA。
- 选型需实测验证。

# 9. 小结

**结论先行**：注意力变体围绕显存、速度与复杂度三个维度展开，GQA 与 FlashAttention 已成为现代 LLM 的默认组合，长上下文则依赖窗口与稀疏等方案。

## 9.1 核心要点

- MHA 质量最好但 KV Cache 大。
- GQA 是当前主流，兼顾质量与效率。
- FlashAttention 用分块计算降低显存、提升速度。
- 滑动窗口适合长文本，但丢失长距离依赖。
- KV Cache 优化是推理性能的关键。

## 9.2 记忆口诀

```
显存大就减头，MQA 到 GQA
访存慢上 Flash，分块不物化
序列长开窗口，局部加全局
缓存省靠量化，分页减碎片
```

**要点**：

- 三个维度：头数、访存、感受野。
- 两个标配：GQA + FlashAttention。
- 一个关键：KV Cache 优化。
