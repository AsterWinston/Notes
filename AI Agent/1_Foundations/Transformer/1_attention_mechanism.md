# 1. 核心思想

## 1.1 结论先行

**注意力 = 根据相关性加权聚合信息**。它让模型在处理某个位置时，动态地"看向"输入中最相关的部分，而不是一视同仁地处理全部输入。

## 1.2 原理：注意力是什么

### 1.2.1 认知类比

```
人看图片时会聚焦重点区域
注意力机制：让模型聚焦相关的输入部分
```

人看一张照片时不会平均地看每个像素，而是快速扫视、聚焦重点。注意力机制把这个过程数学化：为每个输入分配一个权重，权重越大表示越"关注"。

### 1.2.2 从加权平均到注意力

普通的加权平均，权重是固定的；注意力的加权平均，权重由输入内容动态计算。这就是"动态"二字的关键：权重随输入而变，因此能建模上下文相关的关系。

## 1.3 公式/图示：注意力的抽象形式

```
output = Σ_i  α_i · value_i
α_i   = 归一化的相关度（Σ α_i = 1）
```

```
       输入序列
          │
          ▼
   ┌──────────────┐
   │ 计算相关度权重 │
   └──────────────┘
          │
          ▼
   ┌──────────────┐
   │  加权聚合值   │
   └──────────────┘
          │
          ▼
        输出
```

| 要素 | 作用 |
|------|------|
| 相关度 | 决定关注谁 |
| 权重归一化 | 保证加权平均 |
| 值聚合 | 产生输出 |

## 1.4 边界与坑

| 坑 | 说明 |
|----|------|
| 把注意力当"解释" | 权重高不等于因果重要 |
| 忽略归一化 | 权重不归一就不是加权平均 |
| 权重固定 | 失去动态建模能力 |

注意力的计算代价与序列长度平方相关，这是它与循环网络（RNN）的核心权衡：RNN 顺序处理、代价线性但难以并行；注意力完全并行、代价平方但训练高效。

## 1.5 要点

- 注意力 = 根据相关性加权聚合信息。
- 权重由输入动态计算，而非固定。
- 抽象形式：`Σ α_i · value_i`。

# 2. Query / Key / Value

## 2.1 结论先行

注意力用三个角色描述"检索"过程：Query（查询）表达"我要找什么"，Key（键）是每条信息的标签，Value（值）是每条信息的内容。

## 2.2 原理：检索类比

### 2.2.1 Q/K/V 的角色

```
类比检索：
Query（查询）：我要找什么
Key（键）：  每条信息的标签
Value（值）：每条信息的内容

Attention = 用 Query 匹配 Key，按匹配度加权 Value
```

### 2.2.2 与数据库检索的对应

| 数据库 | 注意力 | 说明 |
|--------|--------|------|
| 查询条件 | Query | 描述需求 |
| 索引键 | Key | 用于匹配 |
| 记录内容 | Value | 被返回的信息 |
| 相似度排序 | 注意力权重 | 软匹配 |

数据库是"硬匹配"（命中或未命中），注意力是"软匹配"（所有键都按相似度贡献一部分）。

### 2.2.3 Q/K/V 从何而来

Q、K、V 通常不是原始输入，而是输入经过三个可学习线性投影（projection）得到：

```
Q = X · Wq
K = X · Wk
V = X · Wv
```

投影矩阵 `Wq`、`Wk`、`Wv` 让模型学习"如何提问""如何打标签""如何提取内容"，是注意力可训练的核心参数。

## 2.3 公式/图示：计算流程

```
         Q
         │
    ┌────┼────┐
    ▼    ▼    ▼
   K1   K2   K3      ← 计算相似度
    │    │    │
    ▼    ▼    ▼
   α1   α2   α3      ← softmax 归一化
    │    │    │
    ▼    ▼    ▼
   V1   V2   V3      ← 加权求和
    └────┼────┘
         ▼
      输出
```

## 2.4 边界与坑

| 坑 | 说明 |
|----|------|
| Q/K/V 混为一谈 | 三者由不同投影产生 |
| 忽略 Value 的作用 | 匹配的是 Key，返回的是 Value |
| 硬匹配思维 | 注意力是软加权，不是选一个 |

Q 与 K 必须维度相同（才能做点积），而 V 的维度可以不同（因为只参与加权求和）。这一点在多向量与交叉注意力实现中尤其重要。

## 2.5 要点

- Q/K/V 是注意力的三个角色。
- 用 Query 匹配 Key，按匹配度加权 Value。
- 注意力是"软检索"，所有键都参与。

# 3. 缩放点积注意力

## 3.1 结论先行

缩放点积注意力（scaled dot-product attention）是 Transformer 的核心算子，公式为 `softmax(QKᵀ/√d_k)V`，由"算相似度、归一化、加权聚合"三步组成。

## 3.2 原理：三个步骤

1. 相似度：`QKᵀ` 计算每个 query 与所有 key 的点积。
2. 归一化：除以 `√d_k` 后做 softmax，得到权重。
3. 聚合：权重乘以 `V`，得到加权和。

## 3.3 公式/图示：公式与代码

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

```python
import math

def softmax(x, dim=-1):
    x = x - x.max(dim=dim, keepdim=True).values
    e = x.exp()
    return e / e.sum(dim=dim, keepdim=True)

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)   # ① 相似度
    weights = softmax(scores, dim=-1)                    # ② 归一化
    return weights @ V                                    # ③ 加权聚合
```

### 3.3.1 矩阵形状

```
Q: (..., n, d_k)
K: (..., m, d_k)
V: (..., m, d_v)
scores = QKᵀ: (..., n, m)
output: (..., n, d_v)
```

### 3.3.2 步骤对照

| 步骤 | 作用 |
|------|------|
| `QKᵀ` | 计算每个 query 与所有 key 的相似度 |
| `/√d_k` | 缩放，防止 softmax 梯度消失 |
| `softmax` | 归一化为权重 |
| `× V` | 加权聚合 value |

## 3.4 边界与坑

| 坑 | 说明 |
|----|------|
| 忘记缩放 | softmax 饱和，梯度消失 |
| softmax 不减去最大值 | 数值溢出（overflow） |
| 形状不匹配 | 转置维度搞错，结果静默错误 |
| 忽略 mask | 填充位被当成有效信息 |

实现中 softmax 前通常还会加 mask：填充位（padding）置 `-inf`，因果位置 `-inf`。mask 是注意力正确性的必要条件，不是可选优化。

## 3.5 要点

- 公式：`softmax(QKᵀ/√d_k)V`。
- 三步：相似度、归一化、加权聚合。
- 实现时注意缩放与数值稳定。

# 4. 为什么要除以 √d_k

## 4.1 结论先行

除以 `√d_k` 是为了把点积的方差归一到 1，避免 softmax 因输入过大而饱和、梯度趋近于零。

## 4.2 原理：方差分析

### 4.2.1 点积方差推导

```
若 Q、K 各维度独立且方差为 1：
  QKᵀ 的方差 = d_k
  d_k 越大，点积越大
  softmax 会变得极端（趋近 one-hot）
  梯度趋近于 0 → 无法学习

除以 √d_k 使方差归一到 1
```

设 `q_i`、`k_i` 独立、均值 0、方差 1，则点积 `q·k = Σ q_i k_i` 的方差为 `Σ Var(q_i k_i) = d_k`，标准差为 `√d_k`。不缩放时，`d_k` 越大，点积幅度越大。

### 4.2.2 softmax 饱和

softmax 对输入幅度敏感：输入很大时，输出趋近 one-hot，梯度趋近 0。缩放把输入标准差拉回 1，使 softmax 工作在线性区间，梯度健康。

### 4.2.3 梯度视角

softmax 的雅可比矩阵含因子 `α_i(1 - α_i)`。当某个 `α_i → 1` 时，该因子 → 0，对应梯度消失。缩放让 `α_i` 分布平滑，从而保留非零梯度。

## 4.3 公式/图示：缩放前后

```
不缩放（d_k 大）：  scores 幅度大 ──▶ softmax 尖锐 ──▶ 梯度≈0
缩放后：            scores 幅度≈1 ──▶ softmax 平滑 ──▶ 梯度健康
```

```
softmax 输出分布
  1.0 ┤            ● 不缩放
      │
      │
  0.0 ┤ ● ● ● ● ●  缩放后
      └──────────────▶ 类别
```

## 4.4 边界与坑

| 坑 | 说明 |
|----|------|
| 用 `d_k` 而非 `√d_k` | 缩放过度，损失区分度 |
| 忘记缩放 | 深层网络训练发散或停滞 |
| 误以为只影响速度 | 影响的是可训练性 |

缩放是注意力能稳定训练的关键设计之一。去掉它，模型在 `d_k` 较大时几乎无法收敛；这也是后续许多注意力变体保留缩放的原因。

## 4.5 要点

- 不缩放时点积方差为 `d_k`。
- 方差过大会让 softmax 饱和、梯度消失。
- 除以 `√d_k` 把方差归一到 1。

# 5. 自注意力

## 5.1 结论先行

自注意力（self-attention）中 Q、K、V 都来自同一个输入序列，因此每个位置都能"看到"其他所有位置。

## 5.2 原理：QKV 同源

```
Self-Attention：Q、K、V 都来自同一个输入序列

每个位置都能"看到"其他所有位置
```

与注意力用于"编码器-解码器"跨序列交互不同，自注意力在单个序列内部建模依赖，是 Transformer 编码器与解码器的基础。

### 5.2.1 自注意力 vs 交叉注意力

| 类型 | Query 来源 | Key/Value 来源 | 用途 |
|------|-----------|----------------|------|
| 自注意力 | 序列 X | 序列 X | 序列内部依赖 |
| 交叉注意力 | 解码器 | 编码器 | 编码-解码对齐 |

交叉注意力（cross-attention）中 Q 来自解码器，K、V 来自编码器，实现跨序列的信息流动，是机器翻译等任务的关键。

### 5.2.2 因果 mask

解码器的自注意力必须加因果掩码（causal mask），把"未来位置"的注意力分数置为 `-inf`，softmax 后权重为 0，确保位置 `t` 只能看到 `≤ t` 的信息，防止训练时泄漏答案。

## 5.3 公式/图示：实现

```python
import torch.nn as nn

class SelfAttention(nn.Module):
    def __init__(self, d_model):
        super().__init__()
        self.Wq = nn.Linear(d_model, d_model)
        self.Wk = nn.Linear(d_model, d_model)
        self.Wv = nn.Linear(d_model, d_model)

    def forward(self, x):
        Q = self.Wq(x)
        K = self.Wk(x)
        V = self.Wv(x)
        return scaled_dot_product_attention(Q, K, V)
```

```
输入 X
 ├──▶ Wq ──▶ Q ┐
 ├──▶ Wk ──▶ K ┼──▶ Attention ──▶ 输出
 └──▶ Wv ──▶ V ┘
```

## 5.4 边界与坑

| 坑 | 说明 |
|----|------|
| 解码器不做 mask | 未来信息泄漏 |
| 混淆自注意力与交叉注意力 | 后者 Q 与 KV 来源不同 |
| 忽略位置编码 | 自注意力本身无序 |

自注意力是置换等变（permutation-equivariant）的：打乱输入顺序，输出只会被同样打乱，不会改变。因此必须额外注入位置编码（positional encoding），模型才能感知词序。

## 5.5 要点

- 自注意力：Q、K、V 同源。
- 每个位置可关注全序列。
- 解码器需因果 mask 防止泄漏。

# 6. 多头注意力

## 6.1 结论先行

多头注意力（multi-head attention）把 `d_model` 分成 `h` 个头，各自独立做注意力，再拼接并线性变换，使模型能同时关注不同子空间的信息。

## 6.2 原理：子空间并行

### 6.2.1 为什么多头

```
把 d_model 分成 h 个头，各自独立做注意力，再拼接
```

```
d_model = 512, h = 8 → 每个头 64 维

多头的好处：
- 不同头关注不同模式（语法、语义、位置）
- 增强表达能力
```

单头注意力只有一组权重，只能学到一种"关注模式"；多头让每个头在自己的低维子空间里独立学习，最后融合，等价于多个视角的集成。

### 6.2.2 头维度与计算量

每个头的维度 `d_head = d_model / h`。总计算量与单头相近，因为各头维度之和等于 `d_model`，只是并行分组。

## 6.3 公式/图示：实现

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        self.num_heads = num_heads
        self.head_dim = d_model // num_heads
        self.Wq = nn.Linear(d_model, d_model)
        self.Wk = nn.Linear(d_model, d_model)
        self.Wv = nn.Linear(d_model, d_model)
        self.Wo = nn.Linear(d_model, d_model)

    def forward(self, x):
        B, T, C = x.shape
        Q = self.Wq(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        K = self.Wk(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        V = self.Wv(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)

        out = scaled_dot_product_attention(Q, K, V)          # 每个头独立
        out = out.transpose(1, 2).contiguous().view(B, T, C)  # 拼接
        return self.Wo(out)
```

```
d_model = 512, h = 8
 ┌───────────────────────────┐
 │ 头1 头2 头3 ... 头8（各64）│
 └───────────────────────────┘
       │ 各自 Attention
       ▼
   拼接 → 512 → Wo → 输出
```

## 6.4 边界与坑

| 坑 | 说明 |
|----|------|
| `d_model` 不能被 `h` 整除 | 头维度不整，需调整 |
| 忘记 `transpose`/`contiguous` | 拼接时形状错乱 |
| 头数越多越好 | 单头维度过小，表达受限 |

多头并不是简单地把单头复制多份，而是让每个头拥有独立的投影矩阵，从而学习互补的模式。去掉多头（`h=1`）会显著削弱表达能力。

## 6.5 要点

- 多头把 `d_model` 切成 `h` 个子空间。
- 各头独立注意力后拼接再投影。
- 不同头学习不同关注模式。

# 7. 注意力的复杂度

## 7.1 结论先行

标准注意力的时间与空间复杂度都是 `O(n² · d)`，`n` 为序列长度，这是长上下文的核心瓶颈。

## 7.2 原理：平方从何而来

### 7.2.1 计算量

```
时间与空间复杂度：O(n² · d)
n = 序列长度，d = 维度

序列翻倍 → 计算量翻 4 倍
```

注意力矩阵 `QKᵀ` 的形状是 `n × n`，其中每个元素都要计算并存储，因此对 `n` 是平方级。

### 7.2.2 显存

除计算外，注意力权重矩阵本身占显存 `O(n²)`，是长序列显存爆炸的主因，也是各种高效注意力（FlashAttention、稀疏注意力）优化的对象。

## 7.3 公式/图示：增长曲线

```
n    注意力矩阵元素数 (n²)
8    64
64   4,096
512  262,144
4096 16,777,216
```

> 这是长上下文的核心瓶颈，催生了各种高效注意力（见 `4_attention_variants.md`）。

## 7.4 边界与坑

| 坑 | 说明 |
|----|------|
| 只算 FLOPs | 忽略显存带宽瓶颈 |
| 以为线性近似无损 | 近似注意力有精度损失 |
| 忽略 batch 维度 | 实际显存还要乘批大小与头数 |

## 7.5 要点

- 复杂度 `O(n²·d)`，对长度平方级。
- 序列翻倍，计算量翻四倍。
- 长上下文的瓶颈催生高效注意力。

# 8. 注意力的可解释性

## 8.1 结论先行

注意力权重可以可视化为"关注图"，直观展示模型在何处聚焦，但它不是严格的因果解释。

## 8.2 原理：注意力即关注

### 8.2.1 指代消解例子

```
注意力权重可视化为"关注图"：
  "它" → 指代的对象
  动词 → 主语/宾语
```

```
The animal didn't cross the street because it was too tired
                                        ↑
                              "it" 高度关注 "animal"
```

在上面句子中，代词 "it" 的注意力权重会集中到 "animal"，直观反映了指代关系。

### 8.2.2 注意力的局限

注意力权重反映的是"信息流动的路径"，但高权重不必然意味着因果重要。后续研究指出，注意力图可以被人为扰动而模型输出不变，因此只能作为参考，不能当作严格解释。

### 8.2.3 多头多层的综合

单个头的注意力图信息有限，通常需要：

- 把同一层所有头平均或分别观察。
- 跨多层对比，看信息如何逐层抽象。
- 结合残差连接与前馈网络（FFN）理解整体信息流。

## 8.3 公式/图示：注意力热图

```
         The animal didn't ... it ...
The   [ .9  .02 .01 ... .01 ]
animal[ .05  .8  .03 ... .02 ]
it    [ .1   .6  .05 ... .1  ]  ← "it" 关注 "animal"
```

## 8.4 边界与坑

| 坑 | 说明 |
|----|------|
| 把注意力当解释 | 权重≠因果重要性 |
| 只看单头 | 需综合多头与多层 |
| 忽略残差与 FFN | 信息并非只走注意力 |

注意力可视化是理解模型的有用起点，但不应据此断言"模型这样想"。严谨的归因需要因果实验（如消融、扰动）配合。

## 8.5 要点

- 注意力权重可可视化为关注图。
- 能直观展示指代、主谓等关系。
- 它是参考，不是严格的因果解释。

# 9. 小结

## 9.1 关键结论

- 注意力 = 用 Query 匹配 Key，加权聚合 Value。
- 缩放点积注意力：`softmax(QKᵀ/√d_k)V`。
- 除以 √d_k 防止 softmax 梯度消失。
- 多头注意力让模型关注不同模式。
- 注意力复杂度 O(n²)，是长上下文的瓶颈。

## 9.2 一句话回顾

注意力用内容动态计算权重，是 Transformer 建模长距离依赖的核心，也是长上下文成本的主要来源。
