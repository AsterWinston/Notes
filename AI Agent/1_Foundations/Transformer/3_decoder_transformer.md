# 1. 为什么 LLM 用 Decoder-only

**结论先行**：大语言模型（Large Language Model，LLM）的主流选择是仅解码器（Decoder-only）结构，因为它的训练目标（预测下一个 Token）与推理方式（自回归生成）天然一致，且结构最简单、最容易扩展。

## 1.1 三种范式回顾

**原理**：Transformer 有三种用法，区别在于使用编码器还是解码器、注意力是否加因果掩码。

```
Encoder-only（BERT）：双向注意力，适合理解
Decoder-only（GPT）：因果注意力，适合生成
Encoder-Decoder（T5）：适合序列到序列

LLM 要生成 → Decoder-only 最自然
```

| 范式 | 代表 | 注意力 | 预训练目标 |
|------|------|--------|------------|
| Encoder-only | BERT | 双向 | 掩码语言建模 |
| Decoder-only | GPT | 因果 | 下一 Token 预测 |
| Encoder-Decoder | T5 | 双向 + 因果 | 去噪/序列到序列 |

### 1.1.1 训练目标与推理的一致性

Decoder-only 的预训练目标就是"给定前文，预测下一个词"。推理时模型也正是"给定前文，生成下一个词"，两者完全对齐。而 Encoder-only 的掩码语言建模在推理时并无对应的生成过程，需要额外设计。

### 1.1.2 统一所有任务为文本生成

在 Decoder-only 中，分类、抽取、问答、翻译都可以改写为"输入一段文本，续写一段文本"，从而用一个模型、一个目标处理所有任务。

## 1.2 Decoder-only 的优势

| 优势 | 说明 |
|------|------|
| 结构简单 | 只需解码器 |
| 生成自然 | 自回归与预训练目标一致 |
| 易扩展 | 加深即可提升 |
| 统一 | 一个模型处理所有任务 |

**原理**：结构简单意味着工程实现、并行训练、显存优化（如 KV Cache）都更直接；生成自然意味着无需为推理单独设计解码策略以外的机制；易扩展意味着缩放定律（Scaling Law）更容易被验证和应用。

## 1.3 代价与权衡

**边界与坑**：

- 因果注意力只能看到左侧上下文，无法像双向注意力那样利用右侧信息，对纯理解任务略逊。
- 自回归生成是串行的，逐 Token 推理，延迟高于一次前向。
- 单向建模导致"上文越短、预测越不确定"，对长距离依赖的利用依赖位置编码质量。

**要点**：

- LLM 主流是 Decoder-only。
- 优势：简单、生成自然、易扩展、任务统一。
- 代价：单向性、串行推理。

# 2. 因果掩码

**结论先行**：因果掩码（Causal Mask）通过把注意力分数矩阵的上三角置为负无穷，强制每个位置只能关注自身及之前的位置，从而保证训练时的并行计算不泄露未来信息。

## 2.1 掩码的作用

**原理**：训练时整个序列一次前向，如果第 i 个位置能看到第 j > i 个位置，就相当于"偷看答案"，模型学不到真正的预测能力。掩码把不允许的位置权重压到 0。

```
每个位置只能看到自己和之前的位置：

位置:  1  2  3  4
 1:    ✓  ✗  ✗  ✗
 2:    ✓  ✓  ✗  ✗
 3:    ✓  ✓  ✓  ✗
 4:    ✓  ✓  ✓  ✓
```

> 掩码保证训练时不会"偷看"未来，与推理时一致。

## 2.2 实现方式

**公式**：注意力分数先缩放，再加上掩码，最后 Softmax：

```
scores = Q · Kᵀ / √d_k
scores = scores + M          # M 的上三角为 -inf
attn   = softmax(scores)     # -inf 位置权重为 0
```

### 2.2.1 上三角掩码

```python
def causal_mask(seq_len):
    # 上三角为 -inf，softmax 后为 0
    mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1)
    return mask.masked_fill(mask == 1, float('-inf'))
```

### 2.2.2 数值实现细节

- 使用 `float('-inf')` 或极大的负数（如 -1e9）均可，前者更规范。
- 现代实现常用布尔掩码配合 `masked_fill`，或直接在 Softmax 前加偏置矩阵。
- 与填充掩码（Padding Mask）合并时，两者取并集即可。

## 2.3 常见误区

| 误区 | 澄清 |
|------|------|
| 掩码只在训练用 | 推理逐 Token 时同样隐含因果性 |
| 掩码改变了注意力数学 | 它只是把非法位置权重置零 |
| 加掩码后仍是置换不变 | 掩码引入方向，破坏置换等变性 |

**边界与坑**：若掩码方向写反（保留下三角之外的错误区域），模型会看到未来，训练损失可能更低但推理完全失效，这是常见实现错误。

**要点**：

- 因果掩码保证只能看过去。
- 实现即上三角置 -inf 后 Softmax。
- 掩码方向写反是典型 bug。

# 3. 自回归生成

**结论先行**：自回归（Autoregressive）生成是把已生成的序列不断作为新输入，每次只预测下一个 Token，直到遇到结束符（EOS）。

## 3.1 逐步生成过程

```
输入:  "今天天气"
  ↓
预测:  "真"
输入:  "今天天气真"
  ↓
预测:  "好"
输入:  "今天天气真好"
  ↓
预测:  <EOS>  （结束）
```

**原理**：第 t 步的输出依赖第 1 到 t-1 步的全部输出，形成链式分解：

```
P(x1, x2, ..., xn) = ∏ P(x_t | x_1, ..., x_{t-1})
```

## 3.2 采样策略

**原理**：模型输出的是词表上的概率分布，如何从中选词决定了生成风格。

### 3.2.1 贪心与束搜索

| 策略 | 做法 | 特点 |
|------|------|------|
| 贪心（Greedy） | 每步取概率最大 | 快，易重复 |
| 束搜索（Beam Search） | 维护 k 条候选路径 | 质量高，计算多 |

### 3.2.2 温度与 Top-k/Top-p

| 策略 | 做法 | 效果 |
|------|------|------|
| 温度（Temperature） | 缩放 logits 再 Softmax | 高温更随机，低温更确定 |
| Top-k | 只在概率前 k 个中采样 | 过滤长尾 |
| Top-p（核采样） | 在累计概率达 p 的最小集合采样 | 动态候选数 |

温度的作用可写为：

```
probs = softmax(logits / T)
```

T → 0 退化为贪心，T = 1 为原始分布，T > 1 更平坦。

## 3.3 生成代码

```python
def generate(model, prompt, max_new_tokens):
    tokens = tokenize(prompt)

    for _ in range(max_new_tokens):
        logits = model(tokens)           # 前向
        next_token = sample(logits[-1])  # 采样
        tokens.append(next_token)

        if next_token == EOS:
            break
    return detokenize(tokens)
```

**边界与坑**：上述朴素实现每步都重新前向整段序列，计算量随长度平方增长；生产实现会缓存历史键值（KV Cache），使每步只需计算新 Token。

**要点**：

- 自回归 = 链式条件概率分解。
- 采样策略控制随机性与多样性。
- 朴素实现需 KV Cache 加速。

# 4. 训练 vs 推理

**结论先行**：训练时利用因果掩码一次前向处理整个序列，高度并行；推理时只能逐 Token 串行生成，这是解码器效率问题的根源。

## 4.1 训练：并行

**原理**：给定完整序列，一次前向即可得到每个位置的下一 Token 预测，所有位置的损失同时计算，充分利用 GPU。

| 阶段 | 特点 |
|------|------|
| 训练 | 并行处理整个序列（掩码保证因果） |
| 推理 | 逐 token 串行生成 |

## 4.2 推理：串行

```
训练：一次前向处理所有位置（利用掩码）
推理：每生成一个 token 都要一次前向 → 慢
```

> 这是推理慢的根本原因，催生了 KV Cache 等优化。

### 4.2.1 KV Cache 的直觉

推理第 t 步时，前 t-1 个位置的键（Key）与值（Value）不会改变，可缓存复用，避免重复计算，把每步复杂度从 O(t²) 降到 O(t)。

### 4.2.2 显存换时间

KV Cache 用显存换取速度，其大小随序列长度线性增长，成为长上下文推理的显存瓶颈，由此引出 GQA、量化等优化。

## 4.3 Teacher Forcing 与曝光偏差

**原理**：训练时每一步的输入都使用真实前缀（Teacher Forcing），而非模型自己的预测；这使训练高效，但也导致训练与推理的分布不一致，称为曝光偏差（Exposure Bias）。

**边界与坑**：曝光偏差在长序列生成时可能累积误差；实践中通过数据规模、采样训练或强化学习缓解。

**要点**：

- 训练并行、推理串行。
- KV Cache 是推理加速的关键。
- Teacher Forcing 带来曝光偏差。

# 5. 预训练目标

**结论先行**：Decoder-only 的预训练目标是下一 Token 预测（Next Token Prediction），损失为每个位置的交叉熵（Cross Entropy）之和。

## 5.1 下一 Token 预测

```
下一 Token 预测（Next Token Prediction）：

输入:  [BOS] 今 天 天 气 真 好
目标:  今   天 天 气 真 好 [EOS]

损失 = 每个位置的交叉熵之和
```

**原理**：把输入右移一位作为目标，每个位置都提供一个监督信号，因此一条长度为 n 的序列贡献 n 个训练样本，数据利用率极高。

## 5.2 损失函数

**公式**：交叉熵损失

```
L = - (1/N) Σ_t log P(x_t | x_<t)
```

```python
loss = cross_entropy(logits[:, :-1], targets[:, 1:])
```

| 符号 | 含义 |
|------|------|
| logits[:, :-1] | 每个位置的预测分布 |
| targets[:, 1:] | 右移一位的真实 Token |
| N | 有效 Token 数（不含填充） |

### 5.2.1 为什么用交叉熵

交叉熵等价于最大似然估计，梯度形式简洁，且与 Softmax 组合后梯度为"预测减真实"的差值。

### 5.2.2 损失归一化

通常按有效 Token 数而非总 Token 数归一，避免填充（Padding）位置稀释损失。

## 5.3 从语言建模到指令微调

**原理**：预训练获得通用语言能力，指令微调（Instruction Tuning）用"指令-回答"数据继续训练，让模型学会遵循人类意图；对齐阶段再用人类反馈强化学习（RLHF）或直接偏好优化（DPO）调整偏好。

| 阶段 | 数据 | 目标 |
|------|------|------|
| 预训练 | 大规模文本 | 语言建模 |
| 指令微调 | 指令-回答对 | 遵循指令 |
| 对齐 | 偏好数据 | 符合人类偏好 |

**边界与坑**：语言建模能力与对齐目标是分离的，微调可能带来"对齐税"（Alignment Tax），即在某些基准上性能下降。

**要点**：

- 预训练目标 = 下一 Token 预测。
- 损失 = 右移一位的交叉熵。
- 后续经指令微调与对齐。

# 6. 位置编码

**结论先行**：注意力本身是置换不变的（Permutation Invariant），不含顺序信息，因此必须显式注入位置编码（Positional Encoding）。

## 6.1 为什么需要位置信息

```
注意力本身无序（置换不变）
必须注入位置信息 → 位置编码
```

> 详见 `5_positional_encoding.md`。

**原理**：若交换输入序列中两个 Token 的位置，自注意力的输出只是相应交换，模型无法区分"猫追狗"与"狗追猫"。

## 6.2 从正弦到 RoPE

| 方案 | 做法 | 特点 |
|------|------|------|
| 正弦编码 | 固定三角函数 | 可外推，原论文方案 |
| 可学习编码 | 每个位置一个向量 | 简单，难外推 |
| 旋转位置编码（RoPE） | 旋转 Q/K 向量 | 相对位置，现代主流 |

**公式**：RoPE 通过对查询与键施加与位置相关的旋转，使内积只依赖相对位置：

```
⟨R_m q, R_n k⟩ = f(q, k, m - n)
```

## 6.3 外推问题

**边界与坑**：训练时见过的最大长度之外，位置编码可能失效，导致长上下文性能骤降。常见缓解手段包括位置插值（Position Interpolation）、NTK 感知缩放与 YaRN 等。

**要点**：

- 注意力不含顺序，必须注入位置。
- RoPE 是现代主流。
- 外推是长上下文的关键难点。

# 7. 结构细节（现代 LLM）

**结论先行**：现代 LLM 在原始解码器基础上做了若干替换：归一化用 RMSNorm、位置用 RoPE、注意力用 GQA、激活用 SwiGLU、并去掉偏置项。

## 7.1 标准解码器块

```
Input Embedding
  ↓
[Decoder Block] × N
  ├── RMSNorm
  ├── 多头注意力（RoPE + GQA）
  ├── 残差
  ├── RMSNorm
  ├── 前馈网络（SwiGLU）
  └── 残差
  ↓
RMSNorm
  ↓
LM Head（输出层）
```

## 7.2 现代组件一览

| 组件 | 现代做法 |
|------|----------|
| 归一化 | RMSNorm（Pre-LN） |
| 位置编码 | RoPE |
| 注意力 | GQA/MQA |
| 激活 | SwiGLU |
| 偏置 | 多数去掉（bias-free） |

### 7.2.1 RMSNorm

**公式**：只做均方根缩放，不减均值：

```
RMSNorm(x) = x / √(mean(x²) + ε) · γ
```

相比 LayerNorm 少了求均值与偏置，计算更省，效果相当。

### 7.2.2 SwiGLU

**公式**：门控线性单元的一种：

```
SwiGLU(x) = (xW₁ ⊙ swish(xW₃)) W₂
```

其中 swish(z) = z · sigmoid(z)。门控机制提升了表达能力，但引入额外矩阵，故 d_ff 常取约 8/3·d_model 以平衡参数量。

## 7.3 与原始解码器的差异

| 项目 | 原始 | 现代 |
|------|------|------|
| 归一化 | LayerNorm Post-LN | RMSNorm Pre-LN |
| 位置 | 正弦编码 | RoPE |
| 注意力 | MHA | GQA |
| 激活 | ReLU | SwiGLU |
| 偏置 | 有 | 多数去除 |

**边界与坑**：这些替换并非必须同时采用，不同模型的组合各异；迁移实现时需注意归一化位置与偏置有无。

**要点**：

- 现代解码器 = Pre-LN + RMSNorm + RoPE + GQA + SwiGLU。
- RMSNorm 与 SwiGLU 更省更稳。
- 组合因模型而异。

# 8. 参数规模

**结论先行**：Decoder-only 模型的参数量近似正比于层数与模型维度的平方，注意力与 MLP 的矩阵是主要来源。

## 8.1 单层参数拆解

```
模型大小 ≈ 层数 × 每层参数

每层参数：
  注意力：4 × d_model²（Q/K/V/O）
  前馈：8 × d_model²（d_ff = 4×d_model）
  → 约 12 × d_model²
```

| 模块 | 参数量 | 占比 |
|------|--------|:----:|
| 注意力 | 4·d_model² | 1/3 |
| 前馈 | 8·d_model² | 2/3 |

## 8.2 总参数估算

**公式**：

```
总参数 ≈ 12 × L × d_model²
```

| 符号 | 含义 |
|------|------|
| L | 层数 |
| d_model | 隐层维度 |
| 12 | 每层系数近似 |

### 8.2.1 词表项

输出层与嵌入层的参数量为 V × d_model，当词表很大时不可忽略，且常通过权重共享减少一份。

### 8.2.2 估算的用途

快速判断模型规模量级、估算显存与算力需求，是工程决策的常用手段。

## 8.3 实例对照

| 模型 | d_model | L | 约算参数 |
|------|:-------:|:-:|:--------:|
| GPT-2 Small | 768 | 12 | 124M |
| GPT-2 XL | 1600 | 48 | 1.5B |
| LLaMA-7B | 4096 | 32 | 7B |

**边界与坑**：GQA 会减少 K/V 投影的参数，SwiGLU 会改变前馈项系数，故实际参数与 12·L·d_model² 会有偏差。

**要点**：

- 单层约 12·d_model²。
- 总参数近似 12·L·d_model²。
- 词表项在大词表下不可忽略。

# 9. 常见误区

**结论先行**：关于解码器的因果性、位置与缓存，存在若干常见误解，澄清它们有助于正确理解推理过程。

## 9.1 关于因果性

| 误区 | 澄清 |
|------|------|
| 因果掩码只是训练技巧 | 它是 Decoder-only 的定义性约束 |
| 推理时不加掩码也没关系 | 逐 Token 推理天然满足因果，但实现仍需一致 |
| 因果模型无法理解 | 它通过海量数据学习双向语境 |

## 9.2 关于位置与缓存

| 误区 | 澄清 |
|------|------|
| 位置编码可有可无 | 没有它模型无法区分词序 |
| KV Cache 改变输出 | 它只是复用中间结果，数值等价 |
| 上下文越长一定越好 | 受位置外推与注意力稀释影响 |

**边界与坑**：KV Cache 与训练时的并行前向在数值上应一致，若实现中掩码或位置偏移处理不同，可能导致训练与推理结果不一致。

**要点**：

- 因果性是结构定义。
- 位置编码必不可少。
- KV Cache 数值等价，不改变输出。

# 10. 小结

**结论先行**：Decoder-only 以因果掩码和下一 Token 预测为核心，训练并行、推理串行，并通过现代组件不断优化效率与稳定性。

## 10.1 核心要点

- LLM 主流是 Decoder-only 结构。
- 因果掩码保证只能看到过去。
- 训练并行、推理串行（逐 token）。
- 预训练目标是下一 Token 预测。
- 现代改进：RMSNorm、RoPE、GQA、SwiGLU。

## 10.2 记忆口诀

```
因果掩码定方向，下一 Token 是目标
训练并行推理慢，KV Cache 来救场
Norm 换 RMS，位置用 RoPE
注意力 GQA，激活 SwiGLU
```

**要点**：

- 抓住"因果 + 自回归"两条主线。
- 记住现代组件的五个替换。
