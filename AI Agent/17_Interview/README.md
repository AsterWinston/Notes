# 1. 模块定位

本模块汇总 AI Agent 方向的高频面试考点，按主题组织，与前面各模块一一对应，便于针对性复习与自测。

## 1.1 模块说明

本模块不是新知识的讲授，而是对全链路知识的一次「压缩与索引」：每个文件都对应一个前置模块，把该模块里最可能被问到的点提炼成可直接作答的条目。

一句话概括：这里是**面试前的检索目录与自测题库**，而不是又一份原理教材。

## 1.2 与其他模块关系

```
  1_Foundations ~ 16_Applications
            │
            ▼
  17_Interview（考点映射 + 答题框架）
            │
            ▼
        面试现场表达
```

- 上游：全部前置模块，本模块不引入新原理。
- 下游：无，属于学习路径的终点站。

## 1.3 使用方式

- 先读本 README，确定自己的薄弱主题。
- 再按主题进入对应文件，逐条自问自答。
- 最后做系统设计与项目讲述的模拟演练。

建议不要从头顺读，而是带着「哪个问题我答不上来」的清单去查，效率最高。

# 2. 学习目标

## 2.1 能力目标

- 快速回顾核心考点，形成体系化表达。
- 掌握系统设计题的答题框架。
- 能清晰讲述自己的项目与取舍。

## 2.2 复习目标

- 能把散点知识串成「原理 → 工程 → 生产」的完整叙事。
- 能在追问下讲清技术选型的理由与代价。
- 能对不熟悉的点诚实说明，而不是硬编。

## 2.3 自检标准

| 检查项 | 达标标志 |
|--------|----------|
| 原理深度 | 能解释「为什么」而不只是「是什么」 |
| 工程取舍 | 能说出方案 A 与方案 B 的代价对比 |
| 项目真实 | 能回答每个技术决策背后的具体原因 |
| 表达结构 | 先结论、再展开、最后给权衡 |

三项考察中，「原理深度 + 工程取舍 + 项目真实性」缺一不可。

# 5. 关键知识点速览

## 5.1 核心要点

- 面试考察「原理深度 + 工程取舍 + 项目真实性」。
- 系统设计题先讲清需求与约束，再讲方案与权衡。
- 项目讲述用 STAR 结构，突出技术难点与量化收益。
- 手写题重点考 ReAct 循环与工具调用闭环。

## 5.2 高频追问

### 5.2.1 原理类

为什么用这个方案，代价是什么，边界在哪里。回答时要给出数量级感受，而不是模糊形容。

### 5.2.2 工程类

线上出问题怎么定位，怎么回滚，怎么防复发。这类问题考察的是有没有真正上过线。

### 5.2.3 取舍类

A 与 B 怎么选，在什么条件下会换选。承认没有银弹，往往比给出标准答案更加分。

## 5.3 常见误区

### 5.3.1 只背结论

能说出名词却讲不出原理，一旦被追问「为什么」就露馅。

### 5.3.2 项目注水

把别人的功能写进简历却答不出细节，追问两轮即会崩。

### 5.3.3 回避权衡

只讲方案好的一面，被问到代价时无法回答，显得没有真正做过判断。

# 6. 答题方法论

## 6.1 通用结构

- 先给结论，再展开论证，最后补充权衡。
- 主动暴露一个取舍点，引导面试官进入你熟悉的领域。
- 遇到不会的题，先讲思路再说明边界，避免沉默或硬编。

## 6.2 系统设计框架

| 步骤 | 要点 |
|------|------|
| 澄清需求 | 目标用户、核心场景、规模量级 |
| 明确约束 | 延迟、成本、一致性、合规 |
| 给出方案 | 架构分层、数据流、关键组件 |
| 说明权衡 | 方案对比、失败模式、降级策略 |
| 收尾 | 评测指标、上线路径、演进方向 |

## 6.3 项目讲述框架

用 Situation（背景）、Task（任务）、Action（行动）、Result（结果）四段展开，重点讲技术难点与量化收益。

## 6.4 追问应对话术

- 被问「还有别的方案吗」：至少给出一个替代方案，并说明为何当时不选。
- 被问「量级是多少」：给出估算过程，而不是背一个精确数字。
- 被问「如果重做」：讲清当时的约束，以及现在会改进的点。

# 9. 模拟演练

## 9.1 单题演练

- 随机抽取一个主题文件，限时 5 分钟口头作答。
- 录音回放，检查是否有「只讲是什么、不讲为什么」的问题。
- 对卡壳的点做标记，回到前置模块补齐。

## 9.2 全流程演练

| 环节 | 时长 | 重点 |
|------|:----:|------|
| 自我介绍 | 2 分钟 | 突出 AI Agent 相关经历 |
| 原理问答 | 15 分钟 | 深度与边界 |
| 系统设计 | 20 分钟 | 需求到权衡 |
| 项目追问 | 15 分钟 | 真实性与取舍 |
| 反问环节 | 5 分钟 | 体现思考深度 |

## 9.3 复盘方法

- 把每场演练的失分点写成清单，逐条回到本模块对应文件。
- 区分「不会」与「没讲清」：前者补知识，后者练表达。
- 连续两场演练都失分的点，视为最高优先级。

# 10. 高频主题速记

## 10.1 必背概念

| 概念 | 一句话解释 |
|------|------------|
| 注意力 | 按相关度加权聚合上下文的机制 |
| KV Cache | 缓存历史键值以换取推理速度，代价是显存 |
| 分块 | 把长文档切成检索单元，决定召回粒度 |
| 重排 | 对初筛结果再精排，提升最终质量 |
| ReAct | 推理与行动交替的 Agent 循环 |
| 工具调用 | 模型输出结构化参数并由外部执行 |
| 幂等 | 同一请求重复执行结果一致 |
| 熔断 | 依赖持续失败时快速失败，避免雪崩 |
| 注入 | 恶意输入劫持模型行为的攻击方式 |
| LLM-as-Judge | 用模型充当评审给结果打分 |

## 10.2 一句话回答模板

- 原理题：先说机制，再说代价，最后说适用边界。
- 工程题：先说问题现象，再说定位手段，最后说防护措施。
- 设计题：先说需求约束，再说方案，最后说权衡与降级。
- 项目题：先说背景目标，再说难点，最后说量化收益。

## 10.3 面试当天提醒

- 先想 3 秒再答，结构清晰胜过语速快。
- 不确定的点主动说明边界，比硬编更可信。
- 把面试当成技术交流，遇到好问题可以反问。
