# 1. Transformer 的核心是什么？

**答**：自注意力机制（Self-Attention）。

```
Attention(Q,K,V) = softmax(QKᵀ/√d_k)V
```

- Q/K/V 由输入线性变换得到；
- 除以 √d_k 防止 softmax 梯度消失；
- 多头让模型关注不同模式；
- 相比 RNN，可并行且能捕捉长距离依赖。

## 1.1 深入原理

### 1.1.1 缩放点积

点积随维度增大而方差变大，导致 softmax 进入饱和区、梯度趋近于零。除以 √d_k 把方差拉回 1 附近，训练更稳定。

### 1.1.2 多头注意力

把 Q/K/V 投影到多个子空间并行计算，再拼接投影。每个头可关注不同模式，如语法、指代、位置。

## 1.2 追问

- 为什么需要位置编码？注意力本身无序，必须显式注入位置信息。
- 为什么是 O(n²)？每个 token 都要与所有 token 计算相似度。

## 1.3 生产视角

- 长序列下注意力是主要成本，FlashAttention 通过分块减少显存读写。
- 推理时可用 KV Cache 避免重复计算，见第 5 题。

# 2. 为什么 LLM 用 Decoder-only？

**答**：
1. 自回归生成与预训练目标（下一 Token 预测）一致；
2. 结构简单，易扩展；
3. 一个模型处理所有任务；
4. 训练时并行（因果掩码），推理时串行。

## 2.1 深入原理

### 2.1.1 因果掩码

因果掩码（Causal Mask）让每个位置只能看到左侧 token，保证训练目标与推理行为一致。

### 2.1.2 与 Encoder-Decoder 对比

| 结构 | 代表 | 适用 |
|------|------|------|
| Encoder-only | BERT | 理解类任务 |
| Encoder-Decoder | T5 | 翻译、摘要 |
| Decoder-only | GPT | 通用生成 |

### 2.1.3 上下文学习

Decoder-only 天然支持把示例放进提示，实现少样本学习（Few-shot Learning）。

## 2.2 追问

- Decoder-only 能理解吗？能，理解能力可由生成目标隐式学到。
- 为什么不是纯 Encoder？纯 Encoder 不擅长自回归生成。

## 2.3 生产视角

- 统一结构让一个模型服务多任务，降低运维复杂度。
- 推理串行意味着延迟随输出长度线性增长。

# 3. Tokenizer 的作用？中文 Token 怎么算？

**答**：把文本切成子词单元再映射为 ID。

- 现代 LLM 用 BPE/WordPiece/SentencePiece；
- 英文约 1 token ≈ 4 字符；
- **中文约 1 token ≈ 1~1.5 字**；
- Token 数决定成本、延迟与上下文占用。

## 3.1 深入原理

### 3.1.1 子词切分

子词切分（Subword Tokenization）在词表大小与未登录词之间取平衡，常见词整体保留，罕见词拆成片段。

### 3.1.2 BPE 与 SentencePiece

| 算法 | 特点 |
|------|------|
| BPE | 合并高频字节对 |
| WordPiece | 按似然合并 |
| SentencePiece | 直接在原始文本上操作，语言无关 |

## 3.2 追问

- 为什么中文更贵？中文信息密度高但 token 粒度不固定，通常比英文消耗更多 token。
- 如何估算成本？按 token 计费，输入输出分开计。

## 3.3 生产视角

- 上线前必须用真实语料测 token 分布，别用平均值拍脑袋。
- 控制上下文时优先裁剪历史，而不是截断关键指令。

# 4. 采样参数有哪些？

| 参数 | 作用 |
|------|------|
| temperature | 随机性 |
| top_p | 核采样（推荐） |
| top_k | 取概率最高的 k 个 |
| repetition_penalty | 惩罚重复 |
| beam search | 确定性任务 |

**推荐组合**：temperature + top_p。事实任务 T=0.1~0.3，创意 T=0.9~1.2。

## 4.1 深入原理

### 4.1.1 温度缩放

温度在 softmax 前缩放 logits：T<1 使分布更尖锐，T>1 更平坦，T=0 退化为贪心。

### 4.1.2 核采样

核采样（Nucleus Sampling）只保留累计概率超过 top_p 的最小词集合，动态适应分布形状。

### 4.1.3 惩罚项

重复惩罚降低已出现 token 的概率，但过大可能导致语义漂移或语法错误。

## 4.2 追问

- top_p 和 top_k 能同时用吗？可以，但通常只用其一，避免相互干扰。
- 什么时候用 beam search？输出确定性要求高且质量优先，如翻译。

## 4.3 生产视角

```java
public record SamplingConfig(
        double temperature, double topP, int topK, double repetitionPenalty) {

    public static SamplingConfig factual() {
        return new SamplingConfig(0.2, 0.9, 40, 1.05);
    }

    public static SamplingConfig creative() {
        return new SamplingConfig(1.0, 0.95, 0, 1.10);
    }
}
```

- 参数应集中配置，按任务路由，避免散落在各处。
- 评测时固定随机种子，保证结果可复现。

# 5. KV Cache 是什么？为什么重要？

**答**：缓存历史 token 的 K、V，避免重复计算。

```
显存 ≈ 2 × L × n_kv_heads × head_dim × seq_len × batch × bytes
```

优化：GQA/MQA 减少 KV 头数、KV 量化、PagedAttention、滑动窗口。

## 5.1 深入原理

### 5.1.1 为什么能省

自回归每步只需新 token 的 Q，但需要全部历史 K/V。缓存后每步只算一个新 token，复杂度从 O(n²) 降到 O(n)。

### 5.1.2 显存构成

| 项 | 含义 |
|----|------|
| 2 | K 和 V 各一份 |
| L | 层数 |
| n_kv_heads | KV 头数 |
| head_dim | 单头维度 |
| seq_len | 序列长度 |
| batch | 批大小 |
| bytes | 每元素字节数 |

### 5.1.3 优化手段

PagedAttention 把 KV 分页存储，减少碎片；滑动窗口只保留最近若干 token。

## 5.2 追问

- 为什么 batch 越大显存越紧张？KV Cache 随 batch 线性增长。
- 能只缓存部分层吗？可以，但会损失精度，需评测。

## 5.3 生产视角

- 长上下文与高并发争夺显存，需设置最大序列与并发上限。
- KV Cache 是推理显存的主要占用，扩容前先看它的曲线。

# 6. GQA 与 MQA 的区别？

| 类型 | KV 头数 | KV Cache | 质量 |
|------|:-------:|:--------:|:----:|
| MHA | = Q 头数 | 100% | 最好 |
| GQA | Q 的 1/2~1/8 | 12%~50% | 接近 MHA |
| MQA | 1 | ~12% | 略降 |

**GQA 是当前主流**（LLaMA、Qwen）。

## 6.1 深入原理

### 6.1.1 分组共享

分组查询注意力（Grouped-Query Attention）把 Q 分成若干组，每组共享一组 K/V，在质量与显存间取折中。

### 6.1.2 权衡

KV 头越少，显存与带宽越省，但表达力下降。GQA 的经验比例是 1/4 到 1/8。

## 6.2 追问

- 为什么 MQA 质量略降？所有 Q 头共享同一 K/V，压缩过强。
- GQA 需要重训吗？需要，从头训练或继续预训练。

## 6.3 生产视角

- 选模型时优先看 KV 头数，它直接决定并发能力。
- 高并发场景下，GQA 相比 MHA 可显著提升吞吐。

# 7. 量化有哪些方式？

| 格式 | 场景 |
|------|------|
| GPTQ | GPU 4bit |
| AWQ | GPU 4bit，精度略优 |
| GGUF | CPU/本地 |
| INT8 | 几乎无损失 |
| INT4 | 性价比拐点 |

量化后**必须评测**效果损失。

## 7.1 深入原理

### 7.1.1 量化原理

用低比特整数近似权重或激活，减少显存与带宽。分对称与非对称、逐张量与逐通道。

### 7.1.2 训练后量化与量化感知训练

| 方式 | 说明 |
|------|------|
| PTQ | 训练后直接量化，简单快速 |
| QAT | 训练中模拟量化，精度更好 |

### 7.1.3 激活量化

权重易量化，激活含离群值，常需保留部分高精度通道。

## 7.2 追问

- INT4 一定比 INT8 差吗？通常略差，但工程收益大，需按任务评测。
- 量化影响长上下文吗？会，长序列误差累积更明显。

## 7.3 生产视角

- 量化后必须重跑评测集，对比精度、延迟与吞吐。
- 关键任务可保留 FP16 兜底，非关键任务用低比特。

# 8. RoPE 是什么？

**答**：旋转位置编码，通过旋转 Q/K 向量注入**相对位置**信息。

优点：相对位置、可外推、无额外参数。被 LLaMA、Qwen 等广泛采用。

## 8.1 深入原理

### 8.1.1 旋转机制

把 Q/K 按位置角旋转，两个 token 的内积只依赖它们的相对距离，天然编码相对位置。

### 8.1.2 外推

通过调整旋转基频（如 NTK 插值、YaRN），可把训练长度外推到更长序列。

### 8.1.3 与其他位置编码对比

| 编码 | 类型 | 外推 |
|------|------|------|
| 绝对位置 | 可学习/正弦 | 弱 |
| 相对位置 | 偏置 | 中 |
| RoPE | 旋转 | 强 |

## 8.2 追问

- RoPE 为什么能外推？相对距离的表达可平滑延展。
- 直接外推有效吗？通常需要插值或微调，否则质量下降。

## 8.3 生产视角

- 长上下文能力依赖位置编码与训练长度，别只看宣传参数。
- 扩展上下文后必须实测「中间遗忘」问题。

# 9. 推理的两个阶段？

| 阶段 | 特点 | 瓶颈 |
|------|------|------|
| Prefill | 并行处理输入 | 算力 |
| Decode | 逐 token | 显存带宽 |

- TTFT 受 Prefill 影响；
- TPS 受 Decode 影响；
- 连续批处理提升吞吐。

## 9.1 深入原理

### 9.1.1 Prefill

一次并行处理整段输入，计算密集，决定首 token 延迟（TTFT）。

### 9.1.2 Decode

每步只生成一个 token，访存密集，决定每秒 token 数（TPS）。

### 9.1.3 连续批处理

连续批处理（Continuous Batching）动态拼接请求，提高 GPU 利用率。

## 9.2 追问

- 为什么 Decode 是带宽瓶颈？每步都要读取全部权重与 KV Cache。
- 如何降低 TTFT？缩短输入、做提示缓存、提高算力。

## 9.3 生产视角

- 交互场景关注 TTFT，批处理场景关注 TPS。
- 用指标区分两阶段，才能定位是算力不足还是带宽不足。

# 10. 推理模型（o1/R1）与普通模型的区别？

**答**：推理模型在回答前进行**长链思考**，用测试时计算换质量。

- 训练靠可验证奖励的 RL；
- 在数学、代码等可验证任务提升明显；
- 成本与延迟高（5~20x），需按任务路由。

## 10.1 深入原理

### 10.1.1 测试时计算

推理模型在解码阶段生成长思维链（CoT），用更多计算换取更高正确率。

### 10.1.2 可验证奖励

通过答案可自动判定的任务（数学、代码）提供奖励信号，用强化学习优化推理过程。

### 10.1.3 与普通 CoT 对比

| 维度 | 普通 CoT | 推理模型 |
|------|----------|----------|
| 训练 | 提示引导 | RL 训练 |
| 成本 | 低 | 高 |
| 可验证任务 | 中 | 高 |

## 10.2 追问

- 所有任务都该用推理模型吗？不该，简单任务用普通模型更划算。
- 思维链能完全信任吗？不能，仍可能推理正确但结论错误。

## 10.3 生产视角

- 按任务难度路由：简单走小模型，难题走推理模型。
- 设置最大思考预算，防止成本失控。

# 11. MoE 是什么？

**答**：混合专家，用多个专家子网络 + 路由器，每次只激活 top-k 个。

```
参数量 >> 激活参数量
推理成本看激活参数，显存看总参数
```

代表：Mixtral、DeepSeek-MoE、Qwen-MoE。

## 11.1 深入原理

### 11.1.1 路由机制

路由器（Router）为每个 token 选择 top-k 专家，只计算被选中的专家，节省算力。

### 11.1.2 负载均衡

若 token 集中到少数专家，会造成负载不均。训练时用辅助损失鼓励均衡。

### 11.1.3 稀疏与稠密对比

| 类型 | 计算量 | 显存 | 质量 |
|------|:------:|:----:|:----:|
| 稠密 | 全参 | 全参 | 基准 |
| MoE | 激活参 | 全参 | 接近或更好 |

## 11.2 追问

- MoE 推理更快吗？算力更省，但显存需求不降，且路由有开销。
- 为什么显存看总参数？所有专家都要加载进显存。

## 11.3 生产视角

- MoE 适合算力受限但显存充足的场景。
- 部署时关注专家并行与通信开销。

# 12. Scaling Law 的结论？

- **Kaplan**：优先扩大参数量；
- **Chinchilla**：参数量与数据等比（20 token/参数）；
- **现代实践**：过训练（更多数据）以降低推理成本。

## 12.1 深入原理

### 12.1.1 Kaplan 与 Chinchilla

Kaplan 认为参数优先；Chinchilla 修正为参数与数据同比例增长，同样算力下数据不足是浪费。

### 12.1.2 过训练

现代模型用远超 Chinchilla 比例的数据训练，前期成本高，但推理更省、效果更好。

## 12.2 追问

- Chinchilla 是铁律吗？是指导，不是硬约束，需结合推理成本权衡。
- 数据会用完吗？高质量数据紧张，合成数据与数据筛选变得重要。

## 12.3 生产视角

- 选型时对比「每 token 成本」而非只看参数量。
- 过训练模型往往在同等效果下更便宜。

# 13. 预训练、SFT、RLHF 各做什么？

| 阶段 | 作用 |
|------|------|
| 预训练 | 学习语言与知识（下一 Token 预测） |
| SFT | 学会遵循指令（只在 assistant 部分算损失） |
| RLHF/DPO | 学会偏好（哪种回答更好） |

## 13.1 深入原理

### 13.1.1 预训练

在海量文本上做下一 token 预测，获得语言能力与知识，但不会「听话」。

### 13.1.2 监督微调

监督微调（SFT）用指令-回答对训练，损失只在 assistant 部分计算，让模型学会遵循指令。

### 13.1.3 偏好对齐

RLHF 用人类偏好训练奖励模型再强化学习；DPO 直接用偏好数据优化，更简单。

## 13.2 追问

- 为什么 SFT 只算 assistant 部分？否则模型会学着生成用户提问。
- 三阶段能省吗？小模型常可省略 RLHF，但通用助手通常需要。

## 13.3 生产视角

- 领域微调通常只做 SFT，成本可控。
- 对齐阶段的数据质量比数量更重要。

# 14. DPO 为什么比 RLHF 简单？

**答**：DPO 跳过奖励模型与强化学习，直接用偏好数据优化：

```
提高 chosen 概率，降低 rejected 概率
```

只需 Policy + Ref 两个模型（RLHF 需 4 个）。

## 14.1 深入原理

### 14.1.1 隐式奖励

DPO 证明偏好优化可转化为一个闭式损失，奖励被隐式表达，无需单独训练奖励模型。

### 14.1.2 模型数量对比

| 方法 | 需要的模型 |
|------|-----------|
| RLHF | Policy、Ref、Reward、Critic |
| DPO | Policy、Ref |

### 14.1.3 稳定性

DPO 训练更稳定、调参更少，但可能过拟合偏好数据，需控制强度。

## 14.2 追问

- DPO 一定更好吗？不一定，RLHF 在复杂偏好上仍有优势。
- Ref 模型作用是什么？约束策略不偏离原模型太远。

## 14.3 生产视角

- 偏好数据需人工标注或模型筛选，质量决定上限。
- DPO 适合快速迭代，RLHF 适合追求极致效果。

# 15. 灾难性遗忘是什么？如何缓解？

**答**：微调后模型忘记预训练能力。

缓解：低学习率、少轮数（1~3）、数据混合、LoRA、正则化。

## 15.1 深入原理

### 15.1.1 成因

微调数据分布窄，梯度更新覆盖了预训练学到的权重，导致通用能力退化。

### 15.1.2 缓解手段

| 手段 | 原理 |
|------|------|
| 低学习率 | 减小扰动 |
| 少轮数 | 避免过拟合 |
| 数据混合 | 保留通用分布 |
| LoRA | 冻结主干，只训练旁路 |

### 15.1.3 LoRA

低秩适配（LoRA）冻结原权重，仅训练低秩增量，天然缓解遗忘且省显存。

## 15.2 追问

- 遗忘能完全避免吗？不能，只能缓解。
- 怎么检测遗忘？在通用评测集上回归测试。

## 15.3 生产视角

- 微调后必须跑通用能力回归，不能只看领域指标。
- 保留基座模型随时可回退，是重要的风险控制。
