# 1. 模块定位

没有记忆的 Agent 只是一次性问答。记忆决定 Agent 能否"记住用户、积累经验、长期协作"。本模块讲清短期/长期记忆、会话管理、上下文压缩与记忆检索。

## 1.1 本模块解决什么问题

记忆系统是 Agent 从"无状态工具"升级为"长期协作伙伴"的关键。它要回答六个层次的问题：

| 层次 | 问题 | 本模块对应内容 |
|------|------|----------------|
| 输入层 | 有限的上下文窗口如何分配 | 上下文窗口管理、消息裁剪 |
| 会话层 | 多轮对话如何组织与隔离 | 短期记忆、会话管理 |
| 持久层 | 跨会话如何记住用户与经验 | 长期记忆、持久化 |
| 检索层 | 何时、如何把记忆召回进上下文 | 记忆检索、相关性排序 |
| 优化层 | 长对话如何不撑爆窗口 | 上下文压缩、摘要 |
| 治理层 | 遗忘、去重、隔离、并发如何处理 | 遗忘机制、会话隔离 |

### 1.1.1 记忆不是"存得越多越好"

记忆的价值不在容量，而在"在对的时刻召回对的内容"。存得越多，噪声越大、召回越难、成本越高。因此本模块既讲写入，也讲召回、去重与遗忘。

### 1.1.2 记忆与上下文的分工

上下文窗口是"工作内存"（RAM），长期记忆是"硬盘"（Disk）。模型每次只能看到被组装进窗口的内容，记忆系统的本质工作是"从硬盘中挑出此刻最该进 RAM 的部分"。

### 1.1.3 记忆的生命周期

记忆系统不是"存了就好"，而是一条完整流水线：

```
写入 → 存储 → 召回 → 注入 → 更新 → 遗忘
```

| 阶段 | 关键问题 | 常见手段 |
|------|----------|----------|
| 写入 | 什么值得记 | 重要性打分、去重 |
| 存储 | 存在哪里 | KV、向量库、图库 |
| 召回 | 取哪些 | 相似度、时间衰减、混合排序 |
| 注入 | 如何进上下文 | 摘要、格式化、预算裁剪 |
| 更新 | 如何纠错 | 覆盖、合并、版本 |
| 遗忘 | 如何淘汰 | TTL、容量上限、低分淘汰 |

## 4.4 一个最小会话记忆示例

下面示例演示"按会话隔离 + 窗口截断 + 摘要"的基本骨架，仅用于建立直觉。

```java
public class SessionMemory {

    private final Map<String, Deque<Message>> sessions = new ConcurrentHashMap<>();
    private final int maxMessages;
    private final Summarizer summarizer;

    public SessionMemory(int maxMessages, Summarizer summarizer) {
        this.maxMessages = maxMessages;
        this.summarizer = summarizer;
    }

    public void append(String sessionId, Message message) {
        Deque<Message> history =
                sessions.computeIfAbsent(sessionId, id -> new ArrayDeque<>());
        history.addLast(message);
        compressIfNeeded(history);
    }

    private void compressIfNeeded(Deque<Message> history) {
        if (history.size() <= maxMessages) {
            return;
        }
        List<Message> overflow = new ArrayList<>();
        while (history.size() >= maxMessages) {
            Message oldest = history.pollFirst();
            if (oldest == null) {
                break;
            }
            overflow.add(oldest);
        }
        if (!overflow.isEmpty()) {
            history.addFirst(Message.system("[摘要] " + summarizer.summarize(overflow)));
        }
    }
}
```

> 生产环境还需补充持久化、并发控制、TTL 过期与摘要的幂等性。

# 5. 关键知识点速览

## 5.1 核心结论

- 上下文窗口是"工作内存"，长期记忆是"硬盘"。
- 会话管理 = 会话标识 + 历史存储 + 上下文组装 + 过期策略。
- 上下文压缩是长对话与长任务能跑下去的刚需。
- 记忆不是越多越好，召回精度与去重同样重要。
- 生产环境必须处理会话并发、隔离与持久化。

## 5.2 术语表

| 术语 | 含义 |
|------|------|
| 短期记忆 | 当前会话内的消息历史 |
| 长期记忆 | 跨会话持久化的用户与经验信息 |
| 情景记忆 | 具体事件与交互经历 |
| 语义记忆 | 抽象事实与知识 |
| 程序性记忆 | 技能、流程与操作方式 |
| 上下文压缩 | 在保留关键信息前提下缩短上下文 |
| 召回 | 从记忆中取出相关内容注入上下文 |
| 遗忘 | 主动或被动地淘汰低价值记忆 |
