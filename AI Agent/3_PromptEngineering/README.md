# 1. 模块定位

## 1.1 本模块解决什么问题

提示工程（Prompt Engineering）是与大模型交互的"第一性技能"，也是 Agent 行为的直接控制手段。本模块从基础写法讲到推理范式，再讲到企业级 Prompt 管理，回答三个核心问题：

- 如何写出模型能稳定理解的指令？
- 如何让模型完成多步推理与工具调用？
- 如何把 Prompt 当作可版本化的资产来管理？

Prompt 不是"随便问一句"，而是对模型输出概率分布的引导。理解了这一点，才能明白为什么结构、示例、上下文与版本管理都会显著影响效果。

## 1.2 在整体知识体系中的位置

```
   2_LLM ──► 3_PromptEngineering ──► 6_AgentCore
                    │
                    ├──► 4_LLMEngineering
                    ├──► 12_Evaluation
                    └──► 15_Security
```

本模块是"模型能力"与"Agent 行为"之间的桥梁：向下依赖对模型原理的理解，向上支撑 Agent、评测与安全。学习顺序上，它通常排在模型基础之后、Agent 核心之前。

## 1.3 与其他模块的边界

| 相邻模块 | 本模块负责 | 对方负责 |
|----------|------------|----------|
| `2_LLM` | 如何写指令 | 模型原理与训练 |
| `4_LLMEngineering` | Prompt 内容设计 | 版本化工程实现 |
| `6_AgentCore` | ReAct 提示写法 | Agent 运行时框架 |
| `12_Evaluation` | 用评测驱动 Prompt | 评测体系与指标 |
| `15_Security` | 注入防御提示 | 安全策略与网关 |

明确边界可以避免重复学习：本模块关注"怎么写"，相邻模块关注"怎么工程化与怎么评测"。

## 1.4 本模块的学习产出

学完本模块，你应该能交付以下产出：

| 产出 | 说明 |
|------|------|
| 结构化模板库 | 按角色与用途组织、可复用的 Prompt |
| 推理范式对照表 | CoT / Self-Consistency / ToT / ReAct 的适用场景 |
| 结构化输出规范 | 带 JSON Schema 约束的输出模板 |
| Prompt 管理方案 | 版本、注册、灰度、回滚、审计五件套 |
| A/B 实验设计 | 离线评测集 + 线上分流 + 显著性检验 |

# 2. 学习目标

## 2.1 能力目标

- 掌握结构化、可复用的 Prompt 写法。
- 掌握 CoT、ReAct、ToT 等推理提示范式。
- 理解上下文工程与 Prompt 注入风险。
- 能把 Prompt 当作"可版本化的资产"进行管理。

## 2.2 分层目标

| 层次 | 目标 | 对应文件 |
|------|------|----------|
| 入门 | 会写清晰、结构化的指令 | 1 到 3 |
| 进阶 | 会设计推理与工具调用提示 | 4 到 7 |
| 工程 | 会做结构化输出与上下文优化 | 8 到 11 |
| 安全与管理 | 会防注入、做版本与 A/B | 12 到 14 |

## 2.3 自检清单

学完后可用下面的清单自检：

- 能否说清 system、user、assistant 三种角色各自的职责？
- 能否为一个任务写出零样本与少样本两版提示并解释差异？
- 能否说明 CoT 为什么能提升多步推理？
- 能否在 ReAct 中区分"推理"与"行动"两步？
- 能否为一个输出设计 JSON Schema 并处理解析失败？
- 能否识别一段 Prompt 中的注入风险并给出防御方案？
- 能否为一个 Prompt 建立版本、灰度和回滚机制？
- 能否设计一个带统计显著性检验的 A/B 实验？

## 2.4 推荐学习方式

- 先读后改：读完一篇，立即用真实任务改写一次。
- 对照实验：同一任务写两版，用评测或 A/B 对比。
- 沉淀模板：把有效写法整理进个人模板库。
- 复盘误区：记录失败案例，比记录成功案例更有价值。

# 3. 文件清单

## 3.1 基础篇

| 文件 | 大纲 |
|------|------|
| `1_prompt_basics.md` | Prompt 是什么、模型如何理解指令、常见误区 |

基础篇的目标是建立"指令-结构-示例"的基本直觉。建议边读边改，用同一个任务尝试不同写法，并记录效果差异。

## 3.2 推理范式篇

| 文件 | 大纲 |
|------|------|
| `4_chain_of_thought.md` | 思维链、零样本 CoT、显式推理与答案抽取 |
| `5_self_consistency.md` | 多路径采样投票、多数表决、适用场景 |

# 5. 关键知识点速览

## 5.1 核心结论

- Prompt 是"对概率分布的引导"，不是传统编程。
- CoT 提升推理，ReAct 打通"思考-行动"闭环。
- 上下文工程 = 决定"给模型看什么"，比单纯改措辞更重要。
- Prompt 必须版本化、可回滚、可评测。
- 只要 Prompt 里拼接了外部内容，就存在注入风险。

## 5.2 常见误区

| 误区 | 纠正 |
|------|------|
| 措辞越华丽效果越好 | 结构清晰比辞藻更重要 |
| 一次改很多点 | 一次只改一个变量 |
| 凭感觉判断优劣 | 用 A/B 与评测数据 |
| Prompt 不用版本管理 | 与代码同等对待 |
| 模型能自动忽略恶意内容 | 需显式防御注入 |

## 5.3 一页速查表

| 主题 | 一句话记住 |
|------|------------|
| 结构 | 角色分工 + 分隔符 + 格式约束 |
| 少样本 | 示例要典型、均衡、不与评测集重复 |
| CoT | 让模型先推理再给答案 |
| Self-Consistency | 多次采样，投票取多数 |
| ReAct | 推理与行动交替，直到得到答案 |
| ToT | 把推理变成树搜索，按需回溯 |
| 结构化输出 | 用 Schema 约束字段与类型 |
| 上下文工程 | 优先放最相关、最新的信息 |
| 注入防御 | 外部内容一律视为不可信数据 |
| 管理 | 版本、注册、灰度、回滚、审计 |
| A/B | 先离线后线上，做显著性检验 |

## 5.4 记忆口诀

```
结构先行，推理分层；
上下文为王，注入必防；
版本可回滚，效果靠数据。
```
