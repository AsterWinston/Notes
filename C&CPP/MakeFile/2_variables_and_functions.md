Makefile 一旦超过二十行，重复的编译器、重复的选项、重复的文件列表就会到处都是。变量和函数是让 Makefile 从"能跑"变成"可维护"的第一道分水岭。本篇重点讲清四种赋值的**展开时机**差异——它是绝大多数"变量值怎么不对"问题的根因。

# 1. 为什么需要变量

## 1.1 从重复说起

没有变量时，`g++ -std=c++17 -Wall -Wextra -O2` 这样的选项要在每条规则里重复一遍。想加一个 `-g`，得改三处；漏改一处，不同目标文件的编译选项就不一致，链接时可能出现难以定位的 ABI 问题。用变量改写：

```makefile
CXX      := g++
CXXFLAGS := -std=c++17 -Wall -Wextra -O2

main.o: main.cpp
	$(CXX) $(CXXFLAGS) -c main.cpp -o main.o

user.o: user.cpp
	$(CXX) $(CXXFLAGS) -c user.cpp -o user.o
```

★ **关键认知**：Makefile 的变量本质是**文本替换**，不是编程语言里的类型化变量。`$(CXXFLAGS)` 展开后就是一段字符串，Make 不关心它是文件名、选项还是命令。理解"文本替换"这四个字，后面的展开时机就顺理成章了。

## 1.2 引用语法与命名

引用变量可以用 `$(NAME)`，也可以用等价的 `${NAME}`。单字符变量可以简写成 `$X`，如 `$@`、`$<`；多字符变量必须加括号。

变量名可以包含几乎任意字符，但工程上建议只用字母、数字和下划线，全大写表示全局配置，小写表示局部或函数参数。

⚠ **关键认知**：`$CXXFLAGS` 只会展开成 `$C` 后面跟字面量 `XXFLAGS`，因为 Make 只把 `$` 后的**单个字符**当作变量名。多字符变量必须写 `$(CXXFLAGS)`，这个错误不会报错，只会静默产生空值，极难排查。

# 2. 四种赋值

## 2.1 递归展开 `=`

```makefile
OPT      = -O2
CXXFLAGS = $(OPT) -g
```

`=` 定义的是**递归展开变量**（recursive variable）：赋值号右边的内容被原样存起来，直到变量被**引用**时才展开。

```makefile
A = $(B)
B = one

all:
	@echo $(A)   # 输出 one
```

因为 `A` 在引用时才去查 `B` 的当前值，所以如果在引用前把 `B` 改成 `two`，输出就会变成 `two`。

## 2.2 简单展开 `:=`

```makefile
A := $(B)
B := one

all:
	@echo $(A)   # 输出空，因为赋值时 B 还不存在
```

`:=` 定义的是**简单展开变量**（simply expanded variable）：赋值号右边在**定义的那一刻**就展开完毕，之后不再变化。

## 2.3 条件赋值 `?=`

```makefile
CXX ?= g++
```

只有当变量**尚未定义**时才赋值。常用于提供默认值，同时允许外部环境或命令行覆盖：

```bash
CXX=clang++ make
```

## 2.4 追加赋值 `+=`

```makefile
CXXFLAGS := -O2
CXXFLAGS += -g
```

追加的行为取决于变量原本是哪种类型：

| 原变量类型 | `+=` 的行为 |
|------------|-------------|
| 简单展开（`:=`） | 右边立即展开，再追加 |
| 递归展开（`=`） | 右边原样追加，留到引用时展开 |
| 未定义 | 等价于 `=`，即递归展开 |

## 2.5 四种赋值对比

| 运算符 | 名称 | 右边何时展开 | 典型用途 |
|--------|------|--------------|----------|
| `=` | 递归展开 | 每次引用时 | 值依赖后续变量定义 |
| `:=` | 简单展开 | 定义时立即展开 | 大多数场景，行为可预测 |
| `?=` | 条件赋值 | 视原类型 | 提供可被覆盖的默认值 |
| `+=` | 追加 | 视原类型 | 累积选项、追加源文件 |

★ **关键认知**：**默认优先用 `:=`**。它的值在定义时就固定，读代码时不用在脑子里模拟展开链条。只有当你确实需要"延迟到使用时才求值"（例如后面才定义的变量、需要每次重新执行 `$(shell)`），才用 `=`。

# 3. 展开时机与经典坑

## 3.1 递归变量在引用时才展开

```makefile
TARGET = $(OBJ)
OBJ    = main.o
```

如果反过来用 `:=` 而 `OBJ` 还没定义，就会得到空值。这是"顺序敏感"的典型例子。

## 3.2 `$(shell)` 被重复执行

```makefile
BUILD_TIME  = $(shell date +%Y-%m-%d)   # 每次引用都执行一次 date
BUILD_TIME := $(shell date +%Y-%m-%d)   # 只执行一次，结果固定
```

如果这个变量在十条规则里被引用，`=` 版本会调用十次 `date`，不仅慢，还可能因为跨秒而得到不一致的值。

## 3.3 命令行与环境变量的优先级

Make 查找变量值有优先级顺序，从高到低大致是：**命令行覆盖（`make CFLAGS=-O3`）> Makefile 中的赋值 > 环境变量 > Make 内置默认值**。如果希望 Makefile 里的值不被命令行覆盖，用 `override`：

```makefile
override CFLAGS += -Wall
```

⚠ **关键认知**：`make CFLAGS=-O3` 会覆盖 Makefile 里的所有 `CFLAGS` 赋值（包括 `+=`），除非加了 `override`。调试"为什么我的选项没生效"时，先确认命令行有没有传同名变量。

# 4. 自动变量

自动变量是 Make 在**执行每条规则时**自动填好的"当前上下文"，只能在命令中使用。

## 4.1 常用自动变量

| 变量 | 含义 |
|------|------|
| `$@` | 当前目标名 |
| `$<` | 第一个依赖 |
| `$^` | 所有依赖，去重，以空格分隔 |
| `$+` | 所有依赖，保留重复 |
| `$?` | 比目标新的依赖 |
| `$*` | 模式规则中 `%` 匹配到的词干 |

## 4.2 使用示例

```makefile
CXX := g++

app: main.o util.o
	$(CXX) $^ -o $@      # 等价于 g++ main.o util.o -o app

main.o: main.cpp
	$(CXX) -c $< -o $@   # 等价于 g++ -c main.cpp -o main.o
```

★ **关键认知**：自动变量让规则可以**脱离具体文件名**书写。`$<` 和 `$@` 让同一条模式规则适用于任意 `.cpp`，这是第 3 篇模式规则能成立的基础。

# 5. 常用函数

函数调用语法是 `$(函数名 参数1,参数2,...)`，参数之间用逗号分隔。

## 5.1 文本处理

```makefile
SRCS := main.cpp util.cpp order.cpp

OBJS1 := $(SRCS:.cpp=.o)                 # 后缀替换简写
OBJS2 := $(patsubst %.cpp,%.o,$(SRCS))   # 等价的通用写法
NAME  := $(strip   alice   bob  )        # 去掉首尾空白并合并中间空白
```

常用文本函数速查：

| 函数 | 作用 |
|------|------|
| `subst 旧,新,文本` | 字面替换 |
| `patsubst 模式,替换,文本` | 按 `%` 模式替换 |
| `strip 文本` | 去首尾空白、压缩中间空白 |
| `findstring 子串,文本` | 查找子串，返回子串或空 |
| `filter 模式...,文本` | 保留匹配项 |
| `filter-out 模式...,文本` | 排除匹配项 |
| `sort 列表` | 排序并去重 |
| `word n,文本` | 取第 n 个单词 |
| `words 文本` | 统计单词个数 |

## 5.2 文件名处理

```makefile
FILES := src/main.cpp src/util.cpp

DIRS  := $(dir $(FILES))        # src/ src/
NAMES := $(notdir $(FILES))     # main.cpp util.cpp
BASE  := $(basename $(NAMES))   # main util
SUFF  := $(suffix $(NAMES))     # .cpp .cpp
ALL_C := $(wildcard src/*.cpp)  # 展开当前存在的文件
```

`wildcard` 是在 Makefile 里获取文件列表的标准方式，它发生在读取阶段。

⚠ **关键认知**：`wildcard` 只匹配**执行 make 时真实存在**的文件。新加了一个源文件但 Makefile 没有重新读取，它不会自动出现——这不是 bug，因为 Makefile 本来就是每次 `make` 重新解析的，只要重新执行即可。

## 5.3 `shell` 函数

```makefile
GIT_HASH := $(shell git rev-parse --short HEAD 2>/dev/null)
BUILD_DIR := $(shell pwd)/build
```

`$(shell ...)` 在**读取阶段**执行命令，把标准输出中的换行替换成空格后返回。它适合取单行结果；多行输出会被压成一行，需要保留换行时，通常改为在命令里直接写文件。`shell` 函数里如果要写 `$`，必须写成 `$$`，否则会被 Make 当作变量引用。

## 5.4 控制函数

```makefile
DIRS := src lib
SRCS := $(foreach d,$(DIRS),$(wildcard $(d)/*.cpp))
```

`foreach` 的语法是 `$(foreach 变量,列表,表达式)`，对列表中每个词展开一次表达式。

`call` 用来调用自定义函数（本质是带参数的变量），`eval` 则把展开后的文本重新交给 Make 解析，二者常配合生成规则。`if` 函数适合在表达式内部做选择，例如 `MODE := $(if $(DEBUG),debug,release)`。

## 5.5 函数参数的空白陷阱

函数参数里的空格是**有意义的**。例如 `$(subst a, b,text)` 的第二个参数会变成 ` b`（带前导空格），写的时候不要为了"好看"在逗号后加空格。

# 6. 条件判断

## 6.1 `ifeq` / `ifneq` / `ifdef` / `ifndef`

```makefile
DEBUG ?= 0

ifeq ($(DEBUG),1)
CXXFLAGS += -g -O0
else
CXXFLAGS += -O2 -DNDEBUG
endif
```

四种形式：

| 指令 | 判断内容 |
|------|----------|
| `ifeq (a,b)` | 两个字符串是否相等 |
| `ifneq (a,b)` | 两个字符串是否不等 |
| `ifdef VAR` | 变量是否已定义且非空 |
| `ifndef VAR` | 变量是否未定义或为空 |

`ifeq` 也支持引号形式：`ifeq "$(DEBUG)" "1"`。

## 6.2 条件判断发生在读取阶段

条件在 Make 读取 Makefile 时就已经决定，命令里不会再有 `if` 的逻辑。

⚠ **关键认知**：条件判断**不能使用自动变量**。`$@`、`$<` 只在执行某条规则时才被赋值，而 `ifeq` 在读取阶段就要给出结果。想在规则内部按目标名分支，只能写成 shell 的 `if`，或者用变量拼接。

# 7. 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 变量展开为空 | 写成了 `$CXXFLAGS` | 改成 `$(CXXFLAGS)` |
| 值比预期少了前缀 | `+=` 追加到了递归变量，且原值未展开 | 统一改用 `:=` |
| `$(shell)` 执行很多次 | 用了 `=` 定义 | 改成 `:=` |
| 命令行传参没生效 | 被 Makefile 覆盖 | 用 `?=` 或加 `override` |
| 函数结果多出空格 | 逗号后加了空格 | 删除参数间多余空格 |
| `ifeq` 判断失效 | 变量里有隐藏空白 | 用 `$(strip ...)` 包一层 |

# 8. 动手练习

1. 用 `=` 和 `:=` 各定义一个依赖 `$(shell date +%s)` 的变量，在三条规则里引用，观察 `make -n` 输出是否一致，解释差异。
2. 把第 1 篇的 Makefile 改造成使用 `CXX`、`CXXFLAGS`、`SRCS`、`OBJS` 四个变量，要求只改一处就能把 `-O2` 换成 `-O0`。
3. 写一个 `ifeq` 分支：`make DEBUG=1` 时加入 `-g -O0`，否则加入 `-O2 -DNDEBUG`；再用 `make -n` 验证两条路径生成的命令。

# 9. 小结

| 主题 | 要点 |
|------|------|
| `=` | 引用时才展开，可能随后续定义变化 |
| `:=` | 定义时立即展开，行为可预测，优先使用 |
| `?=` | 仅在未定义时赋值 |
| `+=` | 追加，展开时机随原变量类型 |
| 自动变量 | `$@` 目标、`$<` 首个依赖、`$^` 全部依赖 |
| 函数 | 文本、文件名、`shell`、`foreach`、`call` |
| 条件 | `ifeq` 等在读取阶段求值，不能用自动变量 |
