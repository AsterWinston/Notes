函数是 C 程序的基本复用单位，也是理解调用开销、作用域和内存布局的入口。很多初学者能写出函数，却说不清"参数到底怎么传进去""局部变量放在哪""递归为什么会栈溢出"。本篇从声明与定义讲起，深入栈帧和递归，再补充可变参数与生命周期规则。

# 1. 函数基础

## 1.1 声明与定义

**声明**告诉编译器函数的签名，**定义**提供函数体：

```c
// 声明（原型）：返回类型、函数名、参数类型
int add(int a, int b);

// 定义：包含函数体
int add(int a, int b) {
    return a + b;
}
```

| 概念 | 内容 | 是否分配代码 |
|------|------|-------------|
| 声明 | 返回类型、名字、参数类型 | 否 |
| 定义 | 声明 + 函数体 | 是 |

★ **关键认知**：C 要求**先声明后使用**。把声明放在头文件、定义放在 `.c` 文件，是跨文件复用的标准做法。没有声明就调用，C99 之后属于错误。

## 1.2 参数传递

C 只有**值传递**。函数拿到的是实参的副本：

```c
#include <stdio.h>

void change(int x) {
    x = 100;           // 只改副本，不影响调用方
}

int main(void) {
    int a = 1;
    change(a);
    printf("%d\n", a); // 仍然是 1
    return 0;
}
```

想修改调用方的变量，必须传**地址**：

```c
void change(int *x) {
    *x = 100;          // 通过指针写入原变量
}

int main(void) {
    int a = 1;
    change(&a);
    printf("%d\n", a); // 100
    return 0;
}
```

★ **关键认知**：所谓"数组传参"本质上也是值传递——传的是**首元素地址的副本**。因此函数内修改数组元素会影响调用方，但修改指针本身（让它指向别处）不会。

## 1.3 返回值

```c
int add(int a, int b) {
    return a + b;      // 返回值通过寄存器或栈传回调用方
}

void print_hello(void) {
    printf("hello\n"); // 无返回值
}
```

⚠ **关键认知**：声明了非 `void` 返回类型却"走到末尾没有 `return`"，在 `main` 之外是未定义行为。`-Wreturn-type` 会给出警告，不要忽略。

# 2. 栈帧

## 2.1 调用过程

每次函数调用都会在栈上分配一块区域，叫**栈帧**（stack frame），保存参数、返回地址和局部变量。

```text
调用 add(1, 2) 的过程：
1. 调用方把参数放入寄存器或压栈
2. 执行 call 指令，把返回地址压栈
3. 被调函数保存旧栈帧指针，建立新栈帧
4. 执行函数体
5. 恢复栈帧，ret 返回到返回地址
```

## 2.2 栈帧布局

x86-64 下典型布局（地址从高到低）：

```text
高地址
┌──────────────────────┐
│ 调用方的栈帧          │
├──────────────────────┤
│ 参数（超出寄存器部分）│
├──────────────────────┤
│ 返回地址              │  ← call 指令压入
├──────────────────────┤
│ 保存的 rbp            │  ← 被调函数压入
├──────────────────────┤
│ 局部变量              │
│ ...                  │
└──────────────────────┘
低地址
```

★ **关键认知**：栈的大小有限（Linux 默认约 8 MB），且**函数返回后栈帧立即失效**。返回局部变量的地址，得到的是指向已释放栈内存的悬空指针。

```c
int *bad(void) {
    int x = 42;
    return &x;      // 错误：x 随栈帧销毁
}

int *good(void) {
    static int x = 42;  // 静态存储期，函数返回后仍有效
    return &x;
}
```

# 3. 递归

## 3.1 递归三要素

递归函数必须包含：

1. **终止条件**：什么时候不再递归。
2. **递归调用**：把问题缩小后调用自身。
3. **状态收敛**：每次调用都向终止条件靠近。

```c
#include <stdio.h>

int factorial(int n) {
    if (n <= 1) {
        return 1;              // 终止条件
    }
    return n * factorial(n - 1); // 递归调用，n 逐步减小
}

int main(void) {
    printf("%d\n", factorial(5)); // 120
    return 0;
}
```

调用展开：

```text
factorial(5)
└── 5 * factorial(4)
    └── 4 * factorial(3)
        └── 3 * factorial(2)
            └── 2 * factorial(1)
                └── 1
```

## 3.2 递归的代价

| 维度 | 递归 | 迭代 |
|------|------|------|
| 可读性 | 树、分治等问题更直观 | 线性问题更直接 |
| 空间 | 每层一个栈帧，O(n) | 通常 O(1) |
| 风险 | 深度过大导致栈溢出 | 无栈溢出风险 |
| 性能 | 有调用开销 | 通常更快 |

★ **关键认知**：递归不是"更高级的循环"。当递归深度可能达到十万级时，即使逻辑正确也会栈溢出。尾递归在部分语言能被优化成循环，但 **C 标准不保证尾调用优化**，不要依赖它。

⚠ **关键认知**：`fib(n) = fib(n-1) + fib(n-2)` 的朴素递归复杂度是 O(2^n)，`fib(40)` 就要算上亿次。改用迭代或记忆化，是递归优化的第一课。

# 4. 可变参数

C 用 `<stdarg.h>` 支持可变参数，最典型的是 `printf`：

```c
#include <stdarg.h>
#include <stdio.h>

int sum(int count, ...) {
    va_list ap;
    va_start(ap, count);   // 从最后一个固定参数开始

    int total = 0;
    for (int i = 0; i < count; ++i) {
        total += va_arg(ap, int); // 按 int 读取下一个参数
    }

    va_end(ap);            // 清理
    return total;
}

int main(void) {
    printf("%d\n", sum(3, 10, 20, 30)); // 60
    return 0;
}
```

★ **关键认知**：可变参数**没有类型检查**，读取类型必须与传入类型一致。把 `double` 当 `int` 读，或数量对不上，都会得到垃圾值甚至崩溃。现代代码应优先用"数组 + 长度"或结构体替代可变参数。

# 5. 作用域与生命周期

## 5.1 作用域

作用域决定"名字在哪里可见"：

| 作用域 | 范围 | 示例 |
|--------|------|------|
| 块作用域 | `{}` 内 | 函数内局部变量 |
| 函数作用域 | 整个函数 | `goto` 标签 |
| 文件作用域 | 整个源文件 | 全局变量、函数 |
| 函数原型作用域 | 参数列表中 | 原型里的参数名 |

## 5.2 存储期

存储期决定"对象活多久"：

| 存储期 | 关键字 | 生命周期 | 典型对象 |
|--------|--------|----------|----------|
| 自动 | 无（默认） | 所在块结束 | 局部变量 |
| 静态 | `static` | 整个程序 | 全局变量、静态局部变量 |
| 动态 | `malloc` / `free` | 手动控制 | 堆对象 |

```c
void counter(void) {
    static int n = 0;  // 只初始化一次，跨调用保持
    ++n;
    printf("%d\n", n);
}
```

★ **关键认知**：`static` 修饰局部变量改变的是**存储期**，不是作用域。变量仍然只在函数内可见，但值会一直保留到程序结束。

⚠ **关键认知**：全局变量默认具有外部链接，其他文件可以通过 `extern` 访问；加 `static` 后变成内部链接，仅本文件可见。头文件里定义变量（而非声明）会导致多重定义错误。

# 6. 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 忘记声明 | 隐式声明警告或错误 | 先声明后使用，或包含头文件 |
| 返回局部变量地址 | 悬空指针，值随机 | 返回 `static`、堆内存或由调用方传入缓冲区 |
| 递归无终止条件 | 栈溢出 | 补终止条件并确保收敛 |
| 递归深度过大 | 段错误 | 改迭代或显式栈 |
| 可变参数类型不匹配 | 读到垃圾值 | 严格保证类型与数量一致 |
| 原型与定义不一致 | 链接失败或调用错乱 | 让定义与声明完全一致 |

⚠ **关键认知**：函数原型里写 `int f()` 表示"参数未指定"，不是"无参数"。无参数要写 `int f(void)`，这样才能让编译器检查调用时是否多传了参数。

# 8. 小结

| 概念 | 要点 |
|------|------|
| 声明与定义 | 声明给签名，定义给函数体 |
| 参数传递 | 只有值传递，改外部变量要传地址 |
| 栈帧 | 每次调用分配，返回即失效 |
| 递归 | 终止条件、递归调用、状态收敛三要素 |
| 可变参数 | 无类型检查，数量与类型必须自洽 |
| 作用域 | 名字可见范围，块、函数、文件 |
| 存储期 | 对象存活时间，自动、静态、动态 |
