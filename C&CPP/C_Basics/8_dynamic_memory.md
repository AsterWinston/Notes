栈上的变量随作用域自动分配和释放，但程序经常需要在运行时决定大小、或让数据活过函数调用。这时就要用堆内存。堆给了程序员最大的自由，也把所有责任一并交了出来：泄漏、悬空、双重释放、越界，每一种都能让程序在看似无关的地方崩溃。本篇把四个核心函数和四类典型错误讲透。

# 1. 堆内存

## 1.1 为什么需要堆

| 存储区 | 分配方式 | 生命周期 | 大小确定时机 |
|--------|----------|----------|-------------|
| 栈 | 自动 | 作用域结束 | 编译期 |
| 静态区 | 全局/`static` | 程序结束 | 编译期 |
| 堆 | `malloc` 系列 | 手动释放 | 运行期 |

```text
高地址
┌──────────────────────┐
│        栈            │  局部变量，向下增长
├──────────────────────┤
│                      │
│        堆            │  malloc 分配，向上增长
├──────────────────────┤
│    .bss / .data      │  全局与静态变量
├──────────────────────┤
│    .text             │  代码
└──────────────────────┘
低地址
```

★ **关键认知**：堆内存不会自动回收。函数返回只销毁栈帧，不会释放 `malloc` 出来的内存。只要忘了 `free`，这块内存就一直被占用，直到进程结束。

## 1.2 malloc 与 free

```c
#include <stdlib.h>

int *p = malloc(10 * sizeof(int)); // 申请 10 个 int
if (p == NULL) {
    // 申请失败，必须处理
    return -1;
}

p[0] = 1;
free(p);      // 释放
p = NULL;     // 置空，防止悬空
```

要点：

- `malloc` 返回 `void *`，C 中可隐式转换为任意指针类型，**不需要强转**。
- 参数是**字节数**，习惯写法是 `n * sizeof(*p)`，避免类型改动后漏改。
- 失败返回 `NULL`，必须检查。
- `free(NULL)` 是安全的，什么都不做。
- `free` 后指针不会自动置空。

★ **关键认知**：`malloc(0)` 的行为由实现定义，可能返回 `NULL`，也可能返回一个不可解引用的非空指针。无论哪种，都应该配对 `free`，且不要解引用。

## 1.3 calloc 与 realloc

```c
int *a = calloc(10, sizeof(int)); // 申请并清零
int *b = realloc(a, 20 * sizeof(int)); // 扩容到 20 个
```

| 函数 | 是否清零 | 用途 |
|------|----------|------|
| `malloc` | 否，内容不确定 | 一般申请 |
| `calloc` | 是，全零 | 需要初始为 0 的数组 |
| `realloc` | 保留旧内容 | 调整已分配块大小 |

`realloc` 的陷阱在于**原指针可能失效**：

```c
int *tmp = realloc(a, new_size);
if (tmp == NULL) {
    // 扩容失败，a 仍然有效，需要保留并释放
    free(a);
    return -1;
}
a = tmp;   // 成功后才覆盖原指针
```

⚠ **关键认知**：不要写 `a = realloc(a, n)`。一旦失败，`realloc` 返回 `NULL`，而原来的 `a` 仍然有效，直接覆盖会导致**内存泄漏**。

# 2. 生命周期

```c
void use(void) {
    int *p = malloc(sizeof(int)); // 堆块开始
    *p = 42;
    free(p);                      // 堆块结束
    // *p 此后再访问就是悬空指针
}
```

```text
malloc ──► 可用 ──► free ──► 不可用
              │                 │
              └── 可读写         └── 再访问即 UB
```

★ **关键认知**：判断一个指针能否解引用，只看**它指向的存储期是否还在**。栈指针看作用域，堆指针看是否已 `free`。这两条规则能解释绝大多数指针崩溃。

# 3. 典型错误

## 3.1 内存泄漏

申请了却从未释放：

```c
void leak(void) {
    int *p = malloc(100 * sizeof(int));
    // 忘记 free，函数返回后指针丢失，内存再也无法释放
}
```

循环里更容易累积：

```c
for (int i = 0; i < 1000000; ++i) {
    char *buf = malloc(1024);
    // 忘记 free，累计泄漏约 1 GB
}
```

| 后果 | 表现 |
|------|------|
| 内存占用持续上升 | 长时间运行后 OOM |
| 性能下降 | 分配器碎片增多 |
| 难以定位 | 泄漏点与崩溃点相距很远 |

## 3.2 悬空指针

内存已释放，指针仍被使用：

```c
int *p = malloc(sizeof(int));
free(p);
*p = 1;          // 悬空指针，未定义行为
```

正确做法：

```c
free(p);
p = NULL;        // 置空后至少能在解引用时立刻崩溃，便于定位
```

## 3.3 双重释放

同一块内存释放两次：

```c
int *p = malloc(sizeof(int));
free(p);
free(p);         // 双重释放，堆结构被破坏
```

⚠ **关键认知**：双重释放会破坏分配器的内部链表，可能在**下一次 `malloc` 时**才崩溃，而且崩溃位置与错误位置无关。`free` 后置 `NULL` 能让第二次 `free(NULL)` 变成安全的空操作。

## 3.4 越界访问

```c
int *p = malloc(10 * sizeof(int));
p[10] = 1;       // 越界写，破坏堆块头或相邻块
free(p);
```

堆越界往往不会立刻报错，而是在后续 `free` 时被分配器检测到，报出 `heap corruption`。

## 3.5 错误配对

| 错误 | 后果 |
|------|------|
| `free` 栈地址 | 崩溃 |
| `free` 栈地址 + 偏移 | 崩溃或破坏堆 |
| `free` 全局数组 | 崩溃 |
| `free` 后再次 `free` | 双重释放 |
| 用 `delete` 释放 `malloc`（C++ 混用） | 未定义行为 |

★ **关键认知**：`malloc` 与 `free`、`new` 与 `delete` 必须严格配对。C 代码里不要出现 `delete`，C++ 代码里不要用 `free` 释放 `new` 出来的对象。

# 4. 调试方法

## 4.1 AddressSanitizer

GCC 与 Clang 都支持，能在越界、释放后使用、双重释放发生时立刻报错：

```bash
gcc -g -fsanitize=address -fno-omit-frame-pointer demo.c -o demo
./demo
```

输出会包含错误类型、访问地址和完整调用栈，是定位内存问题的首选工具。

## 4.2 Valgrind

Linux 下的动态分析工具，不需要重新编译：

```bash
valgrind --leak-check=full ./demo
```

| 工具 | 平台 | 优点 | 缺点 |
|------|------|------|------|
| AddressSanitizer | 跨平台 | 快、报错精确 | 需要重新编译 |
| Valgrind | Linux | 无需改编译 | 慢，平台受限 |
| MSVC CRT 调试堆 | Windows | 集成 Visual Studio | 仅 Windows |

## 4.3 编码习惯

| 习惯 | 作用 |
|------|------|
| 申请后立即检查 `NULL` | 避免空指针解引用 |
| `free` 后置 `NULL` | 避免悬空与双重释放 |
| 谁申请谁释放 | 明确所有权 |
| 用 `n * sizeof(*p)` | 避免字节数算错 |
| 函数出口统一清理 | 配合 `goto cleanup` |

★ **关键认知**：内存管理的第一原则是**明确所有权**。一块内存由谁负责释放，必须在接口设计时就写清楚，否则调用双方都以为对方会释放，或者都释放一次。

# 5. 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 忘记检查 `NULL` | 空指针崩溃 | 申请后立即判断 |
| `a = realloc(a, n)` | 失败时泄漏 | 用临时指针接收 |
| 忘记 `free` | 内存持续增长 | 配对释放，或用 ASan 检测 |
| `free` 后使用 | 随机崩溃 | 置 `NULL` |
| 双重释放 | 堆损坏 | 置 `NULL`，明确所有权 |
| 越界写 | 堆损坏 | 严格检查下标 |
| 释放非堆地址 | 崩溃 | 只 `free` `malloc` 返回值 |

⚠ **关键认知**：`sizeof(pointer)` 永远是指针大小，不是它指向的数组大小。`malloc(sizeof(p))` 只会分配 8 字节，这是动态内存里最常见的低级错误之一。

# 6. 动手练习

1. 写一个动态数组，支持追加元素和自动扩容，用 `realloc` 实现，并处理扩容失败。
2. 故意制造一次内存泄漏和一次双重释放，分别用 AddressSanitizer 和 Valgrind 定位。
3. 实现一个链表，确保每个节点在删除时都被释放，最后用 `--leak-check=full` 验证零泄漏。

# 7. 小结

| 概念 | 要点 |
|------|------|
| 堆 | 运行期分配，手动释放，不随作用域回收 |
| `malloc` | 分配未初始化内存，失败返回 `NULL` |
| `calloc` | 分配并清零 |
| `realloc` | 调整大小，用临时指针接收结果 |
| `free` | 只释放，不置空，`free(NULL)` 安全 |
| 泄漏 | 申请后丢失指针，无法释放 |
| 悬空指针 | 释放后继续使用 |
| 双重释放 | 破坏堆结构，置 `NULL` 可防 |
| 调试 | AddressSanitizer 优先，Valgrind 补充 |
