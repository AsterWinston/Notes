C 的类型系统看着不复杂，但整数宽度、有符号与无符号混合运算、浮点精度、运算符优先级，每一条都能让程序在"编译通过"的前提下悄悄算错。本篇把基本类型、`sizeof`、溢出、转换规则和运算符优先级逐一拆开，重点讲清楚那些让初学者困惑的现象背后的机制。

# 1. 基本类型

## 1.1 整数类型

C 的整数类型宽度不是完全固定的，标准只规定了**最小范围**，具体字节数由实现决定。

| 类型 | 典型宽度（64 位） | 最小范围 | 说明 |
|------|------------------|----------|------|
| `char` | 1 字节 | 至少 8 位 | 是否带符号由实现决定 |
| `signed char` | 1 字节 | -127 ~ 127 | 明确带符号 |
| `unsigned char` | 1 字节 | 0 ~ 255 | 明确无符号 |
| `short` | 2 字节 | -32767 ~ 32767 | 至少 16 位 |
| `int` | 4 字节 | -32767 ~ 32767 | 至少 16 位，通常 32 位 |
| `long` | 4 或 8 字节 | 至少 32 位 | Windows 为 4 字节，Linux 为 8 字节 |
| `long long` | 8 字节 | 至少 64 位 | C99 引入 |
| `size_t` | 8 字节 | 无符号 | `sizeof` 的返回类型 |

★ **关键认知**：不要假设 `int` 一定是 4 字节、`long` 一定是 8 字节。需要**精确宽度**时用 `<stdint.h>` 里的 `int32_t`、`uint64_t` 等类型，这是跨平台代码的基本纪律。

```c
#include <stdint.h>

int32_t count = 100;      // 明确 32 位有符号
uint64_t total = 0;       // 明确 64 位无符号
```

## 1.2 sizeof 运算符

`sizeof` 在编译期求值，返回类型是 `size_t`，单位是**字节**。

```c
#include <stdio.h>

int main(void) {
    printf("char      = %zu\n", sizeof(char));
    printf("int       = %zu\n", sizeof(int));
    printf("long      = %zu\n", sizeof(long));
    printf("long long = %zu\n", sizeof(long long));
    printf("pointer   = %zu\n", sizeof(void *));
    printf("size_t    = %zu\n", sizeof(size_t));
    return 0;
}
```

注意 `sizeof` 的几个易错点：

```c
int a[10];
size_t n1 = sizeof(a);        // 40，整个数组
size_t n2 = sizeof(a[0]);     // 4，一个元素
size_t n3 = sizeof(a) / sizeof(a[0]); // 10，元素个数
```

⚠ **关键认知**：`sizeof` 对数组和指针的结果完全不同。数组名在 `sizeof` 里**不会退化**为指针；但一旦作为函数参数传入，数组就退化成指针，`sizeof` 只剩下指针大小。

```c
void f(int arr[10]) {
    // 这里 sizeof(arr) 是 8，不是 40
}
```

## 1.3 整数溢出

有符号整数溢出是**未定义行为**（UB），编译器可以假设它不会发生，从而做出各种优化；无符号整数溢出则按模 2^n 回绕，是定义良好的。

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int max = INT_MAX;
    // max + 1 是有符号溢出，属于未定义行为
    printf("%d\n", max);

    unsigned int u = UINT_MAX;
    u = u + 1; // 无符号回绕，结果一定是 0
    printf("%u\n", u);
    return 0;
}
```

★ **关键认知**：判断溢出要在**运算之前**做，不能等算完再看结果。例如检查 `a + b` 是否溢出，应写成 `if (b > 0 && a > INT_MAX - b)`。

# 2. 有符号与无符号

## 2.1 转换规则

当有符号与无符号混合运算时，C 的"寻常算术转换"会把有符号数转成无符号数：

```text
int + unsigned int
      │
      ▼
int 被转换为 unsigned int
      │
      ▼
按无符号规则计算，负数变成很大的正数
```

```c
#include <stdio.h>

int main(void) {
    int a = -1;
    unsigned int b = 1;

    if (a < b) {
        printf("数学上 -1 < 1\n");
    } else {
        printf("-1 被转成无符号，变成了很大的数\n");
    }
    return 0;
}
```

实际输出是第二句，因为 `-1` 转成 `unsigned int` 后等于 `4294967295`。

## 2.2 经典陷阱

```c
// 错误写法：无符号减到负数后回绕，循环几乎不会结束
for (unsigned int i = 10; i >= 0; --i) {
    // i 永远 >= 0，条件恒真
}
```

正确写法有两种：

```c
// 写法一：用有符号类型
for (int i = 10; i >= 0; --i) {
    // ...
}

// 写法二：用"大于 0 再减"的形式
for (unsigned int i = 10; i > 0; --i) {
    // 处理 10..1
}
```

★ **关键认知**：只要参与比较的一方是无符号，整个表达式就按无符号比较。把 `-Wall -Wextra` 打开，GCC 和 Clang 会对 `signed` 与 `unsigned` 比较给出警告，这是最划算的防线。

# 3. 浮点数

## 3.1 表示与精度

C 提供三种浮点类型，遵循 IEEE 754：

| 类型 | 典型宽度 | 有效十进制位 | 范围（约） |
|------|----------|-------------|-----------|
| `float` | 4 字节 | 6 ~ 7 位 | ±3.4e38 |
| `double` | 8 字节 | 15 ~ 16 位 | ±1.8e308 |
| `long double` | 8 / 16 字节 | 平台相关 | 平台相关 |

浮点数用"符号位 + 指数 + 尾数"表示，很多十进制小数无法精确存储：

```c
#include <stdio.h>

int main(void) {
    double a = 0.1;
    double b = 0.2;
    double c = a + b;

    printf("%.17f\n", c);        // 0.30000000000000004
    printf("%d\n", c == 0.3);    // 0
    return 0;
}
```

## 3.2 浮点比较

不要用 `==` 直接比较浮点数，应判断差值是否小于一个容差：

```c
#include <math.h>

int nearly_equal(double a, double b) {
    return fabs(a - b) < 1e-9; // 容差按业务精度选择
}
```

⚠ **关键认知**：`NaN` 与任何值比较（包括它自己）都返回假，`NaN != NaN` 为真。判断 `NaN` 要用 `isnan()`，不能用 `x == NAN`。

# 4. 运算符

## 4.1 优先级与结合性

常见优先级从高到低：

| 优先级 | 运算符 | 结合性 |
|--------|--------|--------|
| 1 | `()` `[]` `.` `->` | 左 |
| 2 | `!` `~` `++` `--` `(type)` `*` `&` | 右 |
| 3 | `*` `/` `%` | 左 |
| 4 | `+` `-` | 左 |
| 5 | `<<` `>>` | 左 |
| 6 | `<` `<=` `>` `>=` | 左 |
| 7 | `==` `!=` | 左 |
| 8 | `&` | 左 |
| 9 | `^` | 左 |
| 10 | `\|` | 左 |
| 11 | `&&` | 左 |
| 12 | `\|\|` | 左 |
| 13 | `?:` | 右 |
| 14 | `=` 及复合赋值 | 右 |
| 15 | `,` | 左 |

★ **关键认知**：优先级表不用背全，但要知道**位运算低于比较运算**这个反直觉点。`x & 1 == 0` 实际是 `x & (1 == 0)`，应写成 `(x & 1) == 0`。

```c
if (x & 1 == 0) { }     // 错误：先算 1 == 0
if ((x & 1) == 0) { }   // 正确：先取最低位
```

## 4.2 位运算

| 运算符 | 名称 | 示例 | 结果 |
|--------|------|------|------|
| `&` | 按位与 | `0b1100 & 0b1010` | `0b1000` |
| `\|` | 按位或 | `0b1100 \| 0b1010` | `0b1110` |
| `^` | 按位异或 | `0b1100 ^ 0b1010` | `0b0110` |
| `~` | 按位取反 | `~0b1100` | 全 1 取反 |
| `<<` | 左移 | `1 << 3` | `8` |
| `>>` | 右移 | `16 >> 2` | `4` |

⚠ **关键认知**：对**有符号负数**右移的行为由实现定义，可能是算术右移也可能是逻辑右移。需要位操作时优先用无符号类型。

# 5. 类型转换

## 5.1 隐式转换

隐式转换发生在赋值、函数传参、混合运算和返回时，方向通常是"窄变宽、有符号变无符号"：

```text
char → short → int → long → long long → float → double
                     │
                     └── 有符号与无符号相遇时，转无符号
```

窄化转换会丢数据：

```c
int x = 300;
char c = (char)x;   // 300 超出 char 范围，结果由实现定义
```

## 5.2 显式转换

显式转换用强制类型转换，表达"我知道自己在做什么"：

```c
double d = 3.99;
int i = (int)d;          // 3，向零截断
size_t n = (size_t)i;    // 明确转成无符号
```

★ **关键认知**：强制转换只改变**解释方式**，不改变内存里的位。把 `float` 指针强转成 `int` 指针再解引用，属于违反严格别名规则的行为，结果不可移植。

# 6. 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 假设 `int` 是 4 字节 | 换平台后溢出 | 用 `<stdint.h>` 固定宽度 |
| 有符号与无符号比较 | 负数被判为很大 | 统一类型或加显式转换 |
| 直接比较浮点 | `0.1 + 0.2 != 0.3` | 用容差比较 |
| 位运算不写括号 | `x & 1 == 0` 逻辑错 | 给位运算加括号 |
| `sizeof` 数组当指针 | 函数内拿到 8 | 额外传长度 |
| 有符号溢出 | 优化后行为诡异 | 运算前检查边界 |

⚠ **关键认知**：`-Wall -Wextra -Wconversion` 能提前暴露大部分隐式转换问题。初学者最该养成的习惯，是让编译器替自己盯住类型。

# 8. 小结

| 概念 | 要点 |
|------|------|
| 类型宽度 | 标准只保证最小范围，精确宽度用 `<stdint.h>` |
| `sizeof` | 编译期求值，数组与指针结果不同 |
| 整数溢出 | 有符号是 UB，无符号按模回绕 |
| 有符号与无符号 | 混合运算转无符号，负数变大 |
| 浮点 | 二进制无法精确表示多数小数，用容差比较 |
| 优先级 | 位运算低于比较，务必加括号 |
| 转换 | 隐式窄化丢数据，强制转换不改内存位 |
