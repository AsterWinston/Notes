C 是一门"看起来简单、用起来凶险"的语言。它的语法规则不多，但真正决定程序能否跑起来的，是源码如何经过预处理、编译、汇编、链接变成可执行文件。本篇从 C 的定位讲起，把这条流水线完整走一遍，并给出 GCC、Clang、MSVC 三套工具链的最小命令。

# 1. C 语言的定位

## 1.1 为什么今天还要学 C

C 诞生于 1972 年，却仍然排在操作系统、嵌入式、数据库、编译器和各类运行时的核心位置。原因不是它"高级"，而是它**离硬件足够近，又比汇编可读**。

| 特性 | 含义 | 典型影响 |
|------|------|----------|
| 贴近硬件 | 能直接操作内存与寄存器映射 | 驱动、内核、单片机 |
| 静态类型 | 类型在编译期确定 | 早期发现错误，运行时开销小 |
| 手动内存管理 | 由程序员申请与释放 | 性能可控，也最容易出 bug |
| 编译为原生代码 | 无虚拟机、无解释器 | 启动快、体积小 |
| 标准统一 | C11、C17 等 ISO 标准 | 跨平台可移植 |

★ **关键认知**：C 的"简单"指的是**语言特性少**，不是**容易写对**。它把大量责任交给程序员，编译器只保证语法和类型层面的合法性，内存越界、悬空指针、未定义行为都不在保护范围内。

## 1.2 标准与编译器

本模块以 **C11 / C17** 为准。C17 主要是缺陷修复，没有引入新语法，因此两者在绝大多数代码上一致。

| 编译器 | 平台 | 常用命令 | 特点 |
|--------|------|----------|------|
| GCC | Linux、macOS、Windows（MinGW） | `gcc` | 生态最广，警告选项丰富 |
| Clang | Linux、macOS、Windows | `clang` | 报错信息友好，工具链完善 |
| MSVC | Windows | `cl` | Visual Studio 默认，Windows 原生 |

查看版本：

```bash
gcc --version
clang --version
```

# 2. 从源码到可执行文件

## 2.1 四个阶段总览

一个 `.c` 文件要变成可执行程序，通常经历四个阶段：

```text
hello.c
   │
   ▼
┌──────────────┐   展开 #include、#define，删除注释
│   预处理      │   gcc -E hello.c -o hello.i
└──────┬───────┘
       ▼
┌──────────────┐   语法分析、类型检查、生成汇编
│    编译       │   gcc -S hello.i -o hello.s
└──────┬───────┘
       ▼
┌──────────────┐   把汇编翻译成机器码，生成目标文件
│    汇编       │   gcc -c hello.s -o hello.o
└──────┬───────┘
       ▼
┌──────────────┐   合并目标文件与库，解析符号地址
│    链接       │   gcc hello.o -o hello
└──────┬───────┘
       ▼
    hello（可执行文件）
```

★ **关键认知**：编译器驱动（`gcc`、`clang`）只是**调度器**，它依次调用预处理器、编译器、汇编器和链接器。理解这四个阶段，才能看懂"为什么头文件找不到""为什么 undefined reference"这类报错的来源。

## 2.2 预处理

预处理阶段只做文本替换，不检查 C 语法。主要工作包括：

- 展开 `#include`，把头文件内容原样插入。
- 展开 `#define` 宏。
- 处理 `#if`、`#ifdef` 等条件编译。
- 删除注释，保留行号信息。

```c
#include <stdio.h>
#define PI 3.14159

int main(void) {
    printf("%f\n", PI * 2); // 预处理后 PI 被替换成 3.14159
    return 0;
}
```

只做预处理：

```bash
gcc -E hello.c -o hello.i
```

打开 `hello.i` 会看到 `stdio.h` 被展开成上千行声明，这就是头文件"体积大"的原因。

## 2.3 编译

编译阶段把预处理后的 C 代码翻译成汇编，同时做完整的语法与类型检查。

```bash
gcc -S hello.i -o hello.s
```

生成的 `hello.s` 是平台相关的汇编，例如 x86-64 下会看到：

```text
main:
    pushq   %rbp
    movq    %rsp, %rbp
    ...
    call    printf
```

⚠ **关键认知**：语法错误、类型不匹配、未声明标识符都在这个阶段报出，所以报错行号指向的是源码，而不是汇编。

## 2.4 汇编

汇编器把汇编文本翻译成机器指令，输出**目标文件**（`.o` 或 `.obj`）。目标文件里已经是机器码，但地址尚未最终确定。

```bash
gcc -c hello.s -o hello.o
```

目标文件包含三类内容：

| 内容 | 作用 |
|------|------|
| 代码段 `.text` | 函数机器指令 |
| 数据段 `.data`、`.bss` | 已初始化、未初始化的全局变量 |
| 符号表 | 记录函数与变量名，供链接使用 |

## 2.5 链接

链接器把多个目标文件和库合并，解析符号引用，最终生成可执行文件。

```bash
gcc hello.o -o hello
```

链接分两种：

| 方式 | 产物 | 特点 |
|------|------|------|
| 静态链接 | 库代码被复制进可执行文件 | 部署简单，体积大，更新需重编 |
| 动态链接 | 运行时加载 `.so` / `.dll` | 体积小，可共享，依赖环境 |

★ **关键认知**：`undefined reference to 'foo'` 是**链接错误**，不是编译错误。它表示某个函数被调用、也通过了编译，但链接器在所有目标文件和库中都找不到它的定义。

# 3. 工具链命令速查

## 3.1 GCC 与 Clang

两者命令高度兼容，日常可以互换。

| 选项 | 作用 |
|------|------|
| `-std=c17` | 指定 C 标准 |
| `-Wall -Wextra` | 打开常用警告 |
| `-Werror` | 把警告当错误 |
| `-g` | 生成调试信息 |
| `-O0` / `-O2` | 优化级别 |
| `-I dir` | 添加头文件搜索路径 |
| `-L dir` | 添加库搜索路径 |
| `-lname` | 链接名为 `libname` 的库 |
| `-o file` | 指定输出文件名 |

一个推荐的初学者编译命令：

```bash
gcc -std=c17 -Wall -Wextra -Werror -g hello.c -o hello
```

## 3.2 MSVC

在 Visual Studio 的"开发者命令提示符"中：

```bash
cl /std:c17 /W4 /Zi hello.c
```

| 选项 | 作用 |
|------|------|
| `/std:c17` | 指定 C 标准 |
| `/W4` | 较高警告级别 |
| `/Zi` | 生成调试信息 |
| `/I dir` | 添加头文件路径 |
| `/Fe:name.exe` | 指定输出名 |

⚠ **关键认知**：MSVC 对 C 标准的支持历史上落后于 GCC/Clang，部分 C11 特性默认关闭。跨平台项目应尽量使用两者都支持的公共子集，并在 CI 中分别构建。

## 3.3 一次完整构建

```bash
# 预处理
gcc -E hello.c -o hello.i

# 编译为汇编
gcc -S hello.i -o hello.s

# 汇编为目标文件
gcc -c hello.s -o hello.o

# 链接为可执行文件
gcc hello.o -o hello

# 运行
./hello
```

日常开发不需要手动分四步，`gcc hello.c -o hello` 会自动完成全部流程。分步执行的价值在于**观察中间产物**，排查问题时非常有用。

# 4. 最小可运行程序

## 4.1 完整代码

```c
#include <stdio.h>   // 声明 printf，预处理阶段展开

int main(void) {     // 程序入口，返回 int 给操作系统
    printf("Hello, C!\n"); // 向标准输出打印一行
    return 0;        // 0 表示正常退出
}
```

## 4.2 逐行说明

| 代码 | 含义 |
|------|------|
| `#include <stdio.h>` | 引入标准输入输出声明，尖括号表示系统头文件 |
| `int main(void)` | 主函数，`void` 表示不接受参数 |
| `printf(...)` | 格式化输出函数，`\n` 是换行符 |
| `return 0` | 返回退出码，非 0 通常表示失败 |

★ **关键认知**：`main` 的返回值不是给调用者看的，而是给**操作系统**看的。脚本和 CI 通过退出码判断程序是否成功，因此不要随意返回非 0，也不要在非 `main` 函数里写 `return 0` 当作"成功"。

## 4.3 编译并运行

```bash
gcc -std=c17 -Wall -Wextra hello.c -o hello
./hello
```

预期输出：

```text
Hello, C!
```

在 Windows 的 PowerShell 中运行：

```bash
gcc hello.c -o hello.exe
.\hello.exe
```

# 5. 常见错误与排查

| 现象 | 阶段 | 原因 | 修复 |
|------|------|------|------|
| `fatal error: stdio.h: No such file` | 预处理 | 头文件路径缺失或工具链未装 | 安装编译工具链，检查 `-I` |
| `expected ';' before ...` | 编译 | 漏分号、括号不配对 | 看报错行及其上一行 |
| `implicit declaration of function` | 编译 | 没包含对应头文件 | 补 `#include`，C99 后属于错误 |
| `undefined reference to 'foo'` | 链接 | 只声明未定义，或没链接库 | 补实现，或在命令末尾加 `-lfoo` |
| `cannot open output file` | 链接 | 程序正在运行，文件被占用 | 关闭进程后重试 |
| `Permission denied` | 运行 | 没有执行权限 | `chmod +x hello` |

⚠ **关键认知**：看到报错先判断**阶段**。预处理错误找头文件和宏，编译错误找语法和类型，链接错误找函数定义和库。阶段判断对了，排查范围立刻缩小一半。

# 6. 动手练习

1. 写一个输出自己名字的程序，分别用一条命令和四步命令编译，对比中间文件大小。
2. 故意删掉 `#include <stdio.h>`，观察 `printf` 的报错信息，理解"声明"和"定义"的区别。
3. 用 `gcc -E` 展开一个包含自定义头文件的程序，找到自己的宏被替换的位置。

# 7. 小结

| 概念 | 要点 |
|------|------|
| C 的定位 | 贴近硬件、静态类型、手动内存管理 |
| 预处理 | 展开头文件与宏，不做语法检查 |
| 编译 | 语法与类型检查，生成汇编 |
| 汇编 | 生成目标文件，符号未最终定位 |
| 链接 | 合并目标文件与库，解析符号 |
| 工具链 | GCC、Clang 命令兼容，MSVC 单独一套 |
