JSON 是接口传输和配置文件中最常见的数据格式，语法看起来简单，但精度丢失、重复键、安全反序列化等问题很容易踩坑。本篇从语法和类型讲起，帮助初学者具备读写、校验和排查 JSON 的基础能力。

# 1. JSON 是什么

## 1.1 定位与使用场景

JSON（JavaScript Object Notation）是一种**与语言无关的文本数据格式**，当前标准是 RFC 8259。它只描述数据，不描述行为。

典型用途：

| 场景 | 例子 |
|------|------|
| Web API | 请求体、响应体 |
| 配置文件 | 前端项目配置、工具配置 |
| 日志 | 结构化日志字段 |
| 消息队列 | 事件 payload |
| 数据交换 | 不同语言、不同系统之间传递数据 |

JSON 流行的重要原因是：语法简单、可读性好、几乎所有语言都有成熟解析库。

## 1.2 与 JavaScript 对象的关系

JSON 的语法来自 JavaScript 对象字面量，但二者不是一回事：

```javascript
// JavaScript 对象字面量：可以不加引号、可以有方法、可以注释
const user = {
    name: "alice", // 注释
    say() { console.log("hi"); }
};

// JSON：键必须双引号、不能有方法、不能有注释
{
    "name": "alice"
}
```

主要差异：

| 特性 | JavaScript 对象 | JSON |
|------|-----------------|------|
| 键 | 可加引号也可不加 | 必须双引号 |
| 字符串 | 单引号或双引号 | 只能双引号 |
| 注释 | 支持 | 不支持 |
| 函数/undefined | 支持 | 不支持 |
| 尾随逗号 | 允许 | 不允许 |
| `NaN`/`Infinity` | 支持 | 不支持 |

★ **关键认知**：JSON 是一种**数据交换格式**，不是 JavaScript 代码。不要用 `eval` 解析 JSON，也不要假设 JSON 文件能直接当作 JS 脚本运行。

# 2. 基本语法

## 2.1 对象与数组

对象用 `{}` 表示键值对集合：

```json
{
  "id": 42,
  "name": "alice",
  "active": true
}
```

数组用 `[]` 表示有序列表：

```json
{
  "tags": ["go", "java", "json"],
  "users": [
    {"id": 1, "name": "alice"},
    {"id": 2, "name": "bob"}
  ]
}
```

规则：

- 键必须是字符串，且用双引号。
- 键值对之间用逗号分隔。
- 最后一个成员后面**不能有逗号**。
- 对象和数组可以任意嵌套。

## 2.2 字符串与转义

JSON 字符串必须用双引号包裹：

```json
{
  "name": "alice",
  "quote": "她说：\"你好\"",
  "path": "C:\\Users\\alice",
  "unicode": "\u4f60\u597d",
  "newline": "第一行\n第二行"
}
```

常见转义：

| 转义 | 含义 |
|------|------|
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\/` | 斜杠，可转义也可不转义 |
| `\b` | 退格 |
| `\f` | 换页 |
| `\n` | 换行 |
| `\r` | 回车 |
| `\t` | 制表符 |
| `\uXXXX` | Unicode 码点 |

⚠ JSON 字符串中不能直接包含未转义的控制字符（例如裸换行）。需要换行时写成 `\n`。

## 2.3 数字与布尔值

JSON 只有一种数字类型，不区分整数和浮点数：

```json
{
  "int": 42,
  "negative": -7,
  "decimal": 3.14,
  "exponent": 1.2e3,
  "zero": 0
}
```

不允许的写法：

```text
01        // 不允许前导零
+1        // 不允许正号
.5        // 不允许省略整数部分
1.        // 不允许省略小数部分
0x1F      // 不允许十六进制
NaN       // 不允许
Infinity  // 不允许
```

布尔值只有两个：

```json
{"enabled": true, "deleted": false}
```

## 2.4 null

`null` 表示"空值"：

```json
{
  "name": "alice",
  "email": null
}
```

需要区分两种情况：

| 情况 | 示例 | 含义 |
|------|------|------|
| 字段缺失 | `{"name":"alice"}` | 没有提供 email |
| 字段为 null | `{"name":"alice","email":null}` | 明确提供了空值 |

★ **关键认知**：字段缺失和字段为 `null` 在业务上可能完全不同。例如 PATCH 更新时，缺失表示"不修改"，`null` 表示"清空该字段"。设计 API 时要明确约定。

# 3. 合法与非法示例

合法：

```json
{
  "id": 1,
  "name": "alice",
  "roles": ["admin", "user"],
  "profile": {
    "age": 18,
    "email": null
  }
}
```

非法及原因：

```json
{
  'name': 'alice'    // 键和字符串都不能用单引号
}
```

```json
{
  "name": "alice",   // 最后一个成员后不能有逗号
}
```

```json
{
  "name": "alice"    // 不能有注释
  // 这是注释
}
```

```json
{
  name: "alice"      // 键必须加双引号
}
```

```json
{
  "value": NaN       // 不允许 NaN
}
```

# 4. 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 单引号 | 解析器报 unexpected token | 全部改成双引号 |
| 注释 | 解析失败 | 删除注释，或用支持注释的 JSON5/YAML |
| 尾随逗号 | 解析失败 | 删除最后一个逗号 |
| 未加引号的键 | 解析失败 | 键加双引号 |
| BOM | 某些解析器报错或首字段异常 | 保存为无 BOM 的 UTF-8 |
| 中文乱码 | 字符显示错误 | 确认 UTF-8 编码 |
| 数字精度丢失 | 大整数末位变化 | 用字符串传输大整数 |
| 重复键 | 不同解析器取不同值 | 避免重复键，校验时检测 |

# 5. 动手练习

1. 手写一份包含对象、数组、字符串、数字、布尔值和 `null` 的 JSON。
2. 故意加入单引号、注释、尾随逗号，分别用 `jq` 或在线校验器观察报错位置。
3. 把一份 YAML 配置改写成 JSON，注意字符串引号和注释的处理。

```bash
# 使用 jq 校验并格式化
jq . data.json
```

# 6. 小结

| 类型 | 示例 | 注意 |
|------|------|------|
| 对象 | `{"key":"value"}` | 键必须双引号 |
| 数组 | `[1,2,3]` | 有序、可嵌套 |
| 字符串 | `"hello"` | 双引号、转义 |
| 数字 | `42`、`3.14` | 不区分整数和浮点 |
| 布尔 | `true`、`false` | 小写 |
| null | `null` | 表示空值 |

语法禁区：单引号、注释、尾随逗号、未加引号的键、`NaN`/`Infinity`、前导零。
