TOML 是 Rust 的 `Cargo.toml`、Python 的 `pyproject.toml` 以及大量现代工具共用的配置格式。它没有缩进陷阱，类型写得很直白，但表、点号键、表数组这些概念第一次见时容易混淆。本篇从定位和最小示例出发，把 TOML 1.0 的键值、表、数组、日期、字符串和注释一次讲清。

# 1. TOML 是什么

## 1.1 定位与设计目标

TOML（Tom's Obvious, Minimal Language）是一种**面向配置文件的文本格式**。它的目标不是替代 JSON 做网络传输，而是让人写配置时"一眼看懂、改起来不容易错"。

它的设计取舍很明确：

- **类型显式**：字符串必须有引号，数字就是数字，布尔值只能写 `true` / `false`。
- **结构显式**：用 `[table]` 和 `[[array]]` 表达层级，不靠缩进。
- **语法少**：没有锚点、没有多文档、没有隐式类型转换。
- **可注释**：支持 `#` 行注释，适合写清每个配置项的用途。

| 场景 | 例子 |
|------|------|
| Rust 工程 | `Cargo.toml` |
| Python 打包 | `pyproject.toml` |
| 静态站点 | Hugo 的 `config.toml` |
| 应用配置 | 数据库、日志、服务参数 |
| 工具链配置 | `rustfmt.toml`、`taplo.toml` |

★ **关键认知**：TOML 的核心价值是**用显式语法换掉隐式规则**。YAML 靠缩进和类型推断，写错时往往"能解析但含义变了"；TOML 要求你把引号、括号、表头都写出来，错了通常直接报语法错误。⚠ 代价是同样一份嵌套数据，TOML 写起来比 YAML 啰嗦。

TOML 看起来像"加强版 INI"，但它并不是 INI 的严格超集，而是一门有独立语义的小语言。它与 JSON、YAML 的详细取舍留到第 4 篇展开。

# 2. 最小示例与基本结构

## 2.1 一份能跑的配置

```toml
title = "TOML 示例"                 # 顶层键值对
enabled = true                      # 布尔值

[owner]                             # 表：一组相关键
name = "Alice"
email = "alice@example.com"

[database]
host = "127.0.0.1"
port = 5432
timeout_ms = 3_000                  # 数字下划线提升可读性

[[servers]]                         # 表数组：每个元素是一张表
name = "alpha"
ip = "10.0.0.1"

[[servers]]
name = "beta"
ip = "10.0.0.2"
```

逐段理解：

1. 第一个 `[owner]` 之前的 `title`、`enabled` 属于**根表**。
2. `[owner]` 开启一张新表，后面的键都挂在 `owner` 下，直到出现下一个表头。
3. `[database]` 同理，`host`、`port`、`timeout_ms` 都是它的子键。
4. `[[servers]]` 不是普通表，而是**表数组**；每写一次就向数组追加一个元素。

★ **关键认知**：TOML 的层级由**表头**决定，不由缩进决定。缩进只是为了好看，写多写少都不改变语义；这一点和 YAML 正好相反。

## 2.2 键值对与注释

最基本的单位是 `键 = 值`：

```toml
name = "alice"        # 字符串
age = 18              # 整数
active = true         # 布尔值
url = "https://example.com/#anchor"   # 引号内的 # 是普通字符
```

规则只有几条，但每条都要记牢：键在同一张表内必须唯一；键区分大小写；等号两边推荐各留一个空格；值不能为空。

⚠ **关键认知**：TOML 没有 `null`。需要表达"未设置"时，通常约定**省略该键**，由程序在读取时给默认值；不要试图写 `key = null`，它会直接解析失败。`#` 只有在字符串外部才是注释开始，URL 里的 `#` 放在引号内才安全。

# 3. 键的写法

## 3.1 裸键与引号键

**裸键**（bare key）只能由字母、数字、下划线和短横线组成：

```toml
name = "alice"
max-retry = 3          # 短横线合法
user_name = "bob"      # 下划线合法

"user name" = "alice"          # 含空格，必须加引号
"db.host" = "127.0.0.1"        # 点号在引号内是普通字符
'key with "quote"' = 1         # 单引号键，内部可含双引号
```

## 3.2 点号键

点号键（dotted key）用 `.` 表达嵌套，效果等同于开一张子表：

```toml
# 下面两行会创建 database 表及其子键
database.host = "localhost"
database.port = 5432

# 与表头写法等价，但二选一，不能同时写
# [database]
# host = "localhost"
# port = 5432
```

也可以直接写在根表里：

```toml
server.host = "0.0.0.0"
server.port = 8080
server.tls.enabled = true
```

★ **关键认知**：点号键是**语法糖**，它会创建中间表。`server.tls.enabled = true` 会依次创建 `server`、`server.tls` 两张表，再放入 `enabled`。⚠ 同一个键不能既用点号键定义、又用表头重复定义，否则会触发"重复定义"错误。

# 4. 值类型

## 4.1 字符串

TOML 有四类字符串，区别在"是否转义"和"是否跨行"：

| 写法 | 名称 | 是否转义 | 能否跨行 |
|------|------|---------|---------|
| `"..."` | 基本字符串 | 是 | 否 |
| `'...'` | 字面量字符串 | 否 | 否 |
| `"""..."""` | 多行基本字符串 | 是 | 是 |
| `'''...'''` | 多行字面量字符串 | 否 | 是 |

基本字符串支持常见转义，字面量字符串则原样保留内容：

```toml
path = "C:\\Users\\alice"       # 反斜杠要写两次
regex = '\d{4}-\d{2}-\d{2}'     # 单引号里反斜杠不用翻倍
raw_path = 'C:\Users\alice'     # Windows 路径推荐写法
```

多行字符串适合写说明、SQL、证书：

```toml
description = """
第一行
第二行，反斜杠续行会把换行和缩进吃掉 \
这一行会接在上一行后面
"""
```

⚠ **关键认知**：多行基本字符串会**自动去掉紧跟开引号的第一个换行**，所以 `"""` 后直接换行不会产生空行。行尾写 `\` 可以去掉换行和下一行的前导空白，常用来拼接长句。

## 4.2 数字与布尔

```toml
count = 42
million = 1_000_000        # 下划线可读性分隔
hex = 0xFF                 # 255
octal = 0o755              # 493
binary = 0b1010            # 10

pi = 3.14159
avogadro = 6.022e23
positive_inf = inf

enabled = true
disabled = false
```

★ **关键认知**：TOML 1.0 的整数按 **64 位有符号整数**设计，范围是 `-2^63` 到 `2^63-1`。⚠ 超出范围的数字应改用字符串或拆成多个字段；另外十进制整数不允许前导零，`0123` 是非法写法。

## 4.3 日期与时间

TOML 原生支持四种日期时间类型，写法遵循 RFC 3339：

```toml
offset_dt = 1979-05-27T07:32:00Z              # 带时区的日期时间
local_dt = 1979-05-27T07:32:00                # 本地日期时间，无时区
local_date = 1979-05-27                       # 只有日期
local_time = 07:32:00                         # 只有时间
```

★ **关键认知**：**带时区**和**不带时区**是两种不同的类型。带 `Z` 或偏移的表示一个绝对时刻；不带时区的只是一个"墙上时间"，解析器不会替你补时区。⚠ 做跨时区业务时，优先使用带偏移的写法，否则同一份配置在不同服务器上含义不同。

## 4.4 数组与内联表

数组用方括号，元素用逗号分隔，可以跨行并允许末尾逗号：

```toml
ports = [8000, 8001, 8002]
hosts = [
  "10.0.0.1",     # 每行一个，方便增删
  "10.0.0.2",
]
```

内联表用花括号在一行内写完一张表：

```toml
point = { x = 1, y = 2 }
user = { name = "alice", age = 18 }
```

★ **关键认知**：TOML 1.0 允许数组元素类型不同，比如 `mixed = [1, "two", true]` 是合法的。⚠ 内联表则严格得多：必须单行、不允许尾逗号，而且**定义后就是封闭的**，不能再通过 `[point]` 或 `point.y = 2` 扩展。

# 5. 表与表数组

## 5.1 标准表

表用 `[表名]` 声明，后面的键归属这张表：

```toml
[server]
host = "0.0.0.0"
port = 8080

[server.tls]
enabled = true
cert = "/etc/ssl/cert.pem"
```

子表 `[server.tls]` 的父表不需要提前声明，TOML 会自动创建。

★ **关键认知**：表头一旦出现，**后续所有键都归它管**，直到下一个表头。这也是为什么"根表键必须写在第一个表头之前"——表头之后就没有"根表"的位置了。

## 5.2 表数组

表数组用双括号 `[[名称]]`，每次出现都向同名数组追加一张表：

```toml
[[products]]
name = "Hammer"
sku = 738594937

[[products]]
name = "Nail"
sku = 284758393
```

表数组里也可以嵌套子表：

```toml
[[servers]]
name = "alpha"

[servers.tls]
enabled = true

[[servers]]
name = "beta"

[servers.tls]
enabled = false
```

★ **关键认知**：`[servers.tls]` 会挂到**最近一个** `[[servers]]` 元素上，而不是全部元素。⚠ 这是 TOML 里最容易写错的结构之一：想让每个服务器都有 TLS 配置，就必须在每个 `[[servers]]` 后面各写一次 `[servers.tls]`。

# 6. 常见错误

| 错误 | 现象 | 修复 |
|------|------|------|
| 重复定义同一个键 | `duplicate key` | 合并或删除重复项 |
| 同一张表定义两次 | `table redefined` | 把键合并到同一个表头下 |
| 内联表换行或加尾逗号 | 解析失败 | 改成单行，去掉尾逗号 |
| Windows 路径用基本字符串 | `\U` 被当成转义 | 用单引号或双写反斜杠 |
| 想写 `null` | 解析失败 | 省略键，由程序给默认值 |
| 表数组子表位置写错 | 配置挂到了上一个元素 | 在每个 `[[...]]` 后重新声明子表 |

# 8. 小结

| 概念 | 写法 | 要点 |
|------|------|------|
| 键值 | `key = value` | 同表内唯一，区分大小写 |
| 表 | `[table]` | 后续键归它管，父表自动创建 |
| 子表 | `[a.b]` | 等价于嵌套表 |
| 点号键 | `a.b = 1` | 语法糖，不能与表头重复定义 |
| 表数组 | `[[items]]` | 每次追加一个元素 |
| 字符串 | `"..."` / `'...'` | 双引号转义，单引号原样 |
| 日期 | `1979-05-27T07:32:00Z` | 带时区与不带时区是不同类型 |
| 数组 | `[1, 2, 3]` | 可跨行，允许尾逗号，可混类型 |
| 内联表 | `{ x = 1 }` | 单行、无尾逗号、定义后封闭 |
| 注释 | `# ...` | 字符串外的 `#` 才生效 |
