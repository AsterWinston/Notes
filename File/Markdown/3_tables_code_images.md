表格、代码块和图片是技术文档里出现频率最高、也最容易写错的三类元素。表格错一列就读不下去，代码块漏了语言标识就没有高亮，图片路径写错就是一个个红叉。本篇把这三块的语法、边界和工程实践讲透，重点放在"跨平台仍然正确"。

# 1. 表格

## 1.1 基本语法

GFM 表格由表头行、分隔行和数据行组成：

```markdown
| 姓名 | 年龄 | 城市 |
|------|------|------|
| 张三 | 18   | 北京 |
| 李四 | 20   | 上海 |
```

三条硬规则：

- 第一行是表头，不能省略。
- 第二行是分隔行，用 `-` 和可选的 `:` 构成。
- 表头单元格数量必须与分隔行一致，否则整张表不成立。

首尾的竖线可以省略，但建议保留，源码对齐更清楚。

★ **关键认知**：表格的**列数由分隔行决定**，不是由表头或数据行决定。数据行多出来的单元格会被丢弃，少的部分补空。所以出现"内容被吃掉"时，先数分隔行有几个 `---`。

## 1.2 对齐方式

在分隔行的冒号位置控制对齐：

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
| a      | b    | c      |
```

| 写法 | 效果 |
|------|------|
| `:---` | 左对齐 |
| `:---:` | 居中 |
| `---:` | 右对齐 |
| `---` | 默认，通常左对齐 |

数字列建议右对齐，便于比较大小；状态、标签类短文本居中；说明文字左对齐。

## 1.3 单元格内容

单元格里可以使用行内语法：

```markdown
| 命令 | 说明 |
|------|------|
| `npm install` | 安装依赖 |
| **必填** | 不能为空 |
| [文档](https://example.com) | 外部链接 |
```

限制也很明确：

- 不能放标题、列表、代码块等块级元素。
- 不能直接换行，需要换行时写 `<br>`。
- 单元格里的竖线必须转义成 `\|`。

★ **关键认知**：竖线转义对**行内代码同样生效**。写成 `` `a | b` `` 仍然会被当成两个单元格，必须写成 `` `a \| b` ``。这是表格里最反直觉的一点。

## 1.4 复杂表格的边界

Markdown 表格**不支持合并单元格**，也不支持表头分组、表注。遇到这些需求只有两条路：

| 方案 | 优点 | 代价 |
|------|------|------|
| 拆成多张简单表 | 可移植、易维护 | 结构表达力弱 |
| 改用 HTML `<table>` | 能合并、能加样式 | 源码难读、平台可能过滤 |

```html
<table>
  <tr>
    <th rowspan="2">模块</th>
    <th colspan="2">指标</th>
  </tr>
  <tr>
    <th>延迟</th>
    <th>吞吐</th>
  </tr>
</table>
```

⚠ 多数平台会保留基础 HTML 表格，但 GitHub 会过滤 `style`、`class` 等属性，样式类写法不可依赖。能用简单表表达时，不要为了合并单元格牺牲可维护性。

# 2. 代码

## 2.1 行内代码

用一对反引号包裹：

```markdown
执行 `npm run build` 生成产物。
```

内容本身含反引号时，外层用两个反引号，并在内侧留空格：

```markdown
``使用 ` 包裹的代码``
```

渲染结果是 `` ` `` 被正确保留。规则是：外层反引号数量必须多于内容中连续反引号的最大数量。

## 2.2 围栏代码块

三个及以上反引号或波浪号开启，关闭围栏长度不得小于开启围栏：

````markdown
```bash
# 启动开发服务器
npm run dev
```
````

```text
~~~text
用波浪号也可以，内部出现反引号时更省心
~~~
```

要点：

- 开围栏后可写语言标识，关闭围栏后不能写任何东西。
- 代码块内部不再解析 Markdown，`*`、`#`、`[]` 都原样保留。
- 代码块放在列表项里时，整体要缩进到列表内容对齐的位置。
- 四个空格缩进也能形成代码块，但无法标语言，新文档不建议使用。

## 2.3 语言标识

语言标识决定语法高亮和部分平台的复制行为。常见取值：

| 类别 | 标识 |
|------|------|
| 前端 | `html`、`css`、`scss`、`js`、`ts`、`jsx`、`tsx`、`vue` |
| 后端 | `java`、`go`、`python`、`rust`、`c`、`cpp`、`csharp` |
| 数据与配置 | `json`、`yaml`、`toml`、`ini`、`xml`、`sql` |
| 脚本与终端 | `bash`、`shell`、`powershell`、`bat`、`console` |
| 文档与图表 | `markdown`、`text`、`mermaid`、`latex`、`diff` |

★ **关键认知**：语言标识写错不会报错，只会**静默失去高亮**。比如把 JavaScript 写成 `javascrip`，页面照常显示，但代码全是黑白。文档评审时应该把"围栏是否有语言"列为检查项。

## 2.4 代码块里的特殊内容

代码块中要展示围栏本身时，外层用更长的围栏：

`````markdown
````markdown
```js
console.log("嵌套示例");
```
````
`````

⚠ 代码块里的长行不会自动换行，移动端会出现横向滚动。示例代码尽量控制在 80 到 100 列；必须保留长行时，在正文里说明"向右滚动查看"。

# 3. 图片与链接

## 3.1 图片语法

```markdown
![系统架构图](images/architecture.png "系统架构")
```

三个部分：

- `![alt]`：替代文本，图片加载失败或读屏时使用。
- `(src)`：图片地址，可以是相对路径、绝对路径或完整 URL。
- `"title"`：可选，鼠标悬停提示。

## 3.2 路径：相对与绝对

假设目录结构如下：

```text
project/
├── docs/
│   ├── guide/
│   │   ├── setup.md
│   │   └── images/
│   │       └── step-1.png
│   └── images/
│       └── logo.png
└── README.md
```

在 `docs/guide/setup.md` 中引用图片：

| 写法 | 解析结果 | 适用场景 |
|------|----------|----------|
| `images/step-1.png` | 同目录下的 images | 最推荐，随文件移动 |
| `../images/logo.png` | 上一级的 images | 跨目录共用资源 |
| `/images/logo.png` | 站点根目录 | 站点部署，子路径下易失效 |
| `https://cdn.example.com/a.png` | 远程地址 | 外部资源，注意稳定性 |

★ **关键认知**：相对路径以**当前 Markdown 文件所在目录**为基准，不是以仓库根目录为基准。同一个 `images/logo.png`，写在 `README.md` 和 `docs/guide/setup.md` 里指向的是两个不同位置。

⚠ 以 `/` 开头的根路径在 GitHub Pages 的项目子路径部署中经常 404，因为站点实际挂在 `/repo-name/` 下。除非确认部署在域名根目录，否则一律用相对路径。

## 3.3 相对链接与锚点

链接到同仓库的其他文档：

```markdown
[下一篇](4_math_and_diagrams.md)
[返回目录](../README.md)
```

链接到本文标题：

```markdown
[跳到对齐方式](#12-对齐方式)
```

锚点由标题自动生成，通用规则是：

1. 转小写。
2. 空格转连字符 `-`。
3. 去掉标点符号。
4. 保留中文等 Unicode 字符。
5. 同名标题追加 `-1`、`-2` 区分。

所以 `## 1.2 对齐方式` 的锚点通常是 `#12-对齐方式`。

⚠ 锚点生成规则**由渲染器决定**，不同平台对中文、点号、括号的处理并不完全一致。跨平台文档尽量链接到文件而不是细粒度锚点；必须链接锚点时，构建后实际点一次。

## 3.4 可访问性

alt 文本不是可有可无的装饰：

```markdown
![登录页面包含用户名、密码和提交按钮](images/login.png)
```

写法建议：

| 场景 | alt 写法 |
|------|----------|
| 信息型图片 | 描述图片传达的关键信息 |
| 功能型图片 | 描述点击后会发生什么 |
| 装饰型图片 | 留空 `![](decor.png)` |
| 公式截图 | 同时给出公式文本 |

★ **关键认知**：alt 的作用是**在图片不可见时替代图片传递信息**，不是给图片起名字。写 `alt="图片"`、`alt="截图"` 等于没有写。读屏用户和图片加载失败的读者都依赖它。

## 3.5 尺寸控制与 HTML

Markdown 原生语法不能指定宽高。需要控制尺寸时改用 HTML：

```html
<img src="images/architecture.png" width="720" alt="系统架构图" />
```

本仓库的约定是图片放在同级 `images/` 目录，并用：

```html
<img src="images/01.png" width="100%" alt="示意图" />
```

⚠ 一旦改用 HTML，就失去了 Markdown 图片语法的一部分可移植性，部分平台还会过滤属性。只在确实需要控制尺寸、居中或加说明时使用，普通配图优先 `![]()`。

# 4. 常见错误

| 现象 | 原因 | 修复 |
|------|------|------|
| 表格没渲染 | 分隔行缺失或列数不匹配 | 补分隔行，逐列对齐 |
| 单元格内容被截断 | 竖线未转义 | 写成 `\|` |
| 表格换行失效 | 单元格不支持直接换行 | 用 `<br>` |
| 代码没有高亮 | 语言标识拼错或缺失 | 改为正确标识 |
| 代码块提前结束 | 内容里有更长的围栏 | 外层加长围栏 |
| 图片显示红叉 | 相对路径基准搞错 | 以当前文件目录为准 |
| 锚点跳转失败 | 标题改过或规则不同 | 构建后实测，优先链文件 |
| 图片撑破布局 | 未限制宽度 | 用 HTML `width` 或压缩图片 |

# 5. 动手练习

1. 写一张包含四列、三种对齐方式的表格，其中一列放行内代码，代码内容包含竖线，验证转义是否正确。
2. 在 `docs/guide/` 下新建文档，分别用同目录、上级目录、根路径三种方式引用同一张图片，部署到子路径后观察哪些失效。
3. 写一个包含嵌套围栏的示例：外层四个反引号，内层三个反引号加 `js` 标识，确认渲染后内层围栏原样显示。

```bash
# 检查文档中的本地图片路径是否存在
npx markdown-link-check docs/**/*.md
```

# 6. 小结

| 元素 | 核心规则 | 最常见错误 |
|------|----------|------------|
| 表格 | 分隔行决定列数 | 竖线未转义、列数不齐 |
| 对齐 | 冒号位置控制 | 冒号写反 |
| 行内代码 | 反引号数量多于内容 | 内容含反引号时未加长 |
| 代码块 | 开围栏标语言，关闭围栏更长 | 语言拼错、围栏被提前闭合 |
| 图片路径 | 以当前文件为基准 | 误用根路径 |
| 锚点 | 标题自动生成 | 跨平台规则不一致 |
| alt | 替代图片传递信息 | 写成"图片" |
