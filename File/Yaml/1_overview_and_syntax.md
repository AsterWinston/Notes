YAML 是配置文件领域最流行的格式之一，Kubernetes、GitHub Actions、Docker Compose 都用它描述结构。它看起来比 JSON 干净，但缩进敏感、隐式类型多，初学时很容易写出"看着对、解析错"的文件。本篇从最小示例出发，讲清缩进、键值、列表、嵌套、注释和文档分隔符这些地基。

# 1. YAML 是什么

## 1.1 定位与使用场景

YAML（YAML Ain't Markup Language）是一种**面向人类阅读的数据序列化格式**。它只描述数据，不描述行为，与 JSON、XML 属于同一类工具。

它的设计目标很直接：

- 用缩进表达层级，减少括号和引号。
- 支持注释，适合需要说明的配置文件。
- 能表达映射、序列、标量三种基本结构。

典型用途：

| 场景 | 例子 |
|------|------|
| 容器编排 | Kubernetes 的 Deployment、Service |
| CI/CD | GitHub Actions、GitLab CI |
| 本地开发 | Docker Compose、devcontainer |
| 应用配置 | Spring Boot、ESLint、Ansible |
| 文档头信息 | 静态站点生成器的 front matter |

★ **关键认知**：YAML 的核心价值是**可读性**，代价是**结构靠缩进承载**。这意味着它对空白字符极其敏感，机器比人更容易被"差一个空格"骗到。写 YAML 的第一原则不是"少写字"，而是"结构清晰、缩进一致"。

## 1.2 与 JSON 的关系

YAML 是 JSON 的超集（严格说是 YAML 1.2 的 JSON schema 兼容 JSON）。任何合法 JSON 都是合法 YAML：

```yaml
{
  "name": "alice",
  "tags": ["admin", "user"]
}
```

但反过来不成立——YAML 有 JSON 没有的注释、锚点、多行字符串。日常使用中，YAML 更适合人手写，JSON 更适合机器传输。

⚠ **常见误解**：兼容不等于等价。YAML 的隐式类型、缩进规则、锚点等特性在转成 JSON 时会丢失或变形，不能假设两者可以无条件互换。

# 2. 最小示例与基本结构

## 2.1 最小示例

一份能解析的 YAML 可以简单到一行：

```yaml
name: alice
```

这表示一个映射（mapping），键是 `name`，值是字符串 `alice`。加几个字段：

```yaml
name: alice
age: 18
active: true
```

★ **关键认知**：YAML 文件在顶层通常是一个**映射**或**序列**。顶层写多个键，它们属于同一个映射；顶层写 `-` 开头的行，它们属于同一个序列。理解"当前缩进层级属于哪个父节点"是读懂 YAML 的关键。

## 2.2 缩进规则

YAML 用缩进表示层级，规则只有几条，但每条都要遵守：

| 规则 | 说明 |
|------|------|
| 只能用空格 | **禁止用 Tab**，多数解析器直接报错 |
| 同一层级缩进相同 | 差一个空格就是不同层级 |
| 子节点必须比父节点深 | 通常缩进 2 个空格 |
| 缩进量不强制 | 2、4 都行，但全文要一致 |

正确写法：

```yaml
server:
  host: 127.0.0.1
  port: 8080
```

错误写法：

```yaml
server:
    host: 127.0.0.1
  port: 8080      # 错误：两个子键缩进不一致
```

⚠ **关键认知**：YAML 不要求固定缩进宽度，但要求**同一父节点下的兄弟节点对齐**。混用 2 空格和 4 空格会让解析器把 `port` 当成 `host` 的子键，或者直接报结构错误。编辑器里建议开启"显示空白字符"。

## 2.3 键值对（映射）

映射由 `键: 值` 组成，冒号后面**必须有一个空格**：

```yaml
name: alice          # 正确
age:18               # 错误：冒号后没有空格，会被当成一个普通字符串
```

键可以是字符串、数字，甚至带引号：

```yaml
"user-name": alice
1: first
```

值的类型由内容决定，可以嵌套：

```yaml
database:
  host: localhost
  port: 5432
  username: admin
```

★ **关键认知**：冒号加空格是 YAML 的分隔符。`key:value` 没有空格时不是映射，而是一个普通的标量字符串 `"key:value"`。这是新手最常犯、也最难一眼看出的错误之一。

## 2.4 列表（序列）

列表用 `-` 开头，每个 `-` 表示一个元素：

```yaml
fruits:
  - apple
  - banana
  - orange
```

`-` 后面要有一个空格。列表可以缩进在键下面，也可以顶格：

```yaml
# 写法一：缩进在键下
fruits:
  - apple
  - banana

# 写法二：不缩进（合法，但可读性差）
fruits:
- apple
- banana
```

⚠ **关键认知**：`- ` 后面的空格不能省。`-apple` 是一个字符串，不是列表元素。另外，列表项之间的缩进必须一致，否则会被解析成嵌套。

# 3. 嵌套结构

## 3.1 映射套映射

```yaml
app:
  name: demo
  server:
    host: 0.0.0.0
    port: 8080
  database:
    host: db.local
    port: 5432
```

结构图：

```text
app
├── name: demo
├── server
│   ├── host: 0.0.0.0
│   └── port: 8080
└── database
    ├── host: db.local
    └── port: 5432
```

每深入一层就多缩进一级，读的时候按缩进对齐找父子关系即可。

## 3.2 列表套映射

列表元素是映射时，`-` 后面直接跟键：

```yaml
users:
  - name: alice
    age: 18
  - name: bob
    age: 20
```

注意 `age` 与 `name` 对齐（都在 `- ` 后面留出的位置上），表示它们属于同一个列表项。

★ **关键认知**：列表项内部的键要和 `name` 左对齐，而不是和 `-` 对齐。把 `age` 缩进到 `-` 的右边一层，会变成 `name` 的子键，结构就错了。

## 3.3 行内写法（flow style）

除了缩进写法（block style），YAML 也支持类似 JSON 的行内写法：

```yaml
tags: [admin, user, guest]
user: {name: alice, age: 18}
```

行内写法适合短小、不嵌套的数据；层级一深就难读，建议少用。

⚠ **关键认知**：block style 和 flow style 可以混用，但同一份配置里不要来回切换。评审代码时，风格不一致往往意味着有人在复制粘贴时没改干净。

# 4. 注释与文档分隔符

## 4.1 注释

注释以 `#` 开头，作用于该行：

```yaml
# 这是整行注释
name: alice      # 这是行尾注释
```

注意几点：

```yaml
url: http://example.com/#anchor   # 不是注释！因为 # 前面没有空白
color: "#ff0000"                  # 引号内的 # 也不是注释
```

★ **关键认知**：`#` 只有在**行首或前面有空白字符**时才是注释开始。写在字符串中间的 `#` 是普通字符，这一规则让 URL 和颜色值可以裸写，但也容易让人误以为整行被注释掉了。

## 4.2 文档分隔符

一个 YAML 文件可以包含多个文档，用 `---` 分隔：

```yaml
# 第一个文档
kind: ConfigMap
metadata:
  name: app-config

---
# 第二个文档
kind: Secret
metadata:
  name: app-secret
```

`...` 表示文档结束，通常可以省略：

```yaml
kind: ConfigMap
metadata:
  name: app-config
...
```

多文档常用于 `kubectl apply -f all.yaml` 这类场景，一个文件里放多个资源。

⚠ **关键认知**：`---` 必须独占一行（前面可以有空白），后面可以跟注释但不能跟其他内容。写成 `---kind: Pod` 会让解析器把它当成字符串，而不是分隔符。

# 5. 常见错误

| 错误 | 表现 | 修复 |
|------|------|------|
| 用 Tab 缩进 | 解析器报 "found character '\t'" | 全部换成空格，编辑器设 Tab 转空格 |
| 冒号后无空格 | 键值对变成普通字符串 | 写成 `key: value` |
| 同级缩进不一致 | 结构错位或报错 | 对齐同级兄弟节点 |
| 列表 `-` 后无空格 | 被当成字符串 `-xxx` | 写成 `- xxx` |
| 重复键 | 多数解析器后者覆盖前者，部分直接报错 | 避免重复，用校验工具检测 |
| 多文档缺 `---` | 两个文档被合并解析 | 每个文档前加 `---` |

# 7. 小结

| 概念 | 写法 | 要点 |
|------|------|------|
| 映射 | `key: value` | 冒号后必须有空格 |
| 序列 | `- item` | `-` 后有空格 |
| 缩进 | 2 空格 | 禁用 Tab，同级对齐 |
| 嵌套 | 逐层缩进 | 按缩进找父子 |
| 注释 | `# ...` | 需在行首或空白后 |
| 多文档 | `---` | 独占一行 |
| 结束 | `...` | 通常可省略 |

记住一句话：**YAML 的合法性一半靠语法，一半靠缩进**。下一篇进入类型与坑，讲清楚为什么 `NO` 会变成布尔值、`1.10` 会变成 `1.1`，以及引号和多行字符串该怎么用。
