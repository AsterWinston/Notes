YAML 最让人栽跟头的地方不是缩进，而是**类型**。你写的是 `NO`，解析器读出来是布尔值 `false`；你写的是版本号 `1.10`，解析器读出来是数字 `1.1`。这些都不是 bug，而是 YAML 的隐式类型解析在按规则工作。本篇把标量类型、隐式转换、引号和多行字符串讲透，帮你避开配置里最隐蔽的坑。

# 1. YAML 的类型系统

## 1.1 三种节点形态

YAML 的数据模型只有三类节点：

| 形态 | 英文 | 例子 |
|------|------|------|
| 标量 | scalar | `alice`、`18`、`true`、`null` |
| 序列 | sequence | `[a, b]` 或 `- a` |
| 映射 | mapping | `{k: v}` 或缩进键值 |

标量是叶子节点，序列和映射是容器节点。所谓"类型问题"，几乎全部发生在标量上——因为标量**默认不带类型标记**，解析器要根据内容猜。

## 1.2 隐式类型解析

当你写 `age: 18` 时，YAML 并没有显式告诉解析器"这是整数"。解析器按正则规则逐个匹配，命中哪条就是哪个类型：

```yaml
count: 18          # 匹配整数 → int
price: 3.14        # 匹配浮点 → float
enabled: true      # 匹配布尔 → bool
empty: null        # 匹配空值 → null
name: alice        # 都不匹配 → 字符串
```

★ **关键认知**：YAML 的标量默认是**字符串**，解析器先尝试把它解释成数字、布尔、null、日期，只有全部失败才当成字符串。这意味着"不加引号"就等于"把类型决定权交给解析器"，而不同解析器遵循的规范版本可能不同。

⚠ **关键认知**：隐式类型是 YAML 与 JSON 最大的行为差异。JSON 的类型由字面量严格决定（`"18"` 一定是字符串），YAML 的裸 `18` 一定是数字——想要字符串就必须加引号。

# 2. 标量类型

## 2.1 字符串

不加引号、单引号、双引号都可以表示字符串：

```yaml
plain: hello world
single: 'hello world'
double: "hello world"
```

三种写法的区别：

| 写法 | 转义 | 特殊字符 | 适用 |
|------|------|----------|------|
| 裸写 | 不支持 | 部分字符需避开 | 简单值 |
| 单引号 | 仅 `''` 表示单引号 | 保留字面内容 | 含 `:`、`#` 的值 |
| 双引号 | 支持 `\n`、`\t` 等 | 支持 Unicode 转义 | 需要控制字符 |

## 2.2 数字

```yaml
integer: 42
negative: -7
float: 3.14
exponent: 1.2e3
```

YAML 1.1 还支持几种容易出事的写法：

```yaml
octal: 0777          # YAML 1.1 中是八进制 511
sexagesimal: 1:30    # YAML 1.1 中是 90（60 进制）
hex: 0x1F            # 十六进制 31
```

★ **关键认知**：`0777` 在 YAML 1.1 里是八进制，在新版规范里可能被当成十进制或直接报错。涉及权限位、编号这类数字时，**加引号当字符串处理**最省心。

## 2.3 布尔

YAML 1.2 核心规范只认 `true` / `false`。但大量现实解析器（PyYAML、旧版 SnakeYAML）仍按 YAML 1.1 处理，于是下面这些都可能是布尔：

```yaml
a: true
b: false
c: yes       # YAML 1.1：true
d: no        # YAML 1.1：false
e: on        # YAML 1.1：true
f: off       # YAML 1.1：false
```

## 2.4 null

```yaml
empty1: null
empty2: ~
empty3:              # 冒号后什么都不写，也是 null
```

这三种写法在多数解析器中等价。

## 2.5 日期与时间

YAML 1.1 的 timestamp 类型能识别 ISO 8601 风格的值，例如 `2026-11-06`、`2026-11-06T10:30:00Z`。问题在于：有的解析器会把它转成日期对象，有的保留为字符串。跨语言传输时，日期类型经常变成"一边是字符串、一边是 Date"。

⚠ **关键认知**：如果日期只是数据而不是要用日期运算，**加引号**写成 `"2026-11-06"` 更稳定。真正需要日期类型时再用显式标签 `!!timestamp`。

# 3. 隐式转换的坑

## 3.1 Norway problem

最著名的 YAML 类型事故叫 **Norway problem**（挪威问题）。挪威的国家代码是 `NO`，写成：

```yaml
country: NO
```

在 YAML 1.1 解析器里，`NO` 被解析成布尔 `false`。于是"国家是挪威"变成了"国家是假"，下游逻辑彻底错乱。

同类受害者还有：

```yaml
- NO      # 挪威 → false
- no      # → false
- YES     # → true
- ON      # → true
- OFF     # → false
- Y       # YAML 1.1 中可能是 true
- N       # YAML 1.1 中可能是 false
```

★ **关键认知**：任何"看起来像布尔缩写"的字符串都要加引号。国家代码、开关名、缩写词是重灾区。修复方式很简单：

```yaml
country: "NO"
```

⚠ **关键认知**：不要指望换解析器解决问题。同一个文件可能被 Java、Python、JS、Go 的库分别读取，各库对 YAML 1.1/1.2 的支持不一致。**在源头加引号**是唯一可靠的办法。

## 3.2 版本号

```yaml
version: 1.10
```

很多语言里 `1.10` 是数字，而数字的 `1.10` 等于 `1.1`。于是版本号从 `1.10` 变成 `1.1`，语义完全变了。

```yaml
version: "1.10"     # 正确：字符串，保留原文
```

同理，`1.0` 会变成整数 `1`，后面的 `.0` 丢失：

```yaml
version: 1.0        # 可能被读成 1
version: "1.0"      # 正确
```

## 3.3 前导零

```yaml
zip: 01234          # 可能被当成八进制
```

电话号码、邮编、身份证号这类"数字但不参与运算"的值，一律加引号：

```yaml
zip: "01234"
phone: "+8613800138000"
```

# 4. 引号与转义

## 4.1 单引号

单引号内一切按字面处理，只有单引号本身需要转义成两个单引号：

```yaml
text: 'it''s a test'      # 解析为 it's a test
path: 'C:\Users\alice'    # 反斜杠不转义
```

## 4.2 双引号

双引号支持转义序列：

```yaml
text: "line1\nline2"
tab: "a\tb"
unicode: "\u4f60\u597d"
quote: "she said \"hi\""
```

常用转义：

| 转义 | 含义 |
|------|------|
| `\n` | 换行 |
| `\t` | 制表符 |
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\uXXXX` | Unicode 码点 |

★ **关键认知**：需要保留反斜杠时（Windows 路径、正则）**优先用单引号**，避免 `\U`、`\n` 被意外转义。双引号里 `\U` 是非法转义，会直接报错。

## 4.3 需要加引号的场景清单

| 场景 | 例子 | 原因 |
|------|------|------|
| 看起来像布尔 | `NO`、`on`、`yes` | 被隐式转成布尔 |
| 版本号 | `1.10`、`1.0` | 被转成数字丢精度 |
| 前导零 | `01234` | 可能被当八进制 |
| 含 `#` | `a#b` | 可能被当注释 |
| 含 `: ` | `a: b` | 冒号空格是分隔符 |
| 空字符串 | `""` | 裸写会变成 null |
| 日期/时间 | `2026-11-06` | 可能被转成日期对象 |

# 5. 多行字符串

## 5.1 字面块 `|`

`|` 保留换行：

```yaml
script: |
  echo step1
  echo step2
```

解析结果：

```text
echo step1
echo step2
```

## 5.2 折叠块 `>`

`>` 把单个换行折叠成空格，空行保留为换行：

```yaml
desc: >
  this is
  a long sentence
```

解析结果：

```text
this is a long sentence
```

## 5.3 chomping 指示符

块尾换行同样可控：默认 `|`/`>` 保留一个结尾换行（clip），加 `-` 去掉全部结尾换行（strip），加 `+` 保留全部（keep）。例如 `|-` 表示"保留内部换行、去掉结尾换行"。

★ **关键认知**：`|` 和 `>` 的差别只在**内部换行**：`|` 保留每一行换行，`>` 把相邻非空行之间的换行变成空格。写脚本、证书、SQL 用 `|`；写长描述用 `>`。结尾到底留不留换行，用 `-` 精确控制，不要靠猜。

⚠ **关键认知**：块内缩进必须比父键更深，且所有内容行要对齐。一旦某行缩进变浅，块就提前结束，后面的内容会被当成新键。

# 6. 常见错误

| 错误 | 实际解析 | 修复 |
|------|----------|------|
| `country: NO` | `false` | `"NO"` |
| `version: 1.10` | `1.1` | `"1.10"` |
| `zip: 01234` | 八进制数 | `"01234"` |
| `port: "8080"` 却拿去比较数字 | 字符串 vs 数字 | 按需统一类型 |
| `desc: >` 多行 | 换行被折叠成空格 | 需保留换行时用 `\|` |
| 双引号里写 `\U` | 非法转义报错 | 改用单引号或 `\\U` |
| 空值裸写 | `null` | 空字符串写 `""` |

# 7. 动手练习

1. 预测下面每个值被解析后的类型，再用 `yq` 或 Python 验证：

   ```yaml
   a: NO
   b: 1.10
   c: 0777
   d: on
   e: 2026-11-06
   ```

2. 把 "多行 SQL" 分别用 `|` 和 `>` 写一遍，对比解析结果里换行是否保留。

3. 修好下面这段配置，让 `version` 保持字符串、`zip` 保持前导零：

   ```yaml
   version: 1.0
   zip: 01234
   country: NO
   ```

# 8. 小结

| 主题 | 要点 |
|------|------|
| 隐式类型 | 裸标量会被猜成数字/布尔/null/日期 |
| Norway problem | `NO`/`on`/`yes` 可能是布尔，必须加引号 |
| 版本号 | `1.10` 会变 `1.1`，加引号 |
| 前导零 | 可能是八进制，加引号 |
| 引号 | 单引号字面、双引号转义 |
| 多行 | `\|` 保留换行，`>` 折叠换行 |

一句话原则：**数据是"字符串"时就明确加引号，把类型决定权留在自己手里**。下一篇进入锚点与合并键，讲怎么用 `&`、`*`、`<<` 复用配置而不复制粘贴。
